# Agent Note: 기본 데이터 삭제 기준 Codex 공유 액세스

Status: implemented

## 문제

기존 App 독립 실행형 메타데이터 프로세스는 상위 채팅을 유지하는 동안 위성 채팅을 생성하거나 대상을 삭제할 수 없습니다. 이전 격리 실험에서는 공유 런타임이 이러한 작업을 수행할 수 있음을 입증했지만 원래 App 열린 측면 탭에는 외부 닫는 인터페이스가 없습니다. 원본 폐쇄 요청 App 태그는 이미 사용 가능한 데이터 작업의 전달을 방지합니다.。

## 결정

사용자는 대상 기본 데이터의 실제 삭제가 우선하며 원본 데이터 폐쇄를 기반으로 하지 않음을 확인합니다. App 라벨이 차단 조건으로 열렸습니다. 이 결정은 부분적으로 대체됩니다.[런타임 및 태그 동기화 제안 공유](../../proposed/architecture/2026-11-08-codex-shared-desktop-runtime.md)수용 경계; 이전 기사는 원본 증거와 라벨 제한 사항을 유지하며 라벨 동기화가 달성되었으므로 다시 작성하지 않습니다.。

기본 네이티브 Codex 계정 관리는 기존 제어 프로세스를 재사용하고 명시적인 기본 연결 초기화를 제공합니다. 먼저 설치되어 있는지 확인하세요. CLI 의 Unix transport 및 proxy 기능, 작업 재확인, 기본 구성 디렉터리 및 고유 App 프로세스가 정상적으로 종료된 후 원본을 전달합니다. App 지원됨 CLI 경로 구성은 투명 어댑터를 시작합니다. 원본을 수정하지 마세요. App 설치 패키지, 계정 복사 없음, 기본 데이터베이스에 직접 쓰기 없음。macOS 이 기사를 활용하세요 Unix transport；Windows 사용[기존 App 보유 주식 stdio](../bug-fix/2026-11-12-windows-native-side-chat-writer.md)，수명주기와 물리적 증거는 별도로 기록됩니다. 독립적인 Codex 설정、VS Code 및 Linux 원래 액세스 권한 유지。

초기화된 작업 보호 버튼[Desktop 수명주기 범위 및 검증기간](../bug-fix/2026-11-10-desktop-initialization-task-audit.md)검증된 독립성을 구별하다 native CLI 카하라 App owner；계정 전환 보호가 축소되지 않았습니다. 역사적 후보 owner 스냅샷 확인 및 절대 기한 공유를 통한 제한된 병렬성 알 수 없는 상태가 여전히 다시 시작을 거부함。

Mac 원본의 어댑터 App 보류, 원래 초기화 및 기타 구성 유지, 기본 런타임만 유지 stdio 동일한 사용자에게 비공개로 설정 Unix socket。다른 CLI 명령, 시동 구성 감지 및 보조 초기화 투명 전송。Bridge 사용자가 명시적으로 생성하거나 삭제하는 경우에만 일시적으로 동일한 런타임에 연결됩니다. 연결을 끊어도 원본이 종료되지 않습니다 App。게이트웨이에 의해 시작된 경우에만 구성이 가능합니다. App 구성하면 적용되지만 정상적인 시작 중에 공유되지 않으면 다시 시작하는 것이 명시적으로 거부됩니다. writer。기본 macOS 및 Windows 사이드 채팅을 생성하려면 초기화도 필요합니다. 구성되지 않은 경우 사전에 명확한 메시지가 표시됩니다.“계정 관리 → Codex 기본 세션 연결 → 연결 초기화”，독립운전을 시작하지 않은 경우에는 원래의 App，커밋되지 않은 작업을 알 수 없는 쓰기로 간주하지 마세요. 다른 기록 메타데이터 작업은 원래 경로가 차단되지 않도록 초기화되지 않은 경우 원래 경로를 유지합니다. App 보유 이력 삭제。Linux 독립적으로 구성된 메타데이터 경로는 변경되지 않습니다.。

## 신분과 일

- 구성 및 실행 레코드는 개인 권한 및 원자성 쓰기를 사용합니다.。socket 디렉토리는 0700，실제 socket ～을 위한 0600。네이티브 링크 광고 경로와 호환 가능 `/tmp/codex-daemon-UID` 형식: 정규화된 상위 디렉터리 및 파일 이름 OS 경로 바이트 계산 SHA-256，링크 대상을 엄격하게 검증하고 디렉토리 권한을 보호하며 socket 신원; 링크나 진위 여부를 수정하지 마세요 socket 권한. 악수 전후 확인 inode 프로세스 세대와 함께。
- 레코드 바인딩 구성 디렉터리 실행、App、어댑터, 기본 프로세스 생성 및 socket。시작은 준비와 분리됩니다. 두 번째 프로세스는 시작 결과를 알 수 없거나 하위 프로세스가 아직 존재하는 경우 시작되지 않습니다. writer。기존 App 종료 시 런타임을 정상적으로 종료하고 강제로 종료하지 마십시오.。
- 동일한 주문형 뮤텍스는 초기화, 계정 전환/복구 및 동일한 구성 디렉터리에 대한 메타데이터 쓰기에 사용되며 연결, 작업 및 연결 끊김을 다루어 쓰기를 방해하는 수명 주기 작업을 방지합니다. 이 제품은 단일 게이트웨이를 전제로 설계되었습니다.；Release 및 Test 병렬화는 수용 환경일 뿐이며 잠금은 상주 모니터링을 추가하지 않습니다.。GUI／IPC 종료한 후 구성을 작성하거나 시작하기 전에 어댑터와 기본 런타임이 정상적으로 완료될 때까지 기다립니다. 시간 초과 후에도 계정을 덮어쓰지 않고, 자동으로 롤백하고 다시 시작하지 않으며, 강제 종료되지 않습니다.。
- 생성 및 삭제 시 기존 권한, 작업, 하위 범위, 확인 및 영구 원장을 계속 재사용합니다. 확실히 전송되지 않은 경우 재확인할 수 있습니다. 전송되었지만 결과를 알 수 없는 경우 자동으로 재생되거나 다른 런타임으로 다운그레이드되지 않습니다.。
- 성공 후에만 true를 보냅니다. Bridge 신원 attached 쿼리 캐시 무효화 알림. 가짜 원주민이 아닙니다. owner、방송을 보관하거나 삭제합니다. 삭제 결과를 판단하려면 원본 데이터와 과거 존재 여부를 확인하세요. App 닫히지 않은 빈 탭은 알려진 디스플레이 제한 사항입니다.。

## 대안

독립적인 단기 메타데이터 프로세스는 변경이 최소화되어 미보유 이력에 적합합니다. 기록 메타데이터 작업이 초기화되지 않으면 원래 경로가 유지됩니다. 사이드 채팅을 만들 때 먼저 실시간 부모 채팅을 얻습니다. owner，독립형 프로세스로는 다음 문제를 해결할 수 없습니다. owner 의 active writer 충돌하므로 기본값 macOS 사이드 채팅은 공유 연결을 초기화해야 합니다. 전반적인 상황 WebSocket 주소는 어댑터를 생략할 수 있지만 원본은 App 기계의 일부를 비활성화합니다 IPC/조정되었으므로 채택되지 않았습니다. 원본을 수정해서 App 인터페이스 탭을 닫거나 이벤트를 위조하면 유지 관리 및 신원 위험이 증가합니다. 사용자는 실제 삭제 결과가 우선하며 사용되지 않는다는 점에 동의했습니다.。

App 원래 테스트 기록을 읽고 동일한 런타임을 유지하기 위해 연결을 끊었다가 다시 연결하고 정상적으로 종료하여 종료를 완료하며 모델 메시지가 전송되지 않습니다. 설치 예약됨 36 보호된 프로필 및 rc3 대체 패키지, LAN 및 고정 HTTPS 둘 다 최종 리소스와 원래 인증 경계를 반환합니다. 주인 App 기존 실행 및 의사 결정 작업으로 인해 액세스가 아직 초기화되지 않았으며 다시 시작되지 않았습니다. 완성된 설치는 기본 설치와 동일하지 않습니다. ## 영향

공유 모드는 새로운 기능을 추가합니다 App 보유된 투명 어댑터 및 기본 바이트 프록시에는 추가 프로세스 및 직렬화 오버헤드가 있습니다. 초기화되지 않으면 실행되지 않으며 백그라운드 폴링이 추가되지 않습니다. 초기화하려면 원본이 필요합니다. App 유휴 상태이고 정상적으로 재부팅됩니다. 현재 마스터 App 아직 전환되지 않았습니다. 크로스 플랫폼 및 일반 외부 실행은 자동으로 공유 설정을 상속하며 항목이 전달되지 않습니다.。
