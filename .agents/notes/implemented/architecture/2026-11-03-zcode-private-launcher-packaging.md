# Agent Note: Mac Test 의 ZCode 프라이빗 파이프라인 개시자가 게이트웨이 서명에 바인딩되어 있습니다.

Status: implemented

## 문제

Launch Services 원본을 보관할 수 있음 App 시스템 ID는 있지만 게이트웨이의 ID는 넣지 않습니다. 3、4 파일 설명자가 제공됩니다. Electron 디버깅 파이프라인. 반면에 확인해 보세요. Unix socket 사용자 ID를 사용하면 동일한 사용자가 있는 다른 프로그램이 실행기에서 기본 제어 권한을 요청할 수 있습니다.。

## 결정

Mac Test 바깥층에 App 시스템 배경에서만 시작되는 하위 패키지를 포함합니다. 독립적인 서명된 게이트웨이 프로세스는 파이프라인을 보유하고 있으며 실행 프로그램은 게이트웨이가 지정한 원본 서명과 해당 실행 파일만 허용합니다. ZCode。게이트웨이는 원래 창에서 프로토콜, 작업 공간 ID, 명령 및 수신 인터페이스를 확인합니다. 설치 패키지의 릴리스 버전 번호는 판단에 참여하지 않습니다. 런처는 다음을 사용하여 일회성 요청을 합니다. socket 사용자, 권한, 피어 프로세스 감사 토큰, 실제 이미지 및 코드 서명이 모두 일치하면 두 설명자가 전달되고 원본 PID 구현하다 ZCode。사용자는 추가 보조 애플리케이션을 설치할 필요가 없습니다.。

먼저 게이트웨이 바이너리 서명을 완성한 후 마지막 서명을 추가하세요. CodeDirectory 런처의 요약 아카이브 Info.plist，마지막으로 스타터와 외부 레이어에 서명합니다. App。Mac Test 빌드는 명시적으로 호출될 수 있습니다. prepare 및 verify 두 단계. 공식 빌드에 대한 최종 서명 순서는 아직 수정되지 않았으므로 런처가 아직 로드되지 않습니다. 앱이 일반 설치 또는 기존 접근성 기능을 사용할 수 없습니다. helper 개인 파이프를 사용 가능한 것으로 취급。

## 대안

매개변수가 있는 하위 프로세스를 정상적으로 직접 처리합니다. App 스타트업은 증명할 수 없다 Launch Services 신원. 프로세스 이름, 사용자 또는 bundle 또한 ID는 다른 곳에 있는 동일한 이름의 프로그램을 구별할 수 없습니다. 제3자에게 ZCode 고정 독립형 CDHash 동일한 지원 버전의 다른 공식 아키텍처는 제외됩니다. 여기에서 공식 확인하세요 Developer ID、설치 경로 및 실행 파일。

## 영향

지향성 서명 고정 장치로 신원 확인 Test 패키지의 게이트웨이는 피어 ID 확인을 완료할 수 있으며, 다른 위치에 복사된 동일한 바이너리는 거부되며, 패키징 후 교체된 게이트웨이 바이너리는 원래 다이제스트 확인을 통과할 수 없습니다. 요청이 없으면 Naked 부팅이 즉시 종료됩니다. 다양한 릴리스 버전을 시뮬레이션할 때도 프로세스 및 작업 검증이 수행됩니다. 프로토콜 기본 버전, 세션 ID 또는 명령 수신 인터페이스가 일치하지 않으면 액세스가 거부되고 첨부 파일, 모델 또는 Skill 인터페이스할 때 텍스트 세션을 계속 사용할 수 있도록 하세요. 임시 디렉토리, 자체 서명 및 Unix socket，미운영실적 ZCode。잠금 화면 시작 및 중지와 기본 세션 액세스는 기능 승인에 따라 별도로 처리됩니다.。
