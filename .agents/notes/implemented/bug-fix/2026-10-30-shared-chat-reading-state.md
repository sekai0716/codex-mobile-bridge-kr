# Agent Note: 채팅 업데이트는 안정적인 노드를 공유하며 활성 독서 위치는 유지됩니다.

Status: implemented

## 문제

DSH 생각 요약이 확장되고 스크롤된 후 다음 백그라운드 동기화는 요약을 다시 맨 위로 가져옵니다.。v2.1.7 데스크톱 세션 페이지는 변경되지 않은 노드를 재사용하지만 여전히 전체 메시지 컨테이너를 호출합니다. `replaceChildren`，이 노드를 그대로 두고 문서로 들어갑니다. 브라우저의 합성 긴 다이제스트에서 실제 렌더링 기능을 분리하면 정확히 동일한 메시지도 표시됩니다. `scrollTop` ～에서 200 ～이 되다 0；확장된 상태는 그대로 유지됩니다. 원래의 Node DOM 설비는 이 브라우저 레이아웃 동작을 에뮬레이트하지 않으므로 노드 ID와 확장 상태를 확인하는 것만으로는 문제를 드러내지 못했습니다.。

Codex 타임라인은 원래 변경되지 않은 노드를 건너뛰었지만 콘텐츠가 변경된 경우에만 확장된 상태를 유지했습니다. 두 경로는 공유되지 않습니다.“읽고 있는 활동의 텍스트가 업데이트로 인해 다시 맨 위로 이동하면 안 됩니다.”계약。

## 결정

`web/features/chat/activity.js` 공유 제공 `syncChatMessageNodes`、`captureChatActivityState` 및 `restoreChatActivityState`，의존하다 Codex 타임라인과 Claude/DSH 세션 페이지가 직접 사용됩니다. 안정적인 메시지 키는 현재 채팅 컨테이너로 제한됩니다. 동일한 위치의 동일한 노드는 제거되거나 다시 삽입되지 않습니다. 실패한 노드만 삭제하고 필요한 노드를 대상 순서대로 삽입하거나 이동합니다.。

동일한 키 메시지를 교체하거나 기존 노드를 이동하기 전에 활성 접힌 항목의 확장 상태와 수직 및 수평 스크롤 오프셋을 읽고 장착이 완료된 후 복원하십시오. 콘텐츠가 짧아지면 브라우저는 새로운 스크롤 가능 범위에 따라 오프셋을 자릅니다.。Codex 활성 텍스트 비동기 완성 및 도구 이미지 표시 전환도 상태 유지 기능을 재사용합니다. 채팅을 전환하거나 타임라인을 재설정할 때 이전 컨테이너를 먼저 지우고 세션 간에 동일한 키의 읽기 상태를 상속하지 않습니다.。

공유 기능은 두 경로 모두에 로드된 채팅 활동 모듈에 배치되며 새 리소스는 추가되지 않습니다. URL、네트워크 요청, 타이머 또는 공급자 분기. 각 클라이언트는 계속해서 기본 데이터 변환을 담당합니다.，Codex 커서, 페이징 및 델타 프로토콜은 다음과 함께 작동합니다. Claude/DSH 스냅샷 프로토콜은 동일하게 유지됩니다. 외부 채팅의 앵커링 규칙과 팔로우 규칙은 각각 계속 처리됩니다.。

持续跟随最新内容时，超过 240 条的显示窗口可以滑动。Codex 保留最近 160 条及其原 epoch 游标，移除更早的节点和正文详情，向上读取仍经既有分页入口。共享桌面会话页只在当前原生页提供有效 before 游标时收回已加载前缀，保留当前页及其原生游标；没有分页能力的接入不伪造历史游标。阅读旧页、选择文本或历史请求未完成时不裁剪。此处限制的是实时跟随中的前端增长，不裁剪原生补丁基底，不声称当前 native 完整快照已变成分页传输。

## 备选方案

- 각 페이지는 각 요약의 스크롤 값을 자체적으로 저장하고 복원합니다. 표면이 덜 수정되고 오프셋이 보상될 수 있습니다. 그러나 동일한 읽기 규칙을 복사하고 변경되지 않은 노드를 문서 외부에 계속 남겨두면 안정적인 노드와 내부 브라우저 상태를 유지할 수 없으므로 사용되지 않습니다.。
- 전체 데스크톱 세션 마이그레이션 Codex 타임라인: 더 많은 렌더링 코드를 통합할 수 있습니다. 그러나 여기에는 다양한 기록 인터페이스, 커서, 텍스트 페이징 및 요청 상태가 포함되어 이 스크롤 결함의 복구 범위가 확장되므로 두 가지 모두에 실제로 공통적인 노드 업데이트 규칙만 추출됩니다.。

## 시험

`tests/browser/chat-reading-state.browser.js` 3개 세션에 대해 사실적인 렌더러와 제작 스타일을 사용하여 변경되지 않은 새로 고침, 응답 추가, 기록 미리 추가, 시퀀스 변경, 다이제스트 증가, 메타데이터 업데이트, 본문 단축 및 채팅 전환을 확인합니다. 변경되지 않은 새로고침이 계속 통과됩니다. MutationObserver 메시지 컨테이너에 하위 노드 제거 및 재삽입이 없는지 확인합니다. 데스크탑 스냅샷은 다른 메시지를 덮어쓰고 제거합니다.；Codex 활동 확장 후 비동기 본문 읽기에서는 합성 응답을 사용합니다.。

기존의 기록 페이징 브라우저를 동일한 그룹에 유지하고 이를 반환하여 텍스트 로딩이 현재 상태 및 초안과 격리되는지 확인합니다.。Node DOM 고정물 완성 기준 `firstChild` / `nextSibling` 시뮬레이션이 아닌 행동 DOM 실제 브라우저 증거 대신 스크롤 값이 사용됩니다. 구체적인 실행 결과는 다음에 기록됩니다. `.tmp/dsh-reasoning-scroll-20261030/`。Chromium/WebKit 회귀는 다음과 같지 않습니다. iPhone 실제 기계, 설치됨 Test 아니면 정식 버전이 업데이트됐나요？。

네이티브 지향 인증：208 개 Node 왕복 패스；Chromium/WebKit 의 1280px 및 390px 총 조합 8 각 읽기 상태 사용 사례 세트가 실행되는 브라우저 사용 사례가 전달됩니다. 64 어설션 및 기존 기록 페이징 덮어쓰기。102 노트의 디렉토리, 형식 및 상대 링크 확인을 통과하고 아카이브 봉인 확인을 통과했습니다.。

持续窗口回归另以 Chromium/WebKit、1280px/390px 共 8 组运行，Codex 与 Claude/DeepSeek/Antigravity 各连续刷新 621 次，跟随最新时消息节点最多 240。覆盖原游标回取、草稿与当前确认请求、选择文本、向上阅读、分页处理中及手动历史保护；没有原生游标时不裁剪。对应 221 项 Node 回归通过。证据在 `.tmp/recovery-20261116/history-cache/sliding-window-report.json`；此处没有验证或缩小原生完整快照。

## 影响

未变化的消息不再反复脱离文档；思考摘要、工具活动与已折叠上下文共用阅读状态规则。每轮更新仍需比较已加载的消息；持续跟随最新页时使用有界窗口，主动浏览的历史不被后台更新移走。只有替换或移动的活动项读取并恢复滚动偏移，不为每个摘要增加监听器。本修复不改变轮询频率、控件布局、权限、发送与原生会话生命周期。

역사적 기록 감사：[네이티브 컨텍스트 접기](../feature/2026-10-29-native-context-folding.md)본 글과 부분적으로 겹치며, 계속해서 소스 식별 및 기본 접기를 제한하고, 여기서는 읽기 상태 계약을 참조합니다.；[기본 작업 상태 프롬프트 공유](../feature/2026-10-29-shared-chat-progress.md)동일한 소스 코드 모듈에 위치하더라도 제약 실행 상태 표시는 여기서 노드 수명 주기 결정과 겹치지 않으며 변경되지 않습니다. 목록 새로 고침, 파일 미리 보기 스크롤 및 수동적 기록 읽기 기록은 각각 다른 컨테이너 및 읽기 경계를 다루며 이 문서로 대체되지 않습니다. 폐기하거나 보관해야 할 제안서는 없습니다.。

채팅이 처음 열릴 때 읽은 기록이 없다는 것은 최신 뉴스를 따르는 것을 의미합니다. 제로 오프셋은 사용자가 실제로 맨 위까지 읽은 후에만 발생합니다. 사진의 지연된 디코딩은 타임라인 높이를 변경합니다. 최신 내용을 따를 때는 맨 아래에 머무르고 위쪽으로 읽을 때는 표시되는 메시지로 위치를 복원합니다. 공유 세부 정보가 로드되지 않으면 기존 제목, 초안 및 캐시가 유지되며 동일한 프롬프트 영역을 사용하여 재시도를 제공합니다.。390 픽셀 뷰포트 Chromium 및 WebKit 모든 표지 첫 번째 열기, 위로 슬라이딩 및 그림 지연 디코딩。
