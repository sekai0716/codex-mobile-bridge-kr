## 문제

게이트웨이가 시작되고 클라이언트 페이지가 새 창에서 처음으로 열릴 때마다 설치가 다시 열거됩니다. `discovered` 매니페스트는 다시 시작 시 디스플레이 캐싱을 담당하지 않습니다. 정상적인 연결 상태 폴링과 설치 검색은 혼동되기 쉽습니다.。Antigravity 자동 검색에만 들어가고 공유 추가 양식에는 액세스하지 않습니다. 공식 새 버전 CLI 에 설치됨 `.gemini/bin/agy`，IDE 2.6 같은 프로그램을 사용해서 hub 모드에서는 원래 파인더만 허용합니다. `language_server`，이 운영 양식이 누락됩니다.。

## 결정

기존에 저장된 검색 규칙 버전 및 비밀이 아닌 설치 입력이 포함된 설치 매니페스트 `desktop-sessions/settings.json`。시작 시 입력이 동일하고 규칙 버전도 동일하며 알려진 프로그램 경로가 여전히 존재하는 경우 목록이 재사용됩니다. 처음으로 목록이 없거나 규칙이 업그레이드되거나 등록 경로가 변경되거나 알려진 프로그램이 사라지거나 사용자가 다시 검색하면 목록이 재발견됩니다. 새 창은 기존 상태를 먼저 읽고 목록이 확실히 누락된 경우에만 처음으로 검색합니다. 게이트웨이를 닫은 후 로컬 관리도 이 유효 목록을 사용하는 데 우선순위를 갖습니다. 발견된 결과가 2초 동안 프로세스 또는 작업 증거가 아닙니다./작업을 계속하기 위해 쓰기 전 15초 동안 연결 상태 새로 고침, 알림 및 실시간 확인。
