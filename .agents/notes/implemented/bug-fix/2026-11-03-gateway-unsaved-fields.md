# Agent Note: 게이트웨이 저장 열에는 저장할 수 있는 필드만 표시됩니다.

Status: implemented

## 문제

클라이언트 계정 편집기는 초기 스냅샷 이후 게이트웨이 설정 양식에 연결됩니다. 이전 저장 표시줄은 양식의 모든 입력 항목을 열거하고 다음을 사용합니다. DOM ID 스냅샷 키로. 다중 아니오 ID 계정 컨트롤은 키를 공유합니다. 다른 기본값을 읽은 후에는“클라이언트 및 액세스”수정된 것으로 표시합니다. 페이지가 클라이언트 목록으로 돌아온 후에도 편집기는 여전히 숨겨진 하위 페이지에 있습니다. 이전 저장 작업을 통해 계정 인터페이스에 의해 독립적으로 저장되는 필수 필드를 확인할 수도 있습니다.。

## 결정

게이트웨이 설정은“구성 저장”컨트롤이 제출되었습니다. 플래그는 입력 이벤트 수가 아닌 현재 값과 저장된 스냅샷의 차이에서 발생합니다. 연결 추가 및 삭제, 연결 필드 및 LAN 네트워크 카드가 별도로 나열됩니다. 저장 표시줄에는 페이지, 필드 또는 연결 이름만 표시됩니다. 비밀번호、Token 다른 필드의 값은 프롬프트에 입력되지 않습니다. 항목을 클릭하면 해당 페이지, 클라이언트 및 접기 영역이 열리고 컨트롤에 초점이 맞춰집니다. 원래 값으로 다시 변경하거나 저장하면 자동으로 지워지며, 제출 중 후속 편집 내용은 유지됩니다.。

## 대안

현재 계정 편집자를 제외 목록에 추가하면 이러한 오탐지를 제거할 수 있지만, 별도의 패널을 추가하면 계속해서 발생하며 실제로 변경된 필드를 사람들이 찾을 수 없게 됩니다.。

## 영향

격리된 데스크톱 페이지 테스트에서는 이전 코드에서 계정 컨트롤을 동적으로 로드하여 발생하는 잘못된 경보를 재현했습니다. 현실 Chromium 렌더러는 시뮬레이션 백엔드와 협력하여 계정 페이지 로딩이 깔끔하게 유지되고 개요에서 접힌 페이지로 돌아가는지 확인합니다. Codex 데이터 디렉토리 및 포커스, 원래 값을 복원하고 마크를 지우고 저장합니다. 게이트웨이 모델, 자격 증명 저장소 및 클라이언트의 각 저장 인터페이스는 수정할 필요가 없습니다.。
