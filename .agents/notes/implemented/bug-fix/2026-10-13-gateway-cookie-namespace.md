# Agent Note: 게이트웨이 세션 Cookie 인스턴스별로 격리

Status: implemented

## 문제

두 개의 로컬 게이트웨이가 동일한 것을 사용할 수 있습니다 IP 포트는 다르지만 브라우저와 WebView 의 Cookie 포트별로 격리되지 않습니다. 결정된 `codex_mobile_session` 이름을 사용하면 나중에 로그인한 게이트웨이가 이전 게이트웨이의 로그인 상태를 덮어쓰게 됩니다.。

## 결정

게이트웨이는 자체적으로 `auth-sessions.json` 중간 지속성 저장 무작위 `cookieName`。부팅할 때마다 변경됩니다. `instanceId` 비밀번호 정책 수정으로 분리되어 변경되지 않습니다. 새 로그인은 이 이름으로만 발급됩니다. 요청은 값이 유효하지 않은 경우에도 이전 이름으로 돌아가지 않고 이 이름보다 우선합니다. 단지 오래 된 Cookie 토큰이 기본 게이트웨이 세션 테이블에서 여전히 유효한 경우에만 마이그레이션이 허용되고 다음 성공적인 응답으로 전달됩니다. 로그오프하면 로컬 이름만 지워집니다. 다른 게이트웨이가 이전 이름을 가질 수 있습니다.。

`/api/auth` 뒤로 `cookieName` 기본 클라이언트가 저장된 연결 주소에 따라 선택하려면 Cookie。Android 및 iOS 인증이 성공한 후에 이름이 기록됩니다. 이전 게이트웨이 및 경로 격리 릴레이는 여전히 이전 이름을 사용합니다. 알림, 다운로드, 연결 검색 및 제거 프로세스에서는 주소 이름을 사용하며 일시적으로 ID 지속적인 정체성으로。

## 대안

그냥 무작위로 `instanceId` 넣다 Cookie 이름은 동시 프로세스를 즉시 구별하지만 게이트웨이를 다시 시작하려면 전화기를 다시 페어링해야 하므로 영구 로그인이 위반됩니다. 포트별로 설정 Cookie 때문에 실현 불가능 Cookie 프로토콜은 포트를 격리하지 않습니다.。

## 영향

동일한 호스트에 있는 여러 게이트웨이가 공존하고 각각의 로그인을 유지할 수 있습니다. 기존 토큰은 유효 기간 내에 조건부로 마이그레이션됩니다. 공개 추가 Cookie 이름은 인증 비밀이 아닙니다. 기본 클라이언트는 연결 주소별로 이름 매핑을 유지해야 하며 실제 장치의 Cookie 플랫폼 구축을 통해 스토리지 동작을 검증해야 합니다.。
