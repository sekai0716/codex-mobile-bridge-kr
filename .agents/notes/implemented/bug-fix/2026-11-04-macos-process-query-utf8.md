# Agent Note: macOS 프로세스 ID 쿼리가 수정되었습니다. UTF-8 하위 프로세스 환경

Status: implemented

## 문제

데스크톱에서 실행됨 Test 아니요 LANG、LC_CTYPE、LC_ALL。기본 C 지역 아래，macOS `ps` 중국어 디렉토리를 다음과 같이 출력하십시오. `M-...` 이스케이프 리터럴, 커널 ID는 실제 경로를 반환합니다. 개인 파이프는 다음과 같이 서명됩니다. PID 확인을 통과한 후에도 다음 동작과 함께 명령 역할 비교가 계속 실패합니다. `Wrong private ZCode service role`。이는 다른 게이트웨이 실행 경로에 속하기 때문에 이전 파이프가 거부되는 것과는 다른 두 가지 이유입니다.。

## 결정

`bridge/platforms/macos/desktop.py` 정확한 프로세스 목록 PID 명령 쿼리는 하위 프로세스에 대해서만 설정됩니다. `LC_ALL=en_US.UTF-8`，그리고 명시적으로 누르세요 UTF-8 디코딩. 다른 환경 항목을 유지하고 시스템의 로케일이나 호출 프로세스를 수정하지 않습니다. 커널 ID와 사용자를 유지하면서 전체 경로와 매개변수를 축어적으로 계속 비교합니다.、PID 생성, 서명 및 역할 확인, 거부를 점유 가능한 무료 채널로 처리하지 않음。

## 대안

묶음 `ps` 이스케이프된 텍스트를 바이트로 복원하려면 모호성을 처리해야 하며 다른 경로를 동일한 대상으로 잘못 판단할 수 있으므로 사용되지 않습니다. 역할 비교를 무시하면 표면적인 오류는 제거되지만 액세스 경계가 약화되어 사용할 수 없습니다. 패키징 스크립트에만 설정 LANG 사용자가 그럴 것이라는 보장은 없습니다. Finder、로그인 시작 또는 다른 로케일 환경 시작의 결과이므로 공유 쿼리 경계에서 하위 프로세스 환경이 수정되었습니다.。

## 검증

동일한 실제 테스트 수신 구성 요소 PID 커널 경로는 다음과 같습니다. UTF-8 `ps` 매개변수는 완전히 일관됩니다. ～에 `LC_ALL=C` 아래에서는 동일한 경로가 이스케이프됩니다. 실행 중인 게이트웨이에는 3개의 영역 변수가 없는 것으로 확인되었습니다. 4개의 프로세스 쿼리 반환이 전달됩니다. 2초 후에 자동으로 종료되는 또 다른 독립 프로세스가 사용됩니다. C 환경에서는 중국어 매개변수가 그대로 유지되고 호출자 환경이 변경되지 않은 상태로 유지되는지 확인합니다. 이 확인은 운영상 사실이 아닙니다. Agent，또한 모델 메시지를 보내지 않습니다.。

최종 서명 Test 128.10 고정된 쿼리 모듈은 동일한 중국어 프로브를 독립적으로 전달합니다. 8790 게이트웨이가 정상적으로 시작되고 중지됩니다. 현실 8788 콜드 스타트 ​​원본 ZCode 성공, 개인 파이프 및 세션 신원 확인 통과, 동일 Fork 읽기 가능하고 전송 권한을 반환합니다. 그런 다음 공식 리모콘과 HTTPS 승인도 통과되었습니다. 시스템 지역 설정이 변경되지 않았으며 활성화되지 않았습니다. TCP 포트, 느슨하지 않은 역할 또는 시그니처 매칭。
