# Agent Note: 기본 사이드 채팅은 상위 워크벤치를 공유합니다.

Status: implemented

## 문제

Issue #149 원본 하위 채팅이 전체 채팅 컨트롤러를 사용하는 경우 동시에 독립된 워크벤치가 생성됩니다. 하위 채팅에 직접 진입하고 상위 채팅으로 돌아가는 알림은 두 세트의 파일을 전환합니다.、Git、터미널 및 라벨 상태。

## 결정

기본 채팅 실행에서는 여전히 하위 채팅을 사용합니다. ID 표준 컨트롤러; 작업대는 현재만 누른다 provider、host 루트 아버지와 함께 ID 사본을 저장하세요. 하위 채팅을 루트 상위 워크벤치에 닫을 수 있는 탭으로 추가하려면“채팅”상위 채팅으로 다시 전환하세요. 하위 탭을 닫으면 보기만 변경되며 중지, 보관 또는 삭제는 요청되지 않습니다. 사이드 채팅 디렉터리와 새 항목은 항상 루트 상위 채팅에 속하며 하위 워크벤치의 중첩된 항목을 제공하지 않습니다. 기존 기본 중첩 관계는 유지되며 탐색은 기본 관계를 변경하지 않고 서버 측 상위 체인을 따라 루트 상위를 확인합니다.。

알 수 없는 알림 및 하위 채팅 입장은 현재를 통해 전달됩니다. Codex host 페이징 타임라인 메타데이터는 상위 체인을 구문 분석한 다음 워크벤치를 전환합니다. 일반 목록 채팅은 캐시를 먼저 표시하는 원래 프로세스를 유지하며 메타데이터 대기 시간을 늘리지 않는 것으로 알려져 있습니다. 각 채팅 선택은 현재 채팅 재선택을 포함하여 이전 라우팅 요청을 무효화합니다. 기다리는 동안 스위치를 켜세요 provider 이전 결과도 삭제됩니다. 상위 항목을 사용할 수 없습니다. host 또는 신뢰할 수 없는 알림 필드를 기반으로 다른 범위를 구성하지 않고 순환 관계가 명시적으로 실패합니다. 초안, 모델, 첨부 파일, 승인 및 기록은 계속해서 유지됩니다. ID 구하다; 채팅 스크롤 누르기 ID 별도로 녹음했습니다. 파일, 터미널 및 Git 루트 상위 워크벤치의 소유권은 유지되며, 채팅 내 파일 위치 지정은 실제 채팅을 먼저 기준으로 합니다. cwd 구문 분석한 다음 상위 작업 공간에 속하는지 확인합니다.。

## 대안

각 하위 채팅은 독립적인 워크벤치를 유지하고 이전 페이지를 직접 재사용할 수 있지만 이로 인해 이중 레이어 라벨 및 상위 도구 상태 전환 문제가 발생합니다. 또한 하위 채팅 입력, 승인 및 첨부 패널을 완전히 독립적으로 마운트할 수 있지만 표준 채팅 기능은 복제됩니다. 현재 단일 컨트롤러가 유지되며 채팅 ID와 워크벤치 ID만 분리됩니다.。

## 검증

정위 Node 상위 도구 개체가 유지되고 기본 작업 없이 하위 레이블이 닫혀 있는지 확인하십시오.、host/provider 격리, 상위 체인 해결 및 사용 불가 알림/순환 상위 체인이 거부되었습니다. 브라우저 합성 디렉토리 고정 장치는 기본 메뉴 및 생성 작업을 다룹니다. ID、루트 상위 워크벤치 및 하위 탭이 닫힙니다. 브라우저 결과는 이번 라운드에서 임시 증거로 기록되며 휴대폰의 기본 알림이나 실제 모델의 승인과 동일할 수 없습니다.。

## 영향

알 수 없는 항목이나 하위 채팅에는 읽기 전용 페이징 메타데이터 요청이 추가됩니다. 중첩 관계는 추가로 조상을 읽습니다. 새로 시작하지 않습니다 writer 또는 변경 owner、provider、인증、cwd。상위가 사용 불가능할 경우 독립된 하위 워크벤치로 계속 진입할 수 없으며, 원래의 이력 및 관계는 그대로 유지됩니다.。
