# Agent Note: 백그라운드 관찰을 중지하고 확인된 캐시를 재사용하려면 클라이언트를 비활성화하세요.

Status: implemented

## 문제

모바일 액세스가 활성화된 게이트는 쓰기 및 일부 알림을 제한했지만 앱 상태 페이지는 여전히 비활성화된 클라이언트의 기본 연결을 쿼리합니다.、CLI 및 SSH 상태. 기본 Codex 알림 검색, 기존 후속 연결 및 모델 예약 새로 고침도 이 게이트를 완전히 준수하지 않습니다. 원래의 App 이러한 읽기는 계속 실행되면서 프로세스, 네트워크 및 절전 모드 해제 오버헤드를 계속 발생시킵니다.。

Claude CLI 파일 보관 기능에는 프로그램 ID별로 캐시된 다이제스트가 있지만 매번 동일한 프로그램이 다시 실행됩니다. `--version`。기본 메뉴도 트레이가 동일한 상태가 될 때마다 다시 작성됩니다. 이러한 작업은 기능을 줄이거나 약한 네트워크 재시도를 완화하지 않고도 검증된 결과를 재사용할 수 있습니다.。

## 결정

클라이언트 관리자는 로컬 포털과 통합 포털의 활성화 상태를 균일하게 구분합니다. 독립 구성은 자체 등록 상태를 읽습니다. 기본 Claude 비활성화 차단 안 함 활성화 WSL Claude。백그라운드 상태 새로 고침이 기본 어댑터 비활성화를 건너뜁니다.；Codex 구성 준비 정보는 기존 디스플레이 스냅샷을 재사용합니다. 명시적으로 다시 활성화하면 선택한 포털만 실시간으로 검색됩니다. 종료, 계정 전환 및 쓰기는 원래 작업과 신원 확인을 계속 유지하며 디스플레이 캐시로 대체할 수 없습니다.。

Codex Bridge 동일한 활성화 콜백을 통한 제약 조건 백그라운드 알림 검색、SSH 유지 관리, 세션 추적 및 모델 새로 고침. 기본 포털이 비활성화되면 머신과 해당 머신만 SSH 연결을 따르고 원본을 유지하십시오 App、CLI 실행과정, 내역, 원장 및 보류상태 독립적인 Codex 포털은 자체 콜백을 사용하며 기본 스위치로 비활성화되지 않습니다. 비활성화된 포털에 대한 이전 알림 후보나 보류 중인 알림은 계속 관찰 또는 전달을 트리거하지 않습니다. 승인된 기본 작업은 취소되지 않으며 알 수 없는 쓰기는 재생되지 않습니다.。

4개의 클라이언트 모델 디렉터리 타이머는 실행 전에 활성화 상태를 확인하고, 비활성화된 후 늦은 콜백은 더 이상 업스트림을 요청하거나 새로 고침을 다시 예약하지 않습니다.。Codex 기본 모델 디렉터리, 저장된 계정 디렉터리、API 폴더、Skill 백그라운드 새로 고침 및 계정 알림은 동일한 활성화 경계를 사용합니다. 확인된 캐시는 지워지지 않습니다. 명시적인 계정 관리 및 수동 새로 고침은 계속 수행할 수 있습니다. 비활성화해도 업스트림에 들어간 읽기가 종료되지 않으며 원본도 닫히지 않습니다. App 또는 기존 CLI 업무에 필요한 프로세스。

Claude 파일 보관 기능은 성공적으로 확인된 프로그램 버전만 캐시하며 키에는 플랫폼, 정식 경로 및 장치 번호가 포함됩니다.、inode、크기, 수정 시간, 변경 시간 및 요약입니다. 이 프로세스에서는 최대 8개의 항목이 유지됩니다. 오류는 캐시되지 않으며 프로그램 교체 또는 확인 중 변경 사항을 재사용할 수 없습니다. 계정 및 프로세스/작업 안전 확인은 이 캐시에 포함되지 않습니다.。SSH 임시 작업자 프로세스는 이 프로세스 내 캐시를 공유하지 않습니다.。

트레이는 실행 상태, 유효 주소, 사용 중 상태 및 상태 복사에 따라 메뉴를 재사용합니다. 주소 변경, 작업 시작/엔딩과 언어 전환은 여전히 ​​즉시 업데이트됩니다.。

제어판이 전체 스냅샷을 수신한 후 트레이는 실행 상태와 주소를 직접 채택하여 표시에 필요한 필드만 저장합니다. 5초 이내에 새 스냅샷이 수신되지 않으면 트레이는 원래 항목에서 읽혀집니다. 이미 진행 중인 팔레트 읽기는 업데이트된 창 결과를 무시할 수 없습니다. 시작/중지, 페어링, 계정 작업은 원래의 실시간 확인을 계속 수행합니다. 빈 알림 감시 목록은 직접 반환됩니다. 로컬 항목은 로컬 제목만 확인하고, 원격 레이블은 프로필 ID에 의해 무효화된 호스트 캐시를 사용합니다.。

코드 스캔 카운트다운 및 페어링 상태 쿼리는 창이 표시되고 확장된 유효한 QR 코드가 있는 경우에만 실행됩니다. 디스플레이가 복원되면 실제 만료 시간으로 새로 고쳐집니다. 게이트웨이 스냅샷에서 주소가 사라지면 해당 인증이 취소되고 항목이 해제됩니다. 대체된 비동기 수신은 원래 규칙에 따라 계속 처리됩니다.。

클라이언트 등록은 런타임과 분리됩니다. 클라이언트 목록을 처음 시작하고 열 때 설치 정보를 얻을 수 있으며, 닫혀 있습니다. Claude、DSH 및 ZCode 이에 대한 세션 어댑터가 생성되지 않습니다. 사용자가 포털을 명시적으로 열거나 관리하면 게이트웨이는 필요한 인스턴스만 구성합니다. 경계 DSH 액세스는 실제 사용 전에 신원을 확인합니다. 클라이언트 페이지가 숨겨진 후 상태 타이밍이 중지됩니다. 스캔이 성공하면 반환된 목록이 직접 사용됩니다. 계정 패널은 활성화되거나 명시적으로 선택된 입구에 대해서만 생성됩니다.。WSL 목록에 하위 시스템 항목이 없으면 빈 결과가 직접 반환되어 시스템 열거가 제거됩니다.。

## 기존 메모 감사

[클라이언트 없이 관리 용이성](2026-10-16-gateway-with-no-clients.md)부분적으로 중복됨, 비워두고 다시 활성화됨 UI 이 문서에서 백그라운드 리소스 경계를 ​​추가하기로 결정했습니다.。[상태 판독으로 시작 잠금 방지](2026-10-14-client-status-startup.md)부분 중첩, 디스플레이 캐싱과 실시간 보안 검사 간의 구별 유지。[공유 모델 디렉터리](../../implemented/feature/2026-11-04-shared-creation-model-selection.md)부분적으로 겹치는 부분이 있고 기존 디렉터리 ID와 저장소가 사용되며 새 캐시된 복사본이 추가되지 않습니다. 검색된 기본 첨부 파일, 알림 소스 및 작업 모드 메모는 서로 다른 책임을 가지며 대체되거나 삭제되지 않습니다.。

## 영향

액세스를 비활성화하면 정기적인 백그라운드 읽기가 줄어들고 캐시와 원래 작업은 유지됩니다. 활성화된 포털은 기존 읽기-쓰기, 알림 및 재연결 프로세스를 계속 사용합니다. 관리 인터페이스는 여전히 경량 기본 프로세스 목록, 공개 스케줄러 및 보류 항목을 쿼리할 수 있습니다. CLI 프로토콜 판독 및 ZCode 결과적으로 파이프라인 Keepalive는 삭제되지 않습니다. 대부분의 시간에 사용됨 Test、두 버전 모두 클라이언트를 활성화합니다./서로 다른 채널의 12시간 전력 값은 동일한 부하에 대한 절전 비교로 직접 사용할 수 없습니다. 완제품에 대한 후속 측정은 동일한 활성화 구성 및 휴대폰 사용 강도 하에서 이루어져야 합니다.。
