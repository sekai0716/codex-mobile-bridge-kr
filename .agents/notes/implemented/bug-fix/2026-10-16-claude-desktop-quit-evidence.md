# Agent Note: Claude Desktop 데스크톱 작업 목록에 따라서만 종료

Status: implemented

## 문제

macOS 정상적으로 종료 Claude Desktop 작업 확인은 병합된 채팅 목록을 읽습니다. 목록에는 기본 및 SSH Claude Code 역사; 원격 새로 고침 중 `complete` 거짓이더라도 Desktop 의 Code 및 Cowork 완전히 반환되고 모두 무료이며 보고됩니다.“모든 클라이언트 작업이 종료되었는지 확인할 수 없습니다.”。독립형 데스크탑 종료 미리보기도 병합된 목록을 사용하므로 알 수 없는 작업에 대한 확인을 잘못 요청할 수 있습니다.。

## 결정

Claude Desktop 일반 시작 및 중지, 계정 전환 전 유휴 확인, 독립적인 종료 미리보기 및 확인, 기존 내용 직접 읽기 `desktop_listing()` 신선한 Code/Cowork 체크리스트. 인벤토리는 완료되어야 하며 각 데스크톱 세션은 확인 가능한 실행 상태를 제공하고 유휴 상태입니다. 진행 중인 작업이나 권한 확인으로 인해 종료가 방지됩니다. 게이트웨이는 로컬 또는 SSH Claude Code 활성 작업은 여전히 ​​기존 작업으로 구성됩니다. `busy()` 이탈을 방지하려면 확인하세요. 기본 프로세스 ID 스냅샷 및 사전 종료 검토는 변경되지 않습니다.。Windows 명시적 일반 종료가 포함된 시간 제한 기본 확인 경로는 원래 읽기 및 확인 프로세스를 계속 사용합니다.。

## 기존 메모 감사

활성 메모가 검색되었습니다.。[Claude 채팅 목록 병합](../feature/2026-10-14-claude-unified-chat-list.md)병합된 목록을 표시하기로 결정하는 데에는 병합된 결과에 따른 판단이 필요하지 않습니다. Desktop 출구 보안；[클라이언트 상태 읽기](2026-10-14-client-status-startup.md)쓰기 작업에는 제약 조건 표시 캐시를 사용할 수 없으며 이번에는 새로운 읽기가 계속 사용됩니다. 이 두 기사를 변경할 필요가 없습니다.。

## 대안

병합된 목록만 무시 `complete` 원격 새로 고침을 우회할 수 있지만 마스크도 적용됩니다. Desktop 자기 부족 Code/Cowork 덮어썼거나 알 수 없는 실행 상태입니다. 기다리다 SSH 새로 고침이 완료된 후에도 계속 전송됩니다. Desktop 프로세스 독립적인 원격 상태는 종료하기로 결정되며 오프라인 호스트는 항상 차단됩니다.。

## 영향

SSH 기록 또는 원격 새로 고침이 더 이상 발생하지 않습니다. Desktop 거짓 알 수 없는 상태。Desktop 연결이 중단되고, 적용 범위가 불완전하고, 세션 실행 상태를 알 수 없으며, 실제 활성 작업은 여전히 ​​원래 차단 또는 명시적으로 알 수 없는 확인을 유지합니다. 회귀 테스트는 가드 입구에서 오래된 오류를 재현하고 정상 종료, 독립적인 미리 보기 및 2차 확인, 데스크톱 작업 및 권한 대기 및 인계를 포함합니다. CLI 활성 작업。Mac 설치됨 Test 유휴 상태를 종료하려면 일반 종료를 사용하세요. Claude，그러면 별도의 콜드 스타트 ​​초기화가 성공합니다. 공식 게이트웨이와 현재 Codex 호스트 프로세스는 변경되지 않은 상태로 유지됩니다. 여러 클라이언트를 조합하여 복원할 때 초기화 중 하나가 포커스 보호에 의해 중단되고 기록이 유지되었습니다. 연결이 복원된 후 개별 종료가 다시 시작되고 재테스트가 통과되었습니다.。
