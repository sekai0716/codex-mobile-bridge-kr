# Linux 사이드채팅의 공유 런타임 연결

## 문제와 변경

Linux의 영구 사이드채팅 생성은 원본 Desktop의 부모 채팅을 확인한 뒤에도 별도의 stdio app-server를 띄웠다. 원본 런타임이 부모 writer를 보유하면 `thread … already has an active writer`로 거절됐다. macOS·Windows의 공유 연결과 준비 트랜잭션에는 Linux가 등록되지 않았던 것이 원인이다.

기존 Unix 소켓 어댑터와 초기화·메타데이터 잠금을 Linux에서도 재사용한다. Linux 프로세스의 부팅 ID, 시작 ticks, 실제·유효 UID, 실행 파일, 부모 PID를 확인한다. 시작 중 exec 또는 재부모화는 살아 있는 writer 예약을 해제할 근거가 되지 않는다. 연결 전후의 프로세스 및 소켓 세대 검증, `700` 디렉터리와 `600` 소켓 요구 조건은 유지한다.

기존 공유 연결은 그대로 재사용한다. 공유하지 않는 Desktop은 모든 작업의 유휴 상태와 프로세스·설정 경계를 확인한 뒤에만 정상 재시작한다. 바쁘거나 상태를 확인할 수 없으면 준비를 미룬다. 읽기 조회가 초기화를 시작하지 않으며, 활성화·게이트웨이 시작의 기존 준비 진입점을 사용한다.

공유 연결이 없을 때 Linux의 영구 사이드채팅 요청도 네이티브 쓰기 전에 거절한다. 별도 writer, 일반 분기 또는 임시 사이드채팅으로 자동 대체하지 않는다. 결과 미확인 원장은 보존하고 같은 생성 요청을 재전송하지 않는다. 기존 계정·provider·권한·cwd 및 SSH·독립 설정의 경계는 유지한다.

## 검증 범위

`test_linux_desktop_runtime.py`는 실제 Linux `/proc` 세대 조회, 조회 중 세대 변경, UID 불일치, 시작 예약, 실행 환경 전달과 비공개 연결의 세대 교체 거절을 검사한다. 기존 메타데이터 라우팅·계정·어댑터 검사는 Linux의 준비 전 거절과 작업 중 재시작 금지를 포함한다.

`scripts/smoke-linux-desktop-runtime.py --codex …`는 POSIX 파일시스템의 격리된 home과 Python Desktop 대역을 사용한다. 설치된 `0.169.0-alpha.11.1`에서 별도 writer 충돌을 재현하고, 생산 어댑터와 서비스 진입점을 통해 자식 1개 생성·관계 조회·Bridge 재연결·부모 기록 및 런타임 유지·정상 EOF 정리를 확인했다. 계정·원본 Desktop 채팅을 사용하지 않았고 모델 요청은 0건이다. 실제 GUI 정상 재시작 및 휴대폰 상호작용은 이 격리 검사와 구분한다.

NAS의 CIFS 마운트는 POSIX 비공개 모드를 유지하지 않으므로 이 보안 검사를 완화하지 않는다. 소스 수정은 NAS 작업 브랜치에 유지하고, 검증용 사본만 로컬 POSIX 파일시스템에서 실행한다.
