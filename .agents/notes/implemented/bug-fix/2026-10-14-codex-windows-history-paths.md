# Agent Note: 디렉터리 ID로 읽기 Windows 네이티브 Codex 역사

Status: implemented

## 문제

Windows 네이티브 Codex ～에 있을 수도 있다 SQLite 저장 위치 `\\?\C:\...\sessions\...jsonl` 경로를 양식에 기록하고 게이트웨이는 동일한 경로를 수신합니다. `CODEX_HOME` 평범하다 `C:\...` 길。`Path.resolve()` 이 두 가지 다른 표현을 유지하십시오. 이때 경로 텍스트를 기준으로 부모 확인을 통해 실제 레코드가 다음 위치에 있는지 확인합니다. Codex 홈 디렉터리 외부: 채팅이 여전히 목록에 있지만 게이트웨이가 다시 시작된 후에는 저장된 기록을 읽을 수 없습니다. 테스트 중인 격리된 설치된 게이트웨이，JSONL 메모리가 응답을 예상했지만 구문 분석 전에 읽기가 거부되었습니다.。

## 결정

`SessionStore` 관계 검사를 포함하려면 검색 진단 및 기록 읽기에 동일한 레코드 경로를 사용하세요. 일반 구문 분석 경로는 기존 상위 검사를 계속 사용합니다.。Windows 이 검사가 일치하지 않으면 다음을 사용하십시오. `Path.samefile()`，각 기존 레코드의 상위 디렉터리의 실제 ID를 구문 분석된 디렉터리와 비교합니다. `sessions` 또는 `archived_sessions` 디렉토리 비교. 액세스할 수 없는 상위 디렉터리에 대한 액세스 권한을 부여할 수 없습니다. 로그 파일 자체는 확인하기 전에 구문 분석되므로 홈 디렉터리 외부를 가리키는 하위 기호 링크는 여전히 범위를 벗어난 것으로 간주됩니다.。CLI 및 Desktop 원천、provider 런타임 귀속 규칙은 변경되지 않습니다.。

## 대안

연장하다 HTTP 세부 응답 대기가 이 영구 격리 확인에 실패합니다. 확장 경로 접두사를 제거하거나 문자열 접두사를 수락하면 경로 철자가 인증의 기초로 처리되어 인접한 디렉터리나 다른 디렉터리를 혼동할 수 있습니다. Windows 경로 형태. 모든 일반 경로에서 신원 확인을 수행하면 다음을 포함하여 불필요한 파일 시스템 작업이 추가됩니다. SSH 역사 읽기; 따라서 폴백은 다음으로 제한됩니다. Windows 일반 상위 확인 경로 실패。

## 영향

원래 격리 Windows 기본 기록기를 활성화하지 않고도 재부팅 후 저장된 레코드를 읽을 수 있습니다. 회귀 고정 장치는 외부 디렉터리, 유사한 접두사가 있는 형제 디렉터리 및 홈 디렉터리를 탈출하기 위한 기호 링크를 계속 거부합니다. 일반 경로는 ID 대체를 사용하지 않습니다.。Windows 대체는 제한된 수의 디렉터리 ID만 읽으며 액세스할 수 없는 디렉터리는 여전히 액세스를 거부합니다. 성공적으로 읽는 동안 원래 격리는 SQLite、WAL 및 JSONL 해시。

## 기록 파일 및 디렉터리 읽기 누락

2026-11-12 Windows Test 로그는 또 다른 독립적인 상황을 확인합니다. 데이터베이스 레코드는 여전히 존재하지만 해당하는 rollout 더 이상 존재하지 않습니다. 모델 디렉토리는 먼저 기록을 읽습니다. `stat` 모든 곳에서 실패했습니다. 이제 디렉터리 항목은 누락된 기록 파일에 대해 확인된 세션 메타데이터의 프로젝트 디렉터리만 사용하고 provider，원래 디렉터리 캐시와 읽기 논리를 계속 재사용합니다. 이 규칙은 세 플랫폼 모두에 공통됩니다. 채팅 기록은 변경되지 않으며 세션이 활성화되지 않습니다. 권한 거부 및 국경 간 경로는 여전히 오류를 보고합니다. 누락된 내역을 빈 채팅으로 위장하거나 다른 계정으로 돌아가는 글로벌 모델은 없습니다.。

현실 Store 및 Bridge 콜드 디렉터리 회귀는 먼저 동일한 예외를 재현했으며 복구 후 모델을 읽을 수 있었습니다. 또한 정상적인 이력 설정, 프로젝트 정체성, 권한 거부 등도 검증해 총 4개 항목을 통과했다.。Windows 최종 프로그램 합격은 별도로 기록되며, 고립된 회귀로 인해 합격했다고 추정할 수 없습니다.。

## 삭제된 항목에 대한 읽기 전용 디렉터리 도우미 프로세스

Windows `.11` 최종 브라우저 승인에서는 채팅이 연결되었지만 모델 설정에서는 여전히 런타임에 시작할 수 없다고 보고했습니다. 기본 프로그램이 존재하고 버전 쿼리가 성공했습니다. 실패는 세션에 저장된 프로젝트 디렉터리가 사용자에 의해 삭제되었다는 것입니다.，`Popen(cwd=원본 카탈로그)` 뒤로 `WinError 267`。이는 다음과 관련이 있습니다. WSL 입장 가능 여부는 중요하지 않습니다.。

디렉터리 쿼리는 읽기 전용 도우미 프로세스의 시작 위치를 아직 존재하는 가장 최근 상위 디렉터리로만 조정하여 프로젝트 조상의 구성 의미를 유지합니다.；`config/read`、`skills/list`、읽기 권한, 캐시 키 및 세션 자체는 여전히 원래 프로젝트 경로, 계정 및 세션을 사용합니다. provider 끊임없는. 원래 디렉터리가 존재하는 경우 조정이 이루어지지 않으며 권한이 거부되면 오류가 계속 보고됩니다. 사용자의 삭제된 디렉토리를 다시 작성하거나 채팅을 덮어쓰는 대신 이 방법을 선택하십시오. cwd；항상 사용자의 홈 디렉터리에서 시작하면 원래 프로젝트의 조상 구성이 손실될 수 있으므로 사용되지 않습니다.。

회귀는 먼저 누락된 디렉터리 시작 실패를 재현합니다. 수리한 후 실제 하위 프로세스가 시작되고 원본인지 확인합니다. RPC 폴더、provider、`CODEX_HOME`、일반 디렉토리 및 권한은 실패할 경우 재시도되지 않습니다. 디렉토리 테스트 합계 36 항목이 통과됨。Windows 네이티브 설치 `0.167.0-alpha.3.2` 비교 검증 중에 보조 프로세스는 기존 조상에서 시작하여 원래 프로젝트 컨텍스트를 읽고 반환합니다. 8 이전 카탈로그를 복원하거나 모델 라운드를 시작하지 않고도 모델을 만들 수 있습니다. 수리된 정지 프로그램 인터페이스의 승인 여부는 별도로 기록됩니다.。
