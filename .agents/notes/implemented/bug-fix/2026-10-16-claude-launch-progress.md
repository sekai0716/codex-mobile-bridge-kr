# Agent Note: Claude 프로세스가 발견되기 전의 시작 진행 상황

Status: implemented

## 문제

명시적 초기화는 기본 작업자 스레드를 비동기적으로 시작합니다. 첫 번째 클라이언트 상태 스냅샷이 관찰되었을 수 있습니다. `connecting`，그리고 Claude 그 과정은 아직 나타나지 않았습니다. 관리자는 이 스냅샷을 다음으로 변환합니다. `error`，～로 이어지다 UI 정상적인 시작 중에는 연결 실패가 표시됩니다. 오류는 또한 15 1초 동안 보류 중인 캐시 대신 두 번째 상태 캐시는 서명된 후속 연결 표시를 지연시킵니다.。

## 결정

이 단계를 보류 중으로 두세요. `starting`；시작 실패, 취소 또는 필요한 사용자 작업이 여전히 작업자 스레드에 의해 보고됩니다.。`needs-initialization` 나중에 프로세스가 중지되었을 때 여전히 사용할 수 없는 것으로 보고되었습니다. 새로운 활성화 요청이 기다리는 동안 공유 UI 마지막 시도에서 잘못된 스타일을 상속받지 마세요.。

## 대안

동기 대기 프로세스는 상태 읽기를 차단합니다. 프로세스의 존재를 성공적인 연결로 간주하면 서명된 프로세스를 건너뜁니다. Bridge 영수증. 두 옵션 모두 필요하지 않습니다. 기존 보류 상태와 짧은 캐시가 이미 원하는 동작을 제공합니다.。

## 영향

회귀 테스트는 두 플랫폼 분기 모두에서 거짓 긍정을 재현하고 서명된 연결이 유휴 캐시에 의해 차단되지 않고 2초 후에 상태를 대체하는지 확인합니다. 기본 시작에 실패하고, 중지되고, 초기화되지 않은 클라이언트는 여전히 오류를 보고했습니다. 이러한 소스 코드 테스트는 전체 기본 시작 시간을 측정하지 않습니다.。

macOS 및 Windows 설치됨 Test 정상 종료 후 콜드 초기화 허용이 관찰됩니다. `starting` → `connecting` → `connected`，이 기간 동안 거짓양성 오류는 발생하지 않았습니다. 단일 실행은 다음과 같이 구분됩니다. 10.243 및 30.437 몇 초 안에 완료됩니다. 이는 제어된 속도 비교가 아닌 전체 콜드 스타트 ​​관찰입니다. 원래의 Test 보존 설정，macOS 공식 게이트웨이 및 활성 Codex 호스트는 변경되지 않은 상태로 유지됩니다.。
