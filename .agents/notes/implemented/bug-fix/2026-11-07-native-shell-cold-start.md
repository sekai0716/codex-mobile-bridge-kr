# Agent Note: 기본 휴대폰 콜드 로딩은 먼저 호스트를 등록한 다음 스타일을 기다립니다.

Status: implemented

## 문제

iOS 의 document-end 스타일시트를 읽을 수 있는 시간보다 일찍 삽입이 발생할 수 있습니다. 스타일이 누락되면 원본 스크립트가 직접 반환되어 처음 입력할 때 웹페이지와 기본 페이지가 모두 표시됩니다.“더”아직 진입이 완료되지 않았으며 컴퓨터 목록의 호스트 레이아웃이 반환됩니다.。

## 결정

Android 및 iOS 같은 것을 계속 사용 `mobile/shared/web/mobile-ui.js`。애플리케이션 노드가 준비되면 먼저 기본 레이아웃 태그를 등록한 다음 동일 출처 스타일 시트를 읽으십시오. 스타일을 사용할 수 없을 때 리소스 로딩을 모니터링하고, 쓰기 성공 후 모니터링을 취소합니다. 이에 대해 새로운 폴링 또는 재구축 페이지가 추가되지 않습니다. 기본 상호 작용을 반복적으로 등록하지 않고 반복 주입。

이 수정 사항은 Cloud Service Experiment에서 제출되었습니다. `f49f31b` 에서 추출하여 공유 레이아웃 초기화만 변경합니다. 일반 직접 연결도 클라우드 계정, 전달 또는 저장을 도입하지 않고 이를 사용합니다. 둘 다 무작위 token、기본 프레임워크 및 기본 인증 확인은 변경되지 않습니다.。

## 대안

레이아웃을 삽입하기 전에 모든 리소스가 로드될 때까지 기다리면 타이밍 분기를 줄일 수 있지만 호스트 인식이 지연되며 그 동안 두 개의 탐색 세트가 계속 나타납니다. 별도로 수정 Swift 및 Java 단일 플랫폼을 처리할 수 있지만 동일한 논리를 복제할 수 있습니다. 따라서 공유 스크립트에서 이벤트 기반 초기화를 한 번 유지하십시오.。

## 검증

타겟 Node 반품 38 스타일 없는 콜드 로딩, 관련 없는 리소스가 먼저 반환됨, 스타일이 늦어진 후 한 번만 삽입되는 규칙, 메뉴, 기본 테마, 리소스 목록 및 호스트 식별 등의 규칙을 다루는 항목이 전달되었습니다.。UU 이번 후보에는 입장권과 공유 대본의 조합이 포함됩니다.；Node 결과는 완제품을 대체하지 않습니다 WebView 실제 기계로 수용。

## 영향

호스트 레이아웃은 콜드 로딩 중에 시간에 맞춰 인식될 수 있으며, 스타일을 읽을 수 있게 되면 통합 탐색이 복원되며, 백그라운드 타이머가 추가되지 않습니다. 일시적으로 스타일이 지정되지 않은 페이지는 완전한 시각적 스타일을 제공하기 전에 리소스가 복원될 때까지 기다려야 합니다.。

활성 노트를 검색한 후，[iOS 주제 및 알림](../feature/2026-10-28-ios-theme-and-foreground-notifications.md)공유된 주입 스크립트 책임이 부분적으로만 겹치고 주제와 알림 결정이 유지됩니다.；[UU 원격 제어](../feature/2026-11-06-mobile-uu-remote.md)계속해서 컴퓨터 바인딩 및 기본 호출을 담당하며 이 수정 사항으로 인해 권한이 변경되지 않습니다.。
