# Agent Note: 채팅 오디오 및 비디오 재사용 승인 파일 다운로드

Status: implemented

## 문제

네이티브 채팅에서 `![audio](로컬 경로)` 이미 File Index에서 승인되었지만 Markdown 렌더러는 이미지에 대한 미리보기만 생성하며 다른 첨부 파일은 일반 링크가 됩니다. 현실 WAV 의 Range 요청이 반환될 수 있습니다. 206，응답은 범용 바이너리 첨부 파일이었고 채팅에는 재생 제어 기능이 없었습니다. 파일 링크를 추가하는 것만으로는 충분하지 않습니다. #158。

## 결정

공유됨 Markdown 액세서리 구성 요소와 동일한 오디오 및 비디오 컨트롤을 호출합니다. 기존 인증 파일만 URL 플레이어를 생성할 수 있습니다. 외부 링크 및 승인되지 않은 기본 경로는 적극적으로 읽히지 않습니다. 플레이어가 브라우저 기본 컨트롤을 사용합니다.、`preload=none`、동영상 `playsInline`，자동으로 재생되지 않습니다. 기존 파일 링크는 링크와 독립적인 컨트롤을 사용하여 찾기, 미리보기 및 다운로드 메뉴를 계속 트리거합니다.。

플레이어가 원본 파일을 제공합니다. URL 증가하다 `preview=1`，예약하다 relay 접두사, 호스트 및 세션 매개변수。HTTP 포털은 명시적으로 나열된 오디오 및 비디오 접미사에 대한 미디어만 반환합니다. MIME 및 inline；HTML 활성 콘텐츠는 여전히 첨부 파일입니다. 일반적인 다운로드 동작은 변경되지 않습니다. 인증, 파일 ID 및 경로 확인, 크기 임계값、Range、If-Range 스트리밍은 기존 구현을 계속 재사용합니다. 작업공간 미리보기가 상속됨 PDF 미리보기 크기 제한은 채팅 파일이 채팅 다운로드 제한을 상속합니다.。

해당 형식이나 코덱을 재생할 수 없을 때 다운로드 프롬프트를 표시합니다. 트랜스코더를 설치하지 않거나 전체 파일을 메모리 데이터로 변환하지 않습니다. URL。변경되지 않은 메시지는 원래 타임라인을 계속 사용합니다. DOM 은닉처。

## 대안

클라이언트별로 플레이어를 별도로 추가하는 것은 접근하기 쉽지만 반복적입니다. UI 경계를 다운로드하므로 공유 구성요소를 사용하세요. 원격 링크를 미디어로 자동 전환하면 원치 않는 외부 액세스가 발생하므로 링크만 보존됩니다. 전체 파일을 다운로드한 다음 트랜스코딩하면 확장 가능한 형식이 지원되지만 종속성, 메모리 및 대기 시간이 늘어납니다. 현재 원본 파일 다운로드는 호환 경로로 유지됩니다.。

## 영향

후방 18 개 Range/인증/크기/기호 링크 테스트를 통과했습니다. 새로 추가된 인증 및 크기 어설션의 단일 항목이 다시 통과되었습니다. 프런트 엔드 리소스, 첨부 파일 및 카피라이팅 관련 20 항목이 통과되었습니다. 현실 Chromium 의 12 아이템 공유 DOM 좁은 화면의 적용 범위, 텍스트에 두 종류의 링크, 첨부 동영상, 오류 대체, 외부 링크가 로드되지 않는지 확인하세요.。

생산 HTTP 프로세서는 격리된 인증을 통해 사용자 피드백 소스를 읽습니다. WAV，브라우저는 재생 종료를 수신하고 seek 완벽한; 합성하다 WebM 또한 실제 디코딩 재생이 종료되며 둘 다 206。이 확인은 모델 요청을 보내지 않으며 세션을 수정하지 않습니다. 최종 패키징 프로그램과 모바일 호스트는 설치 후에도 승인이 필요하며 브라우저 결과는 3단계 배송 완료로 간주되지 않습니다.。

관련 노트 검색：PDF/HTML 미리 보기는 이 변경 사항과 부분적으로 겹치며 제한된 다운로드 계약을 계속 사용합니다. [PDF 시사](../feature/2026-10-13-pdf-html-preview-and-source-mode.md)；[프로젝트 파일 참조](../feature/2026-10-29-project-file-references.md)파일 권한 및 메뉴에 대한 책임은 계속 유지되며, 이 변경으로 범위가 확장되지는 않습니다. 나머지 파일 전송 설정과 기본 기록 이미지 기록 책임은 변경되지 않습니다.。
