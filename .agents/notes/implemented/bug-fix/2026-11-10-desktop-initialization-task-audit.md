# Agent Note: 네이티브 공유 초기화의 작업 범위 및 검증 기간

Status: implemented

## 문제

공유 연결 초기화는 원본만 변경합니다. App 런타임 시작 방법을 사용하지만 계정 전환을 차단하는 일반 작업을 재사용하며 독립적입니다. native CLI 활성 작업으로 인해 초기화도 방지됩니다. 오류 보고의 또 다른 소스는 작업 확인, 즉 기본 구성의 기록 메타데이터 형성에서 비롯됩니다. 601 원래 구현에서 하나씩 발견했습니다. owner，스냅샷을 기다리세요。20 초를 남은 후보 수로 나눈 첫 번째 요청에는 약 16.6 밀리초，IPC 실제 대기에는 여전히 1초가 추가됩니다. 침묵하는 역사적 후보자들은 실제 업무를 지연시키고 마침내 보고할 것입니다.“아직 선택되지 않은 세션이 있습니다.”。

## 결정

단독으로 사용되는 초기화 Desktop 수명주기 범위。native CLI 경로 표시, 생존 proxy、같은 home 악수와 joined token 이번 라운드에서 검증할 후보만을 식별할 뿐 원본을 증명하지는 않습니다. App 아니요 owner。캐시된 `desktop_owner_probe` 그것이든 `absent`、`unknown`、null 또는 `found` 두 가지 모두 면제가 허용되지 않습니다. 이전 읽기 시간 초과도 인정될 수 있습니다. `absent`。이러한 후보자가 역사적 세트에 포함되지 않더라도 현재 라운드의 실제 라운드에 진입해야 합니다. owner 발견; 오직 정밀도 `no-client-found`、쿼리 전과 후 proxy 및 token 쿼리가 변경되지 않고 종료되기 전에 다시 동일한 조건이 충족되는 경우에만 최종 태스크 판단에서 제외되도록 허용됩니다.。Desktop owner、시간 초과, 연결 끊김, 알 수 없음 또는 변경 사항 발견 proxy、구성 불일치로 인해 보호가 계속 유지됩니다. 대기열 및 알 수 없는 제출에는 지속적인 실행 소유권 증거가 부족하여 계속 차단됩니다. 계정 전환을 위한 인증、provider 및 구성 보호가 좁혀지지 않았습니다.。

원래 작업 검증 유지 Desktop 역사적 후보、attached/subagent 자손、App 관련 원격 및 알려진 Desktop 실시간 세션의 경우 최대 8개 항목을 병렬로 확인할 수 있으며, 현재 게이트웨이가 따라오는 세션은 전체 세션으로 간주되지 않습니다. 모든 일에 있어서 진실을 먼저 찾아라 owner，수동적으로 구독하고 실시간 스냅샷을 확인하세요. 바쁜 상태, 보류 중인 요청, 진행 중인 라운드、owner 연결 끊김 및 개정 불일치는 원래의 판단을 유지합니다. 완료되면 획득한 모든 상태와 제출 기록을 다시 확인하세요.。

IPC 연결, 초기화 및 owner 공유 절대값 읽기 deadline。핸드셰이크는 검증 작업자 스레드에도 적용되며 조정 스레드는 동기적으로 중단되지 않습니다. Unix `sendall` 또는 Windows 작성이 보류 중입니다. 기한이 있는 읽기는 전송 시간을 공제하고 일반 요청의 1초 수신 유예를 첨부하지 않습니다. 일반 쓰기 요청은 원래의 대기 및 결과를 알 수 없는 의미를 유지하며 재생되지 않습니다. 시간 초과 또는 조기 실패가 발생하면 이 임시 세션을 닫습니다. follower 그리고 조용한 작업이 하나씩 끝날 때까지 기다리지 않고 웨이터를 깨우십시오.。`close` 지연을 방지하면서 연결 세대의 socket 또는 응답을 초기화하여 연결을 다시 발행하십시오. 원래 제어 연결은 원본과 동일합니다. owner 영향을 받지 않음。

所核对的本机 Desktop 路由对 `client-discovery-request` 固定等待最多 10 秒，之后才返回精确 `no-client-found`。单次 owner 读取上限为 11 秒，并将候选预算的三分之二留给发现、余量留给快照及最终复核；总操作截止仍为原 20 秒。有大量候选时每项仍按有界并行分摊，不承诺全量历史在期限内完成，也不把未收到的负面回复推断为不存在 owner。

## 备选方案

확인만 `gateway.live` 역사적 규모를 우회할 수 있지만 원본만 놓칠 수 있음 App 실행 중인 작업. 현재 Desktop follower 프로토콜이 완전한지 확인되지 않았습니다. loaded-thread 열거형, 첨부된 채팅 없음 fork；기존 App 내부에 `thread/loaded/list` 및 `thread/fork` 외부와 동등하지 않음 follower 인터페이스이므로 초기화가 필요하지 않다고 주장합니다.。

시간 초과를 균등하게 연장하거나 모두 면제 CLI 변경 사항은 적지만 전자는 여전히 자동 대기를 하나씩 누적하고 후자는 다음으로 인한 변경 사항을 놓치게 됩니다. App 유지된 CLI 소스 세션과 소유권을 알 수 없는 요청입니다. 원래의 적용 범위와 제한된 병렬성을 유지하고 독립적인 것으로만 입증됨 native CLI 제외하다。

## 검증

새로 추가된 회귀는 먼저 독립성을 재현합니다. native CLI 중지되었습니다、601 후보 중 첫 번째 항목이 꼬리를 조용히 막는다. busy、자동 요청은 전체 기한을 초과하고 동일한 사용 사례를 다시 통과합니다. 생산 `assert_desktop_idle` 경로가 별도로 표시되어 있습니다. CLI 역사적 후보와 일치、CLI 기록 수집에 없음, 다른 캐시 probe 상태, 현재 검색 시간 초과 라운드, 종료 전 두 번째 검색 실패 및 token 변화. 고정 장치는 최대 8개의 전송 중인 요청을 유지하고 각 제출을 검토합니다.、Desktop owner、proxy 바꾸다、home 일치하지 않으며 알 수 없는 제출 차단。IPC 제어 가능한 시계를 사용하여 전송 시간이 많이 걸리는 공제, 만료 후 전송 없음 및 기본 쓰기 수신 유예를 확인합니다. 악수 차단, 지각 connect 그리고 늦게 initialize 응답은 검증을 넘어 완료 후 제어를 재개할 수 없습니다.。

검토 및 수정 후，`PYTHONPATH=tests python -B -m unittest test_desktop_runtime_accounts test_desktop_idle test_ipc_deadline` 의 59 오리엔테이션 테스트를 통과했습니다. 첫 번째 버전의 계정, 압축, 세션 관리, 공유 runtime、클라이언트 수명주기 및 대형 프레임 IPC 확장된 기준선이 통과되었습니다. 260 목; 이번에는 수정으로 인해 직접적인 영향을 받는 재실행만 다시 실행됩니다. 59 항목의 경우 이전 기준선은 이러한 새로운 격차에 대한 재검증으로 계산되지 않습니다. 모든 새로운 설비는 합성 상태를 사용하며 공식적인 것은 아닙니다. App 연결, 모델 요청, 실제 fork 또는 App 다시 시작。

## 영향

독립적인 native CLI 초기화 중에 작업을 계속할 수 있으며 계정을 전환해도 원래 보호는 유지됩니다. 작업 확인은 최대 8개의 수명 주기가 짧은 작업자 스레드와 동시 구독을 추가하지만 영구 폴링은 추가하지 않습니다. 대용량 기록이나 확인 불가능한 상태는 기한에 따라 안전하게 거부될 수 있으며, 타임아웃은 유휴 상태로 간주되지 않습니다.。

이 변경 사항은 공유 런타임 토폴로지를 변경하지 않습니다. owner/provider/auth/cwd，첫 번째 연결의 재부팅 없는 마이그레이션도 제공되지 않습니다. 처음으로 공유 방법을 활성화하려면 사용자 확인이 필요하며 영향을 받는 작업이 완료된 후 정상적으로 다시 시작해야 합니다. App 한 번; 참된 주님 App 크로스 플랫폼 수용은 이러한 소스 코드 설비로 대체되지 않습니다.。

## 原生发现时限复验

本机 Codex Desktop 随附 0.169.0-alpha.11.1，安装包路由实现中 discovery 等待 10 秒。纯读取同一历史元数据目标：旧版单次读取上限 6 秒返回读取超时并判 unknown；调整后实际收到原生 `no-client-found`，审计通过。没有读取聊天正文到日志，也没有执行退出、归档或删除。新增匹配原生时限的回归先失败后通过；48 项 Desktop idle/IPC deadline/stream 定向通过，既有 busy、systemError、修订漂移与绝对期限保护均保持。全历史 876 个候选的同机对照仍检出真实 active，并保留大历史/无响应客户端可能不完整的限制。
