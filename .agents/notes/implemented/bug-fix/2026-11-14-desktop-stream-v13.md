# Agent Note: 데스크톱 세션 동기화는 새 버전과 구조적으로 호환됩니다.

Status: implemented

## 문제

원래 액세스만 허용됩니다. v11，기본 업그레이드 v13 유효 이후 상태도 거부됩니다. 연결을 다시 설정해도 이 액세스 제어는 변경할 수 없습니다. 이전 프롬프트에서는 사용자가 원래 클라이언트를 업데이트해야 합니다.。

## 결정

세션 상태 동기화 v11 기준으로。v11 원본 부분 스냅샷 분석 유지；v13 다른 최신 정수 버전과 동일한 제어 키 구조 검사를 통과한 후에도 동기화가 계속되며 추가 필드는 그대로 유지됩니다. 새로운 버전 번호를 알고 있더라도 구조 점검에서 제외될 수 없습니다. 버전 업그레이드 및 새로운 공통 필드에는 수신 허용 목록을 유지 관리할 필요가 없습니다.。

새 버전에서는 세션 인식을 유지해야 합니다. ID、provider、cwd、작업 현황, 승인 수집, 내역 및 도구 항목 컨테이너。canonical 기록 인덱스 참조는 유효해야 하며 작업 상태를 식별할 수 있어야 합니다. 실시간 동기화 및 사전 종료 작업 감사는 이 검사를 공유합니다. 감사 중에 누락되거나 알 수 없는 구조가 발견되면 상태는 알 수 없는 것으로 간주됩니다.。

주요 구조가 변경되면 기록 표시를 유지하고 제어를 일시 중지하며 업데이트에 대한 명확한 메시지를 표시합니다. Bridge。비동기 상태 변경 후 작업 디스패치를 ​​방지하려면 기본적으로 보내기 전에 형식 예외를 다시 확인하세요. 호환되는 스냅샷을 받은 후 자동으로 복원。owner、host、thread、반점 revision 및 CLI provider/cwd 속성 확인은 계속해서 적용됩니다. 전송, 승인, 중지 등의 아웃바운드 메시지는 각각의 일반 버전으로 유지되며 처리 시 원래 결과를 알 수 없습니다.。

증분 메시지는 먼저 후보 상태에 적용 및 확인된 후 마지막 신뢰할 수 있는 상태를 대체합니다. 작업 실패 또는 확인 거부는 기록 캐시를 변경하지 않습니다. 공유 패치 기능은 수정된 경로의 컨테이너만 복사하며, 수정되지 않은 내역은 계속해서 재사용되어 각 증분마다 전체 채팅을 딥 카피하는 것을 방지합니다. 실시간 동기화 및 종료 감사는 동일한 구현을 사용합니다.。
