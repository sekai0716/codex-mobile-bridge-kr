# Agent Note: 연기 HTTP 다음을 사용하여 백로그 대기열을 시작합니다. GET 메시지 구분

Status: implemented

## 문제

콜드 페이지를 로드할 때 역방향 프록시가 많은 업스트림을 열 수 있음 HTTP/1.1 소켓. 수신 백로그가 너무 작으면 프로세서가 실행되기 전에 연결이 거부됩니다. 또한 빈 청크 인코딩 GET 바이트를 구분하는 읽지 않은 메시지는 남게 되며 지속적인 연결 요청 구문 분석은 이를 다음 요청으로 처리할 수 있습니다. 이는 두 가지 다른 전송 실패이므로 별도로 확인해야 합니다.。

## 결정

`GatewayServer.request_queue_size` 명시적으로 다음으로 설정됨 128。OS 제한 보류 중입니다. TCP 백로그 대기열을 모니터링하고 허용된 동시 프로세서 수를 늘리지 마십시오. 모든 수신기는 기존 공유를 유지합니다. 48 슬롯 세마포어 및 20 초 연결 시간 초과입니다. 현지의 CPython 3.12 기본 백로그 대기열은 다음과 같습니다. 5；업데이트된 버전은 다를 수 있으므로 128 이는 모든 사람에게 상대적인 것이 아니라 분명한 목표입니다. Python 버전은 필연적으로 증가할 예정입니다.。

GET 처리 시 요청 본문을 사용하지 않습니다. 배포하기 전에 `Transfer-Encoding` 헤더（해당 값이 비어 있더라도） `Content-Length` 앞뒤 공백을 제거한 후 값이 제대로 맞지 않습니다. `0`，프로세서는 연결을 닫힌 것으로 표시합니다. 일반 자원/API 응답은 여전히 ​​기존 라우팅 확인을 따릅니다. 그런 다음 나머지 요청 본문을 떠나지 않고 연결을 닫습니다./구분된 바이트는 다른 요청으로 구문 분석됩니다. 일반 요청 없음 본문 GET 표준 0 길이 GET 연결 재사용 유지。

인증됨, 정확함 Host/Origin 쌍、CSRF 검사, 활성 연결 허용, 세션 수정 라우팅 및 JSON/업로드 메시지 구분 확인은 변경되지 않습니다.。POST 청킹은 여전히 ​​거부 JSON 요청 본문, 반복되는 길이 및 잘못된 길이입니다. ～ 일지라도 GET 요청 본문에는 구문적으로 정확하고 인증된 스티커가 포함되어 있습니다./보관소 POST，수정 사항은 동일한 연결에서 발송될 수 없습니다. 이는 메시지 구분 경계이며 인증을 대체하지 않습니다.。

## 기존 메모 감사

청취 중인 백로그 대기열을 포함하는 활성 메모가 없거나 읽지 않은 메모가 없습니다. GET 바이트 구분。[Bridge 세션 관리](../../implemented/feature/2026-10-26-bridge-session-management.md)인증된 경우에만 고정/이 결정은 아카이브 경로 경계의 부분 중복에 대해 계속 유효합니다. 기존 아키텍처 보안 장에서는 전송 전략을 문서화합니다. 오래된 결정을 거부하거나 제거할 필요가 없습니다.。

## 대안

- 허용되는 프로세서 동시성 증가: 로드 시 재설정을 줄일 수 있지만 보류 중인 연결 대기열이 아닌 리소스 및 보안 예산이 변경됩니다.。
- 비어 있는 GET 요청 본문: 업스트림 연결 풀을 유지하지만 제한된 메시지 구분 구문 분석 및 읽기 시간 제한이 필요합니다. 받아들이지 않아서 GET 요청 본문의 게이트웨이, 영향을 받는 연결을 닫는 것이 더 작은 수정 사항입니다.。
- 모두에게 GET 사용 안 함 keep-alive：잔여 요청 본문을 피할 수 있지만 일반 비요청 본문 리소스의 연결 풀 이점을 불필요하게 잃게 됩니다.。

GET 요청 본문, 디스패치가 수정되지 않고 반환되지 않았음을 주장 EOF。독립 인증 POST 사용 사례 표지가 로그인되지 않았거나 누락되었습니다. CSRF、실수 Origin、청크 인코딩, 반복/잘못된 길이 및 성공적인 단일 디스패치。

프로세스 내에서 제한된 방식으로 이전 동작을 덮어쓰면 제품 소스 코드를 수정하지 않고도 두 가지 오류를 재현할 수 있습니다. 백로그 대기열은 다음과 같습니다. 5 2초 연결 시간 제한 내에 조명기 시간이 초과되면; 오래된 GET 프로세서에서 읽지 않음 GET 3개의 합성 상위 호출과 3개의 아카이브 호출이 요청 본문에 전달됩니다. 수정 후 7개의 테스트를 통과했습니다. 예상되는 수정 전 실패는 회귀 결과와 별도로 기록됩니다.。

기존 인증, 로그인 보안 필요、Bridge、세션 관리 및 Python 테스트된 총 리소스 157 항목이 통과됨，2 플랫폼으로 인해 항목을 건너뛰었습니다.。Node 의지/릴레이 체크 4 항목이 통과되었습니다. 모든 세션 및 기본 작업 대상은 합성 데이터입니다. 테스트에서는 실제 에이전트 배포, 데스크톱 프로세스, 계정, 채팅, 설치 또는 모델 호출을 사용하지 않았습니다.。

## 영향

콜드 스타트 ​​프록시는 활성 연결 예산을 늘리지 않고도 예상되는 연결 버스트를 대기열에 넣을 수 있습니다. 요청 본문을 구분한 경우 GET 나중에 사용할 수 있도록 바이트를 남겨둘 수 없습니다. HTTP 분석을 요청합니다. 영향을 받은 업스트림 소켓은 연결 풀로 재활용되지 않고 다시 연결됩니다. 일반 자원 GET 재사용을 위해 예약되었습니다. 더 큰 백로그 대기열이 초과된다는 보장은 없습니다. 48 허용된 연결은 긴 연결 포화를 해결하지 않습니다. 실제 에이전트 승인에는 여전히 별도의 배포 확인이 필요합니다. 기존 바이너리/304 응답 도우미는 명시적인 닫기 헤더를 생략할 수 있지만 여전히 소켓을 닫습니다. 이 수정은 응답 동작을 확장하거나 프로토콜 업그레이드를 변경하지 않습니다.。
