# Agent Note: 설치된 채로 두기 DSH 플러그인의 소스 코드 호환성 식별

Status: implemented

## 문제

Test 12 에서 Mac 및 Windows 모두 표시“이미 Harness 액세스를 확인할 수 없습니다.”，다시 검색해도 효과가 없습니다. 실제 플러그인, 연결 파일 및 설치 기록은 그대로 유지되며 소스 경로, 속성 및 바인딩 구조는 모두 유효합니다.。

제출하다 `069ba77e` 프로젝트가 없는 채팅에 대한 기록 위치 읽기 및 수정 추가 `host.mjs`，하지만 이전 버전을 놓쳤습니다 `e608309a` 의 LF/CRLF 소스 코드 요약。`verified_directory` 통과된 것으로 밝혀졌습니다“현재 소스 코드”지점에서는 이를 인식합니다. 소스코드 업데이트 이후 현재 버전도 아니고 이전 버전 목록도 아니어서 거부됩니다. 다음 위치에 고정된 이전 다이제스트를 테스트하세요.“현재 소스 코드”유스케이스에서는 호스트 프로토콜이 수정된 후 유스케이스가 실행되지 않습니다.。

## 결정

창고 추적성을 이전 버전으로 가져옵니다. LF/CRLF 기존 호환성 목록에 요약이 추가되었습니다. 소스 파일, 설치 기록, 구성 경로, 파일 권한 및 자격 증명 구조를 계속 확인하고 플러그인을 자동으로 다시 작성하거나 교체하지 마십시오. token、바인딩 또는 작업 영수증을 지우지 마세요.。

현재 소스 코드 테스트에서는 현재 파일에서 두 줄 바꿈의 재사용 여부만 확인합니다. 시험판 버전에는 두 줄 바꿈을 모두 복원할 수 있고 모든 파일이 변경되지 않은 상태로 유지되는지 명확하게 확인하기 위한 고정된 요약 회귀 기능도 있습니다. 호스트 소스 코드를 수정할 때 이전 버전을 신뢰할 수 없는 소스로 잘못 보고하지 않도록 마이그레이션 테스트를 동시에 실행해야 합니다.。

## 대안

다시 설치하면 새 구성이 생성될 수 있지만 호환성 목록 누락이 숨겨지고 원래 바인딩에 영향을 줍니다. 모든 기록 파일을 허용하려면 소스 코드 확인을 취소하되 이전 프로토콜 액세스의 신뢰 범위를 확장하세요. 액세스 소유권을 변경하지 않고 기존의 정확한 이전 버전 호환성 메커니즘을 채택합니다.。

## 검증

회귀에서는 동일한 문장의 거부 오류를 먼저 재현한 후 요약을 보완한 후 통과합니다.。Mac 실제 설치된 소스코드 요약 및 웨어하우스 `e608309a` 완전히 일관됨；Windows 읽기 전용 검사 결과는 동일한 다이제스트입니다. 실제 액세스에는 여전히 기본 운영 체제가 필요합니다. host 응답, 성공적인 정적 검증이 연결되었음을 의미하지는 않습니다.。

기존 개정 11 바인딩은 계속해서 재사용될 수 있습니다. 새 레코드 위치를 추가하는 기능은 여전히 ​​기본 레코드에 따라 다릅니다. host 버전. 그리고[독립 플러그인 호환성 계약](../feature/2026-10-29-dsh-mobile-and-plugin-compatibility.md)부분 중복: 독립 플러그인의 버전 핸드셰이크는 변경되지 않습니다. 이 수정 사항은 이전 공식 액세스의 소스 코드 화이트리스트에만 적용됩니다. 누락된 문서[연결 수리](2026-11-11-dsh-missing-connector-repair.md)이 수정 사항을 트리거하지 않는 또 다른 오류입니다. 다른 제안은 변경되지 않습니다.。
