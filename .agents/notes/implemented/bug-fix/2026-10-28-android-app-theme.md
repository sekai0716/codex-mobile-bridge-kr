# Agent Note: 기계적 인조 인간 App 통합 테마 및 채팅 상태 유지

Status: implemented

## 문제

안드로이드 폰 설정 테마는 독립적인 설정 창만 변경합니다. 컴퓨터 연결 페이지는 고정된 조명 색상, 채팅을 사용합니다. WebView 브라우저 기본 설정은 기본 설정과 별개이므로 시스템의 어두운 색상, 휴대폰 설정 및 채팅 모양이 서로 일치하지 않습니다.。

## 결정

상속 `bridge/settingsTheme` 의 `system/light/dark` 다음과 같은 세 가지 값 Android App 테마 선택; 계정, 알림 및 기타 표시 설정은 마이그레이션되거나 재설정되지 않습니다. 기본 연결 페이지는 기존 어두운 색상 팔레트를 재사용하고 밝은 색상 팔레트는 기존 색상과 레이아웃을 유지합니다. 기본 `system` ～에 따르면 Activity 현재의 `UI_MODE_NIGHT_MASK` 구문 분석, 명시적인 밝은 색상/다크 커버 시스템。

MainActivity 만들기 WebView 다음과 같은 경우 해당 주제를 제공하세요. Context，페이지가 표시되고, 로드되고, 기본 설정이 변경되고, 시스템 구성이 변경되면 선택 값과 구문 분석된 음영 상태를 주입합니다. 공유 채팅 페이지는 기본 상태를 수신할 때만 이 값을 적용합니다. 일반 브라우저와 iOS 원래의 기본 모양과 느낌 동작을 유지합니다. 채팅에서 테마를 변경하거나 다음을 통해 기본값을 복원하세요. Android 독점 스크립트 포스트백, 현재 재사용 WebView、무작위의 token、동일 출처 및 창 초점 검사에서는 허용되는 세 가지 값만 허용됩니다. 새로운 추가사항 없음 JavascriptInterface。

주제 변경 사항이 유지됨 WebView、채팅 초안, 페이지 탐색 및 워크벤치 재건되지 않음 Activity 또는 웹페이지를 새로고침하세요.。`BridgePresentation` 강조 색상, 글꼴 크기, 밀도 또는 콘텐츠 표시 스위치를 재정의하지 않고 기존 테마 변수 및 모양 컨트롤을 업데이트합니다. 시스템 다크 상태는 기본적으로 제공되며 여전히 지속되는 상태에 의존하지 않습니다. WebView 다시 계산됐나요？ `prefers-color-scheme`。

## 대안

사용 Activity 재건하면 통일될 수 있다 Android 리소스를 확인하지만 사용 중인 리소스를 삭제합니다. WebView；기존 채팅은 초안 및 워크벤치에 남아 있어야 하므로 기본 색상 업데이트 및 페이지 이벤트 동기화를 사용하세요.。

웹페이지만 따라오도록 허용 `prefers-color-scheme` 변화는 적지만 WebView 얕은 상태와 깊은 상태는 호스트에 의해 제어됩니다. `isLightTheme` 영향을 미치며 시스템을 명시적으로 무시하기 위한 전화 설정 선택을 표현할 수 없습니다. 기본적으로 상태를 구문 분석하고 기존 웹 페이지 팔레트를 동기화하여 강제 알고리즘 반전을 방지합니다.。
