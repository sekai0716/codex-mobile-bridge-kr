# Agent Note: 라운드 전반에 걸쳐 답이 없는 비동기 질문 카드를 유지합니다.

Status: implemented

## 문제

Codex 데스크탑은 동시에 여러 개의 비동기 질문을 보유할 수 있습니다.。Bridge 의 `async_requests()` 마지막 라운드만 스캔: 카드에 응답하여 새 라운드를 시작하면 이전 라운드의 다른 카드가 휴대폰에서 검색되고 Web 사라지지만 원래 데스크탑은 응답해야 합니다. 합성 데스크탑 IPC Fixture는 두 개의 카드가 한 개에만 응답한 후 보기 오류가 빈 요청 목록을 반환하는 문제를 재현합니다.。

## 결정

네이티브 상태에서 제공하는 정렬된 내역에서 먼저 누르면 `questionItemId` 각 라운드에서 받은 답변을 수집하고 답변이 없는 질문을 추출합니다. 응답은 후속 입력 라운드, 사용자 메시지 또는 상태에서 올 수 있습니다. `accepted` 리디렉션 메시지; 거부되거나 승인되지 않은 리디렉션 메시지는 카드를 지우지 않습니다.。

각 카드는 원래 차례와 메시지를 계속 사용합니다. ID，각 질문에 대해 원래 메시지를 계속 사용하세요. ID 그리고 색인. 해당 답변이 있는 질문만 제거되며, 같은 카드에 있는 다른 질문은 다른 카드와 별도로 보관됩니다. 일반 승인은 여전히 ​​기본 요청 목록을 통해 이루어집니다. 이 수정은 비동기 문제를 기본 문제로 위장하지 않습니다. RPC 승인 및 자동 회신이나 재생이 추가되지 않음。

현재 기본 스냅샷의 기존 기록만 읽습니다. 전체 기록을 자동으로 로드하거나 세션을 활성화하거나 추출 카드에 대한 모델을 호출하지 않습니다. 기록에 포함되지 않은 카드는 복구된 것으로 간주되지 않습니다.。

## 기존 기록 확인

기존 활성 노트의 비동기 질문, 카드, 답글 표시를 검색한 결과, 이번 라운드의 심사 결정을 기록한 노트는 발견되지 않았습니다. 이 수정사항이 적용됩니다. `ordered_turns()` 기존의 일반 배열과 canonical 다른 기록 캐시를 도입하지 않고 기록 분석。

## 대안

- 프런트 엔드에 임시 저장된 카드는 일시적으로 화면을 유지할 수 있지만 다시 열면 사라지고 백 엔드는 여전히 이전 라운드의 응답을 거부합니다. 따라서 공유 상태 정규화 계층 수정에서。
- 한 라운드만 앞으로 유지하면 변경 사항이 줄어들지만 연속해서 여러 카드에 응답할 때 이전에 답하지 않은 질문을 놓칠 수 있습니다. 질문 지우기를 누르세요 ID 기존 기록을 확인하는 것이 독립적인 카드 의미와 일치합니다.。

## 영향

휴대폰、Web、타임라인 및 알림을 통해 공유되는 요청 예상은 페이지 구조 및 스타일을 수정하지 않고도 일관되게 응답되지 않은 세트를 가져옵니다. 추출 요청은 마지막 라운드로 인해 누락된 항목만 검색하지 않도록 현재 로드된 기록을 순회해야 합니다. 지속성 형식이나 추가 네트워크 요청이 도입되지 않습니다.。

ID 답장 보내기。canonical 과거 사용 사례에는 후속 입력 라운드, 동일한 카드에 대한 부분 응답, 리디렉션 메시지 거부/수락이 포함됩니다. 브라우저 고정 장치는 두 카드를 개별적으로 제출하고, 답변되지 않은 카드를 사용 가능한 상태로 유지하고, 다른 카드를 제출할 수 있는 동안 스냅샷을 업데이트하는 것을 다룹니다. 실제 사용자 세션과 설치 패키지 수락은 별도로 기록되어야 하며 합성 설비로 대체되지 않아야 합니다.。

2026-10-29，이 수정 사항이 포함되어 있습니다. `026784022ab5` Test 이미 Mac、Windows、Linux 빌드, 설치 및 실행 3단자 고정 패키지 회귀가 모두 통과되었습니다. 브라우저 고정 장치는 Chrome 및 WebKit 와이드스크린과 내로우스크린의 4가지 조합이 통과되었습니다. 여기서 확인된 것은 합성이다. IPC 브라우저 다중 카드 의미론을 사용하면 사용자가 실제 데스크톱 세션에서 카드를 쌓은 후 수동 테스트를 대체했다고 주장하지 않습니다. 이 카드 수정에는 공유 요청 예측 및 테스트만 포함되며 인터페이스 스타일은 변경되지 않습니다.。
