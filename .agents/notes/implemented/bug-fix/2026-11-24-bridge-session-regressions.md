# 사이드 채팅 갱신과 반복 조회

사이드 채팅 생성 응답은 자식 ID를 확인하는 데 사용한다. 생성하거나 종료한 직후에는 기존 목록 조회를 취소하고 새 목록을 요청한다. 새 목록의 제목을 같은 워크벤치의 열린 자식 탭에 반영하며, 늦게 끝난 이전 조회는 목록이나 로딩 상태를 바꾸지 않는다.

타임라인의 표시 결과는 원본 상태, 표시 범위, 읽기 기준점이 같은 동안 재사용한다. 라이브 이벤트와 저장 기록 변경은 기존 상태 갱신 경로에서 캐시를 비운다. Git 저장소 후보는 같은 패널에서 보기나 저장소를 전환할 때 재사용한다. 실제 상태와 기록은 매번 읽고, 새로고침과 작업 완료 후에는 후보도 다시 검색한다.

회귀 검사는 앱의 직접 입력에 이어 Bridge 전송을 같은 원본 대화에 한 번 반영하는지 확인한다. 웹에서는 사이드 채팅 생성 전의 목록이 나중에 도착하는 상황과 기존 초안의 보존을 검사한다. 언어를 전제로 하는 브라우저 검사는 언어를 명시하며 자동 검토 검사에는 서버가 전달하는 상태를 사용한다.

Codex 대기열의 개수와 목록은 같은 조회 결과를 사용한다. 숨겨진 탭이 다시 표시되거나 브라우저에 포커스가 돌아오면 새로 조회한다. Bridge에서 보낸 대기 메시지를 Codex가 수락해도 같은 대화를 다시 조회한다. 채팅이나 계정이 바뀌면 이전 조회를 취소하고 늦게 도착한 응답은 무시한다.
