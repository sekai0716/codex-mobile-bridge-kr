# 첨부 업로드 크기 제한 해제

- 웹 선택 단계와 인증된 첨부 HTTP 경로, 첨부 저장소에 있던 파일당 20 MiB 및 메시지당 합계 100 MiB 제한을 해제한다. 메시지당 파일 10개, 인증·CSRF·호스트·채팅 구분, 첨부 ID의 불변성은 유지한다.
- HTTP의 Content-Length를 검증하고 최대 1 MiB씩 읽어 비공개 임시 파일에 저장한다. 전체 해시와 길이가 확인된 후에만 메타데이터를 확정한다. 중간에 끊기면 임시 파일을 지우며 자동으로 재전송하지 않는다.
- 기존 파일·이미지의 Codex 네이티브 첨부 형식은 유지한다. SSH 어댑터는 기존 바이트·Base64 전달 계약을 사용하므로 원격 전송 시 메모리는 파일 크기에 따라 증가한다.
- 이미지 미리보기의 20 MiB 예산, 썸네일 예산, 작업 공간 파일 작업의 별도 제한은 첨부 업로드 한도와 구분한다. APK 네이티브 코드는 바꾸지 않는다.
- 원본 릴리스 커밋 `1004e5ae`에 20/100 MiB 상수가 존재한다. 확인한 이력에는 그 수치를 선택한 이유가 명시되어 있지 않다. 기존 구현은 HTTP 본문 전체를 한 번에 읽고 SHA-256과 원격 Base64 변환을 수행했다. 메모리 사용을 제한하기 위한 수치였다는 설명은 구현에 근거한 추론이며 작성자의 확인된 의도는 아니다.
- Codex Remote의 첨부 API와 같다고 단정하지 않는다. 공개 Codex 코드의 파일 읽기 권한 확인과 스트리밍 처리 원칙을 참고하고, 기존 Bridge의 네이티브 입력 계약을 유지한다.
- 검증: 관련 백엔드 11파일 179개, 웹 첨부·작업 상태 검사 12개 통과. Chromium의 넓은 화면과 390px 화면에서 실제 21 MiB 파일 선택→업로드→원래 첨부 ID 전송 검사 2개 통과. 합성 HTTP와 저장소에서는 101 MiB 초과 저장, 길이 불일치 시 정리, 중복 ID와 인증·CSRF, 업로드 도중 정리 작업과의 경합을 확인했다. 실제 사용자 채팅에 테스트 메시지를 보내지 않았다.
