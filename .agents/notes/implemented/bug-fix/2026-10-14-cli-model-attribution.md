# Agent Note: 라운드별로 기록된 모델 주석 CLI 회신하다

Status: implemented

## 문제

네이티브 CLI `thread/read` 현재 스레드 모델을 제공하지만 각 라운드에 대한 모델 소유권을 제공하지 않을 수도 있습니다. 따라서 기본 연결을 명시적으로 설정한 후 기록 응답에는 다음과 같은 내용만 표시될 수 있습니다. `CODEX`。현재 모델이 전체 라운드에 배정된 경우, 중간에 모델을 바꾼 채팅은 잘못 표시됩니다.。

## 결정

라이브 세션 보기 프레스 ID 기본 라운드를 로드된 저장 기록으로 변환 `turn_context` 협회. 저장 컨텍스트는 실제 모델이 포함된 경우에만 모델 정보를 덮어씁니다. 기본적으로 제공되는 라운드별 모델 필드는 유지됩니다. 새로운 기본 라운드가 시작되면 현재 모델이 캡처되어 라운드에 바인딩됩니다. 이후의 설정 변경으로 인해 라운드 라벨이 다시 지정되지 않습니다. 후속 기본 스냅샷에서 라운드별 모델 필드가 생략되면 라운드별 모델 필드가 사용됩니다. ID 캡처된 설정은 유지됩니다. 명시적으로 제공된 기본 라운드 모델이 우선 적용됩니다. 모델 증거가 누락된 라운드에는 여전히 모델 레이블이 표시되지 않습니다. 기본 콜백 또는 새로 고침은 추가되지 않습니다. SSH 또는 기록을 저장하여 읽을 수 있습니다.。

## 검증

두 개의 기록된 모델과 두 개의 후속 라이브 라운드가 포함된 회귀 픽스처입니다. 현재 스레딩 모델은 두 개의 실시간 라운드 간에 변경되고 두 번째 라운드가 시작된 후 다시 변경된다는 점에서 두 개의 역사적 모델과 다릅니다. 라운드별 모델 없이 기본 스냅샷을 반복적으로 수신하는 경우 두 캡처 태그가 모두 유지됩니다. 명시적인 기본 라운드별 모델이 캡처 태그를 대체합니다.。

## 대안

모든 응답에 현재 모델을 사용하는 것은 간단하지만 역사적 귀인을 위조할 수 있습니다. 기본 콜백 중에 저장된 모든 레코드를 다시 읽으면 메타데이터가 보완되지만 로컬이 추가됩니다./SSH 지연. 따라서 로드된 기록과 기본 라운드별 증거를 재사용합니다.。

## 영향

알려지지 않은 Desktop 기록 태그는 알 수 없는 상태로 남아 있습니다. Desktop 역사적 완성은 현재 모델로 대체될 수 있습니다. 네이티브만 CLI 라운드 바이 라운드 증거는 기록 보관의 누락된 속성을 채울 수 있습니다. 기존 타임라인 회귀 및 기본 혼합 모델 설비로 차이점 검증。
