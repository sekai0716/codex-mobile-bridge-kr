# Agent Note: Claude 서명된 연결 준비 시간

Status: implemented

## 문제

명백한 Claude Desktop 초기화하는 동안 서명된 렌더링 영수증이 표시될 수 있습니다. `status()` 보고서는 연결되어 있지만 기본입니다. DevTools 청소는 아직 진행 중 `reconnecting`。이 기간 동안 인증 목록 요청이 보고됩니다.“Claude 다시 연결하는 중”。

## 결정

현재 커넥터의 서명된 영수증이 승인된 후 이전 읽기 감지가 실패하면 이전 감지가 성공하고 닫혀야 합니다. DevTools 일반 통화에 사용 가능한 사서함을 표시하기 전. 결과가 알려질 때까지 기본 정리가 계속 실행되어 보고됩니다. `consoleCleanupPending`。정리 실패는 기존 수동 종료 프롬프트를 유지합니다. 생성, 귀속, 취소, 전체 소스 주입 및 확인되지 않은 쓰기 확인이 계속 작동합니다.。

처음으로 명시적인 Windows 포그라운드 초기화 중에 기존 소유 프로세스가 없고 영구 연결 토큰이 없는 경우 콘솔 앞에서 이전 렌더러가 새 세대를 따를 때까지 기다리는 단계는 건너뜁니다. 이 초기화 중에 소스 코드가 삽입되기 전에는 어떤 렌더러도 새 토큰에 서명할 수 없습니다. 기존 영구 토큰, 기존 소유권, 재연결 및 다시 시작은 모두 핸드오버 대기를 위해 예약되어 있습니다.。

## 대안

원본 기록을 이전 기록과 비교했습니다.“기본 정리가 완료될 때까지 일반 호출은 계속 차단됩니다.”및“서명 수신 및 필요한 읽기 감지가 통과된 후 먼저 호출을 엽니다.”。이전 경로는 정리와 가용성 간의 대기 상태를 공유했지만 연결이 이미 보고된 후 목록 요청이 거부되었습니다. 첫 번째 Windows 또한 초기화 레코드에는 새 토큰이 주입되기 전에 이전 렌더러에서 서명할 수 없으므로 이전에 소유한 영구 토큰이 없을 때 대기만 제거된다고 명시되어 있습니다. 다른 연결 프로토콜의 비교는 기록되지 않으며 추가 선택 사항도 포함되지 않습니다.。

## 영향

기본 정리가 완료되지 않은 경우 생성된 파일은 이미 첫 번째 목록 요청에 사용할 수 있습니다. Bridge。시뮬레이션의 소스 코드 고정물 Windows/macOS 경로 일시 중지 정리, 확인 중 서명된 목록 응답. 독립적인 Windows 고정물 확인 첫 번째 소유권 대기는 영구 토큰이 없는 경우에만 건너뜁니다. 이러한 고정 장치는 실제 부팅 시간을 측정하지 않으며 플랫폼 승인 및 설치 패키지 확인을 대체하지 않습니다.。
