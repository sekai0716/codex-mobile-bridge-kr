# Agent Note: 수동적으로 보면서 따라하기 CLI 기록 업데이트 저장

Status: implemented

## 문제

첫 번째 수동 읽기는 CLI 라이브 세션에 기록하려면 녹화 스냅샷을 저장하세요. 터미널의 후속 라운드는 동일한 레코드에 추가되지만 세션에 이미 상태가 있으면 후속 타임라인 폴링에서는 기록 읽기 저장을 건너뜁니다. 따라서 전화기는 런타임 경로를 변경하는 작업을 명시적으로 계속할 때까지 초기 대화를 유지합니다.。

## 결정

～에서 CLI 세션이 연결되지 않은 경우 백그라운드 읽기는 저장된 기록을 주기적으로 새로 고칩니다. 로컬에 저장된 기록은 다음과 관계없이 2초의 읽기 간격을 사용합니다. 15 속성 재시도를 실행하는 데 걸리는 시간（초）；SSH 원격 읽기 증가를 방지하려면 원래 특성 재시도 간격을 유지하세요. 정규화된 스냅샷이 변경되지 않은 경우 타임라인 시퀀스 번호가 진행되지 않습니다. 이 작업은 저장된 데이터를 읽기만 하고 스레드를 복원하지 않으며 데몬 프로세스를 시작하지 않으며 기록기를 가져오지 않습니다. 연결된 런타임은 여전히 ​​자체 이벤트를 담당합니다.。

## 검증

통합 픽스쳐는 첫 번째 수동 읽기 이후에 두 번째 터미널 라운드를 추가하여 타임라인 변경에 새 응답이 포함되어 있는지 확인하는 동시에 속성 재시도, 기본 추가 또는 호출을 미리 트리거하지 않습니다. 내용이 변경되지 않은 상태로 반복해서 읽어도 새 행이 생성되지 않습니다. 수정 전에는 테스트가 실패했고 수정 후에는 통과되었습니다.。

## 대안

사용자에게 계속을 클릭하도록 요청하면 새로운 실시간 이벤트가 발생하지만 기록을 읽는 것만으로도 작성자를 얻을 수 있습니다. 모든 폴링을 플러시하면 파일 시스템이 증가하고 SSH 일하고 있는; 제한된 로컬 기록 읽기 간격은 수동 액세스를 읽기 전용으로 유지하면서 가시성 문제를 해결합니다.。

## 영향

실제 격리 원어민 작가가 합격을 하였고, 합격만 하게 되었습니다. GET 게이트웨이 폴링, 2.354 후속 답변은 몇 초 내에 표시되며, 모델이 정확하고 connected=false。SSH 원래 간격을 유지하고 2초 이내에 업데이트를 약속하지 않습니다.。

후속 조치[SSH 오프라인 격리 및 퇴각](2026-10-30-ssh-offline-isolation-and-backoff.md)연결이 끊긴 로컬 시스템으로 동일한 읽기 전용 새로 고침을 확장합니다. Desktop，그리고 SSH 호스트 수준 백오프를 추가합니다. 이 글에서 기록을 저장하는 경계를 바꾸지 말고 쓰기 가능한 증거로 사용할 수 없습니다.。
