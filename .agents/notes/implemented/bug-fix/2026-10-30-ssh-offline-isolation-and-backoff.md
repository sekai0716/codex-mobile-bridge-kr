# Agent Note: SSH 오프라인 격리, 퇴각 및 지역 역사 새로 고침

Status: implemented

## 문제

사용자 피드백 SSH 서버가 오프라인, LAN 및 고정된 후 HTTPS 로그인된 로컬 세션은 다시 연결할 수 없습니다. 공식 버전 v2.1.6 기존과 Test 동시에 영향을 받습니다. 휴대폰이 계속 연결되면 프롬프트“데스크톱에서 아직 이 채팅을 로드하는 중입니다.”，최신 콘텐츠를 검색하거나 전송할 수 없습니다. 사용자가 오프라인으로 전환하도록 요청했습니다. SSH 로컬 운영에 영향을 주지 않으며, 자동 재시도는 백오프를 사용하며, 계정 관리에서 수동 재시도 기능을 제공합니다.。

격리 및 재발 확인된 사례 3건 Bridge 결함: 이 기계와 SSH Bridge 공유 계정 작업 잠금, 원격 활성화 및 읽기 대기는 로컬 활성화를 차단합니다. 5번 연속 오프라인 읽기가 5번 시작됩니다. SSH；로컬 머신 Desktop 세션의 실시간 연결이 끊어지면 기존에 저장된 기록이 새로 고쳐지지 않습니다. 해당 테스트는 수리되기 전에 모두 실패했습니다. 이전 집계 목록, 활동 및 알림 검색도 원격 메타데이터를 동기적으로 기다리며 기본 읽기와 분리되어야 합니다.。

첫 번째 사이트에도 독립적인 네이티브 레이어 문제가 있습니다.：8787、8788 상태 인터페이스가 모두 반환됩니다. 200；독립 원주민 IPC 초기화에 성공했지만 최근 세 개의 기본 세션 중 어느 것도 반환되지 않았습니다. owner，구독도 상태 스냅샷을 받지 못했습니다. 현재 설치된 라우팅 소스 코드 버전의 10초 검색 기간에 따라 단일 읽기 전용 쿼리를 확장한 후 다음을 얻습니다. `no-client-found`。이 확인은 게이트웨이를 거치지 않고, 채팅을 활성화하지 않으며, 메시지를 보내지 않습니다. 설치된 버전은 여전히 ​​원본을 지원합니다 owner 프로토콜 버전 및 상태 버전 11，버전 업그레이드가 호환되지 않는 현상으로 판단할 수도 없고, 현상으로 판단할 수도 없습니다. Bridge 결함이 현장 고장의 유일한 원인으로 추론됩니다.。

## 결정

일반적인 기본 작업은 호스트별로 직렬화되며 다른 호스트는 독립적으로 진행할 수 있습니다. 글로벌 계정 변경 및 애플리케이션 시작 및 중지는 계속해서 모든 호스트의 기내 작업이 완료된 후에만 획득할 수 있는 전용 도어록을 사용합니다. 도어 잠금 장치는 원래 중첩 호출을 지원합니다. 뿌리 Bridge 시스템의 디렉토리, 신뢰 및 생성 항목은 실제 대상 호스트에 따라 해당 작업 도어 잠금 장치에 들어갑니다. 오프라인 호스트는 유휴 상태의 증거로 사용될 수 없습니다. owner/provider/auth/cwd、확인 중지 및 알 수 없는 쓰기 방지가 계속 적용됩니다.。

Codex 전용 도어락 획득 요청을 종료하기 전에 최대 2초 정도 기다리세요. 연결이나 다른 작업으로 인해 도어록이 여전히 점유되어 있는 경우 즉시 반납하십시오.“가지다 Codex 작업이 진행 중이며 종료가 수행되지 않았습니다. 나중에 다시 시도해 주세요.”；종료 없음, 활성화 기본 설정 수정 없음, 백그라운드 큐잉 없음, 원래 작업이 완료된 후 자동 재생 종료 없음. 사용자가 도어 잠금 장치를 성공적으로 획득하기 위해 명시적으로 재시도한 후에는 완전한 새 작업 확인 및 기본 프로세스 ID 확인이 계속 수행됩니다. 이 상한은 대기열만 제한하며 약한 네트워크에서 작업 확인을 단축하거나 시간 초과를 유휴 상태로 처리하거나 일반적인 종료 프로세스를 대체하는 데 사용할 수 없습니다.。

공유 클라이언트 수명 주기는 단계가 2초 정도 걸리거나 단계가 실패하는 경우에만 기록됩니다. `operation-wait`、`task-check`、`native-stop` 결과 및 시간 소모, 일반 빠른 작업에서는 로그가 증가하지 않습니다. 로그에는 세션 ID, 본문, 계정 번호 또는 자격 증명이 포함되지 않습니다. 도어 잠금 대기, 작업 확인 및 기본 종료 시간은 별도로 측정됩니다. 연결 백로그는 운영 체제의 느린 종료로 인한 것일 수 없습니다.。

`bridge/features/network/retry.py` 공유 호스트 백오프 규칙 및 버튼 저장 SSH 별칭으로 격리된 처리 중 상태。Codex 메타데이터, 디렉터리, 파일 읽기 및 Claude Code 읽기 전용 SSH 보조 요청은 동일한 상태를 재사용하며 각 클라이언트에 대한 재시도 알고리즘을 작성하지 않습니다. 실패한 연결에 대한 대기 시간은 약 30초에서 두 배로 늘어납니다. 0.8–1.2 랜덤 지터, 상한은 10분입니다. 대기는 단조로운 시계를 기반으로 합니다. 인터페이스는 예상 재시도 시간을 별도로 변환합니다. 연결이 복원된 후 실패 횟수가 지워집니다. 동시 이전 요청의 성공은 확인된 후속 연결 끊김을 덮어쓸 수 없습니다. 원격 비즈니스 스크립트에서 보고된 오류는 다음과 같이 계산되지 않습니다. SSH 오프라인으로 전송。

냉각 기간 동안에는 읽기가 빠르게 실패하며 만료 시 복구 시도는 한 번만 허용됩니다. 기존 유지 관리 주기는 백오프 기간에 따라 읽기 전용 연결 감지를 시작하고 고정된 간격으로 반복적으로 연결을 설정하지 않습니다. 제거되었거나 별칭이 변경된 등록된 호스트는 더 이상 자동으로 감지되지 않습니다. 자동 감지만 실행되어 고정됨 Python JSON 생성, 전송, 승인, 기타 쓰기를 저장하거나 재생하지 않고 응답합니다. 상태는 지속되지 않으며 게이트웨이가 다시 시작된 후 알 수 없는 상태에서 증거가 다시 설정됩니다.。

계정 관리는 기존 공유를 사용합니다. `AccountsPanel` 등록된 쇼 SSH 호스트, 현재 감지 상태, 다음 재시도 시간 및“다시 시도하세요 SSH 연결”。수동 작업은 냉각 기간을 건너뛰고 전송 중 감지를 호스트와 병합합니다. 읽기 전용 감지는 백그라운드에서 실행됩니다.，HTTP 기다리지 마세요 SSH 타임 아웃. 웹 포털은 로그인을 유지합니다、Host、Origin 및 CSRF 확인, 호스트만 허용됩니다. ID，클라이언트 제공 별칭, 명령 또는 경로를 허용하지 않습니다. 데스크탑 제어 항목은 동일한 서비스 방법을 따릅니다. 탐지 복구만이 증명됩니다. SSH/Python 사용 가능, 기본 세션을 나타내지 않음 owner、모델 서비스 또는 작업이 복원되었습니다.。

집계된 목록, 활동 및 알림 검색은 로컬 결과를 기다리지 않고 제한된 백그라운드 원격 읽기 및 단기 캐싱을 사용합니다. SSH。원격 호스트 목록을 개별적으로 지정하면 해당 호스트가 정상적인 연결에 대한 첫 번째 응답을 보존할 때까지 기다릴 수 있습니다. 불완전하거나 실패한 집계 읽기는 사용할 수 없는 호스트 피드백을 상속합니다. 수동적 읽기는 여전히 작업을 활성화하지 않습니다.。

프로젝트 작업에 대한 잠금 경로는 등록된 호스트 및 프로젝트만 확인합니다. key，선택적 잠금을 위해 모든 호스트를 열거하지 마십시오. 채팅을 생성하면 선택한 호스트의 항목만 열거되며 여전히 전체 항목입니다. key、디렉터리 신원 및 기본 프로젝트 기록 검증 대상 프로젝트 집계 목록의 경우 SSH 기존의 역사적 사용 `RemoteStore.poll`，오프라인 읽기를 기다리지 마세요。Windows 기본 회귀가 프로젝트 신뢰 입구에서 중단되었으며 잠금 열거 프로젝트를 선택한 후 스레드 스택이 유효하지 않은 것으로 판명되었습니다. 새로운 CLI 사용자가 선택한 경우 채팅 SSH 환경에서는 호스트의 프로젝트만 읽고, 집계 배경의 완료되지 않은 과거 프로젝트는 완료됩니다. 기본적으로 로컬 팝업 창은 기다리지 않습니다. SSH；로컬 머신으로 다시 전환하거나, 팝업 창을 닫거나, 환경을 변경한 후 지연된 결과를 무시하고, 읽는 동안 이전 선택 항목을 제출하는 것이 금지됩니다. 예약된 폴링을 추가하지 않고도 동일한 프로젝트 서비스, 디렉터리 ID 및 인증이 사용됩니다. 회귀에는 최초 원격 프로젝트, 단일 호스트 요청, 지연 결과 및 비로그인 거부가 포함됩니다.。

## 대안
