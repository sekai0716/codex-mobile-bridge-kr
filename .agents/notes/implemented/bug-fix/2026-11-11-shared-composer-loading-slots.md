# Agent Note: 공유 입력 영역은 로드 및 오프라인 시 전체 슬롯을 유지합니다.

Status: implemented

## 문제

이전에는 공유 클라이언트 입력 영역만 있었습니다. `composerCapabilities` 역사적 기록을 남길 수 있다 Skill、권한, 첨부 파일 및 작업 모드。Claude 아직 능력을 반환하지 않은 세션은 먼저 불완전한 입력 영역을 표시한 다음 실제 능력에 도달한 후에 컨트롤을 삽입합니다. 첨부파일이 숨겨져 있는 경우，CSS Grid 자동 순위에서는 전송 방법도 첫 번째 행에 배치됩니다. 30 / 26 px，좁은 화면에는 아주 적은 양의 텍스트만 남습니다.。

## 결정

`DesktopSessionsView` 모든 클라이언트에 대해 동일한 모델 세트 유지、Skill、권한, 컨텍스트, 첨부 파일, 전송 방법, 작업 모드, 입력 및 전송 제어. 첫 번째 화면 모델 이름은 저장된 목록에서 읽을 수 있습니다. 목록 메타데이터는 항상 읽기 전용이며 쓰기 권한을 부여할 수 없습니다. 아직 확인되지 않았거나 명시적으로 지원되지 않는 기능은 각각 다음과 같이 표시됩니다. `unknown` 및 `unsupported`，둘 다 비활성화된 슬롯을 유지합니다. 실제 기능과 실시간 연결이 작동을 결정합니다. 읽기 가능한 모델 디렉터리의 기존 호환 항목만 원래 기능 확인을 유지하며 디스플레이 메타데이터로 쓸 수 있는 권한이 없습니다.。

`manager._read(detail)` 기존 기본 제공 어댑터의 기본 입력 계약을 공유 기능에 명시적으로 투영합니다. 기본만 해당 `attachments` 부울 값인 경우에만 누락된 값을 입력합니다. `send` 및 `projectReferences`，명시적인 제한이 우선 적용됩니다.。Claude 의 가치는 관찰된 것에서 나온다. `sendMessage` 방법，DSH 관찰된 것으로부터 `sessionController.prompt`，나머지 액세스에는 실제 전송 클레임이 있습니다. 모든 내장 어댑터는 동일한 기본 입력 경로를 통해 게이트웨이 인증 메시지를 처리합니다. `resolvedReferences`。이는 카탈로그나 온라인 상태를 통해 추측하는 기능이 아닙니다. 누락된 필드 또는 부울이 아닌 값은 알 수 없는 상태로 유지되며 지원 설명이 생성되지 않습니다. 현재 작업 대기열 및 보충은 각 어댑터에 대한 명시적 값을 유지하며 공유 레이어의 값을 보완하지 않습니다.。UI 현재 작업을 전송하고, 대기열에 추가하고, 보완하려면 명시적인 지원이 필요합니다. 프로그래밍 방식 제출도 확인됩니다. 알 수 없는 정보는 발송되지 않습니다.。

离线时输入框继续接受草稿；已有草稿、附件对象和阅读状态不因能力切换而重建。历史或缓存中的展示能力不能开启发送、模型、Skill、权限或工作模式。附件上传仅使用明确的 `attachments: true`；项目引用仅使用明确的 `projectReferences: true`，`cwd` 存在不是支持引用的证据。引用选择、工作台加入和发送使用同一能力门禁；已有引用在能力未知时保留草稿且阻止提交，不擅自省略或清除。ZCode 实时快照可以在原生聊天能力允许时继续发送文字和独立上传的附件，但只有本机会话项目目录仍有效时才声明 `projectReferences`；失效目录不会让文字发送在本地文件预检阶段留下 `unknown` 回执，文件、终端和 Git 工作区返回不可用状态。上传与引用、计划与目标的合并状态均为：任一明确支持则支持，全部明确否定才为不支持，其余为未知。

공유 전송 행은 첨부 파일, 전송 방법, 작업 모드 및 작업 영역을 첫 번째부터 네 번째 열까지 명시적으로 수정합니다. Codex 메인 페이지 `#work-mode` 다른 고객들과 `.work-mode-select`。첨부 파일이나 모드가 다른 항목에 의해 숨겨지면 나머지 컨트롤은 원래 열에 유지됩니다.，320 px 의 26 px 첨부 슬롯은 전송 방법에 의해 점유되지 않습니다.。

## 대안

각 어댑터에서 완료 `composerCapabilities` 기존 클라이언트의 호핑은 줄일 수 있지만, 새로운 클라이언트가 들어오거나 아직 기록을 받지 못한 경우에도 동일한 문제가 여전히 존재하므로 전체 슬롯은 공유 구성 요소에서 처리됩니다. 표시 기능을 실행 기능으로 처리하면 사전에 제어가 가능하지만 실제 권한 확인을 건너뛰므로 표시와 작업이 계속 분리됩니다. 숨겨진 첨부파일을 하나만 추가하세요. CSS 분기는 현재 첫 번째 열 증상을 수정할 수 있지만 다른 숨겨진 컨트롤은 여전히 ​​자동 순위에 의존하므로 4개의 기존 슬롯에 대한 명시적인 열 번호가 사용됩니다.。

## 검증

`tests/desktop-sessions-ui.test.cjs` 표시되지 않는 메타데이터 로드, 명확하게 지원되지 않는 기능, 기능 준비 및 연결 해제를 다루는 4개의 새로운 클라이언트 동일 상태 매트릭스가 추가되었습니다. 원본 컨트롤, 초안 및 첨부 파일 개체가 다시 작성되지 않았는지, 클라이언트 요청이 없는지 확인하십시오. 지원되지 않는 기존 기능이 포함된 어설션은 표시되고 비활성화되도록 업데이트됩니다. 첫 번째 초안 대 `tests/layouts.test.cjs` 함께 달리다 204 개：203 한 항목이 통과되었습니다. 현재 파일 레이블을 사용하여 이미 파일 레이블을 반환한 테스트 하나가 실패했습니다. HEAD 원래 공유 스크립트와 정확히 동일한 사용 사례가 여전히 동일한 오류를 재현하며 이는 이 변경으로 인한 것이 아닙니다. 세 가지 새로운 대상 사용 사례가 검토 증분에 추가되어 통과되었습니다. 예 `cwd` 그러나 인용 기능이 누락된 경우 인용을 선택, 추가 또는 보낼 수 없으며 기존 초안은 손실되지 않습니다. 계획 / 목표 9개의 3상태 조합은 그대로 유지됩니다. 연결되었지만 알 수 없는 전송, 대기열 및 보충 기능을 디스패치할 수 없습니다. 계약 변경 사항을 보낸 후 관련 사용 사례를 실행하고 실제 게이트웨이의 명시적인 전송 응답에 이전 합성 세부 정보를 입력합니다. 영향을 받는 7개 항목을 다시 확인하고 실패할 경우 알려진 반환 파일 태그가 유지됩니다. 반복 실행 없이 변경되지 않은 원래 행렬。

`tests/test_desktop_sessions.py` 현실의 `Claude.dispatch(detail)` → `manager.call(detail)` 계약 테스트에서는 기본 방법을 사용하여 두 개의 응답을 존재 및 제거하여 전송 및 참조 문을 확인하고 원래 대기열 및 보충 기능을 유지합니다. 알 수 없거나 부울이 아닌 메타데이터, 명시적인 비활성화 기능 및 대상 재정의 기존 참조 디렉터리 유효성 검사, 기본 디스패치 및 동기화와 함께 ID 재경기 없음, 총 3번의 패스. 테스트는 기본 메타데이터만 시뮬레이션하고 클라이언트나 모델은 실행하지 않습니다.。

생산 자원 및 격리 loopback 실제로 고정 장치 Ego Chromium 통과하다 320 / 350 / 390 / 1280 px、중국어와 영어로 구성된 8세트의 시험, 각 세트 97 어설션에 따르면 클라이언트와 모델 쓰기가 모두 0입니다. 검사에는 4개의 클라이언트 슬롯 모두, 알 수 없는 것과 지원되지 않는 것의 구별, 초안 첨부 파일 보존, 첨부 파일을 명시적으로 숨긴 후 전송 열 너비 및 전송 버튼 경계가 포함됩니다.。320 px 영어 스크린샷은 육안으로 검사되었습니다. 도구 모음은 가로 스크롤을 유지하고 축소 버튼에 액세스할 수 있으며 전송 라인이 가로로 오버플로되지 않습니다. 이 증거는 휴대폰 기본과 동일하지 않습니다. WebView 아니면 실제 모델 접수 및 수락。

검토 후 최종 증분은 다음과 같습니다. macOS 실제 Ego Chromium 오직 달리다 Codex 메인페이지 제작 입력영역 복제 및 변경 능력 계약：320 / 390 px、중국어와 영어로 구성된 4개 그룹, 각 그룹 22 제로 클라이언트로 전달된 항목 / 모델요청. 입력 중 2개는 실제에서 직접 제공됩니다. manager 단순한 수동 주입이 아닌 세밀한 대응 `true`；원래 컨트롤을 각각 활성화 및 비활성화하는 기본 방법이 있습니까？ 기본 페이지에 있는 두 개의 드롭다운 상자는 각각 두 번째와 세 번째 열에 있습니다. 첨부 파일은 겹치거나 줄 바꿈되지 않고 표시되거나 숨겨집니다.。320 px 영문메인페이지의 첨부파일을 스크린샷과 실제 공유로 볼 수 있습니다. `prepareChat` 알 수 없는 로딩 상태의 스크린샷을 육안으로 검사하였으며, 로딩 상태에서는 첨부 파일이 표시되고 비활성화됩니다. 새로운 Fixture는 브라우저 Use Case로 별도로 등록되며, 후속 조치는 다음과 같습니다. CI 독립적으로 선택 가능。Windows 및 Linux 사용자의 요청에 따라 원격 끝이 일시 중지됩니다. 이 시점에서는 원격 인증이 사용되지 않습니다.。

## 영향

로드 및 연결 해제된 입력 영역의 구조가 안정적이며 알 수 없는 기능과 지원되지 않는 기능을 구분할 수 있습니다. 분명히 지원되지 않는 기능은 여전히 ​​비활성화된 슬롯을 차지하고 좁은 화면 도구 모음은 기존 가로 스크롤을 계속 사용합니다. 이번에는 새로운 기능, 클라이언트별 입력 영역 또는 권한 추론이 추가되지 않습니다. 기존 모델 카탈로그, 영수증 전송, 오프라인 초안, 파일 접근 경계 보존。
