# Agent Note: SSH 디렉토리 읽기 및 Skill 기다리다

Status: implemented

## 문제

Issue #90 이 창고 사용자가 작성함 try2love 제출, 이 기계에서 Codex App 의 SSH 입장; 모델 디렉토리 프롬프트 SSH 읽기 실패，Skill 천천히 열립니다. 사용자는 현재 액세스가 재테스트에 사용될 수 있는 실제 환경이며 격리 고정 장치가 완전한 수락으로 간주되어서는 안 된다는 점을 분명히 이해합니다.。

절연 설비는 세 가지 별도의 문제를 재현합니다. 설치에만 해당 App 없이 런타임 관리 PATH 설치 중 디렉터리 읽기 오류로 인해 존재하지 않는 디렉터리가 선택되었습니다. `.local/bin/codex`；모델 Skill 네트워크 요청 공유 잠금; 만료되었습니다 Skill 목록이 강제로 새로 고쳐지기 위한 동기화를 기다리고 있습니다. 현실 88server 동시에 PATH 및 standalone 런타임 시 누락됨 PATH 픽스쳐는 이 실패를 직접적으로 설명할 수 없습니다. 원래 구현에서는 두 경로 중 하나를 사용하며 전체 디렉터리 쿼리는 다음 위치에 있습니다. `account/read` 기다리다; 독립적인 구성, 모델 목록 및 Skill 대략 읽습니다. 0.3–0.6 초, 인증 모드 쿼리는 약 0.32 초이며 토큰이 반환되지 않았습니다. 초기에는 스택 위치가 다음과 같이 잘못 판단되었습니다. config/read，생성 소스 라인 번호 및 항목 요청에 따라 다음과 같이 수정합니다. account/read。

## 결정

재사용 SSH 네이티브 CLI 기존 관리형 런타임 타겟팅 규칙을 기존에 추가 Catalog 클래스는 두 곳에서 호출되며 원격 끝은 예약되어 있습니다. home、cwd、provider 및 인증。SSH 단기 디렉터리 도우미 프로세스는 원래 런타임만 사용합니다. `getAuthStatus` 인증 모드를 차별화하고 명확하게 합니다. `includeToken=false` 및 `refreshToken=false`，디렉토리 선택으로 변환하고 Fast 필요한 기능 유형은 다음과 관련이 있습니다. requiresOpenaiAuth；전체 작업 공간 경로를 읽지 말고 신원을 위조하지 마십시오. 알 수 없는 유형이 실패했습니다.，API Access는 여전히 현재 업스트림만 사용하며, 실패할 경우 관련 없는 기본 모델로 대체되지 않습니다. 로컬 디렉토리 및 추가됨 CLI 환경 검증 경로는 원래 계약을 유지합니다. 모델 Skill 해당 요청 잠금을 사용하십시오. 내쉬다 Skill 먼저 기존 캐시를 반환하고, 백그라운드 읽기 전용을 통해 업데이트 결과를 새로 고치고, 실패하면 캐시를 유지합니다. 수동 새로고침 및 전송 전 Skill 검증을 통해 원래 계약이 유지됩니다.。

및[SSH CLI 업스트림 모델 디렉토리](../feature/2026-10-18-ssh-cli-model-catalog.md)공유 런타임 선택만 포함된 부분 중복은 데몬 환경 확인을 변경하지 않습니다. ～와 함께[원래의 CLI owner](2026-10-14-cli-existing-owner.md)보완적인 수동 디렉터리 쿼리는 채팅을 재개하거나 메시지를 실행하거나 계정을 전환하지 않습니다. 기존 ID 경계를 대체하기로 결정하지 않았습니다.。

## 대안

단순히 시간 초과를 늘리는 것만으로는 오류 경로와 공유 잠금이 제거되지 않습니다. 웹 페이지에서 실패 프롬프트를 숨기면 디렉토리를 사용할 수 없게 되므로 제외됩니다. 새로운 독립 런타임 검색 모듈을 생성하면 원격 패키징 리소스가 추가됩니다. 이번에는 기존의 것을 사용하겠습니다. Catalog 경로 선택 논리의 여러 복사본이 중복되는 것을 방지하기 위한 파일。

## 영향 및 검증

생성된 실제의 격리된 런타임 실행 SSH 소스 코드, 모델 및 Skill 모두 반환되었습니다. 없이 전체 프로세스를 확인하세요. account/read，Fast 용량은 계속해서 검증되고 있습니다. 기존의 신규 및 기존 관리형 레이아웃、PATH 및 `.local/bin` 대체가 예약되었습니다. 느린 모델이 차단되지 않음 Skill；만료된 목록은 새로 고침이 완료될 때까지 읽을 수 있으며 목록은 실패 시 유지됩니다. 모델 아이덴티티, 네이티브 CLI、독립적인 SSH 소스 리소스、Fast 모듈 경계 회귀를 통과하면 총 147 목; 그중에서 Fast 의 HTTP/Unix socket 처음으로 7개 항목이 샌드박스에 의해 차단되었으며, 전체 그룹이 격리 및 모니터링이 허용되었습니다. 15 해당 항목은 통과되었으며 제품 결함 또는 건너뛰기로 간주되지 않았습니다. 현실 88server、원래의 `/data2/sp/jev` 및 openai provider 읽다 8 모델, 강제로 새로 고침 5.69 초, 캐시 0.32 두번째；132 개 Skill 강제 새로고침 1.00 초, 동일한 인스턴스 캐시가 0.01 두번째. 메시지가 전송되지 않거나 원격 소스 코드가 수정되었습니다./구성에서는 디렉터리 읽기의 기본 캐시만 사용됩니다. 증거는 `.tmp/issue90-20261028/`，제출하지 마세요。

Mac Test 컴파일, 서명 확인 및 덮어쓰기된 버전 설치 `2.1.6-test.20261028.7ec401e3b574`；원래 로그인, 연결 구성 및 초안은 유지되며 공식 버전 및 기본 클라이언트 프로세스는 변경되지 않습니다.，370 패키지된 각 웹페이지 리소스는 소스 코드와 일치합니다. 시동 후 Codex、Claude、DSH 모두 인터페이스에 연결되어 있는 것으로 확인되었으며, 그 중 Claude 사용자가 승인한 초기화 프로세스를 사용하여 복원합니다. 설치 후 기존 LAN 포털을 통해 로그인 Test，같은 진실을 읽어보세요 SSH 세션 디렉터리를 종료하고 이 로그인을 종료하세요.：8 모델 강제 새로 고침 1.10 초, 캐시 읽기 0.36 두번째，132 개 Skill 강제 새로고침 0.99 초, 캐시 읽기 0.02 두번째. 이전 소스코드 보조과정의 콜드리딩 시간은 별도로 기록됩니다. 로컬 웹페이지 접속 종료 설정은 유지되며, 403 디렉터리 오류로 처리됩니다. 설치 및 인터페이스 증거는 각각 위 디렉토리에 있습니다. `install-result.json`、`installed-api-result.json`。

## 위험

후속 조치[SSH 오프라인 격리 및 퇴각](2026-10-30-ssh-offline-isolation-and-backoff.md)디렉토리 등을 위해 SSH 모델 변경 없이 공유 전송 백오프 추가 요청 및 Skill 잠금 및 ID 규칙。

처음으로 캐시가 없습니다. Skill 스캔에는 여전히 기본 런타임 경과 시간이 적용됩니다. 기존 디렉터리 결과는 표시용일 뿐이며 전송 시 확인을 대체할 수 없습니다. 모델의 첫 번째 강제 새로 고침은 여전히 ​​기본 디렉터리 로딩 시간의 영향을 받으며 모든 쿼리가 1초 미만이라고 주장되지는 않습니다.。
