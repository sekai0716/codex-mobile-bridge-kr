# 프로젝트 안의 Git 저장소 선택

## 원인과 기준

채팅의 작업 디렉터리가 저장소의 상위 폴더이면 기존 Git 화면은 그 디렉터리에서만 조회했다.
따라서 바로 아래에 저장소가 있어도 Git을 사용할 수 없다는 응답으로 종료되어 변경 내역과 기록을 열 수 없었다.

설치된 공식 데스크톱 앱 26.1111.21308의 Git 저장소·워크트리 선택 상태와 Git 루트 조회를 읽고, 채팅 cwd와 선택한 Git 대상을 별도로 유지하는 방식을 참고했다.
원본 코드나 원본 앱을 변경하지 않는다. 공식 앱의 전체 프로젝트 탐색 방식을 재현하는 기능은 아니다.

## 변경

현재 프로젝트와 바로 아래의 실제 `.git` 저장소·워크트리를 후보로 제공하고 Git 화면에 선택 목록을 표시한다.
현재 위치가 유효한 Git 작업 위치이면 우선하고, 없으면 정렬된 첫 후보를 사용한다. 선택한 후보가 유지되는 동안 새로고침·모드 변경에도 선택을 보존한다.
같은 이름의 후보는 전체 경로로 구분한다. 이름·경로·명령 출력은 번역 입력으로 사용하지 않는다.

변경 내역·파일 비교·커밋 기록·커밋 상세·과거 파일 비교·브랜치 조회 및 쓰기는 선택한 저장소를 사용한다.
확인창은 열 때의 대상과 상태 버전을 보존하여 이후 선택이 달라져도 다른 저장소에 쓰지 않는다.
저장소별 상태 버전에는 작업 위치를 포함하므로 같은 커밋·색인을 가진 다른 사본에 재사용할 수 없다.

프로젝트 밖 경로, `.git` 내부, 심볼릭 링크·재분석 지점으로의 이동은 거부한다.
POSIX에서는 검증한 디렉터리 핸들을 요청 동안 유지하여 선택 뒤 경로가 교체되어도 다른 위치에서 Git을 실행하지 않는다.
기존 로그인·Host·Origin·CSRF 검사와 결과 미확인 쓰기의 자동 재전송 금지를 유지한다.
선택 목록 조회는 원본 세션의 cwd/provider/auth/owner를 바꾸거나 세션을 시작·재개하지 않는다.

## 검증과 배포 범위

`test_git_workspace.py`는 상위 프로젝트의 하위 저장소 조회·쓰기 분리, 다른 사본의 버전 재사용 거부, 경로 경계, Linux 디렉터리 교체, HTTP 조회·쓰기 계약을 확인한다.
`runGitRepositorySelectionChecks`는 실제 Git 패널과 CSS에서 선택 변경 중 늦게 도착하는 비교 응답, 저장소별 기록·비교, 확인창 대상 고정, 세 언어, 좁은 화면 배치를 확인한다.
파일 시스템과 핸들 검사는 Linux에서 실행했다. Windows·macOS의 실기기 검증은 수행하지 않았다.

PC 게이트웨이와 웹 파일을 갱신한다. Android·iOS 네이티브 소스 변경이나 APK 재빌드는 필요하지 않다.
