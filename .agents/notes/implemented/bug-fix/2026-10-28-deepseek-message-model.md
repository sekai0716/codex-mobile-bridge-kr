# Agent Note: DSH 실제 모델과 과거 요청 사고 강도를 보여주는 답변

Status: implemented

## 문제

DSH 채팅에는 이미 모델 선택기가 있지만 기록 메시지를 변환할 때 응답의 모델 출처와 요청의 사고 강도는 삭제됩니다. 현재 세션 선택으로 모든 메시지를 완료하면 모델을 전환하기 전에 잘못된 주석이 달린 응답이 표시됩니다. 기본 기록 페이지는 연속적인 이벤트 조각이며 요청 헤더는 현재 페이지 앞에 있을 수 있습니다.。

## 결정

응답 모델은 기본적으로 읽습니다. `assistant/message.data.message.source`。사고 강도 가장 최근의 이전 답변 읽기 `request/header.data.header.config.reasoningEffort`，그리고 요청만 provider/model 응답 소스와 일치하는 경우에만 추가하고, 누락되었는지 추측하지 마십시오. 사용될 `model/selection` 생성된 응답의 실제 매개변수를 나타내지 않습니다.。

DSH 플러그인은 기록 페이지 내의 요청 헤더를 순차적으로 연결합니다. 첫 번째 관련 이벤트가 이미 응답인 경우 설치된 이벤트를 전달합니다. Harness 의 `sessionQuery.observeSession` 현재 페이지 경계 이전의 가장 최근 요청 헤더를 콜드-읽고 finally 중간 릴리스 observation。이 읽기는 생성되거나 활성화되지 않습니다. Agent，호출되지 않음 prompt/cancel/selectModel。게이트웨이로 반환된 추가 필드는 다음을 허용합니다. provider/model/reasoningEffort 세 개의 문자열, 완료 header、시스템 프롬프트 및 기타 구성은 반환되지 않습니다.。

커넥터 개정이 다음으로 업그레이드되었습니다. 8，이전 버전에 대한 수명 주기 검사는 계속해서 호환되므로 기존 가용성과 비교하여 업그레이드를 확인할 수 있습니다. 이전 액세스에서는 여전히 소스의 모델을 표시할 수 있습니다. 신뢰할 수 있는 요청 기록이 없으면 추측의 강도가 표시되지 않습니다. 웹페이지는 채팅 레이아웃을 변경하지 않고 기존 응답 서명을 재사용합니다.。

### 기존 기록 확인

[알림 전달 격리](2026-10-28-notification-delivery-isolation.md)부분 중복: 둘 다 읽음 DSH 기록. 하지만 이 문서에서는 표시 메타데이터만 추가하고 완료 상태에는 여전히 기본이 필요합니다. turn/end。동일한 모델 주석 결정은 활성 노트에서 찾을 수 없으며 다른 액세스 및 페이징 기록은 다시 작성되지 않습니다.。

## 대안

현재 세션을 직접 복사 model/effort 가장 간단하고 추가로 읽을 필요가 없습니다. 다만, 나중에 선택한 모델은 예전 답글로 표시될 테니 포기하세요.。

기존 페이지 매김만을 사용하여 반복적으로 기록 페이지를 앞으로 가져옵니다. API，그러나 요청 헤더가 현재 페이지에서 멀리 떨어져 있을 수 있으며 반복적인 페이징으로 인해 읽기 오버헤드가 증폭됩니다. 기본 쿼리 서비스를 사용하여 한 번 콜드 리드（cold read）하고 릴리스합니다. 기존 서비스가 존재하지 않는 경우 모델 소스를 유지하고, 강점을 구축하지 않습니다.。

## 영향

과거 응답은 페이지 기준이 부족할 때 기본 콜드 읽기를 추가하고 실행 중인 내용을 업데이트해야 하는 대신 자신의 모델과 확인 가능한 사고 강도를 보여줄 수 있습니다. DSH 입장. 페이지 매김, 지점 식별, 알림 라운드 및 계정 소유권은 변경되지 않습니다.。

회귀는 사전 페이지 요청, 후속 설정 격리, 동일한 페이지 모델 전환, 강도 없음, 소스 불일치, 이전 액세스 저하, 기본을 다룹니다. observation 릴리스 및 요청 헤더 민감 필드는 외부로 전송되지 않습니다. 실제 머신의 소스 구조는 읽기 전용으로 확인되었으며, 채팅 내용은 출력되지 않습니다.。
