# Agent Note: 모든 클라이언트가 비활성화되어도 게이트웨이는 관리 가능한 상태로 유지됩니다.

Status: implemented

## 문제

마지막 클라이언트 액세스를 닫은 후에도 게이트웨이는 나중에 클라이언트를 다시 활성화할 수 있도록 로그인 및 애플리케이션 관리를 제공해야 합니다. 활성화된 클라이언트가 0개인 경우 이전 페이지가 다시 열렸습니다. Codex 채팅이 새로 고쳐지지 않습니다. 클라이언트 상태가 처음으로 요청되기 전에 로그인된 페이지를 동시에 읽습니다. Codex 목록, 비활성화된 상태의 정상적인 거부가 페이지 오류로 잘못 보고되었습니다. 구성되지 않음 Codex , 디스플레이 스위치가 서버의 기본 활성화 기본 설정과 일치하지 않을 수도 있습니다.。

## 결정

고객 `enabled` 프레젠테이션 값은 설치 및 계정 준비 상태와 별도로 쓰기 게이트와 동일한 지속성 기본 설정 규칙을 사용합니다.。`quitDesktop: false` 여전히 게이트웨이 액세스만 취소하고 기본을 유지합니다. App 및 작업; 명시적으로 종료하고 원래 프로세스 및 작업 확인을 계속합니다. 비활성화된 모든 기본 설정은 게이트웨이가 다시 시작된 후에도 유지되며 시작 검색은 클라이언트를 자동으로 시작하지 않습니다.。

비활성화 후 상태 감지, 알림 추적 및 모델 새로 고침은 활성화 게이트에 의해 균일하게 제한되며 기존 캐시는 유지됩니다. 특정 리소스 경계 및 확인은 참조하세요.[클라이언트의 백그라운드 관찰 비활성화](2026-11-06-disabled-client-observation-and-cache.md)。

해당 페이지는 인증된 관리 입구와 클라이언트가 없는 빈 상태를 유지합니다. 제로 클라이언트에서 다시 시작 Codex 내부 세션 보기가 여전히 Codex，또한 쓰기가 성공적으로 활성화된 후 원래 목록 선택 콜백을 트리거합니다. 쓰기 전 낙관적 전환은 이 목록 읽기를 시작하지 않습니다. 첫 번째 Codex 클라이언트 검색과 동시에 목록 읽기가 계속됩니다. 검색 결과에 선택 항목이 없음이 나타나는 경우 Codex，프리페치 비활성화 오류를 표시하지 않음。

## 대안

로그인할 때 항상 읽기 전에 클라이언트가 찾을 때까지 기다리십시오. Codex 목록은 요청 비활성화를 방지하지만 다시 느리게 활성화됩니다. Codex 접힌 부분 위에. 빈 상태 강제 선택 Codex 이전 콜백을 재사용할 수 있지만 비활성화된 상태는 사용자 선택과 일치하지 않습니다.。
