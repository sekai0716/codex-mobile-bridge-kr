# Agent Note: iOS 연결 검색 중 메뉴 안전 영역 위치 유지

Status: implemented

## 문제

Issue #159 기본 더보기 버튼만 WebView 상위 제약조건. 컴퓨터에 들어가기 전에 오래된 것을 정리하십시오 WebView 그리고 주소 감지 페이지가 표시됩니다. 버튼이 표시되지만 수직 제약이 없습니다. 다시 청소할 때 위치도 손실됩니다.。

## 결정

우선순위가 낮은 안전 영역 상위 제약 조건을 예약합니다. 이미 WebView 맨 위 required 제약 조건은 여전히 ​​채팅 페이지의 위치를 ​​결정합니다.；WebView 아직 생성되지 않았거나 삭제된 후 메뉴는 상단에 추가된 안전 영역을 사용합니다. 4 가리키다. 대체 제약 조건 사용법 defaultLow，모바일 메뉴용 자막 압축을 방지하기 위해 연결된 자막보다 수직 압축 방지 및 스냅 우선 순위를 낮춥니다.。

[UIKit 제약 우선순위](https://developer.apple.com/documentation/uikit/nslayoutconstraint/priority)낮은 우선순위 제약 조건을 허용합니다. required 레이아웃 대상은 관계가 제거된 후에 제공됩니다. 메뉴 조작 및 페이지 탐색은 여기에서 변경되지 않습니다.、Cookie 또는 페어링 확인。

## 대안

모든 항목/브랜치를 종료하고 단독으로 다시 빌드 required 메뉴 제약으로 인해 위치가 수정될 수 있지만 WebView 수명주기가 동기화된 분기입니다. 기존 채팅 앵커를 유지하고 상주 우선 순위가 낮은 백업 제약 조건을 제공하여 두 줄만 변경。

## 검증

설치된 iPhone 17 시뮬레이터에서 실행되는 프로젝트 내 격리 UIKit 프로그램, 레이아웃 코드는 제작 소스 파일을 직접 추출합니다. 수리 전 안전지대 상단 62 클릭, 메뉴 상단 0 포인트와 hasAmbiguousLayout 사실이다; 기존 앵커 포인트는 연결 시 정상이고, 원래 위치로 돌아갑니다. 0 가리키다. 수리 후 기다리는 것도 청소도 모두 66 요점이 있고 모호함이 없습니다. 현실적이 되세요 UIStackView 및 caption1 자막을 사용하는 경우 자막의 높이 14.333 포인트는 고유높이와 일치하며 연결메뉴 상단은 80.333 요점은, 즉 WebView 탑 플러스 4 가리키다。

이 검증은 실제 내용을 다루고 있습니다. UIKit 사용자의 실제 시스템과 동일하지 않은 레이아웃 또는 완전한 최종 서명 App 수락됨. 설비, 컴파일된 제품 및 데이터가 프로젝트에 저장됩니다. .tmp，공식 리소스에 접근할 수 없습니다.。

## 영향

프로브, 연결 및 반환 단계에 대한 메뉴는 계속 표시되고 클릭 가능하며 채팅 페이지의 위치 지정 규칙은 그대로 유지됩니다. 이 지점에서는 감지 대기 시간이나 로그인 바인딩 전환을 처리하지 않습니다.。
