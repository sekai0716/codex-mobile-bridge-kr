# Agent Note: 짧은 읽기 시간 초과 후에도 계속 참여 CLI 작가

Status: implemented

## 문제

네이티브 Goal 완료 이벤트가 백그라운드에 있을 수 있습니다. `thread/read` 새로 고침이 완료되기 전에 도착합니다. 새로 고침 작업자 스레드가 모든 것을 넣었습니다. app-server 읽지 않는 것은 추가된 작가가 사라진 증거로 간주됩니다. 따라서 에이전트와 데몬 연결이 아직 살아 있어도 읽기 시간 초과가 지워집니다. CLI 전화기를 기록 전용 모드로 되돌리려면 상태를 추가하세요.。

## 결정

백그라운드 새로 고침이 발생합니다. `AppServerUnavailable` 참여한 세션은 유지됩니다. 이 재생 가능한 읽기는 제한된 백오프가 있는 단일 작업자 스레드에 의해 재시도되므로 여러 연속 시간 초과를 포함하여 후속 기본 이벤트를 기다리지 않고 최종 라운드가 수렴될 수 있습니다. 각 작업자 스레드는 취소 이벤트를 통해 원래 조인 프로세스에 바인딩됩니다. 이 조인 상태를 닫거나 취소하면 휴면 중인 작업자 스레드가 깨어나 후속 연결을 읽을 수 없게 됩니다. 에이전트의 실제 연결 끊기 콜백은 여전히 ​​모든 참여 상태를 지웁니다. 명백한 `notLoaded` 또는 ID 불일치로 인해 해당 스레드가 여전히 무효화됩니다. 반복 없이 쓰기。

## 증거와 한계

외딴 원주민 Codex 0.162.1 루프백 Goal 회전과 명시성 `complete` 변환은 항상 연결되어 있으며 편집 가능합니다. 혼자 했어요 Goal 사용자 연결 끊김이 재현되지 않습니다. 결정적 어댑터 테스트 Goal 이벤트 완료 후 `thread/read` Timeout은 보고서에 기록 전용 상태를 재현합니다. 수정 후 살아남은 작성자를 유지하고 후속 이벤트 없이 두 번의 시간 초과 후에 완료된 라운드로 수렴됩니다.。

최신 읽기 전용 스냅샷은 사용자가 다음에서 발생한 채팅을 보고했음을 보여줍니다. CLI，하지만 돌아오다 Desktop 모두. 이중 프로세스 절연 고정 장치 증명 Goal 보조 프로세스를 설정하고 지울 수 있습니다. Goal，그 과정에 속한 작가를 붙잡지 않고. 서비스 픽스처는 간략한 기록 전용 상태를 재현하고 소유권 프로세스 연결 해제 이벤트 후 자동 재접속을 수행합니다. Desktop；이는 사용자의 문제가 이 이벤트로 인해 발생했음을 입증하지 않습니다. 연결 변환 로그는 불투명한 스레드만 기록합니다. ID 고정된 이유 카테고리를 구별할 수 있습니다. Desktop 고객/IPC 손실, 스냅샷 확인, 네이티브 스레드/상담원이 분실되고 채팅 텍스트, 프롬프트 단어, 자격 증명 또는 provider 세부。

## 대안

새로 고침이 실패할 때마다 연결이 무효화됩니다. 복구 논리는 간단하지만 살아남은 작가는 버려지게 됩니다. 실패한 모든 연결을 유지하면 실제 연결 끊김이 가려집니다. 따라서 읽기 실패는 동일한 조인 프로세스가 여전히 유효한 경우에만 재시도됩니다.。

## 영향

만료된 읽기는 대체 연결이나 최신 라운드 이벤트를 덮어쓸 수 없습니다. 백오프는 반복 읽기 작업 부하를 제한합니다. 원래 생산 문제를 촉발한 원인은 아직 확인되지 않았습니다. 수정 범위는 재현 가능한 시간 초과 및 타이밍 경합입니다.。
