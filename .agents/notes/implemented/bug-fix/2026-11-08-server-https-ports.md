# Agent Note: 자체 서버 HTTPS 포트

Status: implemented

## 문제

자체 서버 SSH 액세스는 기본값만 허용합니다. HTTPS 포트, 동일한 공용 네트워크를 통과할 수 없음 IP 차이점 HTTPS 포털은 여러 컴퓨터를 연결합니다. 원래의 SSH 또한 검사에서는 공용 주소와 포트를 다음과 같이 하드 코딩합니다. 443。

## 결정

自有服务器 + SSH 接入接受完整 HTTPS 地址中的有效自定义端口。同一公网 IP 的多个入口分别映射到各电脑独立的 SSH 回环端口。保存、Origin 白名单、SSH 检查和导出的部署说明沿用该地址中的端口。IPv4 与 IPv6 都作为 IP 字面量接受；IPv6 保存为压缩的方括号 authority，Host 与 Origin 必须使用同一规范字符串。

HTTPS 인증서 확인 및 정확성 Origin 체크섬 SSH 루프백 모니터링은 계속 적용됩니다. 포트를 생략할 때 사용 443；Cloudflare 및 Tailscale 해당 포트 제약 조건을 유지합니다. 도메인 이름 항목에 대한 인증서 확인에는 여전히 해당 표준 확인 포트가 필요합니다.，IP 포털은 외부에서 제공한 유효한 인증서를 계속 사용합니다.。

이 변경 사항이 채택되었습니다. [heiqiu47 의 PR #146](https://github.com/try2love/codex-mobile-bridge/pull/146)，해당 제출 `29b2c3f646122bc97550856d06a33b186df54943`；로컬로 통합된 보조 도메인 이름、IPv6、기본적으로 포트 및 불법 포트 반환이 확인되며, 이 기록은 창고 형식에 따라 구성됩니다.。

## 대안

Keep 서버 모드만 지원 443、사용자는 기존 역방향 프록시 방법을 변경해야 합니다. 비표준 출입구를 이용할 수 있으나, 자체 서버에서 관리할 수는 없습니다. SSH 백홀 연결. 기존 재사용 HTTPS 주소 정규화 및 포트 확인은 새로운 구성 항목을 추가하지 않고도 원래 연결 프로세스를 유지할 수 있습니다.。

## 영향

여러 개의 독립 게이트웨이가 공용 네트워크를 공유할 수 있습니다. IP 입구는 포트별로 구분되어 있으며, 전개 지시사항과 체크 포트는 사용자가 저장한 주소와 일치한다. 사용자는 다음과 같아야 합니다. HTTPS 서버방화벽 및 클라우드 보안그룹을 포트해제하고 독립적으로 할당 SSH 루프백 포트。

각 게이트웨이는 독립적인 Cookie 이름을 구분하는 로그인입니다. 브라우저는 호스트에 따라 각 호스트에 요청을 보냅니다. HTTPS 포트 전송 Cookie，동일한 호스트의 서비스는 서로를 신뢰합니다. 포트는 그렇지 않습니다 Cookie 격리 경계。

## 검증

回归覆盖 IPv4、IPv6 和域名自定义端口保存、IPv6 压缩与方括号规范化、Host/Origin 精确匹配、旧 expanded allowlist 替换、部署导出、SSH 检查指定端口与默认 443，以及非法端口保存失败。桌面输入支持带方括号的完整 IPv6 URL，也可把 bare IPv6 补成 HTTPS URL；不改公网明文、全局 IPv6 listener 或自动发布范围。认证、精确 Origin/CSRF、TLS 错误无 HTTP 回退的规则使用相关现有回归验证。未在本轮部署真实服务器或执行手机登录、聊天收发；PR 作者描述的 Windows/macOS 连通结果属于贡献者提供的证据。
