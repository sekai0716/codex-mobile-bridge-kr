# Agent Note: Tailscale 입학 인수 및 건강 회복

Status: implemented

## 문제

Tailscale 이전에 성공적으로 연결한 후 포털이 갑자기 실패하고 반복적으로 복구될 수 있는 문제를 수정했습니다. 현장에는 동시에 두 가지 상태가 있습니다.：

- `tailscale funnel status` 여전히 대상 포털이 활성화되어 있다고 표시됩니다.。
- 현재 게이트웨이 `ssh-status-*.json` 하지만 그것은 `blocked`，그리고 시스템에는 그런 항목이 없습니다 `tailscale.exe` 하위 프로세스。

이전 구현에서는 모두 동일한 포트를 사용했습니다. Web 규칙은 다른 서비스로 취급됩니다. 규칙이 현재 게이트웨이를 정확하게 가리키더라도 새 게이트웨이는 `port_in_use` 그런 다음 재시도나 모니터링 없이 바로 종료하세요. 따라서 트래픽은 실제로 tailscaled 오래된 규칙이 남아 있습니다. 규칙이 사라지면 게이트웨이는 항목을 다시 설정하지 않습니다.。

## 결정

`route_state` 구별하다 `none`、`same`、`other`。입구 호스트, 포트, 대상 프록시, 접근 범위만（Funnel/Serve）일치하는 경우에만 인수가 허용됩니다. 대상 프록시가 현재 개인 수신 포트가 아닌 경우 현재 인스턴스의 `/api/health` 대상이 실제로 이 게이트웨이인지 확인하십시오. 동일한 호스트 또는 포트의 다른 구성은 변경되지 않습니다. `blocked`，보장되지 않음。

안정적인 연결 60 1초에 한 번씩 확인하세요. Tailscale 정체성과 Serve 상태; 네트워크 변경 사항을 확인하기 위해 즉시 깨어납니다. 실행 중인 포털이 발견되었습니다. `other` 또는 읽기 실패 후, 3 두 번째 검토: 지속적 3 이류 `other` 방금 입장했습니다 `blocked`；계속해서 읽기에 실패했습니다. 3 시간이 지나면 입구가 사라지고 시작 프로세스로 돌아갑니다. 정상적인 결과 또는 다른 유형의 예외는 연속 횟수를 재설정하여 불완전한 상태로 인해 일반 항목이 영구적으로 닫히는 것을 방지합니다. 처음 시작할 때 다른 서비스는 여전히 액세스를 직접 차단하고 구성을 덮어쓰지 않는 것으로 나타났습니다.。

포그라운드 세션은 독립적인 세션으로 구성됩니다. stdout reader 상태 주기와 함께 공동 관리되는 두 액세스는 동일한 상태 판단을 재사용합니다. 실패한 시작 버튼 3、6、12、24、48、60 초 백오프; 연결이 성공할 때마다 재설정 3 두번째. 네트워크 변경 및 입구 폐쇄로 인해 대기 시간이 중단될 수 있습니다. 하위 프로세스가 끝나면 상태 확인만 활성화하고 실패 백오프를 우회하지 않습니다.。

네트워크가 기본 경로에 대한 변경 사항을 모니터링하면 활성화된 경로를 깨웁니다. Tailscale 및 Quick Tunnel，각 콜백은 예외를 개별적으로 포착합니다. 활성화되지 않음 Tailscale 이 항목의 스레드가 생성되지 않았습니다. CLI 하위 프로세스。Windows 신원 읽기、Serve 상태 쿼리와 포그라운드 프로세스 모두 여전히 사용 중입니다. `CREATE_NO_WINDOW`。

게이트웨이를 닫을 때，`gateway-control.json` 삭제를 위한 짧은 재시도 추가。Windows 스캐너 또는 동시 판독기로 인한 일시적인 현상 `WinError 32` 더 이상 전체 프로세스가 종료되지 않도록 하세요. 삭제할 수 없는 경우 진단 파일을 보관하고 다음 시작 시 덮어쓰도록 둡니다.。

HTTP 긴 폴링 또는 정적 응답 중 활성 클라이언트 중단으로 인해 발생 `ConnectionAbortedError` 정상적인 연결 끊김으로 간주되어 더 이상 게이트웨이 작동 실패로 기록되지 않습니다.。

## 대안

- 유지하다 10 두 번째 고정 검사: 네트워크 이벤트가 없을 때 규칙 손실을 더 빨리 감지할 수 있지만 12 개인 CLI 하위 프로세스; 안정된 상태가 대략적으로 변경됩니다. 2 , 이상이 발생하면 짧은 간격으로 확인합니다.。
- 네트워크 변경 이벤트에만 의존: 유휴 오버헤드는 낮지만 사용자가 수동으로 규칙을 삭제하거나 서비스 자체의 변경 사항을 감지할 수 없으므로 저주파 검사가 유지됩니다.。
- 단일 충돌을 즉시 중지합니다. 다른 서비스를 보호하는 것이 가장 시의적절하지만 단기간에 불완전한 결과가 발생하면 영구적으로 진입이 차단됩니다. 작동 중 지속적인 확인으로 변경되며 충돌 규칙은 절대 덮어쓰지 않습니다.。

## 영향

- 정확히 일치하고 속성이 검증된 레거시 포털을 인계받아 지속적으로 모니터링합니다.。
- 다른 서비스, 다른 목표, 다른 Funnel/Serve 범위는 아직 다루어지지 않습니다.。
- 사용자 또는 이전 인스턴스의 구성이 정리되는 것을 방지하기 위해 인수된 비프런트엔드 입구는 이번 종료 중에 자동으로 삭제되지 않습니다. 계속해서 검증하고 다음 시작을 이어받을 수 있습니다.。
- 수정 사항은 게이트웨이 인증을 변경하지 않습니다.、Origin、CSRF、Tailscale 로그인 상태 또는 사용자 tailnet 설정。
