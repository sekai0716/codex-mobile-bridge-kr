# Agent Note: 텍스트 바로 뒤의 블록 수식 분석

Status: implemented

## 문제

[Issue #94](https://github.com/try2love/codex-mobile-bridge/issues/94) 의 `\[...\]` 블록 수식은 텍스트 바로 뒤에 있고 빈 줄이 없으면 일반 단락이 됩니다. 백슬래시가 먼저입니다. Markdown 탈출 처리. 현지 가져가기 `b9d7b13` 기준선을 위해 실행 [PR #96](https://github.com/try2love/codex-mobile-bridge/pull/96) 의 원래 회귀에서는 대괄호나 이중 달러 기호가 생성되지 않았습니다. `math_block`；코드 및 닫히지 않은 표현식 검사가 통과되었습니다.。

## 결정

예약하다 littltstream 원래 커밋 `35b9bae109d378e9f3e9e0ecf0c309825f0b0cc1`，병합 커밋을 통해 로컬 기록에 통합합니다. 제품 변경은 기존 제품에서만 이루어집니다. texmath 차단 규칙 등록 시 추가됨 `alt: ['paragraph']`，단락을 나누기 위해 블록 수식을 완벽하게 일치시킬 수 있습니다. 무음 감지, 구분 기호, 숫자 및 token 메시지의 원본 텍스트를 전처리하거나 다시 작성하지 않고 생성합니다. 프로덕션 렌더러는 원본을 계속 사용합니다. DOM 구조、KaTeX 보안 매개변수 및 주문형 로딩。

보충 코드 펜스, 들여쓰기 코드, 인라인 코드, 이스케이프 문자, 통화, 인라인 및 독립 수식, 번호 매기기, 목록 및 참조 회귀. 이미 Markdown 및 수식 브라우저 스크립트 액세스 `critical.spec.cjs`，검사를 수행하지 않고 파일만 로드하는 것을 방지하기 위해 프로덕션 리소스를 로드하고 실제 어설션 결과를 확인합니다.。

## 기존 메모 감사

[Markdown 읽기 및 소스 코드 모드](../feature/2026-10-26-markdown-file-modes.md)이 기사와 부분적으로 겹치며 렌더러를 공유합니다. 모드 전환, 소스 코드 복사, 스크롤 및 Mermaid 수명주기는 변경되지 않습니다. 소스 코드 뷰어 메모 및 시작 리소스 복구 메모는 이 단락 규칙 결정과 아무 관련이 없으며 대체된 기록 결정 없이 그대로 유지됩니다.。

## 대안

- 입력 렌더링 전에 빈 줄 채우기: 연속 단락 구문 분석을 직접 피할 수 있지만 코드 및 이스케이프 경계에 대한 추가 식별이 필요하며 구문 분석에 사용되는 원본 텍스트 및 줄 위치도 변경됩니다. 파서의 기본 단락 중단 메커니즘을 채택합니다.。
- 사용자 또는 모델이 항상 빈 줄을 출력하도록 요구합니다. 파서에 대한 변경은 필요하지 않지만 기존 채팅 및 스트리밍 출력은 여전히 ​​오류를 유발할 수 있으며 기존 콘텐츠를 직접 표시해야 하는 요구를 충족할 수 없습니다.。

## 영향 및 검증

적절하게 구분된 블록 수식은 더 이상 선행 빈 줄에 의존하지 않습니다. 채팅하다 Markdown 파일 읽기는 이 구문 분석 항목을 공유합니다. 새로운 스타일, 설정, 종속성 또는 플랫폼 분기가 추가되지 않습니다. 유지관리 비용은 지역적입니다. vendor 관련 회귀는 패치 이후에도 유지되며 추후 업데이트될 예정입니다. texmath 다음 경우에도 단락 동작을 확인해야 합니다.。

Mac 현지 검증：11 개 texmath 사용 사례가 통과되었습니다. 완벽한 Node 프런트엔드 테스트 1,251 항목이 통과됨，1 개 Windows WinError 32 단독 사용 사례는 실패 없이 기존 조건에 따라 건너뜁니다. 실제 Chromium（이 기계에는 이미 Chrome）및 WebKit、1280 px/390 px 4개 그룹 모두 합격, 각 그룹 공연 15 개 Markdown 및 13 링크 안전, 빈 줄 수식 텍스트 없음, 닫히지 않은 스트리밍 콘텐츠, 코드 및 가로 스크롤을 포함한 수식 어설션。8 개 Web 리소스 사용 사례, 모듈 경계 확인 및 차등 공백 확인을 통과했습니다. 로그 및 브라우저 보고서는 다음 위치에 있습니다. `.tmp/pr96-20261028/`，제출하지 마세요。
