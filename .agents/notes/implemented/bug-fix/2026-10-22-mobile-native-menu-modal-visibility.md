# Agent Note: 웹 페이지 대화 상자가 열려 있는 동안 휴대폰의 기본 메뉴 숨기기

Status: implemented

## 문제

모바일 호스트는 기본입니다.“더”메뉴가 그려져 있어요 WebView 위에. 더 길게 Webhook 설정 대화 상자가 메뉴 아래로 스크롤되어 대화 상자가 열릴 때 배경 메뉴가 계속 표시되고 클릭 가능한 상태로 유지될 수 있습니다. 호스트는 기본 뷰 계층 구조에서 추론할 수 없습니다. HTML 대화상자 상태。

## 결정

공유된 휴대폰 스크립트는 문서에 존재하는지 관찰합니다. `dialog[open]`。하나 이상의 대화 상자가 열려 있는 동안 토큰 범위 보내기 `codexbridge-modal:` 팁, 값은 `open`；모두 닫았을 때 전송됨 `closed`。평범한 DOM 변경 사항은 상태 전환 시에만 전송됩니다. 페이지가 다시 포커스를 얻거나 표시될 때 현재 상태가 다시 전송됩니다. 이 계약은 대화 상자 상태를 기반으로 하므로 동적으로 삽입되며 향후 대화 상자에서는 호스트가 해당 계약을 유지할 필요가 없습니다. ID 참여하실 수 있습니다。

Android 및 iOS 현재부터만 수락 WebView、예상되는 origin 그리고 현재 토큰의 신호. 받다 `open` 호스트가 기본 메뉴를 숨기고 비활성화하는 경우 받다 `closed` 메뉴가 복원되면 네비게이션은 메뉴 상태를 재설정합니다. 신호는 일시적입니다. UI 설정이 아닌 상태。[대화상자 배경 닫기 메모](../feature/2026-10-16-dialog-backdrop-dismissal.md)합의된 배경 동작을 끄는 방법 HTML 대화 상자; 이 메모는 대화 상자가 열려 있는 동안의 기본 오버레이 동작을 지정합니다.。

## 대안

매 Webhook 대화 상자 처리기에서 메뉴를 전환하는 것은 간단하지만 다른 대화 상자와 향후 대화 상자에서는 여전히 동일한 오버레이 문제가 발생합니다.。CSS 숨길 수 없어 WebView 이외의 Android 또는 iOS 기본 컨트롤. 관찰 공유 HTML 테두리를 유지할 수 있는 대화 상자 상태 WebView 호스트와의 계약。

## 영향

하나 이상의 대화 상자가 열린 후에는 마지막 대화 상자가 닫힐 때까지 기본 메뉴를 사용할 수 없는 상태로 유지됩니다. 스크롤 및 내부 DOM 변경 사항은 메뉴를 복원하지 않습니다. 초점이 회복되면 상태가 보정되어 이전 신호의 손실 가능성을 보상합니다. 크로스 프로세스 프롬프트는 소량의 호스트 처리를 추가합니다. 브라우저 및 소스 코드 테스트는 상태 전환을 다루며 기본 장치 렌더링은 여전히 ​​다시 빌드해야 합니다. App 검증。
