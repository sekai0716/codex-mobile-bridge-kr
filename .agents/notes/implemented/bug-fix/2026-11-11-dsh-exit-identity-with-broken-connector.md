# Agent Note: DSH 잘못된 액세스로 인해 종료 ID 미리보기가 차단되지 않습니다.

Status: implemented

## 문제

이전 플러그인 삽입이 여전히 삭제된 빌드 디렉터리를 가리키는 경우 전체 종료 미리보기가 먼저 호출됩니다. discover_existing，액세스 세 번째 파일을 확인할 수 없고 대상 프로세스의 ID를 아직 읽지 않았기 때문에 오류가 발생합니다. 저장된 액세스 디렉토리가 유효하지 않게 된 경우，lazy adapter 복구 모듈에 들어가기 전에도 공장이 실패합니다. 액세스 무결성은 연결 복원을 위한 전제 조건이지만 선택한 프로그램 및 데이터 디렉터리의 프로세스 확인을 대체할 수는 없습니다.。

## 결정

복구 모듈은 먼저 생성 시간, 명령 요약, 데이터 디렉터리 및 인식할 수 없는 역할 검사를 유지하면서 선택한 설치의 프로세스 스냅샷을 얻습니다.。manager 회수 입구에서만 만날 수 있음 lazy adapter 의 BridgeUnavailable 선택한 데이터 디렉터리에 연결되지 않은 후보 어댑터를 구성하는 경우 여전히 신뢰할 수 있는 액세스가 아니며 일반적인 연결 팩토리 및 설치 확인이 완화되지 않습니다. 액세스 검색이 실패하거나 플러그인이 없거나 어댑터를 사용할 수 없는 경우 액세스 자격 증명이 작업을 보내는 데 사용되지 않습니다. RPC，작업으로 돌아가기 unknown、검증 가능한 프로세스 수와 명확한 프롬프트 알 수 없는 상태를 유휴 상태로 처리하지 않으며 일반적인 복구 확인을 제공하지 않습니다.。

확인 전에 원래 프로세스와 액세스 증거를 다시 검증해야 합니다. 미리보기 중에 액세스할 수 없는 경우 나중에 사용할 수 있게 되면 다시 미리보기해야 합니다. 구성 오류로 인해 ID 변경 사항을 숨길 수 없습니다. 원래 신뢰할 수 있는 이전 액세스에 대한 작업 확인 및 명시적인 알 수 없는 확인이 유지됩니다. 분명한 busy 계속해서 정상적인 출구를 차단하세요. 기본 배포를 시작하기 전에 이 복구를 사용하세요. token，실패하거나 알 수 없는 결과는 재사용하지 않고 다시 전송합니다.。

Windows 기존의 완전한 복원 및 재사용 stop_deepseek：같은 것만 받아들이세요 profile、엔드포인트 생성 및 지원되는 네이티브 버전 Quit/installer 임무와 신원 보호를 유지한 채 통로를 종료합니다. 창을 닫은 후에는 더 이상 호출되지 않습니다. taskkill 배경을 정리하세요. 정상적인 접근이 없을 경우 자동으로 강제로 변경되지 않습니다. 원래 범위에 프로세스가 없는지 확인한 후 바로 완료됩니다. 추가 요구 사항은 필요하지 않습니다. Host 또는 종료 RPC；명시적으로 다시 시작하도록 선택한 경우에만 기존 시작 프로세스로 들어갑니다.。Mac/Linux 원래 복구 규칙은 변경되지 않습니다.。

명백한 force 계속해서 공유를 사용하세요 toggle 독립적인 확인과 원주민 신원 binder；잘못된 액세스나 종속 작업을 읽지 않으므로 사용자가 명시적으로 중단할 수 있습니다. busy/unknown，그러나 여전히 현재 설치, 프로세스 ID, 범위 및 보호되는 프로세스 규칙이 적용됩니다. 두 번째 세트를 추가하지 마세요. DSH force 상태 머신, 복원 안 함 token 언제 force 확인하다. 실제로 인식 0.2.2-rc.1 아직 확인된 바 없음 installer flag；이 점은 이번 버전이 포커스 없는 일반 종료를 지원했다고 주장하지 않으며, 이전 실제 머신에서 해당 기능이 적용되거나 수정되었다는 주장도 아닙니다. force 실패하다。

## 대안

오래된 바인딩을 지우거나 휴식을 취하세요. verified_directory 연결 프로세스를 계속할 수 있지만 소스, 계정 및 알 수 없는 구성 보호를 우회합니다. ID 미리 보기 전에 플러그인 확인을 유지하면 알 수 없는 상태가 줄어들지만 사용자가 선택한 프로그램의 종료 범위를 볼 수는 없습니다. 일반 종료 실패를 다음으로 자동 변환합니다. CloseMainWindow、taskkill 또는 RM 프로세스나 창이 사라졌다는 것만 증명할 수 있을 뿐, 정상적으로 저장되었다는 것을 증명할 수는 없으므로 사용하지 않습니다.。

누락된 이전 삽입 디렉토리의 원본 재생 증명을 합성합니다. 이전 코드는 프로세스 ID 쿼리 전에 오류를 발생시킵니다.，patch 변경 사항도 없고 기본 작업도 없습니다. 수정 후 실제 DeepSeek 어댑터 고정 장치 검증 ID 표시, 작업 unknown、모두 믿을만하다 RPC、원래 구성은 변경되지 않고 그대로 유지되며 소스 파일이 생성되지 않습니다. 직접 반품 보장 lazy 공장실패, 사전확인과정 변경, 접속상태 변경、busy/unknown、실패하다 token 재생하지 않음、Windows 명시적인 시스템 종료 폴백은 물론 시스템 종료 폴백도 없습니다. force 라우터는 잘못된 어댑터를 로드하지 않으며 작업을 확인하지 않습니다. 현지의40아이템 관련 회복/경영점검 및6사용 가능한 품목 Windows 기본 프로토콜 검사가 통과되었습니다. 총46품목; 중지 상태는 동일한 사용 사례에서 각각 완료 전용 종료 및 명시적 다시 시작을 포함합니다.。

## 영향

잘못된 액세스는 여전히 정상적으로 연결할 수 없고 수정하거나 유휴 상태인 척할 수 없지만 선택한 프로그램의 종료 ID와 번호는 더 이상 숨겨지지 않습니다. 사용자는 컴퓨터에서 정상적으로 종료하거나 독립적으로 미리 보고 명시적으로 강제 종료를 선택할 수 있습니다. 원래 열기 기본 설정은 성공할 때까지 영구적으로 변경되지 않습니다. 오래된 고아 인서트의 전체 백업 및 제어된 교체는 여전히 후속 독립적 수리의 대상입니다.。

프로세스가 종료되고 이전 디렉터리가 완전히 누락된 경우 독립적 확인, 전체 백업 및 정확한 삽입 교체를 참조하세요.[누락된 액세스 수정](2026-11-11-dsh-missing-connector-repair.md)；이것이 허용하는 것은 구성 복구이며 작동 중인 알 수 없는 작업의 정상적인 종료를 완화하지 않습니다.。
