# Agent Note: 새로운 Codex 채팅은 기본 이름 없는 상태로 유지됩니다.

Status: implemented

## 문제

새 양식을 미리 작성하고 강제 제출“새 채팅”，백엔드 무조건 호출 thread/name/set，따라서 영구 원주민 이름이 기록됩니다. 단순히 이름 변경을 제거하는 것도 불완전합니다. 실제 0.167 새로 생성된 빈 채팅은 메타 정보를 읽을 수는 있지만 다음 연결 시 복원할 수 있는 데이터는 없습니다. rollout。

## 결정

채팅 이름은 기본적으로 공백으로 남아 있지만, 최대 까지 채워 넣을 수 있습니다. 120 성격。Codex App、로컬 머신/SSH CLI、WSL 새로 생성된 스레드에만 사용되는 저장 단계를 재사용합니다. 이름 상속이 있습니다. thread/name/set；이름 없이 전화하다 thread/section/move，새 스레드를 초기 상태로 유지 sectionId，네이티브 인터페이스를 통해 구현되었으며 flush 빈 역사. 그런 다음 원본 전체 읽기, 프로젝트 소유권 및 모델 인수 확인이 수행됩니다. 요청 생성에 대한 ID 및 알 수 없는 결과 중복 제거 규칙은 변경되지 않습니다.。

이 단계는 기존 채팅에 사용할 수 없으며 이름, 메시지, 데이터베이스 또는 기본 기록을 위조할 수도 없습니다. 이름이 지정되지 않은 기본 상태가 유지됩니다. App/TUI 후속 명명 기회; 적나라한 app-server 타이틀을 생성하기 위해 모델이 적극적으로 호출된다는 보장은 없으며 게이트웨이는 유료 타이틀 요청을 추가하지 않습니다.。

고정버전 소스코드 기반 [0.167 thread_manager.rs](https://github.com/openai/codex/blob/086ccc833bc9cf01024ad2dd6af7dbd421b6bf9a/codex-rs/core/src/thread_manager.rs#L1174)：명시적인 배치가 먼저 보장됩니다. rollout 다시 구체화하다 flush。sectionId ～을 위한 null 기본적으로 지원되는 비파티션 상태입니다. 공식적인 0.164.0 고정된 소스 코드에도 동일한 인터페이스와 구현 단계가 있습니다. 이전 바이너리에서는 구현되지 않았습니다. 로컬 저장소에는 기본이 필요합니다. SQLite state DB。이 인터페이스는 기본적으로 지원되지 않거나 지속성이 실패할 경우 알 수 없는 생성 확인이 유지됩니다. 이름 변경 및 롤백이 없으며 반복 생성이 없습니다.。

## 대안

그냥 건너뛰세요 thread/name/set 연결을 통해 복원할 수 없는 빈 채팅이 생성됩니다. 공백 또는 고정된 자리 표시자 이름을 설정하는 것은 여전히 ​​원래 명명 의도를 위반하는 것입니다. 가짜 메시지를 보내면 기록이 변경되고 요금이 청구될 수 있습니다. 아무도 채택되지 않았습니다. 첫 번째 메시지가 생성될 때까지 프런트엔드 초안을 임시 저장하면 기존 빈 채팅 및 프로젝트 인계 프로세스가 변경되며, 이번에는 변환이 확장되지 않습니다.。

## 영향 및 검증

새로운 격리 home 실질적인 독립 CLI 0.167.0 마치다 start、파티션 배치 없음, 정상 종료, 다른 프로세스 resume：같은 ID、name=null、turns=[]，rollout 이미 존재합니다。App 내장 0.167.0-alpha.4.1 수정된 내용을 통해 create_empty 프로세스 전반에 걸쳐 복원하고 동일한 결과를 얻습니다. 호출되지 않음 turn/start、공식 자격 증명 또는 유료 모델。

28 아이템 생성과 CLI 수표에 대해 통과（그 중 하나만 Windows 단독점검 Mac 뛰어넘다）；28 개 WSL 신축, 프로젝트 및 인수인계 검사를 통과했습니다. 실제 브라우저는 이름이 처음에 비어 있고 필수가 아니며 빈 값이 유효한지 확인합니다. 세 끝의 최종 빌드와 완전한 페이지 생성은 아직 검증되지 않았습니다.。
