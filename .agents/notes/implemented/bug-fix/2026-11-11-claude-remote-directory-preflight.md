# Agent Note: 원격 Claude 자세한 내용은 원본 작업 디렉터리를 미리 확인하세요.

Status: implemented

## 문제

SSH 및 WSL Claude 세부 정보는 원래 계속할지 여부를 결정하기 위해 로그인 상태만 쿼리했습니다. 역사는 여전히 존재한다 `cwd` 삭제해도 인터페이스는 계속 열려 있어 계속할 수 있습니다. 실제 작업 프로세스는 이후에 복원됩니다. `Path.resolve(strict=True)` 원시 파일 오류가 발생합니다. 기록에 누락된 권한 모드는 또 다른 독립적인 차단 조건입니다. 디렉터리 복구는 사용자의 권한을 채우는 데 사용할 수 없습니다.。

## 결정

읽기 전용을 통한 원격 세부정보 `resume-preflight` 원래 구성 ID 및 기본 세션에 따르면 ID、`cwd`、모델 및 권한 모드 재확인 세션. 원래 디렉터리가 존재하지 않거나, 디렉터리가 아니거나, 액세스할 수 없는 경우 원래 경로와 함께 중국어 이유가 반환되고 계속하는 기능이 꺼집니다. 복구를 수행하기 전에 동일한 디렉터리가 재사용되는지 확인하고 내용을 덮어쓴 후 디렉터리가 다시 변경됩니다. 프리플라이트는 디렉토리를 생성하거나 교체하지 않습니다. `cwd`、채팅을 시작하거나 재개하지 않으며 데스크톱을 시작하지 않습니다. App、모델 요청이 전송되지 않으며 원래 세션 또는 구성이 기록되지 않습니다. 기존의 profile/auth 인증은 계속 실행될 수 있습니다. `auth status --json`，버전 기능 진단은 계속 실행할 수 있습니다. `--version`；읽기 전용입니다. CLI 하위 프로세스는 활성 채팅과 동일하지 않습니다. 알 수 없는 권한은 여전히 ​​사용자가 원래 터미널에서 계속해야 합니다.。

## 관련 기록 감사

[합성 모델 복구](2026-10-16-claude-cli-synthetic-model-reconnect.md)부분적으로 겹치는 부분이 있고, 모델과 알 수 없는 수신 경계가 계속 유지됩니다. 이 문서에서는 원격 디렉터리 실행 전 내용만 다룹니다. 활성 노트에서 동일한 디렉토리 사전 결정을 보유한 다른 기록은 발견되지 않았습니다. 존재하며 추적되지 않음 TCC 제안은 이번 변경사항의 일부가 아닙니다.。

## 대안

실행 단계가 가장 덜 까다로울 때까지 디렉터리를 계속 확인하지만 세부 정보로 인해 복구 포털이 잘못 열리고 이해할 수 없는 원래 시스템 오류가 반환될 수 있습니다. 원래 디렉터리를 자동으로 재구축하면 누락된 경로를 우회할 수 있지만 빈 프로젝트가 생성되고 사용자의 실행 조건이 변경되므로 읽기 전용 프리플라이트 및 명시적 차단이 사용됩니다.。

## 영향

연결되지 않은 재개 가능한 세션 세부 정보의 경우 원래 로그인 쿼리를 대체하기 위해 원격 프리플라이트가 추가됩니다. 또한 프리플라이트는 세션의 원본 메타데이터를 읽어야 합니다. 기록은 여전히 ​​읽을 수 있습니다. 실시간 연결이 있는 경우 이 쿼리는 추가되지 않습니다. 로그인, 계정, 권한 및 프로세스 작성자 확인은 각각의 책임을 유지합니다. 사전 확인을 통과해도 후속 실행 중에 디렉터리가 계속 존재한다는 보장은 없습니다.。
