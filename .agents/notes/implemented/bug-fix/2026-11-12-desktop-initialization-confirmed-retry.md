# Agent Note: 검증이 불가능한 경우 기본 연결 초기화를 명시적으로 확인합니다.

Status: implemented

## 문제

제한된 병렬 검증은 긴 기록에 대한 항목별 대기 시간을 줄이지만 기본 IPC 응답하지 않으면 여전히 시간 초과됩니다. 초기화 페이지에서는 한 번만 재시도할 수 있습니다. 사용자는 명확하게 명시된 요구 사항에 따라 알 수 없는 작업이 중단될 수 있다는 점을 인정하면서 정상적으로 다시 시작할 수 없습니다.。

## 결정

첫 번째 초기화에서는 여전히 확인 작업이 완료됩니다. 작업 상태를 사용할 수 없거나 확인 기간이 만료되어 이 작업이 실패한 경우에만 반환됩니다. `taskStateUnavailable`，공유 계정 패널만 표시됩니다.“초기화를 강제로 계속 진행”。재확인 후 새 요청 식별자를 사용하여 백그라운드에서 기본 작업과 프로세스를 다시 확인하세요. 확인은 아직 사용할 수 없는 작업 상태에만 적용되며 알려진 사용 중 및 알 수 없는 작업 상태에는 적용되지 않습니다./대기 중인 쓰기, 프로세스 생성 또는 구성 디렉터리 변경。

기간 소진시 별도 사용 `TaskAuditIncomplete`，상속을 계속하다 `ValueError`，일반 종료를 상속받지 않음 허용됨 `TaskStateUnavailable`。따라서 일반 종료, 계정 전환 등 발신자에 대한 기존의 엄격한 규칙은 변경되지 않습니다. 검증 시간이 초과되면 이번에 받은 스냅샷과 제출물을 다시 확인하여 침묵하는 후보자가 다른 내용을 취재하는 것을 방지하세요. owner 전달된 바쁜 증거。

“강제로 계속 진행”사용자가 위험을 확인한 사용 불가능한 작업 판단만 건너뛰고 일반 종료가 호출됩니다. 강제 종료는 사용되지 않으며 초기화가 자동으로 반복되지 않습니다. 권한, 계정, 기록 및 쓰기 영수증은 원래 계약에 남아 있습니다.。

HTTP 초기화 포털과 데스크톱 직접 연결은 동일한 요청 계약을 사용합니다. 이는 선택 사항이며 다음 용도로만 사용할 수 있습니다. `true` 의 `acknowledgeUnavailable`。포털은 로그인을 유지하면서 추가 필드를 계속 거부합니다.、CSRF、기본 데스크탑 범위 및 비밀번호 없는 액세스 제한; 실제 검증 실패 여부와 계속 진행 가능 여부는 여전히 계정 관리 로직에 따라 결정됩니다.。

명시적 초기화에는 저장된 데스크톱 프로그램 경로가 없으며 다음 위치에서 시작할 수도 없습니다. CLI 설치 위치 도출 App 기존 재사용 시 `DesktopApp.scan` 설치된 데스크톱 애플리케이션을 찾은 다음 원래 프로그램 확인을 수행합니다.。Windows Store App 그리고 독립 CLI 이들은 서로 다른 디렉토리에 위치할 수 있으며 인접한 디렉토리를 파생하지 못하는 경우 불특정 프로그램으로 잘못 보고될 수 없습니다. 이 롤백은 사용자가 확인한 초기화 중에만 실행됩니다. 상태 새로 고침에 전체 검사를 추가하지 않으며 저장된 프로그램 선택을 수정하지도 않습니다.。

## 대안

대기 시간을 연장해도 여전히 응답하지 않는 네이티브 문제를 해결할 수 없습니다. IPC；기록 캐시를 기반으로 유휴 상태를 직접 판단하면 표시 데이터가 종료 자격 증명으로 처리됩니다. 시간 초과를 복구 가능한 종료 오류로 균일하게 변경하면 다른 라이프 사이클 호출자의 권한이 확장됩니다. 초기화 관련 명시적 확인을 사용하고 엄격한 기본값을 유지합니다.。
