# 전송 버튼과 추론·Fast 표시 설정

## 결정

- Codex 전송 방식 목록은 작업 모드 왼쪽의 원래 위치에 표시한다. 기본 선택 `auto`는 대기 중 `send`, 실행 중 `queue`로 변환하며 서버 전송 모드 계약은 유지한다. 대기열 미지원 연결에서는 실행 중 기본 전송을 막고 지원하는 조종 동작을 목록에서 선택하게 한다.
- 대기열 카드에 ‘지금 보내기’를 제공한다. 기존 ID를 유지해 실행 중에는 조종, 대기 중에는 즉시 전송으로 처리한다. 표시한 메시지의 버전과 계정이 다르면 전송하지 않는다. 자동 대기열 처리와 같은 잠금 아래에서 먼저 불확정 영수증을 저장하며, 중복 클릭이나 응답 유실로 같은 메시지를 재전송하지 않는다. 목표 활성화 대기와 CLI 해제 상태는 우회하지 않는다. WSL에서도 원래 프로젝트·제공자와 기존 영수증을 유지한다.
- 기존 초안의 즉시·대기 선택은 새 기본 동작으로 복원한다. 명시적으로 선택한 `steer`는 작업이 끝날 때까지 유지한다. 미확인 전송의 요청 ID, 초안·첨부·인용·Skill 보존은 기존 전송 추적을 사용한다.
- `bridge-appearance`에 `expandReasoning`을 추가한다. 초기값은 켬이며, 화면 설정의 ‘추론 요약 기본 펼침’에서 끄고 켤 수 있다. 현재 타임라인에서 직접 펼치거나 접은 선택은 이후 갱신과 기본값 변경 중 유지한다. 숨겨진 항목과 잘리지 않은 요약은 자동 상세 조회를 하지 않는다.
- 컨텍스트 표시 바로 왼쪽에 Fast 번개 토글을 둔다. 모델 창과 같은 Fast 지원·속도 해석을 사용한다. 기존 설정 API에 현재 모델·추론 강도를 그대로 보내고 `fastMode`만 전환한다. 저장·적용 확인 중에는 중복 클릭을 막으며 다른 대화·계정·모델로 넘어간 응답은 반영하지 않는다.
- 프록시 원본 IP는 기존 `trustedProxies` 정책을 사용한다. 로컬 배포의 신뢰 프록시 등록으로 해결하며, 모든 전달 헤더를 일괄 신뢰하는 코드 변경은 하지 않는다. 설치 환경의 IP와 인증 데이터는 저장소에 기록하지 않는다.

## 검증

- 전체 프런트엔드 128개 파일: 등록 테스트 1,636개 중 1,635개 통과, Windows 전용 1개 건너뜀. 등록 테스트 외 직접 assertion을 수행하는 5개 파일도 성공.
- 큐·조종·메시지 관리·Codex CLI/WSL·HTTP·인증·리소스 경계 관련 백엔드 13파일 355개 통과. 전체 백엔드 source-only 실행은 종료 코드 143으로 중단되어 완주 결과를 확인하지 못했다. 파일 권한과 loopback이 필요한 검사는 POSIX 임시 사본에서 실행.
- Chromium의 넓은·좁은 화면 검사 14개에서 실제 전송 콜백, 대기열의 지금 보내기·중복 클릭·초안 보존, 미확인 전송 보존, 펼침 설정의 저장·복원, 수동 접힘 보존, 상세 조회 범위, Fast 토글·모델 보존 확인. 320·390·1280px 배치와 한국어·영어 표시 확인. 합성 Codex IPC에서는 실제 게이트웨이의 즉시 전송, 원래 ID, 동시 클릭, 영수증 유실과 재전송 방지를 검사한다.
- Android 네이티브 리소스와 프로토콜은 변경하지 않는다. 기존 APK가 읽는 PC 게이트웨이 웹 자원을 갱신한다. 브라우저 검증은 Android 실기기 검증을 대신하지 않는다.
