# Agent Note: Codex 채팅 중 visualize

Status: implemented

## 문제

이전에는 휴대폰에서 데스크톱 채팅에서 생성된 메시지를 표시할 수 없었습니다. visualize 콘텐츠. 파일 승인 및 스크립트 격리를 유지하면서 공유 채팅에서 상호 작용을 유지해야 합니다.。

## 결정

Codex 채팅 본문에서 완료 `visualize` 콘텐츠 인용은 대화형 콘텐츠를 원래 위치에 표시합니다. 공유하다 Web 브라우저와 휴대폰 모두 포함 App。구문 분석은 절대값을 지원합니다. HTML 길、`title` 및 `mode: "wide"`，코드 블록, 인라인 코드 및 사용자 메시지는 텍스트로 유지됩니다. 메시지 페이징 및 텍스트 확장도 파일 설명자를 제공합니다.。

## 파일 및 호스트 경계

- `GET /api/sessions/{thread}/visualizations/{id}` 뒤로 UTF-8 소스코드 및 내용 요약。ID 채팅 도우미 메시지의 전체 인용문에서 가져온 것입니다. 요청 시 확인을 위해 전체 대화 보기를 다시 읽으세요. 인증은 타임라인 표시 창과 별개입니다. 기존 병합 규칙은 기록 접두사를 저장하는 데 사용되며, 전체 스냅샷에서 삭제된 참조는 동시에 무효화됩니다. 파일은 실행 호스트의 프로젝트 디렉터리로 제한되거나 Codex visualizations 디렉토리, 팔로우 Workspace 다음을 사용한 안티 심볼릭 링크 읽기 1 MiB 상한。
- 승인 후에도 원래 경로 구성 요소와 함께 전달됩니다. Workspace，먼저 사용하지 않고 abspath 겹. 그렇지 않으면 `link/../file.html` 의 resolve 인증 경로와 실제 읽기 경로는 다를 수 있습니다. 회귀는 기본 및 독립형으로 재현 및 거부되었습니다. SSH 페이로드는 동일한 읽기 기능을 재사용합니다.。
- 참조 구문 분석은 보조 메시지 텍스트를 균일하게 수신합니다. 네이티브 히스토리와 표준화된 대화는 데이터 구조를 서로 변환할 필요 없이 각각 텍스트를 제공합니다. 수동 읽기는 원래 세션과 실행 호스트를 사용합니다.；SSH 요청자 `visualize_payload.read_request` 구성, 모듈 소스 코드가 집중되어 있습니다. `worker_source` ～에 따르면 Python 구문 구문 분석은 가져오기에 의존하며 기본 작업 공간 읽기 규칙을 재사용합니다. 리소스 매니페스트 테스트는 페이로드 소스 파일을 다루고, 세션 테스트는 실제 생성된 읽기 요청에서 실행을 격리합니다. 중계 전달만 허용됨 GET，그리고 장치 범위에 고정 미리보기 셸을 제공합니다.。
- `/visualize-shell` 별도의 인증 및 채택 opaque-origin sandbox；인라인 스크립트만 허용하고 수정됨 CDN 정적 스크립트/스타일/세례반，API 네트워크, 서브프레임, 양식 및 기본 권한은 격리된 상태로 유지됩니다. 평범한 HTML 미리보기는 원래 전략을 따릅니다.。Android/iOS 이 정확한 미리보기만 추가하세요. URL；휴대폰 App 이번 기본 탐색 변경 사항을 포함해야 합니다.。

## 상호 작용 및 수명주기

- 테마 변수, 기본 제어 스타일, 라벨 전환, 런타임 시 프롬프트 및 아이콘 로딩을 제공하며 다음과 호환됩니다. `window.openai.widgetState`、`setWidgetState`、`theme`、`notifyIntrinsicHeight` 및 `sendFollowUpMessage`。
- 차트는 가시 영역 및 보고서 높이를 기준으로 로드됩니다. 원본 전체화면 dialog 컨테이너가 들어갑니다 top layer，iframe 원래 상위 노드는 항상 유지됩니다. 인라인 dialog 유지하다 closed 상태는 스타일별로 표시됩니다. 휴대전화가 처리 상태로 돌아가면 실제로 전체 화면으로 전환되는 휴대전화만 표시됩니다. open dialog。
- `setWidgetState` 호스트가 성공적으로 저장한 후 단일 항목의 상한을 확인합니다. 16 KiB，기껏해야 유지하다 100 개；localStorage 게이트웨이 및 로그인 ID, 채팅, 메시지, 파일 상속 ID 콘텐츠 요약에서 키를 분리합니다. 읽기 호환 가능한 현재 페이지가 이미 존재합니다. sessionStorage 상태. 메시지를 닫은 후 페이지를 다시 그리고 새로 고치고 다시 열면 저장된 상태를 복원할 수 있습니다. 모든 스크립트 메모리와 일반 제어 상태는 전체 화면에서 유지됩니다. 교차 메시지 다시 그리기 복구가 통과되었습니다. widgetState 인터페이스 완료。
- `sendFollowUpMessage` 질문 내용만 표시하고“입력창에 넣기”버튼, 호스트 버튼 재사용 `bridge-compose-prompt` 및 기존 초안/프로세스를 보냅니다. 채팅 전환 및 노드 파괴 시 요청을 취소하고 제거합니다. iframe 청취자와 함께。

## 대안

곧장 HTML 채팅 삽입 DOM 기존 스크립트 격리는 보존할 수 없습니다. 웹 페이지를 독립적으로 열면 컨텍스트가 손실되므로 제한된 미리보기 셸과 공유 메시지 렌더링이 사용됩니다. 파일 읽기 멀티플렉싱 Workspace，두 번째 경로 권한 세트를 설정하지 않고 구현。

만 사용 sessionStorage 에서 Android/iOS 풀어 주다 WebView 매개변수는 나중에 손실되므로 상태를 복원하기 위해 채팅을 다시 열어야 하는 요구 사항을 충족할 수 없습니다. 백엔드 상태 테이블이나 주기적인 쓰기 요청을 추가하지 않고 기존 브라우저 영구 저장소를 대신 사용합니다. 다양한 방문 origin 브라우저 저장 공간에 따라 상태가 여전히 격리되어 있으며 차트 데이터가 자동으로 전송되지 않습니다.。

## 검증

Python 회귀 커버리지 참조 해상도, 경로/크기/코딩/심볼릭 링크 경계, 패시브 세션 및 저장 내역 확인, 표시 창 및 권한 부여가 독립적이고 독립적입니다. SSH 소스코드 실행 및 게이트웨이/릴레이 인증 및 CSP。브라우저가 다음으로 반환됩니다. Chromium 및 WebKit 넓고 좁은 뷰포트에 대한 프로덕션 렌더링 및 런타임 수행, 상호 작용, 테마, 전체 화면 스크립트 메모리 검사, 상태 복원 저장, 메시지 간 상태 격리, 질문 초안, 재시도 및 네트워크 격리。

Android 사용자의 실제 테스트를 통과했습니다.；iOS 소스 코드 검토가 완료되었으며 실제 기계 상호 작용은 해당 플랫폼에서 독립적으로 허용됩니다.。

## 영향

～ 위에 Android 실제 측정값은 PR 저자 노트. 로컬 통합은 두 개의 작성자 제출을 유지하고 독립적인 개정 제출을 추가합니다. 이번 라운드 Windows/Linux 실제 기계 검증은 수행되지 않습니다. 미리보기 셸을 열려면 휴대폰에 새 버전의 기본 탐색이 필요합니다. 보통 HTML 미리보기 전략은 변경되지 않습니다.。
