# Agent Note: Markdown 파일 읽기 및 소스 코드 모드

Status: implemented

## 문제

Markdown 파일은 렌더링 결과만 읽을 수 있으며 전체 원본 텍스트를 직접 볼 수는 없습니다. 참조 위치에는 여전히 소스 코드 줄 위치 지정이 필요합니다.。

## 결정

Markdown 사용 HTML 기존 모드버튼의 모습, 기존 렌더러를 이용하여 읽기, 소스코드를 활용한 모습 BridgeSourceView。복사 버튼은 항상 서버 측의 원본 텍스트를 복사합니다. 사용자의 활성 전환은 브라우저의 전역 기본값으로 기록되며 새로 열린 파일은 이 기본값을 채택합니다. 참조 위치는 소스 코드에 강제 적용되며 기본값을 재정의하지 않습니다. 각 레이블은 두 모드의 수직 및 수평 스크롤 위치를 저장하고 모드 변경은 워크벤치의 스크롤 캐시를 동기화합니다. 소스 코드 DOM 모드 간에 유지되며 내부 스크롤 컨테이너의 수직 및 수평 위치를 명시적으로 복원하여 줄 바꿈 선택을 유지합니다. Workbench 레이블 전환은 또한 노드 제거로 인해 수평 위치가 재설정되는 것을 방지하기 위해 소스 코드의 내부 스크롤 컨테이너를 복원합니다.。

각 읽기 인스턴스에는 독립적인 Mermaid scope。읽기 종료, 탭 닫기 또는 작업 공간 재설정이 모두 정리됩니다. scope，만료된 비동기 렌더링 및 잔여 전체 화면 차트를 방지합니다. 워크벤치 자체는 전체 화면에서 동일한 콘텐츠 노드를 유지하고 원본 레이블을 사용하여 스크롤하고 복원합니다.。

## 기존 메모 감사

소스 코드 보기 메모는 부분적으로 겹치며 정확한 원본 텍스트, 독립적인 줄 번호 및 강조 표시를 계속 제한합니다. 이 결정은 다음에 대해서만 책임이 있습니다. Markdown 패턴 및 라이프사이클, 소스 코드 구성요소를 대체하지 않음。

[텍스트 바로 뒤의 블록 수식 분석](../bug-fix/2026-10-28-adjacent-display-math.md)이 기사와 부분적으로 겹치는 공유 렌더러의 단락 경계를 수정했습니다. 소스 코드 복사, 모드 전환 및 스크롤 규칙은 변경되지 않습니다.。

## 대안

- 소스코드를 독립된 태그로 사용: 동시에 볼 수는 있지만 파일 태그 개수를 소모하고 기존 태그와는 다릅니다. HTML 모드 상호작용。
- 모두 Markdown 계속해서 워크스테이션을 공유하세요 Mermaid scope：캐시 재사용은 더 많지만 단일 모드 정리는 열려 있는 다른 파일에 영향을 미칩니다.。

## 영향

다시 읽기로 전환하면 차트가 다시 생성됩니다. scope；원본 텍스트는 내용을 렌더링하지 않고 재구성됩니다. 로컬 저장에 실패하더라도 기본 설정을 계속 전환할 수 있지만 다시 로드한 후 읽기로 돌아갈 수 있습니다.。HTML、PDF 및 이미지 미리보기는 기존 경로를 유지합니다.。
