# Agent Note: 임시 사이드 채팅은 표준 채팅 인터페이스를 재사용합니다.

Status: implemented

## 문제

기본 사이드 채팅이 마이그레이션된 후에는 영구 하위 채팅만 생성될 수 있으며 임시 공유 컨텍스트의 목적은 상실됩니다. 이전 패널을 직접 복원하면 다른 입력, 첨부 및 승인 인터페이스 세트가 동시에 복원되어 계속해서 기능적 차이가 발생합니다.。

## 결정

사이드 채팅 디렉터리는 기본 영구 생성과 명시적 임시 생성을 모두 유지합니다. 원본을 임시로 생성하고 재사용 SideChats、독립 실행형 런타임 및 ephemeral fork，생성된 컨텍스트와 구성만 사용됩니다. 기본 채팅 작업이 계속되지 않거나 기본 채팅이 호출됩니다. resume 또는 turn/start。기본 생성 실패는 자동으로 임시 생성으로 다운그레이드되지 않으며 알 수 없는 쓰기는 원래 작업 식별자를 계속 사용합니다.。

임시 아동 ID 좁은 범위를 통해 TemporarySession 어댑터가 표준 채팅에 들어갑니다. HTTP 계약. 워크벤치, 타임라인, 입력 영역, 모델, 권한, 승인, 업로드 및 메시지 관리는 기존 구성 요소를 재사용합니다. 임시 어댑터에는 상위 실행기로의 기본 전달이 없습니다. 보관, 삭제, 재연결, 메시지 분기 등의 지속 가능한 작업은 명시적으로 거부됩니다. 임시 세션에는 계속해서 게이트웨이 비밀번호 보호가 필요하며 업로드 미리 보기는 지속적으로 캐시되지 않습니다. 커밋을 대기열에 넣기 전에 임시 세션 작업 디렉터리에 대해 프로젝트 참조가 재검증됩니다.。

탭을 닫으면 보기만 남습니다.；“마치다”현재 임시 라운드를 중단하고 독립 런타임 입력을 닫은 후 정상 종료를 기다립니다. 성공 후 메모리와 업로드 디렉터리를 지웁니다. 일반 종료 시간 초과는 종료를 강제하지 않고 콘텐츠를 지우지 않으며 재시도를 위해 임시 라우팅 ID를 유지합니다. 게이트웨이를 다시 시작해도 임시 세션이 복원되지 않습니다. 메인 채팅, 네이티브 히스토리 및 공유 daemon 석방되지 않는다。

표준 메시지 목록은 수신만 합니다. queued/unknown 할 일과 수락된 임시 메시지는 공유된 수신 쿼리를 통해 확인되어 알 수 없는 전송으로 잘못 표시되는 것을 방지합니다. 원본 메시지에 시간이 부족한 경우 새로 도착한 임시 메시지에 대해서는 수신 시간만 기록되며, 과거 시간은 위조되지 않습니다.。

## 대안

원래 독립 패널을 복원하면 변경 사항이 줄어들지만 복사된 입력, 업로드, 권한 및 메시지 수신은 표준 인터페이스에서 분기되었습니다. 모든 임시 작업을 메인에 넣습니다. Bridge 영구 세션, 계정 및 기록 읽기에 침입할 수 있으며 임시 변환을 쉽게 수행할 수 있습니다. ID 원래 데스크톱 런타임으로 잘못 처리되었습니다. 따라서 기존 임시 운영 로직은 유지하고, 명확한 표준 계약 적용만 추가합니다.。

기본 실패를 임시 세션으로 자동 변환하면 지속성이 변경되고 기본 응답이 손실될 때 반복적으로 생성되므로 두 생성 모두 항상 사용자가 명시적으로 선택합니다.。

## 영향

임시 사이드 채팅에는 더 이상 기본 공유 초기화가 필요하지 않으며 여전히 기존 로컬 데스크톱 사이드 채팅 입구로 제한됩니다. 이 방법으로는 열리지 않습니다 SSH 또는 CLI 학부모 세션. 임시 콘텐츠는 기본 기록에 들어가지 않으며, 백그라운드 알림 및 지속적인 기록 작업이 없으며 인터페이스는 실제 기능에 따라 표시됩니다.。

방향 회귀 범위 기준 HTTP 입증、CSRF、작업 화이트리스트, 타임라인 증분, 종료 시간 초과 후 라우팅 ID, 대기 중인 참조 재검증 및 기본 생성은 다운그레이드되지 않습니다. 상위 항목을 유지하는 런타임이 설치된 격리된 테스트 writer，인증 컨텍스트、Skill、모델, 사고 강도, 권한, 계획 모드, 사진 및 대기 중인 전송; 모델 응답은 공식 계정이나 결제 요청 없이 기본 합성 서비스에서 제공됩니다. 기본 스레드 목록에 임시 항목이 포함되어 있지 않습니다. ID，상위 히스토리 바이트는 변경되지 않고 그대로 유지되며, 내용을 지우고 프로세스를 종료하기 위해 프로세스가 정상적으로 종료됩니다. 브라우저 검사 및 3단 완제품 승인의 구체적인 결과는 이번 납품 영수증에 기록되며, 이 런타임 테스트는 3단 완제품 승인과 동일하지 않습니다.。
