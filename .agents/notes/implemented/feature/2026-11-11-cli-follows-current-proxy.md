# Agent Note: 이 기계의 호스트 CLI 확인된 프록시 포트를 따르세요.

Status: implemented

## 문제

CLI 서비스가 이전 루프백 프록시를 계속 상속하는 경우 사용자는 포트를 변경한 후 이를 수동으로 복원해야 합니다. 게이트웨이로 직접 환경을 시작하면 이전 터미널에 대해 다른 구성이나 프록시를 사용할 수 있습니다. 자동으로 모두 활성화 home 기본 시스템 프록시는 우회 규칙도 변경할 수 있습니다.。

## 결정

이 기계의 정문과 동일합니다. CODEX_HOME 의 CLI 세션이 명시적으로 계속되거나 새 작업이 제출될 때 확인됩니다.。APP、IDE、독립입구、SSH、WSL 그리고 읽기 전용 기록이나 알림은 기본 포털의 프록시를 사용하지 않습니다. 기본 구성 `respect_system_proxy` 프로세스는 당시 네이티브 라우팅으로 넘겨지며, 오래된 상속 변수로 인해 프로세스가 드레이닝되지 않습니다.。

기본 검증된 생성 프록시를 읽고 변수를 우회합니다. 현재 모델 대상이 직접 연결되거나 우회되지 않는 경우에만 원래 세대의 해당 루프백 에이전트에 더 이상 도달할 수 없으며 현재 사용자의 시스템 설정이 동일한 프로토콜의 도달 가능한 다른 정적 루프백 주소를 제공하여 복구를 준비할 수 있습니다.。macOS 한 번 사용 SystemConfiguration 스냅 사진；Windows 읽다[네이티브 resolver 현재 사용 중인 사용자 Internet Settings](https://github.com/openai/codex/blob/c40729ea5cf8e947481b130c59807273eda2f8e9/codex-rs/http-client/src/outbound_proxy/windows.rs#L54-L90)，글로벌 필요없어 WinHTTP 에이전트 또는 게이트웨이 상속 변수。PAC/WPAD、케이스 충돌, 식별되지 않은 우회 규칙 또는 신뢰할 수 있는 대안이 없는 경우 추측할 수 없습니다.。Linux 이번에는 보편적으로 읽을 수 있는 신뢰할 수 있는 시스템 대체 소스가 확인되지 않았습니다.。

재사용[같은 home 자유 시간](2026-11-11-cli-recovery-waits-for-idle.md)，원본을 유지하세요 ID、cwd、provider 이미 기본 권한이 있습니다. 영향을 받는 프로토콜의 상속된 변수만 교체하고 다른 프로토콜은 그대로 유지합니다.、NO_PROXY 승인되지 않은 변경에 대한 인증; 확인된 계정 변경이 동시에 발생하는 경우 동일한 유지 관리가 수행됩니다. 대기 중인 에이전트의 대상 변경으로 인해 이전 확인이 무효화됩니다. 발송하기 전에 이전 주소는 여전히 유효하지 않으며 새 주소는 계속 사용할 수 있습니다. 원래 세대가 정상적으로 종료된 후 현재 재검증된 유효 주소가 사용되며, 계속하기 전에 새로운 세대가 실제로 에이전트를 상속받는 것을 확인합니다. 시스템 에이전트가 작성되지 않거나 native config，전송된 초안, 알 수 없는 결과가 있거나 이번에 차단된 초안은 다시 전송되지 않습니다.。

## 대안

기존 수동 복구를 유지합니다. 구성 쓰기에는 명시적인 확인, 기본 구성 버전 비교 및 ​​알 수 없는 수신 처리가 필요합니다. 자동 경로는 비밀리에 작성되지 않습니다. `respect_system_proxy`；업스트림이 시스템 프록시 라우팅을 사용하는 경우 환경의 라우팅을 따르지 않습니다. NO_PROXY。설정이 적용된 세션은 기본 동적에 의해 계속 처리되며 새로 활성화된 시스템 정책은 로드된 모델 클라이언트를 핫 업데이트할 수 없습니다. 게이트웨이에서 시작된 프록시 환경을 직접 사용하면 현재 주소가 유효하거나 이 구성에 속한다는 것을 증명할 수 없습니다.。

## 검증

기본 동적 전략, 동일한 프로토콜 선택, 다른 내용으로 돌아가기 home、우회로/PAC/변수 충돌, 이전 주소가 여전히 유효하거나 새 주소에 연결할 수 없음, 병렬 인증 변경, 대기 중 프록시 변경, 교체 프로세스가 예상 프록시를 사용하지 않을 때 계속되거나 두 번 종료되지 않습니다.。

현실 macOS CLI 0.167.0 독립 당시 home 자신만의 것을 사용하세요 TLS 응답 및 루프백 CONNECT 프록시 확인. 오래된 A 원래 스레드와 다른 활성 스레드로부터 두 개의 요청을 받았습니다. 닫다 A 새 초안은 고려되지 않으며 활성 작업이 완료된 후 정상적으로 다시 작성됩니다. 같은 스레드와 cwd 콜드 연결 후 명시적으로 전송된 새 메시지가 실제로 처리됩니다. B 마치다. 3번 예상됨 POST 모두 합성 엔드포인트로 이동하며 원본 메시지는 재생되지 않습니다.，HTTP/ALL/NO_PROXY 및 구성 바이트는 변경되지 않고 유지되며 두 세대의 격리 프로세스가 모두 종료됩니다.。OS 쿼리 결과는 Fixture 주입이고 전체 기계 설정은 변경되지 않았습니다.；Windows 이 경우 시스템 소스 동작은 실제 에이전트 전환이 요구되지 않은 프로토콜 및 시뮬레이션된 회귀입니다. 증거는 `.tmp/feedback-20261111-10/cli-auto-proxy-native-result.json`，테스트 인증서의 첫 번째 라운드가 실패했으며 자체 프로세스가 정리되어 저장되었습니다.。

## 영향

확인된 기본 잘못된 프록시 포트는 명시적 새 항목에서 찾을 수 있습니다. CLI 작업이 트리거되고 사용자가 원본 초안을 다시 보낸 후 안전하게 복구됩니다. 대체 증거가 없거나 복구 영수증을 알 수 없는 경우 원래 진단 및 수동 검사가 유지됩니다. 구성된 다른 에이전트는 대여되지 않으며 강제 종료 기능도 추가되지 않습니다.。
