# Agent Note: 독립적인 Codex 액세스 구성

Status: implemented

## 문제

Issue #106 독립의 CODEX_HOME 포함 VS Code 원래 세션. 이전에 제외된 소스 필터링 codex_vscode，새 항목은 독립 디렉터리에 바인딩될 수 없습니다. 접속, 계정, 실행 ID를 분리하지 않고 경로만 추가하면 기본 기록이나 연결 오류가 혼합됩니다. owner。

## 결정

상속 Codex 항목 레지스트리, 로컬 머신 추가 codex-local 하위 항목, 증가 없음 Agent 상표. 데스크탑 ”액세스 추가 → Codex」얕은 스캔, 기본 폴더 선택 및 수동 입력을 제공합니다. 디렉터리 정규화 후 기본 디렉터리, 별칭 및 중복 등록을 거부합니다. 장치를 저장하고 inode ID, 경로 교체 후 계속 사용을 거부합니다. 구성 관리는 데스크탑에서만 수행됩니다. IPC，원격 임의 디렉터리 구성 인터페이스가 추가되지 않았습니다.。

각 입구는 동일하게 재사용됩니다. Bridge 수업, 혼자 서기 home、원장, 초안 신원 및 항목 ID 격리. 물리적 로컬 머신과 디스플레이 입구가 분리되어 있습니다. 파일 작업은 로컬 머신 공유를 통해 구현됩니다. IPC 의 hostId 아직 local。Web 재사용 Codex 페이지, 모델、Skill、프로젝트 선택기, 권한, 첨부 파일 ＆amp; CLI 서비스를 출시합니다. 독립된 입구를 선택하면 목록과 신규 요청은 이 입구에만 접근하며, 기본 입구로 돌아가 원래 목록을 복원합니다.。

기존 VS Code owner 온라인일 때 먼저 연결을 따르세요. 저장, 검색, 목록 및 알림은 기본 실행을 시작하지 않습니다. 명시적인 확인만 가능 owner 부재 시 사용자는 계속 연결하거나 선택한 항목을 시작합니다. home 네이티브 서비스. 시간 초과 및 알 수 없는 소유권으로 인해 두 번째 실행기가 시작되지 않습니다.。Windows 단일 공유 파이프라인에서 복제 UUID 또는 다른 디렉토리를 읽을 수 없으면 추론을 거부하세요. owner。독립출입구는 기본적으로 열리지 않습니다. Desktop，기본 계정 전환은 제공되지 않습니다. 계정은 원래 계정과 동일하게 유지됩니다 VS Code / CLI 관리하다。

## 대안

- 모든 디렉터리를 기본 입구에 병합: 인터페이스는 간단하지만 입구 ID와 계정이 명확하지 않아 동일한 문제가 발생합니다. UUID 역사적 혼란, 포기。
- 디렉터리당 하나의 디렉터리를 더 엽니다. Desktop：기존 창 프로세스를 빌릴 수 있지만 다음에 따라 달라집니다. GUI 헤드리스 요구 사항과 일치하지 않는 수명 주기, 포기。
- ～을 위한 VS Code 채팅, 첨부 파일, 프로젝트 및 릴리스 로직 복사: 독립적으로 진행하기 쉽지만 반복적으로 공통 동작을 유지하고 포기합니다.。
- 요청에서 언로드 지연 재정의: 이론적으로 이를 통해 독립적인 헤드리스 세션이 작성자를 빠르게 반환할 수 있습니다. 실제 설치 0.162.1 오른쪽 thread/start、thread/resume 이 재정의는 적용되지 않습니다.，daemon start 재정의로 인해 결과가 변경되지 않았으므로 잘못된 재정의를 제거하세요.。
- 사용자 자동 재작성 config.toml 또는 공유 서비스를 중지합니다. 기본 구성의 제거 지연이 적용되지만 이러한 방법은 다른 원래 클라이언트의 동작을 변경하거나 작업에 영향을 미치며 현재 액세스에는 사용되지 않습니다.。

## 영향

기본 실행 구성 요소는 기존 구성 요소에서 나옵니다. Codex 설치; 독립형인 경우 home 아직 아님 daemon 패키지, 만든 Codex 기본 구성 요소를 소개하지 않고 직접 준비 Node、Homebrew 또는 기타 App。IDE 저장되지 않은 파일 및 편집기의 즉각적인 컨텍스트에는 원본이 필요합니다. IDE 온라인, 헤드리스 복구는 기본 저장된 세션만 사용합니다.。

독립적인 home 의 sqlite_home 기본 데이터베이스를 잘못 읽는 것을 방지하기 위해 다른 디렉터리를 가리킬 때 등록을 일시적으로 명시적으로 거부합니다. 사용자 디렉터리와 기본값만 확인하도록 검사를 구성합니다. home 같은 수준의 .codex* 디렉터리, 디스크를 재귀적으로 검색하지 않음。

독립 입구 재사용 작업 게이트를 비활성화하고 허용된 쓰기를 먼저 배출합니다. 이전 요청에 의해 보유된 개체는 종료 후 계속해서 파일 보내기, 업로드, 쓰기 또는 프로젝트 생성을 할 수 없습니다. 기본 항목의 동작은 변경되지 않습니다.。

적극적으로 기존 릴리스 및 유지 released/detached 차이점: 구독을 취소한 후에는 게이트웨이가 더 이상 원본을 자동으로 선택하지 않습니다. VS Code/공유 서비스 클라이언트는 계속할 수 있습니다. 독립형 codex exec 프로세스에서 여전히 네이티브 쓰기 점유가 발생할 수 있으며 네이티브 언로드를 기다려야 합니다. 될 수 없다 detached 글쓰기를 위해 석방되었다고 주장함。
