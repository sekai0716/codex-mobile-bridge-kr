# Agent Note: DSH 범용 플러그인 및 명시적 아카이브 바인딩

Status: implemented

## 문제

제3자 DSH 클라이언트는 프로그램 이름, 시작 방법 및 데이터 디렉터리를 조정할 수 있습니다. 데스크톱 실행 파일을 기준으로 일치시키면 단일 법적 파일이 제거됩니다. Harness 인스턴스는 알 수 없음 또는 다중으로 허위 보고되며, 스캔 시 독립적인 입구가 없습니다.。Issue #59 의 Windows DSH Desktop 0.12.1 장면은 시작 모양의 차이를 반영합니다. 에피사이클이 아니다 Tauri 실제 테스트 개체입니다. 사용자는 분명히 범용 플러그인, 사용자 정의 연결, 제거 및 구성되지 않은 클라이언트 숨기기를 요구하며 특정 제한을 허용하지 않습니다. Tauri 껍데기。

## 결정

독립 패키지 `dsh-codex-mobile-bridge` 동일한 공식 액세스 사본을 재사용하세요. `host.mjs`；코어부터 얇은 패키지 `profileContext` 진짜가 되다 home、profile 및 디렉토리, 비공개 생성 `binding.json`、`connection.json`，원래 루프백 인증 프로토콜을 공유합니다. 플러그인 패키지에는 계정, 토큰, 세션 또는 코어가 포함되어 있지 않습니다. 공식적인 원클릭 설치는 유지됩니다. 수동 모드는 실행 파일 이름에 의존하지 않으며 공식 라이프 사이클 관리자가 시작하거나 종료하도록 두지 않습니다.。

게이트웨이는 바인딩 파일을 선택하거나 사용자가 명시적으로 선택합니다. Harness 데이터 디렉토리에서 검색 `profiles/*/codex-mobile-bridge/binding.json`。읽기 전용 ID 파일을 찾았고, 심볼릭 링크 파일을 건너뛰었고, 네트워크에 연결되지 않았으며, 자동으로 선택되지 않았습니다. 바인딩은 디렉터리 관계, 플러그인 소스 파일 버전 및 인스턴스를 확인합니다. ID，그런 다음 루프백 인증을 통해 프로토콜 개정을 읽습니다. 다시 시작하고 복원하여 원본 인스턴스를 확인하세요. 오류는 공식 클라이언트나 다른 클라이언트로 롤백되지 않습니다. 데스크톱 파일이 없으면 연결 프롬프트가 다음을 가리킵니다. Web/타사 클라이언트를 위한 플러그인 검색 및 바인딩 수동으로 바인딩했지만 엔드포인트가 로드되지 않은 경우 원래 클라이언트에서 파일 플러그인을 다시 로드하라는 메시지가 표시되므로 더 이상 사용자가 데스크톱 액세스를 반복적으로 설치하도록 오해할 수 없습니다. 디렉터리, 끝점 및 구성 변경 사항은 여전히 ​​기존 ID 보호를 사용합니다. 계정 패널은 바인딩된 코어만 읽고 타사 인증 구성을 변경하지 않습니다.。

동일한 게이트웨이에서 활동 유지 DSH 파일. 전환 이전에는 휴대폰 접속만 불가능했으며 앞으로도 계속 사용할 예정입니다. `_changing` 읽기 캐시 및 바인딩 생성을 지웁니다. 쓰기 요청은 기존 멱등성 수신, 알 수 없는 결과 재생 없음 및 보관 확인 프로세스를 계속 사용합니다. 수동 모드에서는 게이트웨이가 타사 애플리케이션을 종료하는 것을 금지하고 타사에 대한 기본 강제 종료를 수행하지 않습니다. 플러그인 측 예약 인스턴스 ID 및 token，끝점 generation 각 부하에 따라 변경됩니다. 활성 파일의 반복적인 로드는 거부됩니다.。

클라이언트 목록은 로컬 설치, 구성, 활성화, 실행 중 또는 수동 바인딩 상태별로 표시됩니다. 설치 및 구성되지 않은 빈 줄은 표시되지 않습니다. 통일된“액세스 추가”항상 이용 가능，DSH 입구에서 직접 수동 설치 및 바인딩을 시작합니다. 내부 provider ID 기존 전화와 채팅 UI 끊임없는；WSL 항목은 독립적으로 판단되며 집계된 상태는 로컬 데스크톱에서 사용 가능한 것으로 간주되지 않습니다.。

## 대안

- 기존 공식 원클릭 액세스를 재사용할 수 있는 각 타사 프로그램 이름에 대한 검색 및 처리 특수 사례를 추가하지만 클라이언트 이름 변경 또는 시작 변경은 여전히 ​​유효하지 않습니다. 따라서 공식 단축키 경로는 그대로 유지되며, 실제 파일에 바인딩된 공통 경로가 추가됩니다.。
- 더 적은 수의 사용자 바인딩 단계로 현재 게이트웨이 구성을 포함하는 전용 플러그인을 내보내지만 로컬 자격 증명과 경로를 배포 가능한 패키지에 넣습니다. 자격 증명이 필요 없는 범용 패키지를 사용하여 실행 중인 코어에서 독립적인 개인 ID를 생성합니다.。
- 제3자를 위한 전체 커넥터를 다시 작성하는 것은 자유롭게 조정할 수 있지만 채팅, 승인, 알림 및 보관이 별도로 유지 관리됩니다. 동일한 출처를 사용하여 내보내기 host，변경 사항을 구현할 때 수동 플러그인을 동시에 업데이트해야 합니다. 이는 또한 확인 없이는 이전 패키지를 계속 바인딩할 수 없음을 의미합니다.。
- 각 타사의 계정 파일 및 종료 동작을 게이트웨이가 직접 관리하도록 하여 모든 관리 버튼을 유지할 수 있지만 현재 해당 버전에 대한 검증이 부족합니다. 수동 액세스는 이러한 작업을 원래 클라이언트에 맡기고 더 작은 계정 관리 범위의 비용을 허용합니다.。

## 영향

사용자는 호환 가능 Harness 클라이언트는 프로세스 식별 규칙의 이름을 바꾸거나 수정할 필요가 없습니다. 가격은 수동 설치, 명시적 파일 선택 및 버전 동기화입니다. 플러그인 설치 디렉터리와 바인딩 파일을 유지해야 합니다. 코어 또는 이와 유사한 것만 존재함 Web 해당 페이지는 플러그인에 필요한 서비스가 있음을 보장하지 않습니다. 향후 다중 동시접속이 지원된다면 DSH 파일을 먼저 확장해야 합니다. provider/host ID 모델은 고정된 모델을 재사용할 수 없습니다. provider 비밀리에 대상 변경。
