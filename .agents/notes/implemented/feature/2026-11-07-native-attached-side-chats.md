# Agent Note: 기본 영구 사이드 채팅 및 표준 채팅 인터페이스 재사용

Status: implemented

## 문제

Bridge 임시 사이드 채팅은 독립 실행형 런타임에 의해 보관되며 기본 사이드 채팅으로 사용할 수 없습니다. Codex App 에서 보기 원래의 App 생성된 사이드 채팅이 일반 채팅 목록에 섞여 있었고, 부모-자식 관계 및 종료 의미가 일치하지 않았습니다.。

## 결정

기본 상위-하위 속성은 다음을 사용합니다. `attached_thread_parent_id`，평범한 `forkedFromId` 사이드 채팅과 동일하지 않습니다. 채팅 목록은 페이징하기 전에 상위 채팅이 여전히 현재 구성의 액세스 가능한 범위 내에 있는 기본 하위 채팅을 숨깁니다. 상위 채팅이 없거나 이 구성 범위에 속하지 않는 경우 하위 채팅을 유지하고 기록이 사라지는 것을 방지하기 위해 해당 채팅의 ID를 표시합니다. 보관된 하위 채팅은 상위 채팅의 사이드 채팅 디렉터리에 계속 포함됩니다.。

종료 및 보관 작업 확인 범위 attached 및 subagent 두 관계로 구성된 전체 하위 항목 집합입니다. 삭제 영수증 존재 여부 확인은 상위 계층에서 검증된 식별 집합만 허용하며, 접근 범위를 확장하지 않습니다.。

새 통화 생성 `thread/fork` 의 `attachToSource: true`、`excludeTurns: true`，전달되지 않음 `ephemeral` 또는 `deferGoalContinuation`。먼저 현재 설치 런타임을 확인하세요. schema，다시 제출하세요. 지원되지 않는 경우 명시적으로 거부하고 임시 채팅으로 돌아가지 마세요. 상위 채팅을 상속하는 구성 디렉터리, 모델, 사고 강도, 권한 및 작업 디렉터리를 만들고, 상속 내역이 보류 중인 실행 요청으로 오인되지 않도록 사이드 토론의 경계를 작성합니다. 메타데이터 프로세스가 호출되지 않습니다. `turn/start`，일반 출시 후에도 표준 채팅 연결 경로는 계속 사용됩니다. 수동 열거 중에는 원래 채팅 연결 경로가 전환되지 않습니다. App 프런트 데스크。

기존 영구 운영 원장을 생성하고 재사용합니다. 응답 손실 후에도 동일한 작업 ID 반복되지 않음 fork；네이티브가 아이를 돌려줬어요 ID 이후 후속 검증 또는 주입 실패에도 해당 값이 유지됩니다. ID，사용자가 확인할 수 있도록 합니다. 기본 관계 및 모델 구성이 확인된 후 경계 및 제목이 추가됩니다.。

학부모 채팅 보존 워크벤치“보조 채팅”접근 가능한 기본 채팅 및 공유 세션 메뉴를 표시하는 탭입니다. 원래 하위 채팅을 유지하면서 기존 전체 채팅 경로에 들어가려면 하위 채팅을 생성하거나 클릭하세요. ID；입력 영역, 첨부 파일, 승인, 중지, 알림 및 기록은 모두 표준 구현을 재사용합니다. 서브 채팅 제공“기본 채팅으로 돌아가기”；디렉터리 탭이나 하위 채팅 보기를 닫으면 보기만 사라지고 중지, 보관 또는 삭제되지는 않습니다. 업그레이드 전에 열린 이전 임시 페이지는 여전히 원래 수명 주기를 완료할 수 있지만 새 버전의 포털은 더 이상 임시 런타임을 생성하지 않습니다.。

## 대안

임시 독립 실행을 계속 사용하면 원래 패널을 유지할 수 있지만 이는 듀얼 엔드 기본 동기화 및 지속성 목표와 충돌합니다. 모두 넣어 fork 가장 코드를 절약하는 사이드 채팅으로 여겨지지만, 일반 브랜치를 숨기므로 네이티브만 사용합니다. attached 필드. 현재 변경사항이 승인되지 않았습니다. SQL 쓰거나 변형하다 Codex 설치 패키지 위조 관계。

사이드 탭에서 또 다른 입력, 첨부 파일 및 승인 코드 세트를 계속 유지하면 페이지 탐색이 방지되지만 이미 기능의 분기가 생성됩니다. 현재 완전한 표준 채팅 페이지가 사용되며 상위 채팅으로의 명확한 복귀가 채택됩니다. 두 번째 채팅 컨트롤러 세트는 추가되지 않습니다. 독립적인 메타데이터 프로세스는 포그라운드 작업 없이 기존에 생성된 링크를 계속 사용할 수 있지만 현재 열려 있는 원본 링크를 보장할 수는 없습니다. App 학부모 채팅은 즉시 새로 고쳐지므로 가짜 채팅이 전송되지 않습니다. owner 방송。
