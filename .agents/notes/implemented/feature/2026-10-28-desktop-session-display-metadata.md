# Agent Note: Claude 및 DSH 분류 및 이름 변경 영수증 표시

Status: implemented

후속 결정：[기본 세션 이름 바꾸기](2026-11-04-native-session-renames.md) 새로운 사용자 요구 사항에 따라 이 문서의 이름 변경 및 별칭 롤아웃을 교체하세요. 이 글은 당시의 선택과 이유를 그대로 담고 있다，Bridge 프로젝트/구역 분류는 여전히 사용됩니다.。

## 문제

[세션 메뉴 공유](2026-10-28-shared-session-menu.md)처음 통합 시 기본 분류가 있는 파일만 API 의 Codex 프로젝트와 파티션을 제공합니다. 그런 다음 사용자는 명시적으로 요청합니다. Claude、DSH 또한 이러한 대조 항목이 있으며 검증 가능한 기본 인터페이스가 없을 때 명확하게 표시된 항목의 사용을 허용합니다. Bridge 분류. 다양한 클라이언트의 프로젝트 의미는 다음과 같이 변경할 수 없습니다. cwd 아니면 채팅을 다시 만들어 강제 통일을 시키거나。

## 결정

게이트웨이 지속성 `DisplayMetadata`，기록 Bridge 프로젝트, 파티션 및 디스플레이 별칭. 해당 작업 페이지에 인터페이스가 표시됩니다.“오직 에서만 Bridge 에서 유효”；휴대폰과 Web 동일한 게이트웨이 레코드를 읽습니다. 분류 기준 provider、액세스 디렉토리, 기본 home、host 및 backend 격리하다, 피하다 Code、Cowork、CLI、WSL 또는 기타 DSH 인스턴스는 서로 라벨을 적용합니다. 원래 세션 ID、cwd、owner、provider、auth 끊임없는。

검증 가능한 기본 기능을 사용할 수 있는 경우 기본 작업 사용의 우선순위를 정하세요.：Claude Code/Cowork 기본 이름 바꾸기；DSH 로드된 세션 기본 이름 바꾸기 및 동기화 cwd Workspace 멤버십 변경。Claude CLI 그리고 언로드됨 DSH 세션이 표시 별칭을 사용하고 이름 변경을 위해 세션을 시작하지 않습니다.。DSH 파티션은 아직 Bridge 분류; 프로젝트와 파티션은 각각 해당 범위를 나타냅니다. 기본 특정 인터페이스, 콜드 세션 제한 및 버전 확인은 다음에서 제공됩니다.[메모에 대한 기본 액세스](2026-10-28-native-session-metadata.md)기록。

`RenameCommands` 기본 쓰기 전에 대상 헤더 및 실행 ID를 저장합니다. 알 수 없는 결과 이후 새 요청 ID 게이트웨이를 다시 시작해도 재배포할 수 없습니다. 후속 읽기 전용 쿼리는 차단을 해제하기 전에 원래 대상을 확인합니다. 분명한 `notSent` 작업을 수정하고 다시 시도할 수 있습니다. 원래 이름 변경 확인 후 기존 이름 삭제 Bridge 목록과 채팅 제목을 만드는 별칭은 기본 결과를 표시합니다. 네이티브 프로젝트는 계속해서 재사용됩니다. `OrganizationCommands` 예상 회원 보호 및 알 수 없는 결과의 지속성。

Bridge 동일한 개인 원자 파일 트랜잭션에서 분류 생성, 선택 및 이름 변경 기록 요청 영수증 표시 동일한 요청을 재시도해도 중복 분류가 생성되지 않으며 후속 분류도 다시 변경되지 않습니다. 항목 선택에서는 예상 멤버십을 사용하여 다른 클라이언트가 방금 완료한 선택 항목을 덮어쓰는 만료된 페이지를 거부합니다. 항목별로 목록을 표시할 때는 명시적인 범주와 파티션을 사용합니다. 표시 범주를 설정하지 않은 이전 세션은 기존 디렉터리 표시 방법을 계속 유지합니다.。

## 관련 기록 감사

- `2026-10-28-shared-session-menu.md`：부분적 중복; 기본 분류를 제공하지 않기로 한 초기 결정은 역사적 맥락을 유지합니다. 이 문서에서는 사용자가 수락한 후속 범위 확장을 기록합니다.。
- `2026-10-28-dsh-generic-plugin-binding.md`：부분적 중복; 인스턴스 바인딩 및 공통 플러그인 경계를 유지하고 특정 타사 애플리케이션 목록을 추가하지 않습니다.。
- `2026-10-26-local-first-session-pins.md`：독립적인 결정; 원래 로컬 우선 순위 동기화 동작은 여전히 ​​맨 위에 유지되며 이 문서에서는 해당 저장 또는 동기화 프로토콜을 변경하지 않습니다.。
- CLI 신규, 복원 및 SSH/WSL 액세스 참고 사항: 시행 ID 제약 조건은 계속 적용됩니다. 이 문서는 이러한 세션의 시작 또는 계정 동작을 변경하지 않습니다.。

## 검증

`tests/test_display_metadata.py` 프로세스 간 객체 재구성 후 지속적인 읽기 및 분류를 다룹니다./별칭 격리, 원본 ID 변경 없음, 중복 생성 영수증, 만료된 선택 거부, 기본 알 수 없는 이름 변경은 재생되지 않음, 전송되지 않은 명확한 이름 수정 가능, 기본 이름 변경으로 별칭 정리 및 DSH 네이티브 프로젝트 및 Bridge 파티션 혼합 범위. 브라우저는 실제 세션을 실행하지 않고도 로그인된 합성 목록에서 3가지 메뉴로 들어가 이름 변경, 프로젝트, 파티션, 복귀를 확인한다. 구성 및 공통 회귀 증거는 다음 위치에 저장됩니다. `.tmp/session-followups-20261028/`；합성 네이티브 인터페이스 테스트는 모든 타사 클라이언트 실제 시스템 검증과 동일하지 않습니다.。

## 대안

기본 인터페이스가 없는 항목을 계속 숨기는 것이 기본 일관성을 보장하는 가장 쉬운 방법이지만 이는 사용자의 명확한 클라이언트 간 조직 요구 사항을 충족할 수 없습니다. 묶음 Bridge 기본 프로젝트인 것처럼 가장하는 카테고리는 사용자를 오도할 수 있으며 cwd 실행 환경을 마이그레이션하므로 하위 범위 힌트를 사용하세요. 직접 전화하다 DSH `sessionController.rename` 인터페이스는 간단하지만 콜드 세션을 재개하는 것이 가능합니다. 따라서 비활성 기본 기능 경계를 유지하고 별칭을 표시합니다.。

## 영향

프라이빗 게이트웨이 추가 `display-metadata.json`、`session-renames.json`，원본 기록 파일을 수정하지 않습니다.。Bridge 표시 카테고리는 원래 클라이언트와 동기화되지 않습니다. 이러한 레코드는 서로 다른 게이트웨이 데이터 디렉터리 간에 공유되지 않습니다. 세션 알 수 없는 쓰기에는 기본 다시 읽기 확인이 필요하며 반복적인 클릭으로 우회할 수 없습니다. 현재 분기는 로컬에만 있고 푸시되거나 게시되지 않습니다.。
