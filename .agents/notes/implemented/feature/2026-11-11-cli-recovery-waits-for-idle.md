# Agent Note: 확인됨 CLI 공유 작업이 끝날 때까지 대기 재개

Status: implemented

[같은 home 기본 계정 팔로우](2026-11-11-cli-follows-native-account.md)이 거래를 명시적으로 계속하는 동안 발견된 확인된 계정 변경 사항을 수신합니다. 작업 대기, 취소, 생성 및 알 수 없는 영수증 보호는 변경되지 않습니다.。

## 문제

로컬 머신 CLI 복원하려면 먼저 동일한 항목을 확인하세요. CODEX_HOME 모든 작업. 이전에는 다른 채팅이 실행 중이거나 승인 대기 중이거나 작업 상태를 알 수 없을 때마다 미리보기 재개가 거부되어 사용자가 다시 확인하고 다시 확인해야 했습니다. 유휴 상태가 될 때까지 요청에서 직접 대기하면 페이지를 차지하거나 확인을 건너뛰거나 기본 호출을 수행하게 됩니다. restart 공유된 작업은 조기 종료될 수 있습니다。

## 결정

검증된 머신에서 macOS/Linux CLI 0.164.0、0.167.0 , 복구 미리 보기는 읽기 전용으로 유지됩니다. 확실한 확인 후, home 확인되지 않은 가용성, 원본 `cli-daemon-recovery.json` 사용 `purpose=recovery`、`phase=waiting` 유지 관리 트랜잭션을 예약하고 시작 스레드를 바인딩합니다. ID、cwd 공급자, 호스트、home、구성, 검증된 기본 생성 및 미리보기 요약입니다. 순수 프록시 복구는 대상의 ID도 보존합니다. 기본 메타데이터와 보존된 메타데이터가 함께 변경되더라도 이전 확인은 유효하지 않은 상태로 유지됩니다. 파견하기 전에 대상을 다시 읽고 원래 아이덴티티를 계속 사용하십시오. 동일한 확인은 동일한 작업을 반환합니다. ID；대기 중이거나 확인되지 않은 쓰기는 다른 작업으로 재정의될 수 없습니다. 취소하면 이전 확인이 무효화되고 새 미리보기로 다시 시도됩니다. 기록에는 신원, 요약, 상태만 저장되며, 인증값이나 기본 환경은 저장되지 않습니다.。

대기는 명시적인 확인이 있어야만 시작되며 유지 관리 잠금은 각 확인 사이에 5초 간격으로 해제됩니다. 상태 검토 및 취소는 기본 확인을 기다리지 않습니다. 취소 및 첫 번째 쓰기 또는 종료 디스패치는 단기 레코드 잠금을 공유합니다. 검사 종료 전 취소, 이전 worker 프록시 설정을 쓰지 않고 종료하거나 계속하지 않습니다. 게이트웨이가 종료되면 대기가 중지됩니다. 다시 시작하면 예약된 대기 기록만 표시됩니다. 확인을 계속하기 전에 동일한 작업을 확인하십시오. 액세스 비활성화, 원래 프로세스/구성이 변경되거나 원래 세션이 해제되면 요청이 더 이상 계속되지 않습니다.。

채팅, 승인, 대상, 백그라운드 터미널 및 게이트웨이 대기열이 로드된 동일한 구성이 매번 확인됩니다./알 수 없는 쓰기 작업 정보가 감지되지 않고 대기 중입니다. 유휴 후 기존 종료, 시작 및 명시적 복구를 재사용합니다. 동일한 생성 프로세스를 한 번만 보냅니다. graceful-only SIGHUP，만료 시 강제로 업그레이드되도록 기본값을 설정할 필요는 없습니다. daemon stop/restart，작업을 중단하거나 자동으로 메시지를 다시 보내지 마세요. 기존 종료, 설정, 시작、resume 보류 중인 확인 영수증은 발송 전에 영구적으로 기록되며, 알 수 없는 결과는 재생되지 않습니다. 같은 home 복구, 릴리스 및 종료 및 릴리스 후 시작 다중 파일 잠금은 서로 다른 게이트웨이가 동일한 서비스에 대해 동시에 유지 관리 작업을 수행하는 것을 방지합니다. 다른 게이트웨이는 여전히 이 요청의 결과를 유지합니다.。

작업이 차단될 때 네트워크 미리보기 제공 `willWait`；아직 전송 중인지 확인 `confirmed` 및 `generation`。다음을 포함한 결과를 기다리는 중 `operationId`、`state` 및 `canCancel`；동일한 스레드를 통한 상태 또는 취소 `cli-network` 제출하다 `action=status` 또는 `action=cancel` 그리고 `operationId`。이 필드 집합은 공유 인터페이스를 통해 액세스되며 읽기 상태는 유지 관리 또는 쓰기 권한 변경을 트리거하지 않습니다.。

## 대안

수동으로 다시 시도하기 전에 사용자에게 작업이 끝날 때까지 기다리도록 계속 요구하면 최소한의 백그라운드 작업을 유지할 수 있지만 사용자가 확인한 복구는 계속할 수 없습니다. 동기식 차단 요청은 수신을 단순화하지만 상호 작용을 차지하고 취소하기 어렵습니다. 또 다른 복구 큐를 생성하면 기존 종료 및 알 수 없는 결과 원장으로 이중 권한이 생성되므로 원래 트랜잭션에는 유휴 단계만 추가됩니다. 토종의 restart 간단하기는 하지만 기본값이 단지 정상적인 비움임을 보장할 수는 없습니다.。

## 검증

스레드 전체에 작업이 있으면 원래 구현이 반환되고 복구할 수 없습니다. 방향 회귀는 먼저 반복된 다음 확인 및 확인하고 자동으로 대기하고 확인 다중화를 반복하고 유휴 상태 후에 정상적으로 종료됩니다./시작하다/계속하다. 복구, 릴리스 및 계정 동기화 110 상태 및 취소, 프로세스 변경, 읽기 전용 다시 시작, 느린 검사의 동기화를 포함하는 제어된 회귀가 통과되었습니다. home 상호 배제, 알 수 없는 작업은 새 작업의 마지막 확인과 호환되며, 알 수 없는 작업은 재생되지 않으며 이미 성공적인 릴리스 확인이 있습니다. 검토 수정은 또한 동시에 변경된 후에도 복원할 수 있는 순수 프록시 대상의 양쪽에 메타데이터를 먼저 재생성합니다. cwd 라우팅 공급자가 바뀌어도 종료되지 않음/시작하다/연결; 최종 유휴 점검 중에 대상이 변경되더라도 배포가 거부됩니다. 원래 성공적인 연결은 원래 ID를 확인합니다.。

macOS 격리 home 설치하여 사용 0.167.0 실제 daemon、두 개의 자체 스레드 및 루프백 합성 Responses 상류. 원본 스레드에 실제 승인 요청이 있는 경우 백그라운드 확인이 유지됩니다. PID 67355，출구가 발행되지 않았습니다. 원래 클라이언트가 승인을 거부하고 완료한 후에는 한 번만 정상적으로 종료되고 시작되었습니다. PID 67722，대상 스레드를 한 번만 연결하십시오.，ID、공급자 및 작업 디렉터리는 변경되지 않았으며 모델이 없는 라운드를 대상으로 합니다. 두 가지 모델 프로토콜 POST 둘 다 자체 소유 루프에 들어가고 업스트림 결제 및 제3자 알림은 0입니다. 두 개의 자기 소유 PID 종료 후 존재하지 않는지 확인하십시오. 증거 `.tmp/feedback-20261111-10/cli-maintenance-native-result.json`。이전에 PATH Cold Start도 실제 이미지를 사용하여 이루어졌으며 PID 두 개의 검증 세대를 기록합니다. `.tmp/c10/native-path-cold-result.json`。

## 영향

복구는 기존 작업이 안전하게 완료될 때까지 기다릴 수 있습니다. 기록 보기 또는 상태 보기로는 유지 관리가 시작되지 않습니다. 확인 또는 취소 home 및 운영 ID 범위에 대해; 다른 home 작업이나 인증은 공유되지 않습니다. 검증할 수 없는 작업을 기다리는 것은 오랫동안 일시 중지될 수 있으며 원래 클라이언트에서 취소하거나 검증해야 합니다. 토종의 API 원자화 없음“유휴 상태일 때만 정상적으로 종료”인터페이스에서 최종 확인 후 원본 클라이언트의 새로운 작업은 기본 드레이닝 규칙에 따라 처리되므로 종료 시 새 작업은 계속 피해야 합니다. 실제 검증의 업스트림은 루프백 장치입니다.；Linux 네이티브、Windows 그리고 원격 끝은 이 실제 실험에 포함되지 않습니다. 이 지점은 계정 또는 에이전트 변경에 대한 트리거 규칙을 변경하지 않으며 강제 종료를 제공하지도 않습니다.。
