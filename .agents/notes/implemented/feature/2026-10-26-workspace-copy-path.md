# Agent Note: 작업공간 메뉴 복사 대상 절대 경로

Status: implemented

## 문제

디렉터리 목록에는 상대 경로만 전달되며 브라우저는 이를 안정적으로 결정할 수 없습니다. SSH、WSL 및 Windows 대상의 절대 경로 형식。

## 결정

기존의 info 작업은 대상에서 수행됩니다. Workspace 경계 확인 후 복귀 absolutePath；파일과 디렉터리는 동일한 링크 없는 액세스 규칙을 따릅니다. 메뉴 클릭 재사용 BridgeClipboard 비동기식 사용자 제스처、HTTP 복사 및 수동 복사 저하를 선택합니다. 다운로드 링크와 해당 동작은 원래 구현으로 유지됩니다. 반환된 절대 경로는 기준이 제거된 프레젠테이션 레이어에만 있습니다. Windows 확장 접두사：`\\?\D:\...` 다음과 같이 표시됩니다. `D:\...`，`\\?\UNC\server\share` 정상적으로 표시 UNC；평범한 UNC 장치 경로는 그대로 유지됩니다. 낮은 수준의 유효성 검사, 열기 및 링크 확인은 계속해서 기본 표준 경로를 사용하며 표시 문자열을 파일 액세스에 다시 전달하지 않습니다. 게시된 모바일 App 알려진 복사 버튼을 통해 이전 `message-copy` 이 마크는 기존의 신뢰할 수 있는 클릭 브리지를 재사용하고 실제 확인 후 성공 프롬프트를 표시합니다.。

## 기존 메모 감사

활성 파일 미리보기 및 소스 코드 메모를 검색합니다. 소스 코드 표시 결정은 부분적으로만 관련되며 경로 복사 계약은 없습니다. 독립적인 목적을 유지。

## 대안

- 브라우저 접합 cwd：요청이 필요하지 않지만 게이트웨이 운영 체제가 대상 시스템을 나타내지 않으며 경계를 재검증할 수 없습니다.。
- 새 경로 추가 API：책임은 분명하지만 존재 여부는 검증 대상 info 필수 메타데이터가 제공되며 라우팅 확장이 필요하지 않습니다.。

## 영향

대상 메타데이터는 복사하기 전에 한 번 읽혀집니다. 대상 파일이 사라지고 링크 또는 세션 전환이 실패하며 추측된 경로가 반환되지 않습니다. 타겟 실행 모듈은 네이티브를 독립적으로 계속 지원합니다.、SSH、WSL 및 기타 클라이언트 작업공간。
