# Agent Note: Android PC 및 채팅 옵션 메뉴

Status: implemented

## 문제

PR #95 개선하다 Android 오른쪽 상단“PC 및 채팅 옵션”그룹화, 색상 일치 및 터치 영역. 앞선 메인 라인을 기반으로 로컬로 구현한 통일된 테마와 세션 메뉴 단계별 복귀, 알림 소스 선택 등이 겹치며 직접적으로 다룬다. MainActivity 이러한 행동을 잃게 됩니다。

## 결정

저자 유지 heiqiu47 원래 커밋 `14f57269c55306d2cbd64a051afd20f847fb8214`，로컬 병합을 통해 통합。GatewayMenu 기본 플로팅 레이어 레이아웃, 색상 및 작업 프리젠테이션만 담당합니다. 여전히 원래 계정, 받은 편지함, 모양, 설정, 새로 고침 및 응용 프로그램 아이콘 입구를 호출합니다.。Lucide 아이콘 선언이 함께 제공됩니다. NOTICE 팩。

메뉴 우선순위 판독이 현재를 통과합니다. WebView、연결 주소 및 생성 확인을 위한 페이지 색상입니다. 읽기가 실패하거나 형식이 유효하지 않은 경우 현재 형식이 사용됩니다. App 주제 Context 색상. 테마 전환 시 이전 오버레이를 닫고 원본을 유지하세요. WebView、초안을 입력하고 양방향 주제 동기화를 수행하세요. 페이지 탐색, 창 구성 변경, 배경 전환 및 페이지 정리는 모두 플로팅 레이어를 닫습니다. 이전 비동기 콜백은 다시 열 수 없습니다.。

Return 키는 색상 일치 콜백을 기다리는 메뉴를 포함하여 기본 메뉴를 먼저 사용합니다. 기본 메뉴가 없을 때 취소 가능이 계속 사용됩니다. HTML `cancel` 이벤트, 세션 메뉴 단계별 복귀 및 채팅 복귀 경로, 복구 불가 PR 이전 버전에서는 직접 `dialog.close()` 논리. 알림 소스 기본 설정, 수신자, 권한, 백그라운드 서비스 및 계정 구성은 변경되지 않습니다.。

## 대안

- 시스템 유지 PopupMenu 자체 구성 요소의 코드를 줄일 수 있지만 이번에 허용되는 페이지 색상 일치 및 그룹 프레젠테이션을 충족할 수 없어 채택됩니다. PR 독립적인 구성 요소로 인해 책임이 제한됨。
- 직접 사용 Activity 기본 Context 구조는 가장 간단하지만 페이지 색상을 사용할 수 없는 경우 사용자의 명시적인 선택을 따른다는 것을 보장할 수 없습니다. App 테마, 기존 사용 `ui.context`。
- 표시된 메뉴의 리턴 키를 처리하는 것만으로 분기를 줄일 수 있지만 색상 일치 및 지연 표시 중에 메뉴가 계속 열려 있을 수 있으므로 표시되는 인스턴스도 이 리턴을 소비합니다.。

## 영향

기본 메뉴의 색상 매칭은 채팅 페이지를 따르며, 기존 대화 메뉴, 테마, 알림 채널 기능은 그대로 유지됩니다. 가격은 유지비 PopupWindow 디스플레이 타이밍 및 수명주기; 현재 색상 구문 분석은 전체 6자리 16진수 색상만 허용하며 다른 형식은 기본 테마 대체를 사용합니다. 이번에는 증가하지 않습니다. iOS 새로운 스타일에 대응하며, 기본 게이트웨이 포트를 조정하지 않으며, 게이트웨이 제품 코드를 수정하지 않습니다.。
