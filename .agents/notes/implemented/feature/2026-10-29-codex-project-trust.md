## 문제

사용자 보충 #100 다음을 가리킨다 Codex App 네이티브 프로젝트와 그 SSH 프로젝트가 아니라 CLI。쓰기 전용 `trust_level` 프로젝트 참가를 증명할 수 없습니다 App 목록; 기존 구현과 새로운 구현 SSH 디렉토리를 등록하려면 컴퓨터로 직접 돌아가야 합니다.。

## 결정

새로운 Codex App 프로젝트는 공유 신뢰 확인 상자를 재사용하여 대상 환경과 전체 경로를 표시합니다. 읽기 전용 요청은 신뢰를 쓰지 않습니다. 등록된 바인딩된 디렉터리 및 장치를 운반할 것인지 확인합니다./inode 및 SSH 별칭 요약. 실행될 때마다 대상 런타임을 통해 디렉터리 ID를 다시 확인합니다. `config/read` 사용자 레이어 버전을 다음으로 가져옵니다. `config/batchWrite` 표준 경로만 교체 `trust_level`，확인 내용을 다시 읽어보세요. 권한 모드를 수정하거나 다른 디렉터리를 대량으로 신뢰하지 않습니다.。

이 기계는 여전히 원본을 사용합니다. `codex://threads/new?path=...`，신뢰가 성공한 후 대기 App 프로젝트 목록 확인。SSH 설치 패키지의 검증된 버전을 사용하세요. `codex-app/config.json` 형식과 `codex://codex-app/apply-config` 입구, 하자 App 프로젝트를 직접 등록하세요. 직접 수정하지 마세요 `.codex-global-state.json`。재시도 설정을 유지하고 가져오기 전에 원래 구성을 확인하세요. 기타 호스트 선언, 등록되지 않은 항목, 변경할 이름, 현재 값을 확인할 수 없는 전역 SSH 시간 초과 또는 동시 수정으로 인해 가져오기가 거부되고 컴퓨터에 메시지가 표시됩니다. App 항목 추가。

등록 결과를 알 수 없는 경우 원래 요청은 유지되며 다시 열리거나 생성되지 않습니다. 등록 성공 후 기존 유지 SSH 빈 채팅 생성 방법; 일시적인 CLI 프로젝트 테이블과 App 의 SSH 프로젝트 테이블은 동일하지 않으며 동일한 프로젝트를 갖도록 요구할 수 없습니다. ID。신규 등록 후 스레드 생성 단계에 진입하면 자동이 아닌 재생 상태가 기록됩니다.。

SSH 목록을 보관하면서 읽은 내용 Codex App 검증된 디렉터리 분류 규칙: 명시적인 회원이 없는 경우 동일한 호스트에서 등록된 항목의 전체 경로와 채팅 cwd 정확히 일치합니다. 기본 프로젝트 메타데이터, 기존 멤버십, 명시적인 프로젝트 없음 상태, 확인된 퇴사 영수증이 우선적으로 적용됩니다. 기본 그룹화 규칙은 그대로 유지됩니다. 상위 디렉토리, 동일한 이름의 디렉토리, 케이스 또는 교차 호스트로 추측할 필요가 없으며 추가 항목이나 채팅 속성 기록이 작성되지 않습니다. 분류된 쓰기 및 이동 확인은 계속 사용됩니다. ## 대안

쓰기 전용 신뢰 구성은 규모가 작지만 기본 프로젝트 등록 증거가 부족합니다. 직접 변경 App 전역 상태는 프로젝트를 즉시 표시할 수 있지만 기본 병합, 브로드캐스트 및 동일 프로세스 상태를 우회하므로 사용되지 않습니다. 기존 원격 구성을 모두 다시 적용하는 것이 더 일반적이지만 다른 호스트에 연결하거나 전역 매개 변수를 수정할 수 있으므로 이번 라운드에서는 명확한 제한 사항을 유지하고 쓰기 범위를 확장하지 않습니다.。

확인만 `thread.projectId` 또는 명시적인 멤버 테이블은 쉽게 다시 읽을 수 있지만 누락되었습니다. App 늙은이에게 SSH Chat의 기본 디렉터리 분류입니다. 런타임 프로젝트를 별도로 가져오면 두 번째 프로젝트 레코드 세트가 생성됩니다. 따라서 동일한 호스트와 등록된 전체 경로의 검증된 일치가 사용되며 기본 쓰기 작업은 추가되지 않습니다.。
