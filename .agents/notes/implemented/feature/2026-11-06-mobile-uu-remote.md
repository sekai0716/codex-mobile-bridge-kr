# Agent Note: 휴대폰을 컴퓨터에 바인딩 UU 원격

Status: implemented

## 문제

휴대폰 사용자는 채팅을 볼 때 PIP를 켜거나 현재 컴퓨터의 원격 제어를 완료해야 합니다. 컴퓨터에는 여러 개가 있을 수 있습니다. Agent、독립적인 구성 및 연결 주소, 세션당 또는 URL 바인딩을 저장하면 인증이 반복되며 컴퓨터를 전환할 때 잘못된 장치를 사용할 수도 있습니다.。

## 결정

모두 Agent 동일한 휴대폰의 ”모양 및 디스플레이” 스위치와 동일한 오른쪽 상단 메뉴를 사용하세요. 스위치는 컴퓨터 기본적으로 꺼져 있습니다. 공유 모바일 스크립트는 메뉴 및 설정 표시를 결정합니다.。iOS、Android 쉘은 로컬 시스템 설정, 장치 선택 콜백 및 시스템 호출을 담당합니다. 웹 페이지는 기능, 스위치, 바인딩 여부 등의 표시 상태만 읽고 원격 제어 브리징 명령을 시작하지 않습니다. 열려 있는 UU 기본 메뉴에서 명시적인 클릭만 발생。

플랫폼 정보는 인증된 게이트웨이 응답을 재사용합니다. Windows 및 macOS 제어되는 컴퓨터는 제어를 가능하게 합니다. 휴대폰 모양 설정은 항상 완전한 원격 제어 모듈을 유지하며 신원이 확인되지 않았고 지원되지 않으며 요청 실패가 별도로 표시됩니다. 8초 동안 기다린 후 대기 프롬프트를 종료하고“다시 확인하다”，알 수 없는 모듈을 지원되지 않는 모듈로 취급하지 말고 모듈을 숨기세요. 설정 대화 상자보다 나중에 삽입되면 스크립트가 즉시 렌더링되고 후속 상태가 제자리에 새로 고쳐집니다. 다시 확인하면 기존 연결 확인만 재사용되고 원격 제어는 시작되지 않습니다. 활성화, 바인딩 해제 및 원격 제어 메뉴에는 현재 컴퓨터 ID, 기본 컨텍스트 및 원래 사용자 작업에 대한 확인이 계속 필요합니다. 컴퓨터를 전환하면 디스플레이 준비 상태가 지워지고 이전 컴퓨터의 권한이 상속되지 않습니다. 동일한 게이트웨이 컴퓨터 바인딩 및 사용 ID（인증자: cookie 이름 계산）, 주소 포함、Agent 채팅과는 아무 관련이 없습니다. 휴대폰에 로컬로 저장 UU 선택기가 반환한 장치 ID입니다. 사용자는 UU 이 컴퓨터를 선택할 때 프로토콜은 게이트웨이 주소에서 파생을 제공하지 않습니다. UU 장치 경로. 컴퓨터를 제거하거나 로그아웃하면 해당 바인딩이 지워집니다. 일반 브라우저는 이러한 설정을 삽입하지 않습니다.。

양쪽 끝 모두 설치 패키지의 ID에 해당하는 콜백을 사용합니다. scheme。바인딩 및 작은 창 요청은 일회성 임의 값을 전달하고 대상 컴퓨터, 작동 및 만료 시간을 기록합니다. 일치 후 요청을 소비합니다. 지연되거나, 반복되거나, 제거되거나, 다른 컴퓨터로 전환된 콜백은 바인딩을 재정의할 수 없습니다. 첫 번째 바인딩이 성공한 후 사용자는 원하는 모드를 클릭하여 리바운드 또는 콜드 스타트 ​​중에 원격 제어가 자동으로 시작되지 않도록 합니다. 작은 창 성공 UU 영수증이 우선하며 전체 화면은 다음 사용자에게만 제공됩니다. UU，따르다[NetEase 크로스 App 규약](https://github.com/netease-uuyc/uuremote-integration-guide)및 [Issue #113](https://github.com/try2love/codex-mobile-bridge/issues/113)。

Android 오직 `com.netease.uuremote` 사용자의 클릭으로 생성된 링크를 보냅니다. 공식 패키지 선언을 통한 매니페스트 쿼리 가시성, 버전이 알려져 있으며 그 이하 4.42 업그레이드하라는 메시지가 표시되는 경우에만. 버전을 쿼리할 수 없거나 버전 이름 형식을 알 수 없는 경우에도 시작이 시도됩니다. 실제 시작 시 누락된 항목이나 시스템 거부가 보고되면 대기 중인 콜백이 각각 지워지고 메시지가 표시됩니다.。[Android 패키지 가시성 문서](https://developer.android.com/training/package-visibility/use-cases)가시성 쿼리는 다른 애플리케이션 실행과 다른 작업임을 설명합니다.。

## 대안

채팅 내 미리보기는 게이트웨이 캡처 화면에서 제어할 수 있지만 새로운 권한, 미디어 채널 및 지속적인 리소스 오버헤드가 필요합니다. 상속 UU 시스템에 설치된 PIP（Picture-in-Picture）, 비디오 및 제어 UU 책임이 있는. 리모콘을 각각 놓으세요. Agent 단일 세션 컨텍스트는 채팅 메뉴 내에서 사용할 수 있지만 컴퓨터 바인딩은 반복적으로 생성됩니다. 따라서 출입구는 휴대폰으로 접속하는 컴퓨터에 속합니다.。

## 검증

지연된 디스플레이 수정 사항은 프로덕션 공유 스크립트의 제어 가능한 타이밍 픽스처에서 먼저 재현됩니다.“알 수 없는 신원이 숨겨져 있습니다.”및“먼저 대화 상자를 연 다음 렌더링하지 않고 주입합니다.”，수정 후에는 알 수 없음, 준비됨, 시간 초과, 명확하게 지원되지 않음, 상태 실패, 늦은 주입 및 신뢰할 수 없는 작업이 포함됩니다. 모듈이 표시된다고 해서 원격 제어 권한이 부여되었음을 의미하는 것은 아닙니다. 실제 장치의 모바일 네이티브 빌드 및 콜드 부팅 디스플레이는 이 배치의 최종 제품과 함께 검증되어야 합니다.。

NetEase 공식 웹사이트에서 배포 Android 4.46.0 위의 패키지 이름을 선언하고 외부에서 열 수 있습니다. `uuremote://external` 입구. 격리 설비 작동 build 49 현실의 `open` 코드는 시작이 허용되지만 사전 쿼리가 비어 있는 상태를 반환하고 시작이 0으로 기록되는 조건에서 업그레이드 잘못된 경보를 재현합니다. 수정 후 동일한 조건에서 버전을 읽을 수 없거나 접두사가 있는 경우 공식 패키지 출시가 시작됩니다. 고정 장치는 알려진 이전 버전, 바인딩도 포함합니다./작은 창문/전체 화면, 항목을 찾을 수 없으며 시스템에서 시작을 거부합니다. 보고 장치의 패키지 관리자 반환 값을 가져오지 못했습니다. 실제 장치의 실제 오류에 대한 시스템 이유와 수정된 바인딩은 여전히 ​​재테스트가 필요합니다.。

공유 설정을 위한 브라우저 고정 장치는 실제 클릭, 기본 닫기, 부족한 작은 창 기능, 플랫폼 숨기기, 번들 해제 및 초안 보존을 포함합니다.。Swift 프로토콜 고정 장치는 격리 기본 설정을 사용하여 바인딩, 특수 문자를 사용한 장치 식별, 콜백 없는 전체 화면, 작은 창 확인, 중복 및 컴퓨터 간 콜백, 제거 후 지연 결과를 확인합니다.。Android 평범한 APK 및 iOS arm64 실제 머신 타겟은 현재 소스 코드에서 컴파일되며 완제품 리소스는 작업 공간과 일치합니다.。Android 패키지 서명 및 기존 Test 같은。iOS 생성됨 unsigned IPA，기존 개발 설명 파일은 이전에 승인된 내용을 다루지 않습니다. iPhone，이 장치에 설치할 서명된 패키지가 생성되지 않았습니다. 현실 UU 계정 선택, 시스템 PIP（picture-in-picture）, 전체 화면 제어 및 모바일 네트워크 전환에는 여전히 물리적 승인이 필요합니다.。

## 영향

게이트웨이 업그레이드가 필요하지 않습니다. 사용하지 않는 휴대폰 UU 새로운 폴링 또는 원격 제어 세션이 없습니다. 독립적인 기본 적응은 양쪽 끝의 콜백 및 장치 권한 유지 관리 비용을 증가시킵니다. 장치가 오프라인 상태이므로 사용자가 다시 시도할 수 있습니다.，UU 반환된 장치가 만료되면 해당 컴퓨터에 대한 이전 바인딩만 지워집니다. 다음을 사용하여 활성 메모를 검색했습니다.[공유 클라이언트 셸](../architecture/2026-11-02-shared-client-shell.md)메뉴 업무에만 해당되며, 원래 결정을 유지합니다.。
