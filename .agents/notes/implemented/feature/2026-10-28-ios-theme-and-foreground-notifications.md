# Agent Note: iOS 글로벌 테마 및 독립적인 전경 알림 동기화

Status: implemented

## 문제

iOS 기본 페이지는 원래 시스템 동적 색상을 사용했고, 채팅 페이지는 테마를 독립적으로 저장했으며, 휴대폰 설정에 대한 통일된 테마 항목이 없었습니다. 사용자 요구사항 iPhone 이미 Android에서 사용할 수 있는 테마와 알림 환경을 경험해 보세요. 기존의 iOS 매번 프론트에서 알려주세요 20 저장된 컴퓨터의 초 단위 연속 확인, 한 컴퓨터의 느린 응답으로 인해 다른 컴퓨터의 알림이 지연됩니다.。

## 결정

iOS 이 기계를 사용하세요 `settingsTheme` 저장 `system/light/dark`，통해 UIWindow 의 `overrideUserInterfaceStyle` 컴퓨터 목록, 설정 및 기본 팝업을 통합합니다. 현재의 WKWebView 이미 생성된 Android를 재사용하세요. `BridgeNativeTheme` 및 `bridge-native-theme` 계약은 테마 선택과 실제 음영 상태만 동기화하며 글꼴, 강조 색상 또는 콘텐츠 표시 기본 설정은 다루지 않습니다. 기본적으로 시스템을 따르십시오. 기본 설정과 웹 페이지 모양을 모두 통합 선택으로 변경할 수 있습니다. 페이지를 새로 고치거나 교체하지 않고 페이지 로드 및 시스템 스타일 변경 시 재동기화 WebView。UIKit 의 trait 콜백은 하위 뷰 상태 이전에 전파될 수 있으며 어두운 상태와 밝은 상태의 읽기는 메인 큐의 다음 실행으로 연기됩니다. 기본 통합 검사에서는 창이 어두워지고 웹 페이지가 여전히 밝은 색상을 수신하며 읽기 지연 후 읽기가 통과되는 문제를 실제로 재현했습니다.。

웹 페이지에서 네이티브로 제한된 테마 이벤트가 양쪽에서 공유되도록 이동되었습니다. `mobile-ui.js`；Android 세션 스크립트가 더 이상 반복적으로 등록되지 않습니다.。iOS 기본 수신은 무작위로 유지됩니다. token、현재 WebView、메인 프레임, 소스 주소 및 현재 주소는 동일한 원점, 전경 상태 및 세 가지 열거 값 검증을 갖습니다.。

프런트에서 연락 5 저장된 모든 컴퓨터를 1초마다 개별적으로 확인합니다. 주소당 전송 중인 요청은 최대 1개입니다. 느린 요청은 다른 주소를 차단하지 않습니다. 원래 이벤트 커서 유지, 첫 번째 전경 기록 기준선, 받은 편지함 지우기, 로그인 Cookie 생성을 확인하고 요청합니다. 포그라운드를 떠나거나 연결을 전환하면 모든 기내 폴링이 취소됩니다. 늦은 콜백은 이전 로그인을 복원하거나 커서를 앞으로 이동할 수 없습니다.。Codex、Claude 및 DSH 동일한 휴대폰 이벤트 소스를 사용하여 알림은 기존 작업 상태만 읽습니다.。

실제 디바이스 네이티브 알림 테스트에서도 소스 첨부로 인한 생성 실패를 재현했습니다. 이전 구현에서는 첨부 파일을 반환한 후 즉시 임시 파일을 삭제했지만, iOS 파일은 알림이 제출된 경우에만 확인됩니다. 대신 원하는 것을 사용하세요. ## 대안

오직 의지하다 WKWebView 의 `prefers-color-scheme` 연결 코드는 줄일 수 있지만 휴대폰의 명시적인 테마와 웹 페이지의 저장된 선택 항목은 통합될 수 없습니다. 기존의 제한된 테마 계약이 사용됩니다. 재건 WebView 색상을 쉽게 다시 적용할 수 있지만 현재 채팅 및 초안이 중단되므로 기존 페이지를 고수하세요.。

APNs 시스템 백그라운드 푸시를 제공할 수 있으나 현재 개인 서명 및 게이트웨이 구성이 조건을 충족하지 않습니다. 연속적인 일반 폴링은 수행할 수 없습니다. iOS 일시 중지된 후에도 실행이 보장되므로 의사 백그라운드 스위치를 추가하거나 로컬 알림 테스트가 원격 푸시 연결과 동일하다고 주장할 필요가 없습니다.。
