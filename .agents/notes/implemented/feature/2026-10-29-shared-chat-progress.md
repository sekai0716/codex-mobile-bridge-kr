# Agent Note: 기본 작업 상태 프롬프트 공유

Status: implemented

## 문제

Claude 및 DSH 기록 인터페이스는 응답이 지속된 후에만 텍스트를 반환할 수 있습니다. 수신 확인 메시지가 사라진 후 채팅 텍스트에는 지속적인 작업 지침이 부족하여 생성 대기, 승인 대기, 연결 실패를 구분하기 어렵습니다. 후속 조치 Agent 액세스에도 동일한 동작이 필요합니다.。

## 결정

`web/features/chat/activity.js` 공유 제공 `renderChatProgress`。Codex 데스크톱 세션 페이지는 실행, 승인, 실패, 연결 및 데이터 최신 상태를 전달하지만 구성 요소는 클라이언트 이름별로 동작을 선택하지 않습니다. 승인은 실행보다 우선하며, 실행 중인 새 작업은 이전 실패 라운드보다 우선합니다. 읽기 실패 표시 상태를 일시적으로 사용할 수 없으며 유휴 상태에서는 작업 프롬프트가 숨겨집니다.。

공유 구성 요소는 기존 기본 증거만 제시하고 세션을 시작하지 않으며 전송 프로세스를 변경하지 않으며 알림을 생성하지 않습니다.。Codex 오프라인 기록 페이지에는 여전히 추가 작업 프롬프트가 표시되지 않습니다. 어댑터는 기본 상태를 계속 해석하며 인터페이스는 오류 텍스트를 통해 작업이 활성 상태인지 여부를 추측할 수 없습니다.。

## 대안

애니메이션을 따로 추가하는 것이 더 빠르지만, 상태 우선순위와 연결 끊김 처리가 중복되므로 기존 채팅 기능 디렉토리를 공유합니다. 최종 텍스트를 그대로 재생하면 스트리밍의 모습이 나오나 실시간 진행의 증거가 없으므로 사용하지 않습니다.。

기본 증분은 독립적인 후속 작업입니다. 검증됨 DSH 의 `agent/assistant-stream` 및 Claude CLI 일부 메시지 이벤트의 경우 증분 프로토콜이 아직 구현되지 않았습니다. 이 변경 사항은 축어적 출력 문제를 해결한다고 주장하지 않습니다.。

## 시험

`tests/desktop-sessions-ui.test.cjs` 실행, 승인, 연결 끊김, 실패, 완료, 채팅 전환 및 알 수 없는 내용을 다룹니다. Agent 이름。`tests/cli-access-ui.test.cjs` 실제 공유 구성 요소 검사 로드 Codex 역사와 복원 행위. 총 2번의 테스트 178 항목이 통과됨。

프런트엔드 반환 완료 1298 항목이 통과됨、1 항목을 건너뛰었습니다. 모듈 경계 및 90 이 메모의 구조 및 상대 링크 확인이 통과되었습니다. 브라우저와 실제 클라이언트 수용은 후속 통합 단계에 속합니다. 이 기록은 단위 테스트를 실제 기계 검증으로 취급하지 않습니다.。

Chrome/WebKit 넓고 좁은 레이아웃의 전송은 기본 상태 브라우저 테스트와 동일합니다. 12 항목이 통과되었습니다. 기존의 Mac Test 의 Code、Cowork、CLI true 목록 읽기 전용 확인 반환 idle，새로운 작업이 트리거되지 않았습니다. 실제 머신비전 승인의 실제 작동 및 완료는 아직 마무리되지 않았습니다. Test 가방。

## 영향

채팅 인터페이스는 작업 상태 규칙을 공유하며 요청이나 타이머를 추가하지 않습니다. 상태 업데이트는 여전히 레거시 폴링 및 네트워크 지연의 영향을 받습니다.。

활성 메모 검색：`SessionActivity`、작업상태, 증분, 작업상태 조회 iOS 프런트 엔드 알림 및 확인 아카이브 기록은 각각 알림 및 쓰기 작업을 제한하고 이 결정을 복제하지 않습니다. 원본 기록은 그대로 유지됩니다.。
