## 问题

원본 사이드 채팅은 원본과 함께 이루어져야 합니다. App 공유 런타임; 수동 초기화는 독립적인 것을 피할 수 있습니다. writer 충돌이 발생하지만 일반 신규 사용자가 구성 항목을 찾기 전에 오류를 경험할 수 있습니다.。Windows 게이트웨이 업데이트를 중지하면 어댑터 시작 경로도 변경됩니다. 이전 구성의 존재는 현재 연결 가능성과 동일하지 않습니다.。

## 결정

默认本机 macOS、Windows 的已启用 Codex Desktop 在网关启动时，由后台流程复用账号模块的准备事务。已核验的共享 owner 直接复用，不审计或重启；App 停止时先准备再启动；运行中但未共享时，仅在唯一进程、配置身份及实时桌面任务均通过核验后正常重启。忙、任务状态未知或其他事务占锁时每 60 秒重新检查，等待不占用账号操作门锁。纯 CLI、独立配置和 Linux 保持原路径。

트랜잭션을 준비하고 선택한 데스크톱 프로그램 경로를 작업 확인에 전달합니다.。IPC 존재하지 않고 콜드 스타트가 허용되는 경우 동일한 경로에 있는 실행 파일과 실시간 프로세스를 검증하는 것은 단독으로 의존할 수 없습니다. CLI 인접한 디렉토리는 데스크탑 프로그램을 재발견합니다.。Windows 완전한 CLI 다음에서 찾을 수 있습니다. F 디스크 독립적 설치，Store 데스크탑은 아직 남아있습니다 WindowsApps；두 위치가 다르다고 해서 데스크톱 작업 상태를 알 수 없다는 의미는 아닙니다. 길의 존재는 의미가 없다. App 퇴사, 준비 전후의 과정 검토 및 신원 검토는 여전히 통과해야 합니다.。

用户重新启用时使用[显式桌面启动](../bug-fix/2026-11-16-explicit-desktop-launch.md)，不以后台准备代替启动回执。

账户模块保留显式“重新准备连接”及未知任务状态下主动确认的恢复入口。准备成功前，创建持久侧聊不另起 writer；[临时侧聊](2026-11-12-temporary-side-chat-shared-ui.md)是用户明确选择的另一种生命周期，不作为静默降级。

모든 게이트웨이는 동일합니다. CODEX_HOME 의 initialization_lock 범위 내에서 읽기 `preparation.json`。처음 중지, 구성 저장 또는 시작 전에 작성됩니다. pending，공유 연결을 확인한 후 쓰기 complete；또한 새 게이트웨이 프로세스는 알 수 없는 결과가 있는 시작을 자동으로 재생할 수 없습니다. 추후 실제 공유가 확인된 경우 owner，그러면 기록이 완료될 수 있습니다. 액세스를 중지하거나 게이트웨이를 종료하면 백그라운드 준비가 취소됩니다. 대기 설정 및 종료 후, 시작하기 전에 다시 취소 여부를 확인하고, 시작된 거래는 검증 기록으로 보관됩니다.。

공유 기능이 지원되지 않는 경우 기존 공유 구성만 없으며 pending、엄격하게 확인 App 멈추고 쓰기 준비를 시작하지 말고 정상적인 작업만 허용하십시오. App 사이드 채팅 준비 실패 이유를 시작하고 계속 표시합니다. 이미 실행 중 App、구성 손상, ID 변경 및 알 수 없는 시작으로 인해 자동으로 성능이 저하되거나 반복적인 시작이 발생하지 않습니다.。

## 대안

수동 초기화를 계속하면 수명 주기 자동화가 줄어들지만 처음 사용할 때 문제 해결이 필요하지 않다는 요구 사항을 충족하지는 않습니다. 시동 중에 무조건 재시작하는 것이 가장 간단하지만, 게이트웨이 2개나 알 수 없는 수신으로 작업을 중단하고 반복적으로 재시작할 수 있으므로 사용하지 않습니다. 단일 게이트웨이의 데이터 디렉터리에 중복 방지 태그를 저장하는 것만으로는 공유를 제한할 수 없습니다. CODEX_HOME 의 다른 인스턴스는 공유 잠금과 동일한 디렉터리에 배치되어야 합니다.。

## 영향

일반적인 공유 시작에는 데스크톱을 다시 시작할 필요가 없습니다. 보안 조건이 충족되지 않을 경우 기존 채팅은 정상적으로 이용되며, 사이드 채팅 준비는 연기됩니다. 새로운 신원조사는 준비 중에만 실행됩니다. 실패한 쓰기는 재생을 위해 폴링되지 않습니다. 원본을 수정하지 않습니다 App 패키지, 계정, 모델 구성 또는 채팅 기록을 설치하고 백그라운드 서비스를 설치하지 않으며 강제 종료하지 마십시오. 원본을 다시 시작할 수 없습니다. App 특정 조건에서 기존 프로세스의 시동 환경을 변경하므로 작동 중 모든 상황이 즉시 준비된다는 보장은 없습니다.。
