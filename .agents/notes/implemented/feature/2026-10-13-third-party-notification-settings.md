# Agent Note: 휴대폰의 타사 알림 구성

Status: implemented

## 문제

원래 휴대폰은 구성만 가능했습니다. PushPlus，Bark 및 ntfy 컴퓨터로 돌아가야 합니다. 세 채널은 실제로 컴퓨터 게이트웨이의 알림 구성과 발신자를 공유하므로 휴대폰에 입구가 없으면 동일한 설정에 대해 서로 다른 작동 기능이 발생합니다.。

## 결정

모바일웹과 App ”제3자 고지”에 기재됨 Bark、ntfy、PushPlus，각 채널 세부정보는 자체 스위치, 서비스 주소, 주제 또는 키만 편집합니다. 일반 영역 편집자 `includeTitle`、`clickBase`、`securityEnabled`、`addressEnabled` 및 `addressName`；전체 세션 요청 및 완료 알림은 기존 설정에 따라 계속 제어되며 기본 모바일 알림 권한은 받은 편지함과 독립적으로 유지됩니다.。

HTTP 인증을 받은 CSRF 확인 후 통과 `/api/notifications/channels/{bark,ntfy,pushplus}` 및 `/api/notifications/channels/common` 쓰기 가능한 필드를 개별적으로 제한합니다. 그것은 재사용한다 `bridge/features/notifications/channels.py` 지속성, 체크섬 발신자, 키 읽기는 저장 여부만 반환합니다. 키를 비워두고 원래 구성을 사용하십시오. 교체하다 Bark 또는 ntfy 주소 제공 시 이전 키 지우기。`/test` 저장된 채널 구성만 전송되며, 사용자가 테스트 버튼을 누른 경우에만 전송됩니다. 오래된 `/api/notifications/pushplus` 노선은 계속 이용 가능。

일반 영역은 성공적으로 읽을 때까지 저장할 수 없습니다. 채널 세부 정보를 닫거나 다시 열거나 입력한 후에는 이전 읽기 결과가 현재 양식을 다시 채워서는 안 됩니다. 서비스 목록에는 구성되지 않았거나 닫혔거나 활성화되지 않았거나 읽기 실패가 표시되어 다음 단계를 쉽게 결정할 수 있습니다.。

게이트웨이의 저장되지 않은 휴대폰 받은 편지함과 채팅 제목 필드는 기본적으로 활성화되어 있으며 저장된 마감 값은 변경되지 않은 상태로 유지됩니다. 기본값과 시스템 카드 경계를 확인하세요.[휴대폰 알림은 이벤트별로 독립적으로 유지됩니다.](../bug-fix/2026-11-08-independent-mobile-notification-events.md)。

## 대안

모바일 측에서 또 다른 알림 구성을 유지 관리할 수 있지만 키와 스위치가 데스크톱 게이트웨이 상태와 충돌하게 됩니다. 바탕화면 설정 스냅샷을 직접 열 수도 있지만 휴대폰과 관계없는 게이트웨이 옵션이 더 많아 쓰기 가능 범위가 확장됐다. 기존 권한 경계에 더 가까워지도록 채널 및 공통 필드별로 제한을 분리합니다.。

## 영향

휴대폰과 컴퓨터에서 동일한 게이트웨이 구성을 수정합니다. 로그인된 모든 장치는 이러한 채널을 수정할 수 있습니다. 채널 테스트는 기존 외부 송신기를 사용하며 서비스가 요청을 수락했음을 확인하는 페이지가 전화기가 요청을 수신한 것과 동일하지 않습니다. 자동 포털 알림은 여전히 ​​게이트웨이 작업과 원래 포털 검색 논리에 의존합니다. 회귀 테스트는 반응형이며 로컬 모의 테스트로 제어됩니다. loopback HTTP，실제 제3자 알림이 전송되지 않음。
