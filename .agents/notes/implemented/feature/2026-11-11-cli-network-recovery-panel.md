# Agent Note: 로컬 머신 CLI 공유 패널을 이용한 네트워크 확인 및 복구

Status: implemented

## 문제

세션 메뉴는 원래 체크섬을 사용했습니다. `window.confirm` 로컬 출시 CLI 재개하여 최종 프롬프트만 표시합니다. 백엔드는 이미 유휴 상태, 취소, 강제 미리 보기 지우기 및 알 수 없는 연결 후 저장된 상태 연결에 대한 연결을 제공하지만 인터페이스는 현재 패널에서 이러한 실제 단계를 볼 수 없으며 강제 영향의 범위를 완전히 표시하지도 않습니다.。

## 결정

`SessionMenu` 같은 것을 사용하다 dialog 의 `cli-network` 하위 뷰에는 각각에 대한 검사 결과가 아닌 검사 결과가 표시됩니다. Agent 복사 복구 인터페이스。`app.js` 원래 세션 콜백은 기존 세션 콜백만 투명하게 전송합니다. `cli-network` 요청하고 열 때 바인딩 CSRF、ID, 클라이언트 및 현재 세션 나열 / 호스트 선택. 확인하면 채팅이 활성화되지 않습니다. 입구에는 본 기계와 등록된 기계만 보관되어 있습니다. Codex home，사용할 수 없음 SSH 계정 복구。

일반 복구에서는 백엔드를 계속 사용합니다. `confirmed + generation` 확인 및 자동 유휴 트랜잭션을 미리 봅니다. 대기 또는 복구 단계에서 패널이 표시되고 원래 ID가 여전히 유효한 경우 읽기 전용 확인은 5초마다 동일합니다. `operationId`；알 수 없는 결과는 지속되지 않고 자동으로 다시 시도됩니다. 사용자가 클릭한 후에만 제출 취소 `action=cancel`，그리고 취소가 성공적으로 접수되면 서버 측에 표시됩니다.。`status`、`cancel` 모두 원래 작업을 가리키며 복구가 다시 시작되지 않습니다.。

명시적으로 요청을 먼저 강제 실행 `forcePreview`，전체 디스플레이 백엔드 `scopeLabel`、알려진 세션 목록과 나열되지 않은 작업의 영향은 사용자가 확인합니다. 방금 받은 것을 제출하고 보관하세요. `generation` 및 `operationId`，null 값을 포함하고 새로운 값을 생성합니다. `requestId`；사용되지 않음 `force:true`，정상적인 복구가 불가능하거나 작업을 알 수 없기 때문에 자동으로 강제 실행되지 않습니다. 네이티브 프로세스의 미리보기가 실제로 표시되는지 확인할 수 없는 이유는 계속해서 돌아와서 다시 확인하세요.。

GET 뒤로 `action=reconnect` 신규 제출 시 독립적인 저장 상태 확인 제공 `requestId`，이전 공급자 설정이나 메시지는 재생되지 않습니다. 쓰기 전송 결과를 알 수 없는 경우 알 수 없는 프롬프트가 유지됩니다. 이 요청에 따라 강제 및 재연결을 수행할 수 있습니다. ID 확인; 정상적인 복구 작업이 수신되지 않았습니다. ID 다시 확인하여 백엔드 트랜잭션을 읽을 때. 모든 경로는 원본 쓰기를 자동으로 다시 보내지 않습니다.。

요청 중에는 현재 동작만 비활성화되며 항상 닫기 및 반환이 가능합니다. 닫기 또는 반환은 인터페이스 관찰만 중지하고 백그라운드 트랜잭션 취소를 선언하지 않습니다. 응답은 여전히 ​​원본에 속해야 합니다. dialog、하위 뷰, 컨텍스트 및 ID 세션 전환 후 지연 확인, 호스트, 클라이언트, 로그인 또는 목록 ID는 새 패널에 기록되지 않습니다. 제출된 백그라운드 복구는 여전히 원래 트랜잭션의 실제 상태를 유지합니다.。

## 대안

팝업창을 유지하고 최소한의 변경으로 몇 가지 프롬프트를 추가하지만 계속 보기, 대기 취소 또는 알 수 없는 결과를 구체적으로 확인할 수 있는 방법은 아직 없습니다. 네트워크 복구를 위한 새로운 관리 세트 생성 dialog 독립적으로 배치할 수 있지만 세션 ID, 복귀 및 모바일 메뉴 동작을 복사하므로 공유를 재사용할 수 있습니다. `SessionMenu`。일반 복구를 사용할 수 없는 것을 강제 진입 비활성화 조건으로 처리하면 버튼 수를 줄일 수 있지만 백엔드에서 사용자가 명시적으로 처리할 수 있도록 허용하는 알 수 없는 작업은 차단됩니다. 강제 기능은 항상 새로 획득한 백엔드 ID 미리 보기에 따라 결정됩니다.。

## 검증

`tests/cli-network-ui.test.cjs` 유휴 및 취소, 전체 범위의 명시적 적용 및 새 요청을 포괄하는 프로덕션 메뉴 핸들러 실행 ID、상태를 저장하고 다시 연결하면 전송이 알 수 없고 확인만 됩니다. 실패 및 취소는 의사 성공이 아니며 ID가 유효하지 않으며 요청이 종료됩니다. / 반환 및 지연 쓰기 영수증 격리。`tests/session-management-ui.test.cjs` 실제 실행 `sessionMenuContext` 콜백, 머신 확인 / 독립적인 home URL 및 정확한 필드, 제외 SSH、CSRF / 신원을 나열하다 / 대화 / 주인 / 클라이언트 변경 사항에 대한 쓰기 전 및 읽기 후 보호. 처음 두 파일 25 항목이 통과되었습니다. 실제 백엔드 전용 반환을 보완하기 위한 검토 `connected: true/false` 즉각적인 결과는 증분 회귀가 통과되었음을 보여줍니다. 확인되지 않은 연결은 복원된 것으로 표시되지 않습니다.。

메뉴 변경 사항 공유, 다른 기본 버전 실행, 복사 및 호환 가능 11 입국: 직접 통과 9명, 격리 2명 VM 표준 브라우저가 누락된 고정 장치 `clearTimeout`；픽스처를 완료한 후 기본 복사 프로토콜을 변경하지 않고 이 두 항목만 다시 확인하여 통과하세요.。

실제 macOS Ego Chromium 390 / 1280 px、중국어, 영어 4개 그룹 각각 31 실제 클라이언트나 모델을 조작하지 않고 생산 메뉴와 합성 프로토콜 영수증을 사용하여 항목을 전달합니다. 대기, 취소, 범위 표시, 명확한 확인, 알 수 없는 저장 상태, 닫기 및 반환 연결 가능성, 지연된 수신 및 패널 다시 열림 없음을 다룹니다. 육안 검사 결과 영문 강제 버튼이 너무 길고 danger 메인버튼의 텍스트와 배경의 대비가 부족하여 기존 흰색 메인버튼과 짧은 동작 단어만 수정하였습니다. 고정된 리소스를 다시 시작한 후 검토만 수행 320 / 390 / 1280 px 영문 확인 버튼, 버튼 안에 텍스트가 들어가고, 흰색 텍스트가 선명한 색상입니다. 대기 패널과 320 px 최종 필수 확인 스크린샷을 육안으로 검사했습니다. 네이티브 강제 종료 / 재연결 기능은 기존 백엔드 수용을 상속합니다. 이 점은 프로토콜 고정 장치나 브라우저 검사가 설치된 것으로 간주하지 않습니다. CLI 실행, 형식 App 또는 고정 세션 수락。

## 영향

사용자는 현재 패널에서 실제 복구 단계를 보고, 대기를 취소하거나, 닫기 및 반환을 유지하면서 강제 범위를 명시적으로 확인할 수 있습니다. 새 인터페이스는 자동 유휴 및 프로세스 확인을 변경하지 않습니다.、home 신원 및 알 수 없는 작업에는 재생 규칙이 없습니다.；CLI 릴리스 그룹화, 기록 관리 및 검색은 이 항목의 범위를 벗어납니다. 닫은 후에는 확인 결과를 다시 열어야 합니다. 인터페이스는 백그라운드에서 자동으로 업그레이드되지 않습니다.。
