# Agent Note: 연결된 휴대폰이 먼저 LAN으로 돌아옵니다.

Status: implemented

## 문제

고정식 및 임시식 HTTPS 왕복 시간은 변동될 수 있으며 정렬로 인해 공용 네트워크 간에 회선 변경이 발생해서는 안 됩니다. 하지만 지역망으로 복귀한 후에도 계속해서 공용망을 사용하게 되면 불필요한 우회가 발생하게 됩니다. 원래의[게이트웨이 바인딩 및 라우팅 설계](../architecture/2026-11-02-mobile-gateway-channels.md)채팅을 다시 작성하지 않고도 이미 줄을 변경할 수 있습니다. 이번에는 선택 조건이 변경되어 원래의 인증, 알림, 타임아웃, 쓰기 수신이 사용됩니다.。

## 결정

컴퓨터에 들어가서 성공적으로 확인된 첫 번째 활성화된 주소를 가져옵니다. 활성 채팅의 자동 모드에서는 로컬 네트워크를 사용할 수 있을 때 성공적인 확인을 통해 공용 네트워크에서 LAN으로 전환할 수 있습니다. LAN에 장애가 발생한 후에는 사용 가능한 공용 네트워크로 돌아갈 수 있습니다. 공용 네트워크에 장애가 발생하고 사용 가능한 LAN이 없으면 수동으로 선택하라는 메시지가 표시됩니다. 다른 공용 네트워크 회선으로 자동으로 점프하지 않습니다. 수동 모드는 항상 사용자가 선택합니다. 새로 고침 지연은 활성화된 주소가 있는 샘플만 업데이트하며 라우팅을 트리거할 수 없습니다. 주소, 값 및 확인 표시는 서로 대체되지 않습니다. 보다 낮음 100 ms 녹색을 사용하다，300 ms 오렌지로 시작하세요，1000 ms 빨간색을 활성화합니다. 샘플이 없거나 도달할 수 없으면 잘못된 시간 소비가 표시되지 않습니다.。

공통 페이지 스크립트는 현재 채널, 네트워크 유형 및 활성화된 주소를 기반으로 후보를 선택합니다. 네이티브 레이어는 감지하기 전에 바인딩 목록을 확인합니다. 활성 세션 속도 테스트는 포그라운드에서만 수행하고, 네트워크 변경 사항이 수신되면 즉시 확인하세요. 안정되면 LAN 시도 간격 90 두번째. 성공적인 인증이 이루어졌습니다. API 트래픽은 예약된 상태 확인을 건너뛸 수 있으며 오래된 연결 해제 표시도 지워집니다. 신원인 척하고 성공적으로 도전할 수 없으며, 새로운 주소를 승인할 수도 없습니다. 공개 로그인/인증 쿼리 및 오류 응답은 성공적인 트래픽에 포함되지 않으며, 늦은 프로브 실패가 실제 이후 성공을 재정의하지도 않습니다. 바인딩 복구 및 상태 경계에 대한 자세한 내용은 다음을 참조하세요.[게이트웨이 바인딩 및 라우팅 설계](../architecture/2026-11-02-mobile-gateway-channels.md)。각 바인딩의 인벤토리 동기화 간격은 최소한 90 초, 내용은 동일하며 다시 작성되지 않습니다. 수동 속도 측정은 목록 업데이트 간격에 의해 제한되지 않습니다. 두 개의 실패한 승인, 백오프 및 알림 긴 폴링 유지。

정기 알림 검사의 목록, 세부 정보, 결과 및 탐지는 디버그 로그에만 입력됩니다. 검사 로그를 작성하기 위해 더 이상 알림 커서를 반복적으로 읽지 않습니다. 느린 스캔, 배달 결과, 요청 실패 및 전송 영수증 연결을 최대 2초 동안 유지합니다. 일반 정적 리소스 요청은 연결을 유지합니다. ID，기본적으로 홉별 레코드는 기록되지 않습니다.。

## 대안

반송을 방지하려면 항상 건강한 주소를 유지하세요. 하지만 집에 돌아오면 여전히 공용 네트워크에 연결되어 있습니다. 그러면 각 라운드에서 모든 주소가 테스트되고 가장 빠른 주소가 선택되어 고정 도메인 이름과 임시 도메인 이름 간에 반복적으로 전환됩니다. 지역 네트워크 변화에 따라 한 번 시도하고, 실패 시 제한된 빈도로 검토합니다. 추후 복구될 근거리통신망을 찾을 수 있으며, 모든 공중망 입구를 계속해서 탐지할 필요가 없습니다.。

## 검증

공유 라우팅 사용 사례는 사이드 홉 및 자동 폴백 없이 공용 네트워크 오류를 다룹니다. LAN、수동 모드, 비활성화됨 LAN 활성 트래픽으로 요청을 줄입니다. 좁은 화면 WebKit 실제 클릭 새로 고침, 오른쪽 정렬 확인, 새로 고침 중 비활성화, 비닝 업데이트 및 전환 명령 실행 안 됨。iOS 18.2 시뮬레이터 전용 Test 묶인, 진짜 HTTPS 및 LAN，공용 네트워크 감지 삽입 실패 및 로컬 네트워크 변경: 다른 공용 네트워크가 선택되지 않았으며 복구 후 통과되었습니다. LAN 인증 응답을 읽었으며 동일함 WKWebView、입력 상자 및 타임라인. 시도의 일부가 고정 장치에 포함되지 않았습니다. 16 초 창 내에 핸드오버가 완료될 때까지 기다리면 고정된 핸드오버 지연이 추론되지 않습니다. 모델이 호출되지 않았고 승인 바인딩이 로그아웃되었습니다.。

## 영향

짓다 45 의 iOS 및 Android 쉘은 위의 규칙을 재사용하고 게이트웨이는 Test 해당 스타일을 제공합니다. 이번 라운드에는 실제로 테스트된 운영자 네트워크가 없습니다.、Android 실제 기계 핸드오버 또는 전체 기계 전력 소비; 네트워크 요청 및 로그의 감소는 배터리 수명 비율로 추정할 수 없습니다.。
