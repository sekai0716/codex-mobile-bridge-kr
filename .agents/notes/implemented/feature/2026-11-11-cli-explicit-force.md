# Agent Note: 명시적으로 강제 종료가 확인되었습니다. CLI 제공하다

Status: implemented

## 문제

일반 복원 및 릴리스는 구성된 작업이 안전하게 완료될 때까지 기다립니다. 기본 작업 상태를 읽을 수 없거나 종료 확인을 알 수 없거나 작업이 대기 중인 경우 사용자는 구성의 원래 프로세스를 명시적으로 중단할 수 있어야 합니다. 강제를 기본 재시도로 사용하거나 구독 취소를 기록기 종료로 사용하면 잘못된 결과가 발생합니다.。

## 결정

원래 복구 및 릴리스는 여전히 각각의 안전한 입구를 통과합니다. 현재 등록된 로컬 시스템을 먼저 미리 볼 수 있도록 명시적으로 강제합니다. CLI 호스트와 CODEX_HOME，저장된 원래 세션 ID 읽기（기본） PID 생성을 기록 및 처리하고, 영향을 받은 것으로 알려진 연결과 대기 중인 세션을 나열하고, 전체 공유 서비스에 나열되지 못한 작업이 포함되어 있음을 나타냅니다. 미리보기는 기본 작업 목록을 건드리지 않으며 세션을 중단하거나 시작하지 않습니다. 확인되지 않은 호스트, 디렉터리, 세션 소스, 프로세스 생성 또는 권한은 계속 거부됩니다. 현재 필수 용량 제한은 프로세스의 로컬 시스템에서 직접 확인할 수 있습니다. Codex CLI 설정。

새 요청을 사용하여 확인 ID 요약을 미리 볼 수 있습니다. 요약 바인딩 호스트、home、생성, 원래 구성, 대상 세션, 알려진 영향 및 기존 유지 관리 상태. 다중화 수행 home 유지보수 잠금; 종료를 실행하기 전에 원래 프로세스 핸들이 여전히 유효한 경우 영수증을 다시 확인하고 기록합니다.。macOS 통해 audit token 생성 확인，Linux 사용 pidfd，Windows 종료 권한이 있는 원래 프로세스 핸들을 사용하십시오. 정상적인 길에서는 강요된 타협이 없다。

기다리거나 이전 결과를 알 수 없는 경우 새로운 명시적 확인을 통해 업그레이드할 수 있습니다. 원래의 알려지지 않은 사업 및 유지 관리 영수증은 유지되며 반복적으로 실행되지 않습니다. 원래 구성이 동일한 이전 대기열은 취소된 것으로 표시될 수 있으며 원본 텍스트는 유지됩니다. 동일한 요청 ID 기존 영수증만 확인할 수 있으며 종료, 시작 또는 메시지가 다시 발행되지 않습니다. 릴리스는 원래 프로세스가 실제로 종료된 후에만 기록됩니다. 오래된 socket 아직 사용 중인 경우에는 확인된 이전 경로와 종료된 기본 프로세스만 허용됩니다. 기본 시작 프로세스는 이전 끝점을 처리하고 파일 자체를 제거하지 않습니다. 강제 복구는 여전히 검증된 것과 동일한 구성 환경을 사용하고 원본을 계속 사용하는 것이 분명합니다. ID/cwd 네이티브로 provider admission 지배. 원래 연결 결과를 알 수 없거나 새 구성 및 인증 소스를 확인할 수 없는 경우 원래 작성자가 종료되었다는 것만 확인할 수 있으며 원래 연결을 다시 구축하거나 재생할 수는 없습니다.。

원래 연결의 알 수 없는 제약 조건은 현재 유지 관리 기록에 남아 있으며 강제 종료 또는 해제 후 자동 전송으로 우회되지 않습니다. 이전 세대의 종료를 확인한 후 원래 검사 입구는 현재 저장된 상태에서 다시 연결하는 옵션을 제공할 수 있으며, 그런 다음 사용자는 새로운 요청을 사용할 수 있습니다. ID 현재 구성 및 생성、ID/cwd/provider 요약이 확인되었습니다. 새로운 연결은 오래되지 않습니다 provider override、메시지가 전송되지 않습니다. 이전 연결의 결과는 아직 알려지지 않았습니다. 새 연결 수신을 다시 알 수 없는 경우 새 프로세스 생성이 유지되며 자동으로 재시도할 수 없습니다. 생성은 여전히 ​​명시적으로 중단되고 나중에 다시 확인될 수 있습니다. 이 새로운 의도는 원래 복구 및 일반 연결 경로를 재사용하고 새 대기열을 추가하지 않습니다.。

## 대안

네이티브 `daemon restart` 기한은 기본 대기를 강제 종료 가능성으로 전환하며 사용자와 정확한 바인딩 생성을 확인할 수 없습니다. ～에 따르면 PID 프로세스의 직접적인 문자열 종료를 방지할 수 없습니다. PID 재사용. 이전 원장을 지운 다음 다시 보내면 알 수 없는 비즈니스가 실행되지 않은 것으로 착각하게 됩니다. 이 구현은 증거를 유지하고 새로운 중단 의도를 구별합니다.。

알 수 없는 지속의 상태 기계 회귀에는 강제 성공 후에도 여전히 차단된 일반 복구가 포함되며, 확인 없이 이전 세대가 종료될 때 재연결이 제공되지 않으며, 새 확인이 지워진 후 연결이 복원되고, 이전 결과가 유지되며, 반복된 새 확인이 다시 시작되거나 계속되지 않습니다. 강제 해제 이후의 일반적인 계속도 이 제약 조건을 유지합니다. 대신 실제를 사용하세요 `CliSessions`、비재진입 시작 잠금 및 연결 실패 분기, 재연결 제한 반환을 알 수 없음, 두 번째 시작 없음을 확인합니다. 연결은 시작 잠금을 유지하지 않으며 계정은 계속 유지됩니다/home 파견 전후에 경계를 유지하고 새로운 의도, 구성 및 세대를 확인합니다. 디스패치 확인 콜백을 통한 제어된 연결은 기존 서비스에만 연결할 수 있으며, 프록시 연결 실패는 더 이상 정상적인 콜드 스타트를 트리거하지 않습니다.。

## 영향

사용자에게는 확인된 공유를 종료하는 명확한 방법이 있습니다. CLI 작업을 읽을 수 없는 경우에도 서비스를 제공합니다. 새로운 서비스가 연결되면 보고서가 복원된다는 것을 증명할 수 있습니다. 원래 프로세스가 종료되었거나 새로운 시작과 연결을 아직 알 수 없다는 것만 증명할 수 있으며 실제 결과가 각각 표시됩니다. 범위 선택 및 모든 릴리스를 통해[공유 구성 릴리스](2026-11-11-cli-scope-writer-release.md)입장; 인터페이스는 동일한 백엔드 계약을 재사용합니다.。
