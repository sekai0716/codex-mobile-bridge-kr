# 도구의 자동 검토와 실행 결과 표시

## 원본 기준과 연결

설치된 공식 데스크톱 앱 26.1111.21308의 자동 검토 변환과 상태 표시를 읽고, `targetItemId`를 기준으로 도구와 검토를 연결하는 방식을 참고했다.
원본 코드를 복사하거나 원본 앱을 변경하지 않는다.

같은 turn 안에 고유한 대상 ID가 있는 명령 실행·파일 변경·MCP·동적 도구에만 검토를 연결한다.
제목·명령문·출력으로 대상을 추측하지 않는다. 중복 ID, 다른 turn의 검토, 과거 기록 페이지 밖의 대상은 독립 검토 행으로 남긴다.
과거 기록을 불러와 대상을 찾으면 연결 상태가 갱신되며 중복 검토 행은 숨긴다.

## 표시와 상세

- `inProgress`: `도구ㆍ자동 검토 중`으로 표시한다.
- `approved`: 검토 상태 문구를 제거한다. 검토 통과를 실행 성공으로 간주하지 않는다.
- `denied`: `도구ㆍ거부됨`으로 표시하고 접힌 활동 묶음 밖에 남긴다.
- `aborted`, `timedOut`, 알 수 없는 상태: 중단·시간 초과·상태 확인 불가를 구분한다.
- 중단된 turn에 남은 진행 중 검토는 중단 상태로 표시한다.

실행 중·실패·중단은 도구 상태로 구분한다. 성공 표시는 종료 코드 0 또는 명시적인 `success: true`가 있을 때만 표시한다.
검토 상태가 있는 명령은 원문 첫 줄을 표시하며, 긴 명령이 말줄임되어도 상태 문구는 보이게 한다.
MCP 도구 이름과 원문 명령은 번역하지 않는다. UI 상태 문구는 한국어·영어·중국어 언어팩에 등록한다.

연결된 검토의 원문 이유와 위험도 등은 기존 상세 본문에 포함하고 기존 분할 조회 제한을 따른다.
첫 화면에는 간단한 상태만 보내며, 펼치기 전에는 상세 이유를 미리 요청하지 않는다.
검토·실행 결과만 바뀌어도 타임라인 버전이 갱신된다.

## 범위와 검증

검토 표시는 읽기 전용이다. 실제 승인 요청, 전송, 원본 owner/provider/auth/cwd, 인증·CSRF를 변경하지 않는다.
Python 모델·타임라인과 공통 웹 파일을 변경하므로 PC 게이트웨이와 웹 갱신이 필요하다. Android·iOS 네이티브 소스 변경이나 APK 재빌드는 필요하지 않다.

`test_tool_review_status.py`는 ID 연결, 모호한 대상, 상태 전환, 실행 결과 분리, 상세 페이징, 과거 기록 결합을 확인한다.
Node 회귀 검사는 상태 문구·성공 근거·원문 도구 이름·활동 묶음을 확인한다.
`runToolReviewStatusChecks`는 실제 웹 리소스를 쓰는 Chromium의 넓고 좁은 화면에서 지연 조회, 상태 갱신, 320px 말줄임, 세 언어 표시를 확인한다.
브라우저 픽스처 검증은 실제 Android WebView 조작 검증과 구분한다.
