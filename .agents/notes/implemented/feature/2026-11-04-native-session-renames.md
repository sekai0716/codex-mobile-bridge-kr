# Agent Note: 공유 이름 바꾸기는 기본 제목만 확인하고 더 이상 표시 별칭으로 대체되지 않습니다.

Status: implemented

## 문제

사용자 요구사항 Claude、DSH 및 ZCode 이름 변경은 호스트 시스템의 원래 세션과 동기화됩니다. 공유 관리자가 이전에 목록에 선언되지 않았습니다. `rename` 가능하다면 직접 작성하세요. Bridge 별칭 표시 및 성공 반환；ZCode 연속 목록은 세션 투영 외부의 능력 필드도 잃으므로 기본 경로도 별칭으로 지정됩니다. 실제 읽기 전용 검사에서는 동일한 독립적인 테스트 세션이 Bridge 사용자가 지정한 이름, 원본 표시 App 의 작업 인덱스는 여전히 원래 이름을 유지합니다.。

## 결정

`DesktopSessions._session_metadata` 기본 이름 바꾸기만 원래 어댑터를 통해 전달됩니다. 준비되지 않은 기능을 명시적으로 거부하고 로컬 별칭을 완료된 것으로 처리하지 않습니다. 이미 알 수 없는 요청이 있는 경우에도 읽기 전용으로 확인할 수 있습니다. 요청을 변경합니다. ID 알 수 없는 결과 보호는 우회할 수 없으며, 이전 수정이 성공한 것을 확인한 후에는 동일한 타이틀을 발송할 수 없습니다.。

공유됨 `RenameCommands` 파견 전 대상, 원본 신원 및 요청 저장 ID。발송 후 제목 및 신원에 대한 읽기 전용 확인; 기본 이벤트 또는 파일 쓰기가 여전히 수렴 중인 경우 반복 쓰기 없이 최대 2초의 짧은 다시 읽기 재시도가 허용됩니다. 이 창은 약한 네트워크 전송 시간 초과가 아니며, 실패가 안전하게 재전송될 수 있음을 의미하지도 않습니다. 신원 변경은 즉시 거부되며 확인되지 않은 쓰기는 알 수 없는 영수증과 함께 남아 있습니다.。

확인된 기본 기능이 있는 목록 항목은 신뢰할 수 있는 원래 이름을 표시하며 더 이상 이전 이름으로 대체되지 않습니다. Bridge 별칭 마스킹. 이전 별칭 데이터는 유지됩니다. 새로운 기본 이름 변경 사항을 다시 읽고 확인한 후에만 세션에 해당하는 별칭이 지워지고 일괄 마이그레이션이나 기록 별칭이 다시 기록되지 않습니다. 원본 프로젝트 및 파티션 Bridge 분류는 변경되지 않습니다.。

## 대안

계속 사용하다 Bridge 별칭은 기본 인터페이스 없이 콜드 세션을 처리할 수 있지만 이번 라운드에는 적합하지 않습니다.“호스트의 원래 세션을 수정해야 합니다.”결정. 로그나 데이터베이스를 직접 다시 작성하는 것은 간단해 보이지만 원래 클라이언트 작성자, 기본 알림 및 지속성 규칙을 우회하여 사용되지 않습니다. 설치 완료 Agent SDK 독립적인 세션 메타데이터 기능을 사용할 수 있지만 이 시스템에는 이러한 종속성이 없습니다. 현재 재사용은 이미 유지됩니다. CLI 이름 바꾸기를 위한 다른 실행기 세트나 파일 위치 지정 구현을 도입하지 않고도 공식적인 제어 흐름으로 충분합니다.。

DSH 고위급 `sessionController.rename` 콜드 세션을 처리할 수 있지만 문제를 해결하거나 복원합니다. Agent；예약하다“먼저 명시적으로 연결한 다음 이름을 변경하세요.”경계。ZCode 현재 프로젝션에 이름 바꾸기 명령을 직접 보내면 원래 세션을 수정할 수 있지만 작업 인덱스에 대한 정식 조정이 없으므로 원래 세션이 사용됩니다. App 사이드바에서도 사용되는 작업 서비스。

## 영향

이름과 영수증은 호스트 스토리지와 일치하며 실패는 더 이상 로컬 성공으로 위장되지 않습니다. 가격은 기본 기능이 아직 연결되거나 발표되지 않았다는 것입니다. CLI/DSH 세션 이름은 일시적으로 바꿀 수 없습니다. 기본 쓰기 결과를 알 수 없는 경우 확인을 위해 다시 읽어야 하며 반복적으로 제출할 수 없습니다. 기본 이름 바꾸기는 제목을 사용자가 선택한 것으로 표시할 수 있으며 후속 자동 이름 지정 동작은 원래 클라이언트에서 관리됩니다. 모델 호출, 계정 전환, 프로젝트 마이그레이션 또는 암시적으로 다른 세션 시작 없음。
