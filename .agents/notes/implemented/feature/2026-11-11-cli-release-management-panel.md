# Agent Note: 현재 Agent 신뢰할 수 있는 구성으로 관리 CLI 풀어 주다

Status: implemented

## 문제

연결 관리는 다른 것을 넣습니다 Agent、호스트는 구성된 연결 및 각 기록 수신과 함께 타일링됩니다. 중복된 영수증으로 인해 현재 연결이 폭증할 수 있으며, 이전에 알 수 없는 결과에 대한 읽기 전용 검사로 인해 최신 릴리스 상태가 거꾸로 보일 수도 있습니다. 사용자는 공유 서비스가 종료되기 전에 연결 또는 현재 구성된 모든 연결을 명시적으로 선택하고 실제 영향 범위를 확인해야 합니다.。

## 결정

공유 설정 및 세션 항목 `CliConnectionsPanel`，현재를 포착하다 Agent、독립형 인스턴스 및 인증된 ID. 지역별로 나열、SSH、WSL 기존의 신뢰할 수 있는 구성 필드에 따라 분류한 다음 그룹화합니다. 세션 입구는 원본으로 고정되어 있습니다. session/host。`scopeKey` / `scopeLabel` / `sharedHome` 공유된 기본 서비스 범위를 나타냅니다.，`configurationKey` / `configurationLabel` 신뢰할 수 있는 독점 프로세스 구성만 나타냅니다. 알 수 없는 구성은 연결별로 독립적으로 표시되며 볼 수 없습니다. location、경로나 성은 같은 범위에 있는 것으로 추정됩니다.。

각 연결은 마지막 제어 작업의 상태만 표시합니다. 백엔드 작업 원장의 삽입 순서를 순차적으로 사용하여 연결합니다. token 세대；`check` 관찰일 뿐 새로운 제어 조작이나 누르기가 되지 않습니다. updatedAt 종류. 이전 작업의 지연 확인은 새 제어 또는 새 연결을 포함할 수 없으며 확인 항목은 확인 보류 상태로 유지됩니다. 접거나 펼칠 때 기본적으로 내역 영수증이 생성되며 서버에서 반환한 이전 작업, 오류 및 알 수 없는 결과가 완전히 유지됩니다.。

공유됨 home 단일 릴리스와 모든 릴리스가 모두 먼저 호출됩니다. `scopePreview`。디스플레이 반품의 진위 여부를 확인하세요 scopeLabel、모두 impact writer，선택되지 않은 연결을 포함합니다. 원본 제출 확인 preview 특정한 keys 및 generation。일반 출시 및 사용 `scopeWait`，명시적으로 새로운 기능을 사용하도록 강제합니다. `scopeForce` 묻다 ID。백엔드만 canCancel 허용된 scopeWait 취소는 취소가 성공한 후에만 표시됩니다. 취소가 완료될 때까지 원래 상태가 유지됩니다. 새로운 명시적 힘은 독립적인 의도이며 이전의 알려지지 않은 작업은 재발행되지 않습니다.。
