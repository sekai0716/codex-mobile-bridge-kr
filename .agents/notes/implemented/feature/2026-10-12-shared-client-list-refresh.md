# Agent Note: Claude 및 DSH 목록의 수동 풀다운 새로 고침

Status: implemented

## 문제

Claude 및 DSH 자동 폴링만 있으므로 사용자는 다음과 같은 작업을 수행할 수 없습니다. Codex 드롭다운을 통해서도 목록이 업데이트되었는지 확인하세요. 원래 새로 고침 항목은 읽기 오류를 무시하므로 수동 새로 고침 성공의 기준으로 직접 사용할 수 없습니다.。

## 결정

Claude 및 DSH 공유할 것이다 `ListSync` 현실을 받아들이다 `.sessions` 컨테이너 스크롤, 상단 드롭다운 임계값 재사용, 수평 취소 및 로드, 성공 및 실패 재시도 프롬프트. 프롬프트는 독립적인 목록 영역에 있습니다. 콘텐츠를 당겨도 스크롤 영역의 높이는 변경되지 않습니다. 짧은 목록과 빈 목록도 터치 영역을 유지합니다.。

`DesktopSessionsView.refreshList()` 목록만 읽으며, 수동 새로 고침은 세션 세부 정보 읽기, 복구, 메시지 또는 승인을 트리거하지 않습니다. 자동 폴링 및 포그라운드 복구와 공유됩니다. `sharedRead` 현재 보기의 목록 처리 Promise；동일한 읽기 라운드에 대해 중복 요청이 추가되지 않습니다. 목록이 실패하면 수동 새로 고침에 오류가 전달되고 연결이 끊어진 응답에는 업데이트가 성공했음이 표시되지 않습니다. 원래 자동 폴링은 타이밍 및 전경 복구를 담당하며 데스크톱 클라이언트 `ListSync` 더 이상 다른 타이머 세트를 별도로 시작하지 않습니다.。

클라이언트 전환, 계정 읽기 무효화, 로그아웃 및 페이지 숨기기 재설정 동작 및 프롬프트; 개정 번호를 새로 고치면 이전 요청이 새 프롬프트를 수정하거나 새 요청의 사용 중 상태를 해제할 수 없게 됩니다. 기존의 generation、읽다 epoch 계속해서 데이터 결과를 제한합니다. 렌더링에서는 최신 검색 및 필터링을 사용하여 선택된 세션, 초안 및 보존할 수 있는 목록 위치를 유지합니다. 목록의 중간은 첫 번째로 표시되는 세션에 의해 우선순위가 지정되며 데이터가 삽입된 후에도 세션의 상대적 위치가 유지됩니다. 앵커 포인트가 사라지면 사용 가능한 스크롤 오프셋이 유지됩니다.。

목록이 이미 있는 경우 처음 두 번의 자동 읽기 실패는 이전 목록을 유지하고 프롬프트가 표시되지 않습니다. 세 번째 연속 실패에는 클릭하여 다시 시도할 수 있다는 메시지가 표시됩니다. 수동 실패 및 이전 목록이 없는 첫 번째 실패는 즉시 프롬프트됩니다. 현재 신원 및 개정 번호 확인을 통과한 목록을 성공적으로 읽으면 제스처 이외의 목록 항목을 포함하여 이전 오류가 지워집니다. 만료된 결과는 삭제되지 않습니다. 인증 실패는 로그인 프로세스로 전달되며 목록 재시도 프롬프트로 사용되지 않습니다.。

과거 결정 검색에서 활성 노트에 동일한 이름이 이미 존재하는 것을 찾지 못했습니다. ListSync/계약을 새로 고치려면 수동으로 아래로 당깁니다. 이 기록은 로컬로 구현됩니다. v2 최적화 검토 번호 4 항목, 쓰기 작업에 대한 연결 관리 또는 재시도 전략을 도입하지 않습니다.。

## 대안

- 각 클라이언트는 독립적으로 제스처를 구현합니다. 경험은 독립적으로 조정될 수 있지만 임계값, 취소 및 프롬프트 논리는 반복됩니다. 이러한 동작은 기존 공유 구성 요소에서 다루어졌습니다.。
- 원래 투표 입구에 직접 호출: 기존 읽기 프로세스를 재사용할 수 있지만 선택한 세션 세부 정보도 읽고 오류가 무시되며 수동 목록 새로 고침 결과를 정확하게 피드백할 수 없습니다.。
- 전체 페이지 새로고침: 구현하기 쉽지만 읽기 상태가 손실되고 관련 없는 초기화가 실행되므로 사용되지 않습니다.。

## 시험

Node 회귀에는 동시 읽기 병합, 완료 대기, 실패 및 연결 끊김 재시도, 필터링 및 초안 보존, 클라이언트 및 계정 만료가 포함되며 이전 요청은 새 요청을 잠금 해제해서는 안 됩니다. 브라우저 검사 격리 390/844/1440px 긴 목록, 짧은 목록, 빈 목록, 상단 동작, 중간 스크롤, 수평 취소 및 다음 두 클라이언트의 재시도 실패 합성 데이터를 사용하고 실제 계정이나 작업을 운영하지 않습니다.。

또한 ListSync 회귀 적용 범위, 이전 목록을 중단하지 않고 단기 자동 실패, 지속적인 실패 프롬프트, 기타 항목 성공 오류 지우기, 인증 실패 및 만료된 결과 보호。

## 영향

세 클라이언트는 제스처와 결과 피드백을 공유하며 수동 확인으로 인해 쓰기 작업이 증가하거나 폴링이 반복되지 않습니다. 단점은 공유 구성 요소가 재설정 가능한 요청 개정 번호를 유지해야 하며 목록 읽기가 폴링 오케스트레이션과 분리된다는 것입니다. 브라우저 확인은 대체되지 않습니다. Android/iOS 실제 기계 WebView 리바운드 경험의 수용。
