# Agent Note: 닫으려면 모달 대화 상자 배경을 클릭하세요.

Status: implemented

## 문제

사용자가 주변 배경을 클릭하더라도，Web 및 Desktop Gateway 모달 대화 상자에는 여전히 명시적인 닫기 컨트롤을 사용해야 합니다. 이 동작은 배경이 뷰의 대부분을 차지하는 좁은 화면에서는 일관되지 않습니다.。

## 결정

공유 리스너는 기본 포인터 동작이 대화 상자 배경에서 시작하고 끝나며 이동이나 스크롤이 없을 때만 모달 대화 상자를 닫습니다. 후속 조치를 기다리고 있습니다 click，그러면 닫기 또는 취소 컨트롤을 사용하여 대화 상자가 호출됩니다. 컨트롤의 비활성화된 상태와 닫기 처리기는 권한을 유지합니다. 컨트롤을 닫지 않는 대화 상자는 취소 가능한 닫기 요청을 받습니다. 기본 시스템 대화 상자는 이 동작의 범위를 벗어납니다.。

리스너는 문서 레이어에 위임되며, 시작 후 삽입되는 대화 상자도 동일한 규칙을 사용합니다.。Web 기존을 통해 `/app.js` 자원 `app.js` 이 스크립트는 이전에 제공되었습니다. 데스크톱 렌더러는 동일한 파일을 직접 로드합니다.。

## 대안

각 대화 상자에 추가 click 프로세서는 알려진 대화 상자를 명시적으로 재정의할 수 있지만 새 대화 상자와 두 개의 렌더링 항목은 쉽게 구별됩니다. 존재하다 `pointerup` 직접 닫으면 들어갑니다. click 발송하기 전에 모달 레이어를 제거하고 아래 페이지를 클릭하여 버튼의 독점 비활성화 상태를 우회할 수 있습니다.。

## 영향

백그라운드 클릭은 기존 닫기 수명 주기를 따릅니다. 내부 블랭킹, 드래그, 스크롤, 내부 누르기, 외부 해제 모두 대화 상자를 열어 둡니다. 렌더 레이어 범위를 약간 늘리기 위해 새로운 리스너와 공유 스크립트를 추가했습니다. 제스처 및 비활성화를 다루는 자동화된 이벤트 흐름 테스트 브라우저와 네이티브 WebView 별도의 육안검사를 거쳐 유해의 실제 제시。

모바일 버전[기본 메뉴 모달 가시성](../bug-fix/2026-10-22-mobile-native-menu-modal-visibility.md)독립 후속 최종 `dialog[open]` 상태, 모든 대화 상자가 닫힐 때까지 호스트 오버레이 숨기기。
