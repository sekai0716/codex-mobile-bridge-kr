# Agent Note: Antigravity 원주민 역사 및 제한된 접근

Status: implemented

## 문제

Antigravity App、IDE、CLI 다른 디렉토리에 기록을 저장하십시오. 포트 로그, 동일한 이름을 가진 프로세스 및 고정된 모델 디렉터리가 직접 연결로 결합되면 원래 세션 소스가 손실됩니다. 대기 중인 메시지는 표시 상태에 따라 자동으로 발송되거나 결과를 알 수 없는 후에 반복적으로 제출될 수 있습니다.。PR #150 제공 SQLite/JSONL 및 Hook 액세스 기반, 로컬 통합은 기존 공유 채팅 인터페이스와 원래 실행자 소유권을 유지해야 합니다.。

## 결정

- `bridge/clients/antigravity/` 负责原生格式、RPC 和 Hook；系统进程与监听核验在 `bridge/platforms/antigravity.py`，不反向依赖客户端业务。
- App、IDE、CLI 历史均按目录来源生成网关 UUID。API 不接受可能跨来源碰撞的裸原生 UUID。展示及模型目录读取不启动 CLI、不创建任务、不派发队列。
- 写入只发送到同用户、同进程世代、官方安装映像、匹配 `--app_data_dir` 且独占 IPv4 loopback 监听的原服务。日志仅提供候选端口；每次 RPC 前后重新核验，不跟随重定向，也不使用代理或重试未知写入。
- 原生发现同时覆盖官方 App 的 `language_server` 与 `.gemini/bin/agy` 的内嵌 LS。新版 IDE hub 的前端端口不替代原生 RPC 监听，资料归属仍由实际 `app_data_dir` 决定。三类程序通过共享默认应用表单补录；安装清单缓存、官方启动形态和无账号真实只读验证见[发现与添加修复](../bug-fix/2026-11-10-client-inventory-and-agy-discovery.md)。
- SQLite 使用 `mode=ro`。不分别复制 main/WAL/SHM 作为快照；历史不可读时该来源暂不可用。发送前直接查询原库，缺行、空状态、查询失败均不能证明空闲。
- 新建聊天携带已登记目录的 file URI。取得新会话 ID 后，按[新会话项目核验](../bug-fix/2026-11-18-antigravity-cascade-workspace.md)确认同来源、同原生进程世代及唯一项目目录，再发送首条消息。明确不匹配、证据缺失、身份变化或结果未知时阻断首条发送；不重试创建或首条发送，保留未知回执。
- 模型仅取原服务目录，目录缓存和设置校验包含来源。旧目录结构或目标缺失时，每次查找对当前选中的在线来源最多实时刷新一次；读写缓存均受原生账号身份约束。刷新失败保留同账号最后成功缓存及原更新时间，目标仍然无法解析时明确报错。旧扁平变体配 `auto` 时从原生目录还原实际档位，手填 `MODEL_` 标识只规范化 ASCII 字母大小写和首尾空白；不提供猜测的独立 effort 或额度数据。
- `accounts=true` 开放共享账号页面；原生身份按 APP、CLI、IDE 分别读取，单来源失败不会遮住其他来源，不依赖先有聊天历史。账号列表仅投影身份白名单和已保存副本的元数据，不读钥匙串或令牌。模型目录按来源分组，不将同名模型合并为另一来源的权限。未保存的原生身份不提供切换操作，额度按钮遵循能力门。
- 默认本机 Google 账号支持保存、改名、删除副本和显式应用。已安装 App 2.29.1、CLI 1.5.3 的二进制静态核验证实普通 OAuth 的 `auth_method=consumer`、空活动 `wif_provider`、非空 `token.refresh_token` 契约；`id_token_email` 只作展示及跨副本一致性核验，不证明登录有效。完整保留原始 JSON 和未知字段；GCP、WIF、旧式无方法记录及自定义 home 不推断为默认登录。
- 三类入口共用系统凭据 `service=gemini/user=antigravity`。默认回退文件是 `.gemini/jetski-standalone-oauth-token`、`.gemini/antigravity-cli/antigravity-oauth-token`、`.gemini/antigravity/antigravity-oauth-token`，保存时保留存在/缺失状态。使用同一系统登录的自定义入口也会受影响，确认文案明确说明；不复制 Electron 数据、聊天、插件秘密或其他目录。平台模块操作系统凭据，客户端处理 Go 编码：Mac 兼容 Base64/旧 hex 前缀，通过 `security -i` stdin、`-U` 更新，不先删后写、不加 `-A`；Windows 使用 `gemini:antigravity`、UTF-8 blob、Persist=2；Linux 选择 login collection，仅不存在时采用 default，锁定或多匹配项不静默绕过。
- 保存和应用前后重新核验原生三类进程均已退出，不强杀 AGY；显式应用的单个已核验桌面入口采用[后续有界正常重启](../bug-fix/2026-11-13-antigravity-account-restart-scope.md)，其余仍需先手动退出。Linux 更新后已删除但仍运行的映像继续视作占用；无关非 dumpable 的 sd-pam 不阻塞，无法核验的原生候选仍拒绝。私有恢复副本记录变更前后值；失败仅回滚本次仍匹配的值，全量读回确认原配置后才移除备份，外部变化不覆盖。写入成功只报告“登录配置已应用，尚未验证登录”，活跃账号仍来自原生状态，不用最后切换记录伪造成功。
- 桌面仍保留 `management` 会话配置区域，并与共享账号面板组合。App、CLI、IDE 分开显示历史和原生服务状态；模型、审批配置仅作用于当前选中的来源及会话，保存复用现有操作记录和模型目录身份校验，不新增账号或审批默认值。读取失败后禁用陈旧配置，重新加载成功才恢复写入。
- `backend` 是历史记录来源的展示分类，`surfaceDirKey` 是实际目录及服务 owner。App 目录内标记 CLI 的记录仍只向 App owner 写入；独立 CLI 目录中的同名原生会话使用另一网关 UUID。新建默认环境优先使用 `surfaceDirKey`，不能由展示标签重选执行器。
- 共享列表识别 APP、CLI、IDE；共享输入区沿用 [已有展示契约](2026-11-04-shared-account-editor-and-zcode-readiness.md) 保留模型、Skill、审批、上下文、附件和工作模式的位置。`composerCapabilities` 仅保留槽位，真实 `capabilities` 决定可操作性；未提供的 Skill、计划和目标模式保持禁用，不进入发送参数。离线仍保留草稿和同一控件结构，并明确提示原生服务未连接。
- 消息时间从原生带时区 ISO 转为共享渲染器要求的 epoch 毫秒；缺失的时间不补造。历史列表仍保留原有秒值格式，由列表的统一转换处理。
- 历史页优先对齐完整回合，但对齐不能越过既有 260 步窗口。单回合特别长时，较早的提示和步骤通过原游标继续读取，不把整个回合重新塞回首屏。601 步单回合反例在旧实现返回 601 条且没有旧页；修复后逐页无重复、无遗漏，旧页不携带当前运行态。保持完整回合有利于阅读，但不能牺牲长会话的可操作性；此处复用现有分页与共享旧页合并，不改变实时控制协议。
- Hook 只在用户启用接入后启动，使用用户资料级单 owner 锁。来源通过会话目录中的 transcript 路径核验。steer 仅在 `PostInvocation` 消费；queue 仅在已确认 `fullyIdle=true` 的正常 `model_stop` 消费。已消费但回执不明的注入不重放；未知/异常停止保留队列。
- 上传的图片及文件保留网关验证后的本机路径，通过共享 `file_mentions` 交给原服务。历史图片继续使用经过会话/项目边界检查的共享预览。这里不宣称原生视觉输入已经实机验证。
- 沿用共享聊天、时间戳、资源、通知、下载和手机跳转；不引入原 PR 的 Light 主题、排队控制条或独立聊天布局。官方图标直接取自 [Antigravity press](https://antigravity.google/press) 的品牌 PNG，文件哈希为 `e0cd08ccd10cd8d08ccf0ba449823ee88495825c0841619618100d3ab089f51e`。
- 在不改变只读与来源隔离契约的前提下补齐原生运行态增强：通过只读 `GetAllCascadeTrajectories` 与按来源隔离的 `agy-wait:{surface}:{cid}:{tid}:{step_index}` / `HandleCascadeUserInteraction` 原生回应 `askQuestion`、`runCommand`、`filePermission`、`elicitation`、`deploy` 等等待交互及子智能体交互，并在 `send` 前拦截未处理等待步骤；模型目录过滤 `disabled`/`Unavailable`/`-disabled` 条目，仅在真实 `quotaInfo` / `planStatus` 存在时透出配额标签、`usageSummary` 与详细步骤 `contextUsage`（`cacheWriteTokens` / `outputTokens`），缺省时保留原纯文本提示；`transcript_full.jsonl` 水合与 `read_image` 执行分支对齐、全文件扫掠、`transcript_full.jsonl` 回退与允许根目录内的符号链接拦截；子任务仍只读展示，不采纳尚未完整核验实时任务关系和后台范围的 `stop-task` 扩展；`HookIPCServer` 写回失败不恢复队列快照。

## 대안

기존 PR 백그라운드 유휴 폴링은 다음에서 수행될 수 있습니다. Hook 부재시 자동으로 발송되지만 스냅샷 및 독립형 표시 CLI 원본을 증명할 수 없습니다. owner 릴리스된 작업, 알 수 없는 결과 재정렬도 반복적으로 작성되므로 이 메커니즘은 유지되지 않습니다. 복사 SQLite 메인 도서관과 WAL/SHM 부분적인 개방 실패는 우회할 수 있지만 복제 간격에 동시 업데이트가 있으므로 일관된 스냅샷이나 미리 쓰기 안전성의 증거로 사용할 수 없습니다. 고정 모델/할당량 테이블에는 전체 선택 사항이 쉽게 표시되지만 현재 계정에 권한이 있음을 증명할 수 없으므로 원래 클라이언트 디렉터리가 사용됩니다. 읽기 전용 계정 페이지는 신원을 표시하기에 충분하지만 계정을 저장하고 적용할 수는 없습니다. 네이티브 컨트랙트를 정적으로 검증한 후 중지된 상태의 제한된 스냅샷 트랜잭션으로 확장되며, 알 수 없는 인증 유형은 아직 공개되지 않습니다. 세 가지 유형의 클라이언트를 자동으로 중지하고 시작하면 수명주기 변경이 확장되므로 원래 클라이언트가 종료된 후 애플리케이션의 경계가 정상적으로 유지됩니다.。PR #150 고쳐 쓰다 `f25d787f` 계정 스냅샷 아이디어를 제공하지만 설치를 연결 및 크로스 플랫폼 애플리케이션으로 처리합니다. Linux 폴더、macOS 이전 키체인 항목을 삭제한 후 `-A` 실패하고 토해내지 않은 재구축, 복구 쓰기 등의 행위는 계속할 수 없습니다.。

## 영향

오프라인 소스에서는 기록을 계속 사용할 수 있습니다. 실시간 전송, 신규, 중지, 모델 및 승인은 검증 가능한 원래 서비스에 의존하거나 Hook。닫기 모바일 액세스만 비활성화하고 종료하지 않고 이 플러그인을 비활성화합니다./강제로 죽이기 Antigravity，원래 기록과 작업을 다시 작성하지 마십시오. 계정 페이지는 기본 ID, 하위 소스 모델 및 기본을 지원합니다. Google 계정 사본; 채팅 이름 변경/아카이브 또는 독립형 effort 아직 열리지 않았습니다. 구하다/애플리케이션은 시스템 자격 증명 인증을 트리거할 수 있으며 일반 새로 고침에서는 자격 증명을 읽지 않습니다. 성공적인 쓰기는 로그인, 지역 및 업스트림 권한의 사용을 보장하지 않습니다.。

기본 휴대폰 화이트리스트 및 아이콘 리소스는 다음과 동기화됩니다. Android 및 iOS 소스 코드. 기존에 설치된 모바일 패키지는 이러한 소스 코드 변경 사항을 자동으로 수신하지 않습니다. 게이트웨이 동결 항목 지원 `antigravity-hook`，일반 소스 코드 항목이 직접 호출됩니다. Hook 스크립트。

## 검증

`test_antigravity_adapter.py` 세 가지 역사 소스와 도구를 다룹니다./생각하다/이미지 정규화, 분기 정렬, 읽기 전용 및 배포 없음, 알 수 없는 유휴 거부, 일관성 실패 종료, 새 프로젝트 확인、Windows drive/공간/UNC URI、소스 모델 캐시/격리 설정, 단일 owner 잠그다、RPC 재시도 및 대기열 단일 소비가 없습니다. 위는 격리 고정 장치 및 합성입니다. RPC，실제 클라이언트 작성이나 3개 시스템 공동 디버깅이 통과되었다는 의미는 아닙니다. 기본 공식 클라이언트는 생성이 아닌 읽기 전용 검색만 허용합니다./계속하다/공식적인 업무를 중단하세요。

공유 입력 영역의 후속 관리 및 수리에는 합성 기본 서비스를 사용합니다.：`tests/test_antigravity_adapter.py` 23 예시가 통과되었습니다. 관련된 두 Node 파일 270 예시 통과、1 예시 기준선이 실패했습니다. 파일 작업공간을 다시 연 후 실패합니다. `active` ～에서 `files` ～이 되다 `chat`，에서 `c22abfce` 독립적인 정적 파일 스냅샷의 반복은 이 복구 범위에 포함되지 않습니다.。Chrome/WebKit Kuanzhai 채팅, 모델 빈 디렉토리/오류, 소스 필터링, 연결/연결이 끊긴 형상과 초안 검사 및 알림 메뉴 저장이 모두 통과되었습니다. 데스크탑 관리는 그대로입니다. App 최소 창 820px 그리고 1280px 모델 확인, 저장 승인 및 오류 비활성화。390px 데스크탑 관리 시뮬레이션은 원본의 일부가 아닙니다 App 사용 가능한 창, 사용 가능하다고 선언하지 않음。
