# Agent Note: 비동기식 질문을 원격으로 건너뛰고 다른 초안을 유지하세요.

Status: implemented

## 문제

네이티브 Codex 비동기 문제 중 하나만 건너뛸 수 있습니다.，Bridge 원래 카드의 모든 질문에 답해야 합니다. 토종의 App 건너뛰기 상태는 다음과 같습니다. renderer 메모리에는 검증된 내용이 없습니다. IPC 소스를 읽고 쓰세요. 답변을 위조하거나, 빈 답변을 제출하거나, 원본을 수정하여 답변을 생성할 수 없습니다. App 듀얼 엔드 동기화를 달성하세요. 사용자는 게이트웨이 범위가 먼저 제공되고 질문을 건너뛰는 데 동의합니다. 다른 질문에 대해서는 사용자가 명확하게 답변합니다.。

## 결정

공유됨 `QuestionSkips` 게이트웨이 데이터 디렉터리, 호스트 시스템 및 Codex 인스턴스를 구분할 수 있도록 디렉터리를 구성한 후 채팅, 요청, 질문 ID 건너뛰기 상태를 저장합니다. 파일은 기존 비공개를 사용하여 불투명 식별자만 저장합니다. JSON 쓰기 기능 지속성, 권한은 다음과 같습니다. 0600；배치가 성공한 후에만 상태가 해제됩니다. 건너뛰기를 반복하면 동일한 영수증이 반환되며, 쓰기 실패가 문제를 숨기지 않습니다. 다시 연결하거나 게이트웨이를 다시 시작해도 상태가 손실되지 않으며 새 폴링이나 모니터링이 추가되지 않습니다.。

기존의 respond 인터페이스 수락 `action: skip` 및 `questionId`，현재 연결된 원래 세션의 비동기 문제만 확인하고, 세션을 활성화하지 않으며, 메시지를 제출하지 않으며, 모델을 호출하지 않습니다. 보기, 알림 및 후속 답변 확인은 동일한 예측을 재사용하고 원래 기록 및 출구 안전 판단은 기본 데이터를 유지합니다. 명령, 파일 및 권한 승인은 여전히 ​​원래 기본 요청을 따르며 건너뛰기를 사용하여 승인을 우회할 수는 없습니다. 시스템 알림센터로 전달된 이력 알림은 철회되지 않습니다.。

공유됨 Web 질문별 카드 ID 컨트롤을 재사용하세요. 건너뛰기는 대상 질문과 제출되지 않은 초안만 제거하고 다른 질문과 다른 카드는 동일한 카드에 그대로 둡니다. DOM 입력으로. 확인 후 HTTP 영수증은 아직 존재하는 대상에만 적용되며 업데이트된 푸시 상태는 이전 요청 목록으로 덮어쓸 수 없습니다. 일반 답변은 여전히 ​​나머지 질문을 명시적으로 제출합니다. 전송 완료 owner 구문 분석 후, action_lock 건너뛰기 또는 건너뛰기 문제를 피하려면 페이지 내의 질문과 텍스트를 다시 확인하세요. CLI 활성 릴리스는 역방향 잠금 시퀀스를 형성합니다.。

이것은 Bridge 휴대폰/Web 네이티브로 선언되지 않은 공유 상태 건너뛰기 Codex App 로컬 건너뛰기 및 원격 양방향 동기화. 이후 네이티브 엔드가 실제 답변을 제출하면 기존 기록 분석이 계속 적용됩니다. 향후 신뢰할 수 있는 네이티브 스킵 계약이 체결될 경우 합병 및 마이그레이션 규칙은 별도로 결정됩니다.。

## 기존 기록 확인

[라운드 전반에 걸쳐 비동기 문제 보존](../bug-fix/2026-10-28-pending-async-cards-across-turns.md) 부분 중복: 기록 구문 분석, 기본 인터페이스 격차 및 위조되지 않은 응답이 계속 유지됩니다. 이 기사는 사용자가 부분 건너뛰기를 명시적으로 수락하고 이전 기사를 대체한 후 새로운 결정입니다.“추가하지 않고 지우기만 함 Bridge 카드 입구”범위 제한 이전 근거를 다시 작성하지 말고 로컬 기능을 기본 동기화로 설명하지 마십시오. 관련 알림, 사이드 채팅 및 모델 생성 기록은 독립적인 책임을 가지며 이 문서에 흡수되지 않으며 보관하거나 삭제할 필요가 없습니다.。

## 대안

- 완전한 기본 양방향 동기화가 원래 목표를 가장 잘 충족하지만 현재 읽거나 삽입할 수 있는 신뢰할 수 있는 소스가 없습니다. renderer 메모리가 원본과 일치하지 않습니다. App 접근 경계. 따라서 명시적인 제한이 유지됩니다.。
- 디스크에 올려놓지 않고 프런트엔드에만 숨겨져 있다가 새로고침하면 다시 나타납니다. 알림 및 기타 전화는 여전히 응답된 것으로 간주됩니다. 공유 게이트웨이 투영은 각 끝에서 규칙 복사를 방지합니다.。
- 빈 답변을 제출하면 원래 답변 인터페이스를 계속 사용할 수 있지만 모델이 계속해서 크레딧을 소비할 수 있으며 다른 질문의 의미도 변경되므로 사용되지 않습니다.。

## 검증

격리 IPC 유스케이스는 먼저 재현하고 건너뛸 수 없으며, 그 다음 질문을 하나씩 건너뛰고 다른 질문에도 평소와 같이 답변하고 영구 복구, 일반 승인 건너뛰기 방지, 중복 수신, 전송 전 동시 검증을 다룹니다. 보관 설비 오버레이 구성/주인/채팅/묻다/문제 격리、0600、쓰기가 실패하고 기본 기록을 수정하지 않습니다. 알림 모음 55 항목이 통과되었습니다. 완벽한 Bridge 첫 번째 키트 라운드 108 항목이 통과됨、2 개 Windows 전용 건너뛰기, 영향을 받은 비동기 응답 사용 사례만 잠금 순서가 조정된 후 다시 테스트됩니다.。

브라우저는 Chrome/WebKit 넓은 확인과 좁은 확인의 네 가지 조합을 사용하여 동일한 카드 및 기타 카드 초안을 유지하고 건너뛰고 다른 답변을 보내지 않으며 순서가 잘못된 확인은 처리된 질문을 복원하지 않습니다. 마침내 8 항목이 통과되었습니다. 새로운 동시 릴리스 픽스처는 이미 직렬 게이트를 보유하고 있는 호스트에서 처음으로 다른 작업을 예약합니다. send 내부에서는 비즈니스 실패 대신 예상되는 차단을 받습니다. 대신에 send 생산 직렬 도어를 풀지 않고 문에 들어가기 전에 두 작업을 시차를 두고 통과합니다.。

이번 라운드에서는 실제 사용자 카드를 작동하거나 모델을 호출하거나 원본을 선언하지 않았습니다. App 양방향 동기화. 달리기 Test 커버리지 설치 및 실제 기계 승인은 이러한 소스 코드 고정 장치 결과와 무관합니다.。

## 영향

Remote는 여러 문제 카드를 독립적으로 처리할 수 있으며 건너뛴 문제는 다시 연결한 후에 복원되지 않습니다. 공유하면 보도가 가능해집니다 Web、iOS 및 Android。비용은 각각의 첫 번째 건너뛰기가 작은 개인 파일에 기록되고 사용자 건너뛰기 횟수에 따라 식별 레코드가 증가한다는 것입니다. 오래된 이력 카드가 다시 나타나는 것을 방지하기 위한 이력 삭제나 자동 만료가 없습니다. 토종의 App 아직 건너뛰지 않은 문제가 여전히 표시될 수 있습니다. 이는 현재 명시적인 범위 경계입니다.。
