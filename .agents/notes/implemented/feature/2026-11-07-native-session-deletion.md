# Agent Note: 네이티브 세션 영구 삭제 및 범위 확인

Status: implemented

## 문제

Issue #138 아카이브 아래에 제공된 영구 삭제를 요청하세요. 기본 사이드 채팅이 지속되면 상위 항목만 삭제됩니다. Bridge 기록을 표시하면 원래 대화가 종료됩니다. 상위 항목을 직접 삭제하면 보관된 보조 채팅이 누락되거나 응답이 손실되면 프로세스가 반복될 수 있습니다.。

## 결정

공유 세션 메뉴는 보조 확인 기능을 제공하여 기본 상위 채팅과 액세스 가능한 모든 하위 채팅을 표시하고 하위 상담원 수도 표시합니다. 확인 후 ID 컬렉션은 즉각적인 메타데이터와 일치해야 합니다. 메뉴 닫기, 반환 및 늦은 범위 응답은 제거를 트리거하지 않습니다. 기본 포커스는 취소입니다. 현재 이 기계에 사용 가능 Codex 그리고 독립 Codex 설정；SSH/WSL 다른 클라이언트에 대해 확인된 기본 삭제 항목이 없으며 사용 가능한 것으로 표시될 수 없습니다.。

원본 삭제 app-server 의 `thread/delete`。기본 제휴는 자녀에서 부모로 처리되며 보관된 제휴 채팅도 범위 내에 있습니다. 일반 지점은 그렇지 않습니다 `forkedFrom` 액세서리로 추정됩니다. 실행 중, 확인 보류, 백그라운드 작업 및 쓰기 보류로 인해 삭제가 방지됩니다.。Bridge 삭제를 위해 세션을 복원하지 말고 사용자를 종료하지 마십시오. App、기본 데이터베이스를 직접 수정하거나 프로젝트 파일을 삭제하지 마십시오.。

삭제하기 전에 구성된 대로 알 수 없는 영수증을 지속적으로 기록합니다. 부분 삭제, 연결 끊김 및 확인되지 않은 기본 오류는 재생되어서는 안 됩니다. 전체 기록된 범위가 기본 저장소에서 사라지는 경우에만 승인이 성공합니다. 첫 번째 명시적 반환 방법은 지원되지 않습니다.、`-32600` 그리고 타겟과 정확히 일치 ID 의 `already has an active writer`，또는 발송 전 확인이 실패하면 실행되지 않은 의도가 지워집니다. 다른 오류는 여전히 알 수 없는 오류로 처리되며 모든 오류를 알 수 없습니다. RPC 오류는 실행되지 않은 것으로 처리됩니다. 하위 키가 삭제된 후 발생하는 오류는 아직 알려지지 않았습니다. 계정 전환, 호스트 ID, 인증 및 CSRF 관련 보호에서는 기존 항목을 계속 재사용합니다.。

사용자가 삭제 메뉴를 다시 열면 게이트웨이는 기본 메타데이터와 비교하여 아직 존재하는 범위를 확인하고 교차하는 알 수 없는 영수증을 반환합니다. ID。이전 요청은 자동으로 재생되지 않습니다. 사용자는 확인란을 별도로 선택해야 합니다.“체크됨”，현재 범위를 다시 확인하세요. 새 요청에서는 다른 범위를 사용합니다. ID 그리고 오래된 영수증을 정확하게 모아서 보관하세요. 이 기간 동안 알 수 없는 새로운 수신 또는 범위 변경으로 인해 실행이 불가능할 수 있습니다. 수표가 실패하고 전송되지 않은 경우 이전 영수증이 보관됩니다. 새 의도가 실제로 전송된 후에만 이전 영수증이 새 요청에 연결됩니다. 하나의 하위 트리만 다시 시도하면 상위 범위에 있는 다른 채팅의 알 수 없는 상태가 지워지지 않습니다.。

## 대안

- 제거만 Bridge 목록 항목: 기본 영구 삭제 및 이중 종료 일관성을 충족할 수 없습니다.。
- 보관 후 자동 삭제: 서로 다른 두 가지 사용자 의도를 혼합하고 취소할 수 없는 작업을 마스킹。
- 자동으로 작업을 중지하고 삭제합니다. 중단 범위를 쉽게 확장할 수 있습니다. 사용자는 먼저 이를 명시적으로 중지한 다음 영구 삭제를 확인합니다.。
- 시간 초과 후 재제출: 부분 완료 후 새로운 관련 콘텐츠가 실수로 삭제될 수 있으므로, 알 수 없는 영수증을 보관하고 확인을 요청하세요.。

## 영향

새로운 상주 프로세스나 폴링이 필요하지 않으며, 오픈 확인 및 실행 중에만 메타데이터를 읽습니다. 삭제는 현재의 기본 런타임 기능과 작성자에 의해 여전히 제한됩니다. 인터페이스에서 제공되는 입구가 모든 클라이언트 버전이 이 방법을 지원한다는 의미는 아닙니다. 기본 삭제는 자체 관련 콘텐츠를 처리하여 텍스트가 이를 숨겨진 목록으로 설명할 수 없음을 확인합니다. 이전에 알려지지 않은 결과는 사용자가 확인하고 재확인해야 합니다. 재시도를 용이하게 하기 위해 기록을 자동으로 지울 수는 없습니다.。

현재 Desktop 자체적으로 기본 삭제 owner 의 `requestClient` 실행 및 홍보 follower IPC 항목은 삭제되지 않습니다. 독립적인 짧은 시간 app-server 원본을 삭제할 권리는 없습니다 App 채팅이 현재 활성 상태가 아니더라도 쓰기 액세스 권한을 유지하는 채팅입니다. 따라서 이러한 유형의 채팅은 원래 클라이언트에서 삭제하거나 자연스럽게 쓰기 권한을 해제한 후 다시 시도해야 합니다.；Bridge 자동 보관 없음, 저작권 확보 없음, 원본 종료 없음 App。
