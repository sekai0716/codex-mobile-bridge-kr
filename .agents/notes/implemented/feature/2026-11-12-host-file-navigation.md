# Agent Note: 파일 페이지는 읽기 전용 호스트 디렉터리 탐색을 지원합니다.

Status: implemented

## 문제

#160 파일 페이지는 채팅 프로젝트 디렉터리에서 시작해야 하며 상위 디렉터리 및 전체 경로 탐색을 지원합니다. 프로젝트 디렉터리가 없는 채팅은 확인된 기본 레코드 위치에서 시작됩니다. 원래 구현에서는 프로젝트 상대 경로에 대한 참조 검색, 업로드 및 전송이 제한되며 프로젝트 외부에서 파일을 찾을 수 없습니다.。

## 결정

기존 작업 공간 인터페이스에 명시적 추가 `scope=host`，목록, 메타정보, 미리보기 및 다운로드만 공개됩니다. 파일 페이지는 원본 워크벤치, 디렉터리 목록, 캐시, 미리보기 및 다운로드 구성 요소를 재사용하고 편집 가능한 전체 경로를 추가합니다. 서버는 절대 경로와 상위 디렉터리를 반환하고 브라우저는 추측하지 않습니다. Windows 드라이브 문자 또는 루트 디렉터리. 기존 목록을 유지하려면 파일 탭을 다시 입력하고 위치 지정을 위해 먼저 로드된 디렉터리를 재사용합니다. 후속 작업을 덮어쓰는 지연 요청을 방지하기 위해 비동기식 메타정보 위치 지정을 위한 생성을 사용합니다.。

호스트 경로는 여전히 원래 디렉터리 핸들과 일반 파일로 확인되며 디렉터리의 심볼릭 링크를 따르지 않습니다.、Windows junction 또는 재분석 지점。Windows 로컬 드라이브 문자와 선택된 현재 프로젝트만 허용합니다. UNC share，다른 네트워크 공유에 대한 자격 증명 액세스는 새 입력을 통해 트리거될 수 없습니다.。SSH/WSL 게이트웨이 시스템의 원격 경로를 해석하지 않고 대상에서 동일한 독립 모듈을 실행합니다.。

채팅 메시지의 파일은 동일한 읽기 전용 항목을 사용합니다. 새로운 경로 매핑은 실제 표시된 경로만 구문 분석합니다. Markdown、목록을 렌더링할 때 파일 참조 또는 기본 첨부 파일은 디스크를 읽지 않습니다. 사용자가 클릭하면 대상 호스트의 작업 공간 인터페이스가 파일 ID, 권한, 링크 및 다운로드 크기를 확인합니다. 경로 확인은 게이트웨이 시스템과 독립적입니다. Windows 게이트웨이 핸들 SSH/WSL 의 Linux 경로는 기본 경로로 해석됩니다. 외부 URL、새로운 네트워크 공유 및 디렉터리 탐색은 호스트 링크를 생성하지 않습니다.。

신뢰할 수 있는 오래된 사진 artifact 예약하다 ID 기본 미리보기; 새 호스트 파일은 다음과 같이 표시됩니다. `image=False`，프로젝트 외부의 그림은 파일 링크를 먼저 표시하며 모델 텍스트만으로는 자동 그림 읽기를 실행할 수 없습니다. 오디오 및 비디오는 여전히 사전 로드되지 않은 공유 재생 컨트롤을 사용합니다. 오래된 artifact 메타 정보는 위치 지정을 위한 절대 경로도 반환하며 원래 다운로드 권한은 변경되지 않습니다.。

목록과 메타정보가 별도로 반환됨 `projectPath`。원본 프로젝트 내의 대상만 업로드하거나 메시지에 참조할 수 있으며, 참조하기 전에 다시 확인해야 합니다.；Git、업로드 및 참조 인터페이스는 호스트 범위를 허용하지 않습니다. 종이클립 선택기는 프로젝트 상대 경로를 계속 사용합니다. 토종의 cwd 파일 탐색에 따라 변경되지 않습니다. 없음 cwd 의 Codex 사용 Store 검증됨 rollout 해당 경로는 초기 디렉터리로 사용되며, 아직 존재하지 않는 채팅 기록은 유추할 수 없습니다.。

## 대안

모든 작업의 ​​루트 디렉터리를 디스크 루트로 변경하면 인터페이스 매개변수가 줄어들 수 있지만 업로드 용량도 늘어납니다.、Git 및 모델 부착 범위이므로 사용되지 않습니다. 새로운 독립형 파일 관리자는 기존 페이징, 미리 보기, 다운로드 및 모바일 상호 작용을 복제하므로 공유 워크벤치에서 계속 구현됩니다. 시작 시 모든 드라이브 문자와 네트워크 공유를 검사하면 차단 및 외부 액세스가 증가합니다. 대신 사용자는 전체 경로를 입력합니다.。
