# Agent Note: 알려진 프로젝트 디렉토리에서 생성 Codex CLI 채팅

Status: implemented

## 문제

새 채팅 대화는 다음에서만 저장할 수 있습니다. App 프로젝트 생성 Codex App 채팅. 오직 Codex CLI 기존 터미널 프로젝트 등 사용된 디렉터리는 새 모바일 채팅을 생성하는 데 사용할 수 없습니다.。

## 결정

할 것이다 Codex App 및 Codex CLI 명시적 채팅 유형으로 노출됨。CLI 선택한 로컬 또는 SSH 호스트에 저장됨 CLI 소스 채팅 메타데이터 메타데이터만 읽는 옵션 나열。CLI 유형, 호스트, 디렉터리 및 요청을 사용하여 요청 생성 ID 열쇠로. 사용자가 양식을 제출한 후에만 기존 네이티브 CLI 데몬, 선택을 누르세요 cwd 및 CLI 소스는 영구 스레드를 생성한 다음 스레드 이름을 지정하고 읽습니다. 라운드를 시작하지 않거나 데스크탑을 열지 않습니다. App。네이티브 CLI 별도의 ID를 사용하여 연결 `codex-mobile-bridge-cli`；게이트웨이가 다시 시작된 후 정확한 originator 로 분류됨 CLI。설치됨 0.162.1 데몬이 수락 `threadSource: cli`，하지만 지속 `source: vscode`，그러므로 필요성이 있는 것으로 확인되었다. originator。기존의 `codex-mobile-bridge` 행은 다음으로 분류되지 않습니다. CLI。런타임이 선택되었습니다. cwd 선택하다 provider 및 인증。

## 검증

소스 코드 테스트 범위 명시적 `thread/start` 통화, 알려진 디렉터리 선택, 반복된 요청 및 변경되지 않은 사항 App 만들다. 격리 Codex CLI 0.162.1 루프백 클램프가 인증되었습니다. HTTP API 만들다 CLI 채팅; 저장 확인 다시 읽기 CLI 소스 및 선택 cwd/provider，그리고 네이티브 데몬을 통해 전송을 완료합니다. 설비가 출력 이벤트를 내보낸 후 사용자 및 보조 메시지가 포함된 기록이 저장됩니다. 네이티브 실시간 `thread/read` 픽스쳐는 빈 항목 목록을 반환하므로 연결된 라이브 뷰에는 도우미 항목이 표시되지 않습니다. 이 고정 장치 제한은 기록 결과 저장에 영향을 미치지 않습니다.。

## 대안

모든 새 채팅 열기 App 기존 경로를 재사용할 수 있지만 생성할 수는 없습니다. CLI 채팅을 기다리세요. 임의의 무료 입력 디렉토리는 알려진 구성 이상으로 프로젝트 선택을 확장합니다. 채팅 유형 및 검색을 명확히 하세요. CLI 디렉토리는 사용자가 선택한 실행 환경을 보유합니다.。

## 영향

생략 kind 이전 데스크탑이 생성될 때 API 여전히 호환 가능。CLI 생성 결과를 알 수 없는 경우 영수증은 유지되며 새 스레드가 생성되지 않습니다. 현실 390px 영어 UI 수락 완료 CLI 수평 오버플로 없이 채팅 생성, 메시지 전송 및 답장 표시。
