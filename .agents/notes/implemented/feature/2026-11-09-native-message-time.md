# Agent Note: 채팅 상호작용은 기본 날짜와 시간을 유지합니다.

Status: implemented

## 문제

메시지 표준화 및 페이지 렌더링은 기본 상호 작용 시간을 잃으며 일부 연결 계층도 화이트리스트 프로젝션 중에 시간 필드를 미리 제거합니다. 수신 시간을 패딩하면 기록, 새로 고침 및 다시 연결에 잘못된 날짜가 생성됩니다.。

## 결정

메시지 계약은 선택사항을 추가합니다. `timestamp`：네이티브 epoch 밀리초 또는 명시적인 시간대 사용 ISO 시간。Claude Desktop 연결 계층 보존 이벤트 `timestamp`，Code/Cowork/CLI 공유 변환은 이 필드를 유지합니다.。DSH 이벤트 이용 `time`；ZCode 라이브 스냅샷 사용 라인 `createdAt`，읽기 전용 내역 사용량 메시지 테이블 `time_created`。Codex 기록 읽기 보존 rollout 이벤트 시간; 네이티브 턴 `turnStartedAtMs` 이번 라운드에서 첫 번째 사용자 메시지의 시간 기준으로 시작 시간을 보조 완료 시간으로 간주할 수 없습니다.。

첫 번째 사용자 메시지의 라운드 타임 롤백은 공유 표준화 계층에서 완료되며 하위 에이전트는 기본 채팅과 동일한 의미를 사용하여 기록을 저장합니다. 페이징 창에서 생략된 첫 번째 입력은 후속 안내 메시지로 시간을 전송할 수 없습니다.。CLI 임시 사이드 채팅은 기본으로 유지됩니다. `turn/started` / `turn/completed` 초 단위로 표현 `startedAt`，기존으로 변환 `turnStartedAtMs`；동일한 기본 메시지의 후속 스냅샷은 생략됩니다. `timestamp` 이전에 받은 시간을 그대로 유지하는 경우 명시적으로 제공하면 새 값을 사용합니다. 자신의 시간이 없는 어시스턴트 메시지는 누락된 채로 남아 있으며 라운드 시작, 완료 알림 도착 또는 현재 시간이 채워지지 않습니다.。

연결 후 `LiveSession.view()` 같은 것만으로 session、turn、네이티브 메시지 ID、유형 및 역할에 대한 고유 키가 저장된 보기에서 보완됩니다.。rollout `response_item` 명시적 네이티브 유지 ID；없어진 ID 디스플레이 일련번호 밴드 `_syntheticId`，협회에 참여할 수 없습니다.。`_timestampSource` 로그 메시지 기록과 네이티브 구별 `item_completed` 완료 이벤트와 `native-turn-start` 롤백; 정확한 메시지 시간은 첫 번째 사용자가 롤백을 시작할 차례보다 우선하며, 실시간 메시지 자체는 시간이 있는 경우 보관됩니다. 중복 키, 다른 네이티브 ID 반복되는 텍스트와 교차 세션 또는 교차 기록은 관련이 없으며 실시간 제어 상태가 수정되지 않습니다.。

실시간 스냅샷에 메시지 시계가 없으면 백그라운드 기록 새로 고침과 연결된 기본 세션을 모두 덮어씁니다. 제한된 디스플레이 캐시에서 기본 메시지 ID와 누락된 시간의 라운드 상태를 추출하고, 동일한 그룹을 최대 4번 읽고, 기존 백오프 및 진행 중 병합을 사용합니다. 텍스트 증분 및 폴링 시퀀스 번호는 예산을 재설정하지 않습니다. 새 메시지 또는 라운드 상태는 새로운 제한된 읽기를 허용합니다. 시간이 채워지면 더 이상 읽기가 이루어지지 않습니다.。SSH 여전히 백그라운드 기록 폴링을 도입하지 않습니다. 시간만 변경되면 프런트 엔드는 작업 표시줄 시계만 업데이트하고 텍스트, 선택 및 플레이어 노드를 유지합니다.。

기본 인덱스 읽기 우선은 프로젝트의 원래 페이징 및 읽기 전용 경계를 계속 유지합니다. 인덱스 메시지에 시간이 누락되면 추가 읽기가 가장 많이 발생합니다. 2 MiB rollout 꼬리, 안정적인 신원에 따라 메시지 녹음 시간만 추가하거나 `item_completed.completed_at_ms`，전체 기록 읽기가 호출되지 않습니다. 첫 번째 줄을 자르는 것은 구문 분석에 참여하지 않습니다. 캐시 ID에는 다음이 포함됩니다. thread、파일 경로, 장치、inode、크기 및 나노초 수정 시간, 인덱스로 돌아가기 전에 파일 상태를 확인하세요. 기본 인덱스 메시지는 만료된 경우 덮어쓰이지 않습니다. 로그 메시지 자체가 작성 시간만 기록하는 경우 동일한 고유 네이티브로 생성할 수 있습니다. ID 명시적 완료 이벤트는 완료 시간을 제공합니다. 완료 시간 필드가 없는 완료 이벤트는 기본 로그 시간을 유지합니다. 테일 예산을 초과하거나 신뢰할 수 있는 신원이 부족한 오래된 기록에는 아직 시간이 없을 수 있습니다.。

공유됨 `activity.js` 모든 채팅 렌더링 항목의 형식을 지정하고 재사용하는 일을 담당합니다. 날짜는 보기 장치의 현지 시간대로 표시되며, 현재 날짜는 다음과 같습니다. 24 시간 `HH:mm`，연도에 걸쳐 날짜와 연도를 보완하고 시간대가 포함된 전체 시간이 의미 레이블 및 프롬프트에 유지됩니다. 누락되거나 유효하지 않거나 시간대 문자열이 없으면 시계가 생성되지 않습니다. 기본 증거 대신 세션 업데이트 시간, 도착 시간 또는 현재 시간을 사용하지 마십시오.。Claude/DSH 동일한 이벤트로 분할된 여러 콘텐츠 조각은 한 번만 표시됩니다.。

메시지 작업 표시줄은 복사, 참조, 편집 또는 분기（가능한 경우） 및 시간별로 정렬됩니다. 초기 생성 및 후속 작업 버튼 추가 모두 시간을 끝에 배치하고 시간은 버튼을 따르며 자동 여백으로 전체 행의 오른쪽으로 밀리지 않습니다. 하위 에이전트 저장 세부 정보는 사본, 참조 및 시간을 제공합니다. 참조는 기존 초안 구성요소를 재사용하고 클릭 시 현재 워크벤치를 확인하여 완료합니다. provider、host、session 신원, 채팅을 전환한 후 다른 초안에 이전 세부정보를 쓰지 않습니다. 읽기 전용 하위 에이전트 레코드는 편집 또는 분기 기능을 추측하지 않습니다. 네이티브 사이드 채팅은 표준 채팅 타임라인과 동일한 작업 표시줄을 사용합니다.。

설치됨 DSH 의 `dsh-client-ui-chat` 소스코드 확인 `formatMessageClock` 이벤트 밀리초, 현재 날짜 사용/크로스 데이/사용자 메시지에 대한 새해 전야 규칙 `data.time`，조수용 `closing.time`；ZCode 메시지에서 설치된 소스 코드 `info.time.created` 시간에 따른 투영. 애플리케이션 패키지는 읽기 전용으로 검사되며, 타사 코드가 추출 및 릴리스되지 않으며, 실제 세션이 연결되거나 수정되지 않습니다.。

이 컴퓨터에 있는 두 개의 기본 로그에 대한 필드 수준 읽기 전용 확인: Assistant `response_item.payload.id` 각기 7/7 및 2/2 기사 및 `item_completed.item.id` 이에 따라 완료 이벤트도 명확하게 전달됩니다. `thread_id`、`turn_id` 그리고 `completed_at_ms`。검증에서는 필드 형식과 일치 횟수만 추출하며, 채팅 텍스트를 출력하거나 모델을 시작하지 않습니다. 이 증거는 현재 로그 형식의 상관 경로를 증명하며 기본 로그 형식이 없음을 보장하지 않습니다. ID 이전 버전 기록을 복원할 수 있습니다.。

## 기존 메모 감사

상호 작용 시간/타임스탬프 검색은 계정 캐시, 알림 이벤트 및 모델 디렉터리 레코드에 도달하지만 이들 중 어느 것도 메시지 표시 결정이 없습니다. 역사와 통제의 분리는 여전히 원래의 경계를 유지하며, 동일한 주제를 가진 제안은 폐기될 수 없습니다.。

## 대안

프런트엔드 최소값만 변경되며, 어댑터에서 폐기한 시간은 복구할 수 없습니다. 세션 업데이트 시간을 통합하는 것은 구현하기 쉽지만 모든 기록 메시지에 동일한 오류 시간이 표시됩니다. 기본 임시 시간을 보존하고 재사용을 위해 형식을 공유합니다. UI，또한 증거가 없는 오래된 기록이 누락된 상태로 남아 있도록 허용합니다.。

## 검증

기본 필드 투영、Claude 화이트리스트、Codex 역사/쪽수 매기기/증가、ZCode 저장 기록, 알 수 없는 시간 및 시간대 오프셋에 대한 방향 검사가 있습니다. 실시간 이벤트 대체 회귀 적용 범위 CLI、임시 사이드 채팅 및 기본 시작 시간이 있는 첫 번째 입력의 경우 확인은 시간이 없는 창이나 보조자의 후속 입력으로 시간을 전송하지 않습니다. 브라우저는 커버 복사 및 참조 순서로 돌아가고, 채팅 전환 후 편집 또는 분기 버튼, 하위 에이전트 세부 정보, 기본 사이드 채팅 및 참조 격리를 동적으로 추가합니다.。WebKit 네이티브와 함께 Chrome 넓고 좁은 뷰포트 합성 검사를 별도로 실행하여 시간 인접 버튼, 수평 오버플로 없음, 이전 메시지가 값을 생성하지 않음, 새로 고침 노드가 유지되는지 확인합니다.。

완료된 아카이브 10 특수 회귀는 안정적인 ID 및 출처, 양방향 중복 키, 중복 텍스트, 교차 session/turn/type、라운드 시작 대체 우선순위, 인덱스 기본 시간 충돌, 동기화 inode 수정 무효화, 캐시 재사용, 바이트 할당 및 첫 번째 줄 잘림, 스레드 격리 및 중간 스캔 수정 거부. 원래 시간, 기록 경로 및 제어 분리 제품군을 포함한 합계 31 포함하여 검사가 완료되었습니다. 30 항목이 통과됨、1 개 Windows 확장된 경로 체크인 macOS 건너뛰기가 예상됩니다. 증분 테스트가 있으며 시간만 변경되고 텍스트 버전은 변경되지 않지만 새 행은 여전히 ​​푸시되는 것으로 확인되었습니다. 프런트 엔드는 전체 행을 비교하므로 업데이트 시 시간이 다시 그려집니다.。

2026-11-12 현실 8788 Test 제어: 피드백 오디오 채팅이 기록 모드에 있을 때 5개의 어시스턴트 응답은 기본 시간을 갖습니다. 또 다른 실제 채팅이 실행 중입니다 `connected=true` 보조자 응답에 시간이 없으면 동일한 행 ID는 시스템의 기본 인덱스에 명확한 완료 시계를 갖습니다. 근본 원인은 기록 새로 고침 시 연결된 모든 세션을 건너뛰고, 기존 완료 기능은 항상 이전에 저장된 보기를 사용하기 때문입니다. 두 가지 새로운 회귀가 추가되었습니다. 첫 번째 실패 후 통과, 재연결 없음, 실시간 상태 변경 없음, 철회 상한 및 새 메시지 계속 읽기를 포함합니다. 시간과 역사/제어 및 격리 관련 27 항목이 통과되었습니다. 이 페이지는 또한 늦은 시계 재구성 메시지 문제를 재현합니다. 보충 읽기 후에는 시계에 따라 별도로 업데이트되며 미디어 노드는 유지됩니다. 실제 게이트웨이 새 버전 설치 후 온라인 완료는 여전히 최종 승인에 포함됩니다.。

## 영향

모든 클라이언트에는 일관된 기본 상호 작용 시간 표시가 있습니다. 독립적인 순찰 타이머나 쓰기를 추가하지 않고도 기존 백그라운드 읽기가 재사용됩니다. 현재는 데이터 의미론, 공유 인터페이스 및 위에서 언급한 진정한 읽기 전용 비교에 대한 비교입니다. 화면별 비교나 각 기본 응용 프로그램의 비교는 없습니다. iPhone/Android 실제 머신 수용은 모든 기본 버전에 대해 픽셀 수준 일관성이라고 할 수 없습니다. 기본적으로 메시지 시간이 누락된 경우에도 여전히 누락됩니다.；Codex 라운드 시작 시간만 제공하고 첫 번째 사용자 메시지만 태그된 스냅샷。
