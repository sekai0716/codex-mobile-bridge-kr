# Agent Note: 게이트웨이 지원 Android 설치 패키지 쿼리 및 다운로드

Status: implemented

## 문제

휴대폰으로는 접속이 불가능합니다 GitHub 언제, 버전을 확인하거나 앱에서 다운로드하세요 APK 모두 실패할 수 있습니다. 브라우저 포털은 네트워크 접근성 변경을 보장하지 않습니다. 컴퓨터 게이트웨이에 사용 가능한 네트워크가 있을 수 있으며 휴대폰이 컴퓨터에 인증된 연결을 설정했습니다.。

## 결정

Android 쿼리 버전은 직접 액세스를 유지합니다. GitHub、현재 연결된 컴퓨터를 통해 실패 후 다시 시도하는 경로입니다. 첫 번째 버전 다운로드에서도 이 순서를 사용하는데, 그 이유는 다음과 같습니다. API 말이 안 돼요 APK 다운로드 주소를 사용할 수 없습니다. 이 다운로드에 대한 자동 롤백 결정은 다음에 의해 이루어졌습니다. [다운로드 방법 선택 기록](2026-10-12-android-update-download-choice.md) 부분적으로 대체된 쿼리 대체 경로와 다음 게이트웨이 계약은 계속 적용됩니다. 휴대폰에서 선택한 버전, 크기 및 요약은 게이트웨이가 고정 공식 창고에서 읽은 자산 기록과 동일해야 합니다. 게이트웨이는 버전 및 자산 ID만 허용하며 어떤 것도 허용하지 않습니다. URL。설치 및 인계 후 계속 사용 [Android 인계 기록 업데이트](../bug-fix/2026-10-12-android-update-handoff.md) 완성된 파일 복구 메커니즘。

게이트웨이는 먼저 개인 캐시에 완전히 다운로드하고 확인한 후 인증된 다운로드 인터페이스를 통해 휴대폰에 전달합니다. 사용 요청 준비 CSRF，진행 쿼리는 긴 요청을 차지하지 않습니다. 다운로드 캐시는 현재 실행 주기 동안에만 유지되며 더 이상 유휴 상태가 되지 않습니다. 24 매시간 주문형 청소, 최대 2개 작업/캐싱, 한 번에 하나의 백그라운드 다운로드, 패키지당 최대 512 MiB。휴대폰은 대기를 취소하고 로그인된 다른 휴대폰에서 재사용할 수 있는 컴퓨터 백그라운드 작업을 유지합니다. 휴대폰에는 프로세스 전반에 걸쳐 완료되지 않은 다운로드를 유지하겠다는 약속이 없습니다.。

기존 첨부 파일 전송을 위한 범위 협상 및 릴레이 스트리밍 프로토콜은 계속해서 재사용됩니다. 릴레이, 커넥터, 게이트웨이는 모두 정확한 업데이트 경로와 방법을 제한하며, 게이트웨이 인증 정보는 선택된 주소로만 전송됩니다.，GitHub 요청에는 이 정보가 포함되지 않습니다. 휴대폰으로 완성도를 다시 확인해보세요 APK 크기와 요약은 최종적으로 확인을 위해 시스템 설치 프로그램에 전달됩니다.。SHA-256 손상을 감지하는 데 사용되며 독립적인 게시자 서명으로 설명되지 않습니다.。

## 대안

- **휴대폰 직접 연결 및 브라우저 개인 정보 보호만 유지**：단일 종단 구현 및 유지 관리는 간단하지만 휴대폰 네트워크에 완전히 연결할 수 없는 경우 두 경로 모두 실패할 수 있으며 컴퓨터에 연결된 네트워크를 사용할 수 없습니다.。
- **상담원 전용 APK 파일**：새로운 인터페이스는 적지만 휴대폰에서 버전 정보를 얻지 못하고 다운로드 단계까지 전혀 도달하지 못할 수 있으므로 쿼리에도 게이트웨이에 대한 백업 경로가 필요합니다.。
- **다운로드하는 동안 컴퓨터가 긴 응답을 직접 전달합니다.**：첫 번째 전송에 대한 대기 시간을 줄일 수 있지만 다운로드와 휴대폰 연결 끊김, 재시도 및 장기간의 데이터 반환 없음 처리 간의 결합이 더 복잡합니다. 무결성, 진행 및 재시도 경계를 명확하게 하기 위해 먼저 캐시하기。

## 시험

`tests/test_mobile_updates.py` 릴리스 채널, 고정 소스, 자산 ID, 동시 재사용, 실패 재시도, 전체 확인, 만료 및 인증을 다룹니다.、CSRF 및 범위 응답；`tests/test_shared_relay.py` 실제 기본 커넥터로 새로운 인터페이스 검증。`GatewayUpdateDownloadTests.java` 장치 접두사, 다이제스트, 리디렉션 금지 및 캐시 무효화 후 다시 준비를 통해 인증된 다운로드를 확인합니다. 커밋 무시에 저장된 시뮬레이터 증거로 빌드 `.tmp/pr32-gateway/`。

독립 테스트 패키지는 LAN 고정 장치를 사용하여 휴대폰 쿼리 및 다운로드 실패와 다운로드 실패만 시뮬레이션합니다. 두 시나리오가 모두 패키지되어 있습니다. macOS 게이트웨이 완료 Android 에뮬레이터에 설치되었습니다. 설치 권한 페이지 중 종료 App 백그라운드 프로세스 후에 설치를 재개할 수 있습니다. 동일한 버전의 테스트 업데이트가 트리거되고 다시 완료될 수 있습니다. 마지막으로 설치된 에뮬레이터에서 제거되었습니다. APK 요약은 제공된 대상 패키지와 일치합니다. 이러한 시뮬레이션 결과는 실제를 나타내지 않습니다. GitHub 네트워크가 확인되었습니다. 그런 다음 사용자는 실제 테스트가 통과되었으며 소스 코드만 병합할 권한이 있다고 보고합니다.。

## 영향

휴대폰은 컴퓨터 네트워크를 사용하여 업데이트를 완료할 수 있으며, 컴퓨터는 다운로드한 패키지를 재사용할 수도 있습니다. 가격은 게이트웨이 저장, 전송 트래픽 및 크로스 엔드 프로토콜 유지 관리입니다. 공유 릴레이도 화이트리스트를 업그레이드해야 합니다. 컴퓨터도 접속불가 GitHub 그리고 캐싱이 없으면 이 기능은 네트워크 문제를 해결할 수 없습니다. 기존 게이트웨이는 휴대폰의 원래 직접 연결 경로에 영향을 미치지 않습니다.。

이력 검색은 앞서 언급한 설치 인계 기록에만 해당하며 부분적으로 중복됩니다.: 원본 GitHub 다운로드 및 설치 복구 제약 조건은 계속 적용됩니다. 이 글은 게이트웨이를 통해 전송되는 소스타입과 인증계약을 추가합니다. 보관해야 할 다른 제안서는 없습니다.。
