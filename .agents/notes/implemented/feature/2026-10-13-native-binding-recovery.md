# Agent Note: 기본 장치 바인딩 복구

Status: implemented

## 문제

오리지널 휴대폰 케이스 WebView Cookie 앱 업그레이드 또는 시스템 정리 후에는 손실될 수 있습니다. 서버는 인증되고 취소 가능한 장치 세션을 계속 유지하지만 기본 셸에는 독립적인 보안 복사본이 없으므로 사용자는 다시 로그인하거나 QR 코드를 스캔해야 합니다.。

## 결정

양쪽 끝의 백업만 통과했습니다. `/api/auth` 확인됨 `trustedDevice` 저장된 컴퓨터 주소로 인덱싱된 세션 토큰。Android 사용 AndroidKeyStore 의 AES-GCM 키의 암호화된 사본, 암호문은 애플리케이션 개인 환경설정에 저장됩니다.；iOS 사용 `WhenUnlockedThisDeviceOnly` Keychain 목. 토큰은 여전히 ​​게이트웨이 또는 릴레이의 기존 세션 테이블에 의해 취소되며 새 비밀번호, QR 코드 또는 취소할 수 없는 두 번째 자격 증명 세트가 추가되지 않습니다.。

WebView 로드하기 전에 다음과 같은 Cookie 안전한 복사본이 없거나 일치하지 않는 경우 기본 엔드는 읽기 전용, 동일한 출처, 리디렉션 금지 및 시간 제한을 사용합니다. `/api/auth` 현재 확인 Cookie 및 보안 사본. 최초 로그인 시 기록을 완료하세요. Cookie 스냅샷, 게이트웨이가 반환되기를 기다리는 중 `cookieName` 그런 다음 해당 토큰을 선택합니다. 이전 이름 ​​마이그레이션은 동일한 토큰만 허용하며 토큰을 변경하지 않습니다. Cookie 위치가 잘못되었습니다. 현재의 Cookie 유효한 경우 일반 인증 콜백에서 복사본을 유지하고 업데이트합니다. 보안 사본은 서버와 그 서버에 의해 유효한 것으로 확인됩니다. Cookie 이름은 게이트웨이에 속하는 경우에만 복원됩니다. 없음 `cookieName` 이전 직접 연결 게이트웨이 및 릴레이는 이전 버전만 허용합니다. Cookie 이름. 복사본이 명백히 유효하지 않은 경우 삭제하고, 네트워크 오류가 있는 경우 다음 시도를 위해 보관하십시오. 열린 페이지를 받았습니다. 401 현재는 실패 주기당 하나의 기본 체크섬 읽기 전용 페이지 다시 로드만 트리거됩니다. 복구에서는 메시지나 쓰기 요청을 재생하지 않습니다. 비동기 검증이 완료되면 장치 자격 증명, 페이지 생성 및 현재를 다시 확인하십시오. ## 대안

다시 저장된 비밀번호 또는 재사용 가능한 스캔 페이로드를 사용하면 다시 로그인할 수 있지만 장기 비밀 및 페어링 기능이 확장됩니다. 별도의 복구 토큰과 HTTP 엔드포인트는 로그인 토큰에서 분리될 수 있지만 새로운 서버 저장소, 해지 및 릴레이 프로토콜이 필요합니다. 기존 기본 장치 세션은 이미 지속적이고 취소 가능하므로 재사용 규모가 더 작습니다.。

## 영향

Cookie 손실된 후에도 여전히 유효한 바인딩은 로그인 화면을 로드하기 전이나 페이지가 이미 열려 있을 때 발생할 수 있습니다. 401 복원 시간; 해지된 후에는 서버를 복원할 수 없습니다. 복구가 필요한 경우 제한된 시간의 읽기 전용 확인이 추가되고 오프라인일 때 원래 페이지 오류 경로가 계속 입력됩니다.。Android KeyStore 또는 iOS Keychain 일반 텍스트 토큰은 사용할 수 없는 경우 일반 기본 설정에 기록되지 않습니다. 실제 장치의 저장소 및 시스템 정리 동작에는 여전히 장치 확인이 필요합니다.。

관련된 Cookie 이름 및 레거시 호환성 규칙은 다음을 참조하세요.[게이트웨이 세션 Cookie 검역 기록](../bug-fix/2026-10-13-gateway-cookie-namespace.md)。이 기록만이 역사적 기록에서 부분적으로 중복됩니다. 게이트웨이 이름 지정을 지정하고 이 문서에서는 기본 안전 복사 및 복구 타이밍을 지정합니다.。
