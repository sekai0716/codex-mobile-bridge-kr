# Agent Note: Android 사용자가 선택한 다운로드 방법 업데이트

Status: implemented

## 문제

실제 테스트에서는 사용자가 ’다운로드 및 설치’를 클릭하면 다운로드할 컴퓨터에 자동으로 진입해 어느 쪽 네트워크를 사용할지 명확하게 결정할 수 없게 됐다. 사용자는 전화기에 접근할 수 없다는 것을 알 수 있습니다. GitHub，셀룰러 네트워크만 사용하고 싶을 수도 있으며 요청 실패로 대체되어서는 안 됩니다.。

## 결정

”다운로드 및 설치”를 클릭하면 두 가지 작업이 표시됩니다. 휴대폰이 직접 다운로드합니다. GitHub 다운로드, 컴퓨터에서 GitHub 다운로드 후 휴대폰으로 전송하세요. 해당 다운로드는 사용자가 클릭한 후에만 시작됩니다. 취소되면 시작되지 않습니다. APK 다운로드 또는 게이트웨이 준비. 다시 다운로드할 때마다 선택 가능, 영구 기본 옵션은 도입되지 않음。

휴대폰으로 직접 다운로드가 실패한 후에는 컴퓨터가 자동으로 사용되지 않습니다. 다운로드 카드는 ”재선택”을 제공하며「GitHub ↗」입구. 후자는 외부 브라우저를 사용하여 현재 감지된 공식 버전을 엽니다. APK 직접 링크의 경우 브라우저가 다운로드를 담당합니다. 원래 작업이 컴퓨터에서 나온 경우에도 게이트웨이 주소나 자격 증명이 브라우저로 전달되지 않습니다. 재개 가능한 작업은 동일한 경로를 다시 선택할 때 재사용할 수 있으며, 경로 변경 시 해당 새 작업을 생성할 수 있습니다. 일시 중지 후 재개는 여전히 선택한 경로를 따릅니다. 컴퓨터를 선택할 때 현재 저장된 컴퓨터 연결을 사용하고 로그인, 버전, 크기 및 요약을 계속 확인하십시오.。

버전 쿼리를 사용하면 직접 쿼리가 실패한 후에도 컴퓨터에서 직접 쿼리를 쿼리할 수 있으므로 휴대폰이 업데이트를 검색하지 못하는 것을 방지할 수 있습니다. 쿼리 성공과 다운로드를 담당하는 쪽은 두 가지 독립적인 결정입니다. 게이트웨이 소스 제한, 캐싱, 인증, 릴레이 및 설치 복구가 상속됩니다. [게이트웨이는 기록 업데이트를 지원합니다.](2026-10-12-gateway-assisted-android-update.md) 및 [설치인계기록](../bug-fix/2026-10-12-android-update-handoff.md)。

## 대안

- **자동 대체 유지**：작동 단계가 거의 없으며 네트워크가 정상일 때 사용자는 소스에 대해 신경 쓸 필요가 없습니다. 그러나 네트워크 경로를 명확하게 선택해야 하는 사용자의 요구 사항을 충족할 수 없으며, 모바일 네트워크를 사용할 수 없음을 알고 있는 사용자가 먼저 기다리고 실패하게 만듭니다.。
- **휴대폰을 선택한 후에도 자동으로 컴퓨터로 돌아갑니다.**：작업이 실패하면 하나의 작업을 저장할 수 있지만 선택한 경로의 의미가 명확하지 않습니다. 실패 후 사용자는 다시 선택하게 되며 재시도 및 브라우저 항목은 유지됩니다.。

## 시험

선택하기 전에 독립형 LAN 테스트 패키지를 사용하여 옵션이 없는지 확인하십시오. APK 요청이나 취소시 다운로드가 되지 않으며, 휴대폰 장애 시 컴퓨터도 장애가 발생합니다. APK 요청, 게이트웨이를 직접 요청하기 위한 컴퓨터 선택, 다운로드 실패 후 재선택 등이 있습니다. 다운로드 실패 카드에 대한 추가 검증「GitHub ↗」외부에서 Chrome 열려 있는 APK 직접 링크, 확인 후 다운로드한 파일 요약이 테스트 패키지와 일치합니다. LAN 결과는 실제를 나타내지 않습니다 GitHub 네트워크가 확인되었습니다. 설치 패키지와 시뮬레이터 검증 증거가 다음 위치에 있습니다. `.tmp/pr32-gateway/`。사용자는 실제 테스트를 통과했으며 소스 코드를 병합할 권한이 있다고 보고했습니다. 이번에는 컴파일되지 않습니다. App 아니면 새 버전을 출시하든지。

## 영향

사용자는 다운로드하기 전에 추가 선택 항목을 추가하는 비용으로 사용 가능한 네트워크를 직접 선택할 수 있습니다. 컴퓨터를 다운로드하려면 현재 게이트웨이가 이 기능을 지원하고 로그인되어 있어야 합니다. 어느 쪽에서도 접근할 수 없습니다 GitHub 여전히 실패할 수 있습니다. 이 변경 사항은 다음으로 제한됩니다. Android 게이트웨이 인터페이스를 변경하지 않고 상호작용 다운로드。

기록 검색은 부분적으로 겹치는 두 개의 관련 레코드에 도달합니다. 게이트웨이 레코드의 다운로드 자동 롤백 부분은 대체되고 서로 연결되며 소스, 인증 및 캐시 제약 조건은 유지됩니다. 설치 인계 기록의 파일 검증 및 복구 제약 조건은 계속 적용됩니다. 완전히 흡수되거나 오래된 제안을 보관할 필요가 없습니다.。
