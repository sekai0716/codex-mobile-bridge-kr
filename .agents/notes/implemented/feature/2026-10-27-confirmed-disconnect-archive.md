# Agent Note: 확인 후 중지, 해제 및 보관

Status: implemented

## 문제

연결을 끊다 Bridge 읽기 연결은 기본 작성자를 해제하지 않습니다. 사용자가 선택한 채팅을 보관하기 전에 중지하도록 명시적으로 요청하고 다음을 입력했습니다.“보관 확인”、오른쪽에 놓으세요.“취소”。중지 실패는 보관으로 이어질 수 없으며 다시 연결한 후 새로운 중지 작업으로 재생할 수 없습니다.。

## 결정

아카이브 요청은 명시적으로 전달됩니다. `disconnect:true`，원래 대상과 확인된 하위 항목의 정확한 계산을 중지하는 선택을 나타냅니다. 이전 요청은 유휴 전용 의미를 유지합니다. 복구 작업은 결코 중단되지 않습니다. 기존 수명주기 검사를 통해 작동 중 새로운 수명주기 검사 방지 Bridge 제출하다. 중지 또는 해제 전에는 기존의 알 수 없는 영수증이 유지됩니다. 중지 후 기본 상태를 다시 읽은 다음 원래 런타임을 통해 보관됩니다. 채팅을 확보하기 위해 공유 앱을 닫지 마세요./관련 없는 프로세스를 악마화하거나 종료합니다. 제어할 수 없는 기본 기여 프로세스는 명시적으로 실패를 보고하고 성공을 위조하지 않습니다.。

확인 상자에는 제목, 실행 호스트 및 중단 결과가 표시됩니다. 보관 확인은 왼쪽에 있고 취소는 오른쪽에 있으며 기본적으로 포커스를 받습니다. 두 버튼 모두 동일한 기존 기본 버튼 스타일과 동일한 너비의 그리드 열을 사용합니다. 모바일 너비의 시각적 수용은 취소 라벨이 너무 좁거나 포장되는 것을 방지합니다. 취소、Escape 대화 상자를 닫아도 요청이 전송되지 않습니다. 복원으로 인해 독립적인 작동이 유지됩니다.。
