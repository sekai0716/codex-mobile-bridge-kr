## 문제

이 제안은 부분적으로 대체됩니다.[네이티브 사이드 채팅](../../implemented/feature/2026-11-07-native-attached-side-chats.md)독립적인 메타데이터 프로세스를 사용하는 옵션[영구 삭제](../../implemented/feature/2026-11-07-native-session-deletion.md)의 채팅방이 오픈되었습니다. 원래의 상위-하위 관계, 작업 원장, 알 수 없는 결과 재생 금지 및 작업 확인 규칙은 계속 유효합니다.。[VS Code 공유됨 owner](../../implemented/bug-fix/2026-11-03-vscode-shared-owner.md)이를 기반으로 다른 액세스 경로를 처리할 수 없습니다. Desktop stdio 공유됨. 이 세 가지 기사는 유지되고 서로 연결됩니다. 다른 히트작 CLI、WSL 보관된 메모는 이 제안으로 대체되지 않습니다.。

## 제안

원본으로 App 지원됨 CLI 경로 구성 액세스 투명 stdio 어댑터. 어댑터는 남아있습니다 App 초기화, 구성, 요청 식별, 알림 및 발행된 서버측 승인 요청 같은 원주민에 의해 app-server 동일한 사용자에게 비공개 로컬 연결 제공，Bridge 별도의 클라이언트 ID를 사용하여 작업을 수행합니다. 채팅 실행, 로그인, 권한 및 프런트 데스크 소유권은 여전히 ​​원본에 의해 제어됩니다. App 유지, 수정하지 않음 App 패키지를 설치하거나 기본 데이터베이스에 직접 쓰십시오.。

첫 번째 스위치는 정상적으로 종료되고 명시적인 초기화와 유휴 상태의 즉각적인 확인 후에 다시 시작됩니다. App。Bridge 연결 끊김 또는 게이트웨이 업데이트로 원본을 종료할 수 없습니다. App 런타임의. 원래의 App 평범한 CLI 도구, 시작 구성 감지, 컴퓨터 작동 지원 런타임 및 WSL 통화 시 실수로 이 공유 서비스에 액세스해서는 안 됩니다.。

프로덕션 액세스가 아직 구현되지 않았으며 현재 마스터가 전환되지 않았습니다. App。원본을 완성하세요 App 생성, 삭제 및 인터페이스 동기화 승인 후 기존 생성 및 삭제 업무 프로세스에 접근할 수 있습니다.。

## 대안

독립 메타데이터가 실행 중일 때 완전한 기록 원장이 있고 수명 주기가 짧으며 변경 사항이 적습니다. 하지만 원본을 넘을 수는 없습니다. App 작성자 잠금이므로 보관되지 않은 원본 기록에만 적용됩니다.。

전반적인 상황 `CODEX_APP_SERVER_WS_URL` 공유 런타임에 직접 연결하는 것이 가능하지만 원본 App 이 모드에서는 다음을 포함하여 기본 클라이언트 조정을 비활성화합니다. Desktop IPC 기존 액세스 기능을 유지하기 위한 요구 사항을 충족하지 않는 부분 상태 방송.。

실제 신원이 포함된 쿼리 실패 브로드캐스트만 위조되지 않습니다. owner，그리고 새로 추가된 목록을 새로 고칠 수 있다는 것이 입증되었습니다. 그러나 삭제 시 태그를 열면 레코드가 메뉴에 다시 병합되며 태그 동기화를 닫을 수 없습니다.。

가짜 기본 삭제, 보관 또는 owner 상태, 수정 App 프론트 엔드, 네이티브 파일 직접 삭제, 알 수 없는 수신 후 삭제 재전송은 사용되지 않습니다. 기본 아카이브 구현에 대한 읽기 전용 검사에서는 태그를 닫기 위해 성공적으로 콜백하기 위해 메뉴에도 의존하는 것으로 나타났습니다. 진실 `thread-archived` 브로드캐스트는 사이드 탭 컨트롤러를 호출하지 않습니다. 따라서 먼저 아카이브한 후 삭제하면 동기화를 완료할 수 없으며, 실패 시 아카이브가 중간 상태로 남을 위험이 높아집니다. 사용하지 마십시오。
