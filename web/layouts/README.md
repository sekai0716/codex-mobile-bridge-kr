# 넓고 좁은 레이아웃

이 레이어는 사용 가능한 크기에 따라서만 페이지를 구성합니다. 브라우저、Android、iOS 호스트 ID 및 기본 메뉴는 다음에서 제공됩니다. `web/hosts/` 관리; 토종의 App 와이드스크린 분할 화면을 사용할 수도 있고, 컴퓨터 브라우저도 좁은 화면 레이아웃으로 들어갈 수도 있습니다.。

| 공들여 나열한 것 | 항목 수정 | 현재 행동 |
| --- | --- | --- |
| Wide：기본 나란히 | `wide/` | 왼쪽의 세션 목록 310px，오른쪽의 남은 공간을 사용하세요. 기본 구조로, 좁은 너비와 중간 너비의 후속 규칙에 의해 재정의됩니다.。 |
| Compact：이하 720px | `compact/` | 대화 목록 및 채팅 표시 전환, 채팅 헤더, 입력 영역 및 클라이언트 세션 레이아웃 조정。 |
| Medium：휴대폰 및 소형 태블릿 확장 | `medium/` | 세션이 시작된 후 워크벤치에 전체 페이지 너비를 제공하십시오. 원본을 유지하다 721–1099px 워크벤치 규칙 및 721–1100px 클라이언트 탐색 규칙。 |
| 작업대 분할 화면 | `viewport.js`、`../features/workspace/workbench.js` | 채팅 컨테이너의 실제 너비를 사용하세요. 도달하다 720px 화면을 분할하려면 다음을 사용하세요. App 호스트 또는 장치 이름은 관련이 없습니다.。 |

`viewport.js` 의 `BridgeLayout` 좁은 화면 미디어 쿼리와 터치 포인터 쿼리도 사용할 수 있습니다. 터미널 입력이 유지됨“기본 셸 또는 터치 장치 또는 좁은 화면”조합조건; 명령 터미널은 `innerWidth` 캐리지 리턴 전송 동작을 결정합니다. 복용하지 마십시오 `bridge-mobile` 화면 너비 추론。

파일、Git、터미널 내부의 반응형 제어 스타일과 기타 기능은 여전히 ​​해당 기능을 따릅니다. CSS；이 디렉토리는 페이지 수준 레이아웃을 담당하며 전체 채팅 인터페이스를 복사하지 않습니다.。

## CSS 주문하다

`web/assets.json` 원본을 위해 CSS URL 소스 파일의 정렬된 배열 정의。HTTP 이 순서대로 릴레이를 연결하고 반환하면 브라우저는 여전히 원래 주소를 요청합니다. 파일 생성이 필요하지 않으며 스타일 요청도 추가되지 않습니다.。

동일한 스타일 시트에서는 기본 규칙, 너비 및 좁은 레이아웃 규칙, 기본 호스트 규칙의 상대적 순서가 유지되어야 합니다. 따라서 일부 기본 및 호스트 스타일은 헤더, 콘텐츠, 입력, 탐색 등의 조각으로 구분됩니다. 모든 레이아웃 파일이나 호스트 파일을 끝으로 이동하지 마십시오. 동일한 선택기는 계단식 순서에 따라 효과를 변경합니다.。

조각을 추가하거나 이동할 때 매니페스트를 동기화하고 실행합니다. `npm run test:desktop`。크기 동작에는 실제 브라우저 확인이 필요하며 최소한 재정의해야 합니다. 390px 세로 화면、844px 가로 화면과 1440px 너비를 조정할 때 와이드스크린, 초안 유효성 검사, 열린 탭, 스크롤 위치 및 분할 화면 기본 설정이 유지됩니다.。
