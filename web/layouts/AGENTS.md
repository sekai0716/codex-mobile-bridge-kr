# 페이지 레이아웃 수정 범위

- 먼저 `README.md`를 읽습니다. `wide/`가 기본 2열 구조를 정의하고, `compact/`와 `medium/`은 이후에 화면 크기별 스타일을 덮어씁니다. 기존 분기점과 캐스케이드 순서를 유지합니다.
- 화면 크기와 호스트는 독립적입니다. 이 계층에서 iOS/Android, UA, `bridge-mobile` 여부를 판단해서는 안 됩니다. 호스트별 표시는 `web/hosts/`, 네이티브 동작은 `mobile/`에서 담당합니다.
- 분할 화면 판단에는 채팅 컨테이너의 실제 너비를 사용합니다. 전체 창 너비나 기기 종류를 직접 사용해서는 안 됩니다. 크기 변경으로 대화를 다시 만들거나, 초안을 비우거나, 사용자의 탭·분할 화면 선택을 초기화해서는 안 됩니다.
- 공통 채팅·파일·터미널 등의 기능은 계속 `web/features/`에서 관리합니다. 기능 내부 컨트롤의 반응형 스타일은 해당 기능과 함께 관리하며, 여기에 페이지 전체를 복제하지 않습니다.
- CSS 규칙을 옮길 때 `web/assets.json`의 순서가 있는 소스 목록도 함께 갱신합니다. 공개 URL, 상대 리소스 주소, 규칙 우선순위를 변경하지 않습니다.
- `tests/layouts.test.cjs`와 리소스 검사를 실행합니다. 배치를 변경한다면 격리된 브라우저 픽스처로 세로·가로·넓은 화면을 검증합니다. UA/class를 모의한 검사는 네이티브 WebView 검증을 완료했다는 뜻이 아닙니다.
