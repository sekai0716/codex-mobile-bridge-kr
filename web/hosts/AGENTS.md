# 호스트 환경별 구현 제약

- 여기서는 browser/iOS/Android 호스트의 실제 특성과 화면 표시를 처리합니다. 화면 너비를 근거로 브라우저를 모바일 앱으로 판단하지 않습니다.
- 좁은 화면, 가로 화면, 터치 입력, 워크벤치 분할 가능 여부의 판단은 `web/layouts/`에서 담당합니다. viewport로 호스트를 추정해서는 안 됩니다. 호스트 전용 CSS의 기존 미디어 조건은 유지할 수 있지만, 공통 레이아웃의 분기점을 여기서 재정의해서는 안 됩니다.
- 네이티브 UA/class는 위조할 수 있는 단서입니다. 권한 부여의 근거로 삼거나 네이티브 token/origin/frame/실제 클릭 검증을 대신해서는 안 됩니다.
- 네이티브 레이아웃 표식은 페이지 스크립트보다 늦게 생길 수 있으므로 조회는 계속 동적으로 수행해야 합니다. 백그라운드 폴링은 추가하지 않습니다.
- Android/iOS 공용 삽입 스크립트는 `mobile/shared/web/`에 둡니다. Java/Swift에 다시 복사하거나 원격 주소에서 로드해서는 안 됩니다.
- CSS를 분리할 때 기존 캐스케이드 순서를 반드시 유지해야 합니다. 순서가 있는 리소스 목록을 갱신하고 결합 결과와 좁은 화면·넓은 화면 레이아웃을 검증합니다.
