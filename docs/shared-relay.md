# 자체 호스팅 공유 중계 (v2 내부 베타)

> 아카이브: 초대 코드 릴레이가 데스크탑 게이트웨이에서 제거되었으며 더 이상 게이트웨이와 함께 실행되지 않습니다. 이 기사는 독립적으로 유지됩니다. relay 서비스의 기록 구성 설명입니다. 개인적으로 접근하려면 다음을 사용하십시오. [자체 서버 + SSH](server-ssh.md) 또는 [Tailscale](tailscale.md)。

공용 네트워크 서버는 여러 사용자에게 연결을 전달할 수 있습니다. 각 사용자는 자신의 컴퓨터 게이트웨이를 설치하고 계속해서 사용합니다. Codex、모델 계정 및 프로젝트。

```text
휴대폰 A → 공유됨 HTTPS 입구 → A 아웃바운드 연결 → A 컴퓨터 게이트웨이 → A 의 Codex
휴대폰 B → 공유됨 HTTPS 입구 → B 아웃바운드 연결 → B 컴퓨터 게이트웨이 → B 의 Codex
```

**릴레이 서버가 필요하지 않음 GUI、감시 장치、Electron 또는 Codex，모델은 필요없어 API Key。** 다음에서만 실행할 수 있습니다. SSH 의 Linux 클라우드 서버에서. 작업이 여전히 사용자의 컴퓨터나 기존에 있습니다. SSH 프로젝트 호스트 실행; 컴퓨터、Codex 게이트웨이를 통해 온라인 상태를 유지해야 함。

현재 개발 버전은 다음에서 사용할 수 있습니다. **네트워크 접속 → 자체 제작 트렁크 · 내부 베타** 기본적으로 등록되지 않거나 활성화되지 않은 자체 서버를 구성하세요. 이전 버전 설치 패키지는 이 항목을 숨기거나 포함하지 않을 수 있습니다. 이 문서는 현재 소스 코드에 해당합니다. 프로젝트 당사자가 주최하는 공공 서비스가 아닙니다.。

## 선택하다 SSH 고정된 입구 또는 자체 구축 릴레이？

- 1인이 사용하고 모든 직접 연결 기능을 유지하고 싶은 경우: 우선순위를 부여할 수 있습니다.[고정 도메인 이름 · 자체 서버 + SSH](server-ssh.md)。중계 애플리케이션을 배포할 필요가 없으며 공용 네트워크 서버가 제공합니다. HTTPS 컴퓨터를 받고 SSH 역방향 연결。
- 여러 컴퓨터 또는 사용자가 입구를 공유하므로 초대 코드 및 장치 관리가 필요합니다. 이 릴레이를 배포하면 컴퓨터가 외부로 나가게 됩니다. WSS 서버에 연결。

두 경로 모두 완전히 우회 가능 Cloudflare Tunnel。도메인 이름은 Alibaba Cloud와 같은 등록 기관에서 계속 갱신될 수 있습니다. 등록기관은 웹 트래픽 경로를 결정하지 않습니다. 계속 사용 중인 경우 실제 서버에 액세스하는 데 사용되는 하위 도메인 이름을 확인하세요. Cloudflare DNS，만 사용 DNS 프록시를 다시 거치지 않도록 구문 분석。

서버 선택시 동시 측정“휴대폰에서 서버로”및“컴퓨터에서 서버로”회선, 패킷 손실 및 대역폭. 국내 지역이 국내 액세스에 더 적합할 수 있지만 특정 클라우드 벤더나 지역이 더 빠를 것이라는 보장은 없습니다. 중국 본토의 Alibaba Cloud 서버는 도메인 이름을 사용하여 제공됩니다. Web 서비스를 이용하려면 해당 등록이 필요합니다. 지역 및 요구사항을 참고하시기 바랍니다.[Alibaba Cloud 공식 설명](https://help.aliyun.com/zh/ecs/cross-region-usage-faqs)。

## 관리자가 서버를 준비합니다.

일반 서비스 사용자 `codex-relay`, Python 3.10 이상(권장 3.13), 공개 도메인 이름과 HTTPS 역방향 프록시를 준비하세요. 다음 경로는 예시이므로 실제 배포 환경에 맞게 조정하세요. 사용자의 `.codex`, PC의 개인 데이터 또는 모델 자격 증명을 서버에 복사하지 마세요.

이 브랜치의 소스 코드를 `/opt/codex-mobile-bridge`，프로젝트 디렉토리에 독립 환경 생성：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-relay.txt
```

포그라운드에서 실행（일반 사용자, 데스크톱 세션 필요 없음））：

```sh
.venv/bin/python -B -m relay --data-dir /var/lib/codex-bridge-relay serve --origin https://relay.example.com
```

데이터 디렉터리는 서비스 사용자만 읽고 쓸 수 있어야 합니다. 서비스는 기본적으로 `127.0.0.1:18790`에서만 수신합니다. 외부 HTTPS 프록시는 원래 `Host`를 유지하고 `WebSocket Upgrade`를 지원해야 합니다. 읽기 제한 시간은 최소 120초, 요청 본문 제한은 20 MiB로 설정하세요. API 캐시와 쓰기 요청의 자동 재시도를 모두 비활성화하세요. `18790` 포트를 인터넷에 직접 공개하지 마세요. 도메인 이름, 인증서와 서버 구성은 관리자가 준비합니다.

장기간 작동에 사용할 수 있습니다. [systemd 서비스 템플릿](../deploy/relay/codex-bridge-relay.service)。먼저 도메인명과 프로젝트 경로를 수정하고 일반 서비스 사용자가 있는지 확인한 후 관리자가 서비스를 설치 및 시작합니다. 템플릿은 시스템 소프트웨어를 설치하지 않으며 필요하지 않습니다. GUI。

자격증명 없는 상태 확인：`GET /health`。응답은 릴레이 서비스가 활성 상태임을 나타낼 뿐 사용자 컴퓨터가 온라인 상태임을 의미하지는 않습니다.。

## Web 관리 백엔드（릴레이와 포트 공유））

터미널 Web 백그라운드에서 동일한 초대 및 장치 기록 공유。Web 백엔드는 릴레이 서비스에서 직접 제공되며 필요하지 않습니다. Node.js、별도의 프런트엔드 프로세스 또는 서버 GUI。관리자는 자신의 컴퓨터에서 브라우저를 사용하여 작업할 수 있습니다.。

처음 사용하는 경우, 동일한 서비스 사용자를 이용하여 서버 단말에서 독립적인 관리키를 생성합니다.：

```sh
.venv/bin/python -B -m relay --data-dir /var/lib/codex-bridge-relay admin-token
```

반품된 물품을 올바르게 보관하세요 `adminToken`，열려 있는 **`https://relay.example.com/relay/admin/`**，키를 붙여 로그인하세요. 이 주소는 모바일 포털 및 컴퓨터 연결과 동일한 도메인 이름과 동일한 백엔드 포트를 공유합니다. `18790`；기존의 HTTPS 프록시는 전체 도메인 이름을 이 포트로 전달할 수 있으며 백엔드를 위해 다른 포트를 열 필요가 없습니다. 직접적으로 공개되지는 않습니다 HTTP 관리 포트。

백그라운드에서는 가능합니다：

- 사용자 메모와 유효기간을 입력하고 초대코드를 생성한 후 중계주소를 포함한 접속정보를 복사하여 해당 사용자에게 비공개로 전송합니다.。
- 초대코드의 사용 가능, 사용, 만료 상태를 확인하세요. 전체 초대 코드는 생성 시 한 번만 표시되며 페이지를 새로 고친 후에는 검색할 수 없습니다.。
- 컴퓨터 이름, 소유권 정보, 온라인 상태 및 등록 시간을 보려면“새로 고침 상태”최신 상태 확인。
- 확인 후 컴퓨터 접속 및 휴대폰 인증을 모두 취소해 주세요. 온라인 연결이 종료됩니다. 에 제출됨 Codex 결과적으로 작업이 취소되지 않습니다.。

관리키가 생성되지 않으면 백엔드에 로그인할 수 없습니다. 아래 터미널 명령을 사용하여 서비스를 관리할 수 있습니다. 관리 키는 사용자 초대 코드, 컴퓨터 토큰, 휴대폰 로그인과 별개입니다. 액세스 사용자에게 관리 키를 발급하지 마십시오.。

백엔드 로그인이 유효합니다. 8 시간이 지나면 자발적으로 퇴장할 수 있습니다. 다시 달리다 `admin-token` 회의**키를 순환하고 기존의 모든 관리 로그인을 즉시 무효화합니다.**，서비스를 다시 시작할 필요가 없습니다. 일반 컴퓨터 및 휴대폰 인증에는 영향을 미치지 않습니다. 이 명령은 키가 분실되거나 유출된 경우 키를 복원하는 데에도 사용할 수 있습니다.。

## 초대코드 발급 및 장비 관리

서버 프로젝트 디렉터리에서 동일한 서비스 사용자로 실행：

```sh
.venv/bin/python -B -m relay --data-dir /var/lib/codex-bridge-relay invite --owner alice --hours 24
```

반환하다 `invitation` 해당 사용자에게 비공개로 전달하세요. 각 초대 코드는 기본적으로 한 대의 컴퓨터만 등록할 수 있습니다. 24 시간이 만료됩니다。`owner` 이는 관리자의 속성 레이블이며 모델 서비스 제공자에 바인딩될 필요가 없습니다. 여러 컴퓨터에 개별적으로 초대 코드 보내기。

등록된 장치 보기（장치 토큰을 표시하지 않음））：

```sh
.venv/bin/python -B -m relay --data-dir /var/lib/codex-bridge-relay devices
```

컴퓨터 및 모든 휴대폰에 대한 인증 취소：

```sh
.venv/bin/python -B -m relay --data-dir /var/lib/codex-bridge-relay revoke DEVICE_ID
```

인증을 철회하면 새 요청은 즉시 거부되고, 기존 장치 연결은 다음 유지 관리 점검 때 닫힙니다(최대 약 5초). 이미 Codex에 제출된 작업은 취소되지 않습니다.

## 사용자가 컴퓨터와 휴대폰을 연결합니다.

1. 이 기능 분기를 포함하는 PC 클라이언트를 사용하십시오. 실행하려면 먼저 소스 코드를 설치해야 합니다. `requirements-relay.txt`。
2. 에서 **네트워크 접속 → 자체 제작 트렁크 · 내부 베타** 관리자가 제공한 정보를 입력하세요. HTTPS 주소, 초대코드, 컴퓨터명, 중계사업자 신뢰 확인 후 등록。
3. 에서 **개요** 게이트웨이를 시작하거나 다시 시작한 다음 공유 릴레이로 돌아가 새로 고치고 컴퓨터가 온라인인지 확인합니다.。
4. 딸깍 하는 소리 **휴대폰 페어링 생성**，모바일 브라우저를 사용하거나 v2 휴대폰 App QR 코드 또는 링크를 엽니다. 링크는 다음에 유효합니다. 5 분。
5. 휴대폰 이름을 입력하고 연결을 신청하세요. 컴퓨터에서 휴대폰 이름을 확인하고 클릭하세요. **승인하다**。
6. 원래 휴대폰을 입력하세요 v2 계속적인 채팅, 승인처리, 파일보기, 터미널 이용 등을 할 수 있는 워크벤치 Git 작업이 승인될 때까지 기다립니다. 권한은 컴퓨터 게이트웨이 및 원래 세션에서 상속됩니다.。

휴대폰은 페어링을 승인한 컴퓨터에만 연결됩니다. 요청의 장치 ID를 바꿔 다른 컴퓨터로 전환할 수 없습니다. 각 컴퓨터는 `/d/<컴퓨터ID>/` 주소를 사용하며, 같은 브라우저나 휴대폰 앱에 여러 컴퓨터를 저장해도 로그인·초안·알림 설정은 분리됩니다. 중계 토큰의 유효기간은 원래 정책대로 180일이며, 사용 중에는 갱신됩니다. 인증 철회 또는 만료 후에는 다시 페어링해야 합니다. 이전 버전의 루트 경로 연결은 유지되며, 여러 컴퓨터를 추가할 때는 새 QR 코드를 사용하세요.

컴퓨터 측에서는 단일 휴대폰을 비활성화하거나, 릴레이를 일시 중지하거나, 전체 컴퓨터를 비활성화할 수 있습니다. 일시 중지에는 릴레이가 온라인 상태일 필요가 없습니다. 등록되어 실행 중인 게이트웨이는 다시 활성화된 후 자동으로 연결됩니다. 첫 번째 등록에는 여전히 게이트웨이를 다시 시작해야 합니다. 컴퓨터 등록을 취소하려면 연결 가능한 릴레이가 필요합니다. 실패하면 머신은 먼저 연결을 일시 중단한 다음 해지를 다시 시도합니다. 새로운 릴레이를 등록하기 전에 기존 등록을 취소해야 합니다.。

## 임시 주소 변경 후 복구

자체 구축된 릴레이는 안정적인 주소 쿼리 입구도 제공합니다. 컴퓨터가 등록되고 릴레이가 활성화되고 휴대폰이 원래 주소를 통해 성공적으로 로그인되면 이 페어링에 바인딩된 쿼리 자격 증명이 기억됩니다. 컴퓨터가 임시 터널 주소가 업데이트되었음을 ​​발견하면 기존 아웃바운드 연결을 통해 항목을 업데이트합니다. 변경되지 않은 경우 반복적으로 보내지 않습니다.。

그 후, 휴대폰은 이전 주소를 열지 못하고 중계기에 새 주소를 쿼리합니다. 지참하지 말고 먼저 휴대폰으로 보내세요. Cookie 새 입구에 원래 컴퓨터 페어링 ID가 있는지 확인한 다음 원래 로그인을 마이그레이션하는 무작위 챌린지입니다. 반환된 내용을 기반으로 하지 않습니다. URL 직접 이체 Cookie，따르지 않을 것이다 HTTPS 자동으로 다운그레이드 HTTP。기존 휴대폰 로그인을 취소하신 후, 신규입장시 본인확인을 통과하실 수 없습니다. 브라우저는 이전 임시 주소를 직접 수집하며 만료된 페이지에 의존하여 자체적으로 검색할 수는 없습니다. 안정적인 중계 컴퓨터 출입구를 수집하는 것이 좋습니다.。

이 복구에는 새 버전의 컴퓨터 게이트웨이와 휴대폰이 필요합니다.
