# Codex、Claude Desktop 및 DeepSeek Harness 연결

v2.0.0 동일한 게이트웨이에 있는 세 가지 애플리케이션 각각에 대한 세션 목록, 구성 및 워크벤치를 제공합니다. 기존 계정, 작업 디렉터리 및 작업은 여전히 ​​원래 클라이언트의 소유입니다. 공유 인터페이스는 세 가지 응용 프로그램의 모델, 권한 및 도구 기능이 정확히 동일하다는 의미는 아닙니다.。

## 자동 검색 및 활성화

오픈 게이트웨이 App 설치된 클라이언트를 자동으로 검사합니다. 존재하다 **클라이언트 및 액세스** 설치, 구성 및 연결 상태를 봅니다. 스캔, 계정 관리 또는 입력 지원 API。나중에 새 클라이언트가 설치되면 다시 검색할 수 있습니다.。

- **Codex**：로컬 데스크톱 프로그램 및 현재 계정 식별/API，기본 및 구성 상속 SSH 대화。
- **DeepSeek Harness**：데스크톱 데이터 디렉터리, 계정, 모델, 프로젝트 및 기록을 재사용하고 로컬 액세스 플러그인을 설치 및 확인합니다. 플러그인을 업데이트해야 하고 클라이언트가 여전히 실행 중인 경우 먼저 작업을 종료한 다음 ”다시 시작하고 연결”하라는 메시지를 따릅니다. 로그인이 완료되지 않았습니다/API 설정시에는 Harness 완료 후 다시 스캔。
- **Claude Desktop**：연결 Code 및 Cowork，평범한 Chat 범위 내에 있지 않음。macOS/Windows 기본 초기화 도우미 제공；macOS 처음 사용하는 경우 게이트웨이 연결 구성 요소에 대한 접근성 권한이 필요할 수 있습니다.，Claude 개발자 모드 및 디렉터리 신뢰는 여전히 사용자에 의해 확인됩니다.。Linux 설치를 찾을 수 있지만 자동 연결은 아직 지원되지 않습니다.。

구성된 클라이언트만 활성화할 수 있습니다. 단순히 게이트웨이 제어판을 열거나 스캔해도 모든 응용 프로그램이 자동으로 시작되지는 않습니다. 활성화된 상태에서 액세스하기 전에 게이트웨이를 활성화하십시오.。Web/전화기에는 활성화된 클라이언트만 표시되며 애플리케이션이 하나만 있는 경우 하단 전환 표시줄이 숨겨집니다. 현재 애플리케이션에 속하는 세션 생성，Claude Code/Cowork 그룹을 접을 수 있습니다.。

## DSH 범용 플러그인 및 맞춤형 액세스

게이트웨이 목록에는 설치, 구성 또는 여전히 활성화된 액세스만 표시됩니다. 스캔 결과가 없더라도 다음에서 스캔할 수 있습니다. **액세스 추가 → DSH / 사용자 정의 Harness** 타사 앱에 특정 이름을 사용하도록 요구하지 않고 설치하고 바인딩합니다. 공식적인 DSH Desktop 원래의 원클릭 설치 방법을 유지합니다.。

에서“타사 클라이언트: 수동 설치 및 바인딩”플러그인 내보내기 ZIP，압축을 푼 후 클라이언트 플러그인 관리를 통해 전체 디렉터리를 설치하고 다시 로드합니다. 그런 다음 코어 생성을 선택하십시오. `binding.json`，또는 선택 **스캐닝 Harness 데이터 디렉토리**，이 디렉토리에서 `profiles` 설치된 플러그인 파일을 선택합니다. 플러그인 ID 파일을 스캔하고 읽으십시오. 바인딩 중에 버전 및 루프백 인증 핸드셰이크를 수행하고, 애플리케이션 이름을 열거하지 않으며, 네트워크 포트를 검색하지 않고, 자동으로 세션을 시작하지 않습니다. 설치 방법, 파일 위치 및 제거 지침은 다음을 참조하세요.[플러그인 사용 지침](../bridge/clients/deepseek/plugin/README.md)。

각 게이트웨이는 동시에 하나로 바인딩됩니다. DSH 파일. 전환하거나 바인딩을 해제하기 전에 먼저만 비활성화하세요. DSH 휴대폰 접속. 바인딩이 실패하면 다른 클라이언트로 대체되지 않습니다. 타사 시작, 종료, 계정 및 API 원래 클라이언트에서 관리하며 게이트웨이는 해당 계정 상태와 모델만 읽습니다. 플러그인은 기존 채팅, 승인, 알림 및 보관 프로토콜을 따르고 원래 세션을 유지합니다. ID、작업 디렉터리 및 권한。

현재 실제 기계 검증은 **macOS arm64、DSH Tauri v0.25.0、Harness 핵심 0.2.1-rc.2**：실제 플러그인 관리자 로컬 설치, 바인딩, 재시작 복구, 채팅, 기본 권한 승인, 모바일 알림 받은 편지함 및 로컬 Webhook、활성 세션은 보관 및 원본을 중지합니다. ID 다시 덮다. 모델 응답은 격리된 루프백 테스트 서비스에서 나오며 유료 업스트림은 호출되지 않습니다. 이번 라운드에서는 모바일 운영체제 알림 표시에 대한 재검증이 없습니다. 다른 타사 클라이언트는 필요한 핵심 서비스를 제공하는 한 이 범용 패키지를 사용해 볼 수 있지만 아직 테스트되지 않은 버전은 호환되는 것으로 확인되지 않았습니다.。Issue #59 의 DSH Desktop 0.12.1 / Windows 이번 라운드의 실제 결과에는 환경이 포함되지 않습니다.。

## 연결 복구 및 종료

Web、모바일 및 데스크탑 게이트웨이에 대한 애플리케이션 관리는 상태, 재연결 및 시작/중지를 제공합니다. 실행 중, 승인 대기 중, 대기 중, 확인되지 않은 결과가 있는 작업은 종료를 제한합니다./스위치; 작업 전에 작업 및 프로세스를 다시 확인하고 디스플레이 캐시를 안전 판단으로 사용하지 마십시오.。

출구 선택 구별 **모바일 액세스만 비활성화**、**정상적으로 종료 App**、**강제 종료 App**。강제 종료에는 추가 확인이 필요하며 클라이언트 내 작업이 중단될 수 있습니다. 정상적인 종료 실패 후 자동 롤백으로 간주할 수 없습니다. 다른 프로그램 종료를 피하기 위해 해당 프로그램의 정체를 알 수 없는 경우에는 계속 거부됩니다. 그만두다 Claude 확인 메시지에는 다시 초기화하려면 컴퓨터 잠금을 해제해야 할 수도 있다는 내용이 표시됩니다.。

Claude 기존 연결을 재사용하는 데 우선순위가 부여됩니다. 화면 보호기/화면이 잠기면 설정된 로컬 연결로 계속 통신할 수 있습니다. 처음 초기화하는 경우 재작업이 필요할 수 있습니다. Console 화면 보호기 종료, 잠금 해제 및 시스템 승인을 기다릴 수 있습니다. 인터페이스 없는 콜드 스타트 ​​보장, 시뮬레이션된 잠금 해제, 비밀번호 또는 잠금 화면 정책 변경이 없습니다. 다시 연결해도 메시지가 자동으로 다시 전송되지는 않습니다. 컴퓨터가 절전 모드일 때 세 클라이언트 중 어느 것도 원격 통신을 유지할 수 없습니다.。

Harness 업그레이드는 원래 구성 및 백업을 유지하며 설치 기록, 플러그인 소스, 엔드포인트 및 데이터 디렉터리가 상호 검증된 후에만 이전 액세스를 복원합니다. 사용자는 다른 게이트웨이를 맹목적으로 제거할 필요가 없습니다.。Harness 액세스 블록의 일반 줄 바꿈 및 백슬래시 연속 줄은 인식에 영향을 주지 않으며 수동으로 단일 줄로 변경할 필요가 없습니다. 잔여 인스턴스는 ID 및 작업 상태에 따라 처리됩니다. 확인할 수 없는 구성은 그대로 남겨져 덮어쓰기보다는 검사가 필요합니다.。

동일한 컴퓨터를 업그레이드하는 경우 먼저 이전 게이트웨이를 중지한 다음 원래 게이트웨이 데이터 디렉터리를 유지하면서 새 버전을 시작합니다. 두 개의 게이트웨이가 동일한 클라이언트 및 작업 수신 세트를 동시에 작동하는 것을 허용하지 않습니다.。

## 대화 도구 및 컨텍스트

Claude/DSH 채팅 목록, 메시지, 사본, 첨부 파일, 파일 재사용/Git/터미널 라벨, 알림, 다운로드 및 분할 화면 구성 요소 사용 가능한 특정 작업은 각 어댑터의 기능에 따라 달라집니다.。Codex 임시 사이드 채팅、Goal、Fast 및 Skills 다른 애플리케이션 지원과 자동으로 동일하지 않음。

### 네트워크 및 액세스

- 기존 LAN 재사용、HTTPS 터널 또는 역방향 프록시 항목, 추가 공개가 필요하지 않음 Harness 포트。
- 자체 구축된 역방향 프록시에 권한이 필요합니다. `/harness/` 아래에 WebSocket Upgrade，충분한 업로드 크기와 연결 시간 초과를 설정합니다. 오픈만 가능 HTML 해당 페이지는 실시간 상호작용이 연결되어 있음을 의미하지 않습니다.。
- 모두 Harness 페이지, 리소스、HTTP API 및 WebSocket 모두 유효한 게이트웨이 로그인이 필요합니다. 쓰기 요청 및 WebSocket 현재 항목의 정확한 원본 주소에서 와야 합니다.。
- Harness 시작 토큰 및 로그인 Cookie 게이트웨이 프로세스 내에서만 저장됩니다. 브라우저는 이를 수신하지 못합니다. 게이트웨이는 Cookie 다음 주소로 전달되지 않습니다. Harness。
- 로그아웃, 로그인 취소, 기기 차단 IP 아니면 그만 Harness 그 이후에는 WebSocket 연결이 끊어집니다。
- 시작 상태 로그가 기록되지 않습니다. Harness 토큰, 모델 자격 증명 및 파일 콘텐츠가 게이트웨이 로그에 입력되지 않도록 하는 원시 출력。
- 지원됨 Content-Length 스트리밍 업로드, 단일 제한 300 MiB；파일 다운로드는 스트림별로 전달됩니다. 청크로 인코딩된 요청 본문을 허용하지 않음。

게이트웨이에 로그인하는 모든 장치는 동일한 것을 사용합니다. Harness 공식 단일 사용자가 포함된 인스턴스 및 데이터 디렉터리 Web 모드 일관성; 이 기능은 서로 다른 사용자 간의 작업 공간 격리를 제공하지 않습니다.。

## DSH 함께 제공됩니다 Mobile 연결

Android / iOS 컴퓨터 연결 페이지가 추가되었습니다. **DSH Mobile**。붙여넣기 클라이언트 Mobile 기능에 의해 생성된 전체 링크 또는 QR 코드를 스캔한 후 선택 DSH Mobile；대상 확인 후，App 클라이언트의 원래 모바일 인터페이스를 열고 경로, 쿼리 매개변수 및 조각을 유지합니다. 링크에 포함된 인증 정보는 기기의 암호화된 저장소에 저장됩니다. 컴퓨터 목록에는 주소 소스만 표시되고 인증 매개변수는 표시되지 않습니다.。

이 유형의 연결은 Bridge 게이트웨이 연결, 통화 없음 Bridge 전용 계정, 알림, 탐지 및 다운로드 API，주입하지도 않고 Bridge 채팅 스크립트. 공지사항 및 웹페이지 테마는 원본에서 가져왔습니다. DSH Mobile 페이지에서 지원하는 기능에 따라 결정됩니다. 필수의 Bridge 알림 및 통합 채팅 인터페이스의 경우 범용 플러그인 경로를 사용하세요. 원래의 Bridge 테마, 뒤로 키 및 알림 소스 스위치는 원래 동작을 유지합니다.。
