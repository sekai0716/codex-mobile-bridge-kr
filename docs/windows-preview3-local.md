# Preview 3 Windows 소스 코드 테스트 지침

에서 Windows x64 개발 머신에서，`start-preview3-windows.cmd` 창고에서 구매 가능 `dist/desktop/win-unpacked` 내장된 데스크탑 실행 App。스크립트는 별도의 `.local/windows-preview3-user` 데이터 디렉터리를 작성하고 시작 영수증을 작성합니다. `.local/windows-preview3-launch`。이 스크립트는 현재 사용자의 Explorer 세션; 상위 프로세스, 세션 및 대상 프로그램을 확인할 수 없으면 오류가 보고됩니다. 앱을 빌드하거나 설치하지 않습니다.。

병합된 클라이언트 검사는 설치 등록 정보를 읽습니다.、App Paths、현재 데스크톱 세션 및 사용자 지정 경로。CLI 런타임 GUI 별도의 경로 확인。Claude 구성 디렉토리는 선택된 실행 프로세스의 증거에 우선순위를 부여합니다. 중지 상태는 디렉터리 증거가 충분한 경우에만 선택되며 계정 소유권을 확인할 수 없는 경우 전환이 거부됩니다. 검색, 실행 및 연결이 다른 상태입니다.。

Windows Claude 열 때 먼저 기존 서명된 연결을 복원한 다음 확인된 기본 입구에 따라 백그라운드 시작 및 초기화를 시도하십시오.。`--startup` 개발자 도구 입구는 선택한 설치 버전의 소스 코드 형식이 검증된 조건을 충족하는 경우에만 사용됩니다. 알 수 없는 버전은 재시도 가능 상태로 돌아갑니다. 명백한“연결 초기화”배경 보조자가 아직 입력을 제출하지 않았고 데스크탑이 대화형이라고 판단되면 전경 부트스트래핑을 사용할 수 있습니다. 취소하면 이 어시스턴트만 중지됩니다. 연결 상태는 현재 상태를 기반으로 해야 합니다. generation 서명된 영수증이 우선합니다.。

액세스 비활성화, 일반 종료 및 백그라운드 강제 종료는 세 가지 독립적인 옵션입니다. 일반 종료에는 알려진 작업과 선택한 응용 프로그램 프로세스를 확인해야 합니다.；Claude 및 Codex 기본 메뉴 사용，DSH 검증된 기본 이탈 채널 사용。Windows 백그라운드에서의 강제종료는 이번에는 명시적으로만 선택되었습니다. `enabled: false, quitDesktop: true, forceDesktop: true` 요청하면 서버는 게이트웨이 상태, 프로그램 경로, 세션을 다시 확인합니다.、PID、생성 시간 및 프로세스 핸들. 모든 종료 방법은 선택한 대상 프로세스가 실제로 사라진 후에만 비활성화된 상태를 저장합니다. 실패하거나 수신이 불확실한 경우 자동으로 재시도하거나 강제 종료를 사용하지 않습니다.。

웹과 모바일 간 전환 Claude/DSH 현재 페이지 메모리의 목록과 세부 정보를 먼저 표시한 다음 새로 고칠 수 있습니다. 캐싱은 전송, 중지 또는 승인 권한을 부여하지 않습니다. 쓰기 작업, 계정 전환, 비활성화 및 로그아웃은 관련 읽기를 무효화합니다. 시작 및 종료에 대한 페이지 시간 초과는 결과를 확인해야 함을 의미하며 사용자는 작업하기 전에 상태를 새로 고쳐야 합니다.。

소스 코드 레이어 반환 항목：

```powershell
python -B scripts/test-backend.py --source-only
npm.cmd run test:desktop
```

`--source-only` 뛰어넘다 Swift、C# 및 Electron 네이티브 실행 픽스쳐. 특별한 격리가 필요함 Windows 네이티브 어시스턴트, 패키징 및 잠금 화면 동작은 테스트 환경에서 검증됩니다. 소스 코드 테스트는 이러한 결과를 나타내지 않습니다. 소스 브랜치 `codex/preview3-windows` 보고됨 선택됨 Windows 테스트 머신에서 검증됨 DSH 종료、Claude 백그라운드 제출 및 서명 연결、Codex 기본 종료 및 일부 잠금 화면 장면 이러한 레코드는 원본 분기에 속하며 이 디렉터리 통합 후 실제 시스템 승인으로 간주될 수 없습니다. 통합 코드를 다시 테스트할 때 특정 버전과 환경을 기록해야 합니다.。
