터미널 세션도 읽기 전용 인덱스입니다. history.jsonl：이름이 지정되지 않은 세션은 최근 터미널 입력에 우선 순위를 두고 후속 입력 검색을 지원합니다. 명시적으로 설정된 이름이 우선 적용됩니다. 원래 데이터베이스 제목과 원래 채팅 기록은 다시 작성되지 않습니다. 검색 일치는 페이지 매기기 전에 수행되며 여전히 소스, 아카이브 및 하위 에이전트 필터링을 사용합니다.。


## WSL ～에 Claude Code

Windows 게이트웨이에도 액세스할 수 있습니다. WSL ～에 Linux 네이티브 Claude Code。배포판 내에서 설치하고 원래 계정 로그인을 완료하거나 API 구성 후 클릭 **애플리케이션 관리 → 스캐닝 WSL 애플리케이션**，에서 Claude 해당 활성화 **WSL Claude Code**。Windows 소유하다 Claude 각각 WSL 액세스는 별도로 시작 및 중지됩니다. 스캔해도 새 입구가 자동으로 활성화되지 않습니다.。

사용 Claude 페이지 보기 기록, 채팅을 계속하고 새 프로젝트 채팅을 만드세요. 새로 생성할 때 해당 항목을 선택하세요. WSL 운영 환경과 Linux 목차. 채팅에 사용됨 Claude Code 모델, 사고강도, 권위、Skill、승인 및 중지 기능, 사용 가능한 실제 옵션은 환경의 기본 사항에 따라 결정됩니다. CLI 반품. 목록 주석 `CLI · WSL` 및 환경 이름; 동일한 경로는 서로 다른 환경에서 별도로 그룹화됩니다. 초안, 모델 캐시, 작업 영수증도 원본 환경에 따라 격리됩니다.。

스캔만 허용 Linux 기본 프로그램, 사용하지 마세요 `/mnt/c` ～에 Windows npm 스크립트 또는 `.exe` ～처럼 WSL Claude。공식 로그인이 아직 남아있습니다. WSL 완료됨; 저장됨 API 통과할 수 있다[WSL 계정 관리](wsl-accounts.md)명시적 가져오기 및 스위치. 게이트웨이가 자동으로 동기화되지 않습니다. Windows 자격 증명을 사용하지 않고 다른 환경의 계정으로 대체하지 않습니다. 기록 탐색은 모델을 호출하지 않으며 액세스를 중지해도 원본이 종료되지 않습니다. CLI 일。

WSL Codex 모델 디렉터리 재사용 12 시간별 캐시, 수동 새로 고침 및 기본 디렉터리 다시 읽기. 캐시는 릴리스 버전, 사용자, 구성 디렉터리, 원래 공급자, 계정 및 구성 ID에 바인딩됩니다. 계정이 변경된 후에는 이전 디렉터리가 재사용되지 않습니다. 현재 모델과 권한, 기타 작업 상태는 여전히 원래 스레드에서 확인되며 캐시는 쓰기 권한으로 사용되지 않습니다.。
