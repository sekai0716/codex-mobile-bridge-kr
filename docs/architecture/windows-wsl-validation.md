다른 곳에서는 WSL 현재 구성 내에서 Magpie 주소가 자격 증명 없이 만들어졌습니다. TCP 연결 확인, 포트에 연결할 수 있습니다. 이는 확인된 실제 업스트림 모델 응답이나 라우팅 그룹의 모든 구성원을 나타내지는 않습니다.。

## 격리된 실제 런타임 검사

`scripts/smoke-wsl-shared-server.py --codex <명확하게 지정된 Linux Codex 프로그램>` 새로운 개인정보를 사용하세요 `CODEX_HOME`、독립적인 app-server 및 localhost 시뮬레이션 모델, 실제 사용하지 않음 Magpie 또는 계정。

다음 동작을 확인하세요.：

1. 원래 연결은 구성 스레드를 생성 및 실행하고 두 번째 연결은 스레드를 계속합니다. 원래 연결은 완료 이벤트를 수신합니다.。
2. 동일한 커밋 ID 한 번만 다시 시도하세요.。
3. 두 번째 연결을 통해서만 메시지가 전송되면 승인을 받지 못합니다. 로드된 동일한 스레드를 명시적으로 구독하면 수신됩니다. 따라서 구현은 사용자가/작업 중 구독, 수동 읽기 중에는 스레드를 재개하지 않음。
4. 원래 요청만 제공됨 `accept`、정책 수정 개체 및 `cancel` 그 때, 허가 없이 제공하지 마십시오 `decline` 또는 지속적인 승인; 실제로 제공된 취소 작업을 사용하면 원래 스레드가 중지되고 테스트 명령이 실행되지 않습니다.。
5. 중지 요청은 원래 스레드의 현재 라운드에 적용됩니다.。
6. Bridge 연결이 닫힌 후 실행 중인 합성 작업이 계속되고 완료 결과가 원래 연결에 의해 수신됩니다.。
7. 테스트 구성은 바이트 단위로 변경되지 않고 유지되며 인증 파일은 생성되지 않으며 모든 모델 요청은 합성 네이티브 서비스로만 전송됩니다.。

Unix 소켓은 다음 위치에 있어야 합니다. Linux 자신의 임시 디렉토리；Windows 마운트된 디스크는 바인딩을 지원하지 않습니다. 다른 테스트 데이터는 프로젝트에 저장됩니다. `.tmp`。테스트는 자체적으로 시작된 서비스 및 전송 프로세스만 정리하고 사용자에게 신호를 보내지 않습니다. daemon 또는 CLI。

격리하다 `.tmp` 작업 영역의 실제 측정 Windows → WSL 파일 메타데이터, 바이너리 다운로드, 이미지 첨부 업로드 및 기본 미리보기 상위 디렉터리 범위를 벗어난 요청은 거부됩니다. 이 테스트는 실제 프로젝트에 작성되지 않거나 Codex 데이터 디렉토리。

## WSL 독립형 애플리케이션 및 모델 목록 수정

이번에는 그럴 것이다 WSL 애플리케이션별로 나열된 환경 `DesktopSessions` 관리결과, 적용 ID 원래 입구 아이덴티티를 유지하세요。Web、모바일 및 데스크탑 관리 스위치는 동일한 등록 상태를 공유합니다. 각 애플리케이션 목록, 계정 읽기, 딥 링크 및 초안은 격리된 상태로 유지됩니다. 이전 등록 데이터는 원본과 직접 호환됩니다. Codex 포털 연결 제어가 페이지에서 제거되었습니다. 비활성화하다 WSL 게이트웨이 자체 연결만 닫습니다. 출구가 표시되지 않습니다 CLI 옵션。
