# 자신의 도메인 이름으로 액세스 Codex

도메인 이름만 사용할 수 있으며 공용 네트워크 서버는 사용할 수 없습니다. **Cloudflare 고정 터널**。한 번 구성하면 전화기는 항상 동일한 것을 사용합니다 HTTPS 주소; 컴퓨터、Codex App 게이트웨이는 온라인 상태를 유지해야 합니다.。

액세스 링크：**휴대폰 → 자신의 도메인 이름 → Cloudflare → 컴퓨터의 터널 → 로컬 게이트웨이 → Codex App**。

이 기사의 사용자 이름 `try2love`、도메인 이름 `try2love.com` 주소 `https://codex.try2love.com` 구성 데모용이며 액세스 가능한 데모 사이트를 나타내지 않습니다. 자신의 사용자 이름과 도메인 이름으로 바꾸십시오. 데스크탑 App 이미 내장되어 있음 cloudflared，설치가 필요하지 않습니다 Python、Node.js 또는 다른 Cloudflare 클라이언트, 서버 불필요 SSH 계정。

## 1. 도메인 이름 추가 Cloudflare

로그인 [Cloudflare 콘솔](https://dash.cloudflare.com)，루트 도메인 이름 추가 `try2love.com`，귀하의 필요에 따라 패키지를 선택하십시오. 이미 웹사이트나 이메일 주소가 있는 경우 먼저 가져온 내용을 확인하세요. DNS 기록, 원본 사이트 및 이메일 기록 유지。

Cloudflare 두 개의 네임서버가 할당됩니다.（Nameservers / NS）주소. 계정에 표시된 값을 복사하세요. 각 도메인 이름은 다를 수 있습니다.。

## 2. 도메인 이름 등록기관에서 수정 DNS 섬기는 사람

Alibaba Cloud에서 도메인 이름을 구매하는 경우 Alibaba Cloud의 이름을 입력하세요.**도메인 이름 관리 → 해당 도메인 이름 → DNS 개정하다 / 개정하다 DNS 섬기는 사람**，네임서버를 다음으로 교체 Cloudflare 두 개의 주소가 제공됩니다. 다른 등록기관도 도메인 이름 관리에서 이 단계를 완료합니다.。

여기서 수정되는 것은 도메인 이름입니다. **DNS 섬기는 사람 / NS**，단순히 구문 분석 기록에 임의의 항목 두 개를 추가하는 것이 아닙니다. NS，또한 도메인 이름을 다른 등록기관으로 이전할 필요가 없습니다. 원래 활성화된 경우 DNSSEC，먼저 누르세요 Cloudflare 레지스트라 폐쇄에 대한 지침 DNSSEC，도메인 이름 활성화 후 통과 Cloudflare 설정。

로 돌아가다 Cloudflare 도메인 이름 상태가 변경될 때까지 기다립니다. **Active / 효율적인**。네임서버 변경에는 몇 시간이 걸릴 수 있으며, 공식 프롬프트는 최대 1시간까지 기다릴 수 있습니다. 24 시간; 캐시 업데이트 시간은 네트워크에 따라 다를 수 있습니다. 활성화 후 후속 구문 분석이 기록됩니다. Cloudflare 관리하다。

## 3. 고정 터널을 생성하고 획득 Tunnel Token

에서 Cloudflare 콘솔 항목 **Networking → Tunnels**；인터페이스의 일부는 다음과 같이 표시됩니다. **Zero Trust → Networks → Connectors / Tunnels**。만들다 **Cloudflared** 터널 유형에는 식별하기 쉬운 이름을 지정하십시오. 예를 들어 `my-codex`。

커넥터 설치 페이지에서 실행 중인 명령을 찾습니다. **Tunnel Token**。일반적으로 명령 끝에 있는 긴 문자열입니다.：App 이 단락이 필요합니다. Token，전체 명령이 필요하지 않습니다. Cloudflare 전반적인 상황 API Key，단말기에 서비스를 반복적으로 설치할 필요가 없습니다.。

Token 이 터널의 연결 자격 증명과 동일하며 자체 터널에서만 가능합니다. App 작성하십시오. 공개 스크린샷, 튜토리얼 또는 창고를 포함하지 마세요.。

## 4. 에서 App 작성하고 시작하세요

1. 열려 있는“네트워크 및 로그인”，다음에 추가 **고정 도메인 이름 · Cloudflare Tunnel**。
2. 휴대폰 접속주소를 입력하세요 `https://codex.try2love.com`，추가 경로 없이。
3. 이전 단계를 작성하세요. **Cloudflare Tunnel Token**，계정 및 비밀번호 로그인 보호 유지。
4. 연결을 활성화하고 구성을 저장한 후“게이트웨이 시작”。LAN 연결을 동시에 유지할 수 있습니다.。

로 돌아가다 Cloudflare，터널 커넥터가 표시되는지 확인 **Healthy / 연결됨**。설치 마법사에서 페이지가 여전히 멈춘 경우 커넥터가 온라인 상태가 된 후 다음 단계를 계속할 수 있습니다.。

## 5. 터널에 공개적으로 액세스 가능한 주소 추가

이 터널에서 **Routes → Add route → Published application** 라우팅을 추가하세요. 이전 인터페이스를 호출할 수 있습니다. **Public Hostname / 호스트 이름 노출**。

| 필드 | 샘플 충전 |
| --- | --- |
| Subdomain / 하위 도메인 | `codex` |
| Domain / 도메인 이름 | `try2love.com` |
| Path / 길 | 비워두세요 |
| Service Type / 서비스 유형 | `HTTP` |
| Service URL / 서비스 주소 | `localhost:8787` |

인터페이스에 완전한 서비스 주소 입력 상자가 하나만 있는 경우 다음을 입력하십시오. `http://localhost:8787`。여기 있어요**동일한 컴퓨터의 게이트웨이 주소**；기본 포트는 다음과 같습니다. 8787，게이트웨이 포트를 수정한 경우 이를 사용하십시오. App 실제 값이 표시됩니다. 휴대폰으로 접속하지 마세요 HTTPS 서비스 주소에 도메인 이름을 입력하세요.。

휴대전화 요청이 처리됩니다.“고정 도메인 이름 → Cloudflare → 컴퓨터에 의해 능동적으로 설정된 터널 → 네이티브 게이트웨이”。따라서 서비스 주소를 입력하세요. `localhost` 외부 네트워크에서도 접속이 가능합니다. 휴대폰과 컴퓨터가 동일한 LAN에 있을 필요도 없고 임시 네트워크로 리디렉션될 필요도 없습니다. Cloudflare 주소。

경로를 저장한 후，Cloudflare 에 대한 링크를 생성합니다 `<터널 ID>.cfargotunnel.com` 의 DNS 기록. 동일한 이름의 레코드가 이미 존재한다는 메시지가 표시되면 먼저 목적을 확인한 후 충돌을 처리하여 원본 웹사이트를 덮어쓰지 않도록 하세요. 이 솔루션에는 하위 도메인 이름이 필요하지 않습니다 A 컴퓨터에 포인트 기록 IP 아니면 다른 서버를 구입하세요。

### 허락하다 HTTP 자동으로 이동 HTTPS

공개 경로 구성이 완료된 후에도 계속 구성해야 합니다. HTTPS 도약. 그렇지 않으면 도메인 이름을 직접 입력할 때 일부 브라우저에서 통과할 수 있습니다. HTTP 로그인 페이지를 표시하려면“컴퓨터에 연결”프롬프트만 표시“교차 사이트 요청은 허용되지 않습니다.”。

에서 Cloudflare 도메인 이름 페이지에 입력하세요. **규칙 → 개요 → 규칙 만들기 → 리디렉션 규칙**：

1. 선택하다“맞춤 필터 표현식”，채우다 `(http.request.full_uri wildcard r"http://codex.try2love.com/*")`，예제 도메인 이름을 자체 게이트웨이 하위 도메인으로 바꿉니다.。
2. URL 선택 리디렉션“동적”，대상 표현식을 입력하세요. `concat("https://codex.try2love.com", http.request.uri.path)`，도메인 이름도 교체하세요.。
3. 상태 코드 선택 **301**，확인하다“쿼리 문자열 유지”，그런 다음 배포。

이 규칙은 지정된 하위 도메인 이름만 업그레이드합니다. HTTP 경로 및 쿼리 매개변수를 요청하고 보존합니다. 다시 열다 `http://codex.try2love.com`，확인 주소는 자동으로 다음으로 변경됩니다. `https://codex.try2love.com` 그런 다음 비밀번호를 입력하세요. 이미 열었습니다 HTTP 로그인 페이지를 새로 고치거나 다시 열어야 합니다. 떠나지 마세요 HTTP 게이트웨이에 주소를 추가하면 소스가 검사를 우회할 수 있습니다.。

## 6. 컴퓨터와 휴대전화를 별도로 인증하세요.

1. 에서 App 딸깍 하는 소리“고정된 출입구 감지”，도메인 이름이 현재 게이트웨이에 연결되어 있는지 확인。
2. 컴퓨터 브라우저에서 열기 `https://codex.try2love.com`，로그인 페이지가 보이는지 확인하고 로그인하세요。
3. 휴대폰 꺼짐 Wi-Fi，동일한 주소에 대한 셀룰러 네트워크 액세스를 사용하여 로그인 확인, 채팅 읽기, 메시지 보내기 및 회신 동기화。
4. 다음에서 이용 가능“모바일 알림”주소를 다시 쉽게 찾을 수 있도록 에서 입장 알림을 구성하고 테스트하세요.。

터널 디스플레이 Healthy 커넥터가 연결되었음을 나타냅니다. Cloudflare，위의 웹 확인을 완료해야 합니다. 고정 주소는 일반적인 재접속으로 인해 변경되지 않습니다. 컴퓨터가 종료되거나 최대 절전 모드로 전환되거나 게이트웨이가 중지되면 이 주소에 일시적으로 액세스할 수 없습니다.。

## 자체 서버 + SSH 필요 없음 root ？？

할 수 있다。**일일설립 SSH 터널은 필요하지 않습니다 root，자동으로 실행되지는 않습니다 sudo。** 예를 들어 일반 사용자 `try2love`，서버에 로그인할 수 있고 생성이 허용되는 한 `127.0.0.1:18787` 원격 포트 전달의 경우 다음을 사용할 수 있습니다.。

| 작동하다 | 필수 권한 |
| --- | --- |
| 서버에 로그인하고 상위 수준 루프백 포트를 설정합니다. SSH 앞으로 | 전달이 허용되는 공통 항목 SSH 사용자 |
| 처음 설치 Caddy、시스템 사이트 구성 작성 및 시스템 서비스 관리 | root 또는 해당하는 sudo 권한이 있는 사용자 |
| 이미 HTTPS 사이트 뒤의 일일 연결 | 평범한 SSH 사용자는 구성을 저장한 후 게이트웨이를 시작할 수 있습니다. |

에서 App 중장“SSH 사용자 이름”일반 사용자 이름을 입력하고 사용자의 비밀번호, 개인 키 또는 Agent。서버 설치, 방화벽 및 SSH 권한은 사용자 또는 관리자가 수동으로 수행합니다.，App 수락하지 않음 sudo 비밀번호, 원격 설치 명령을 실행하지 마세요. ～에 따르면[섬기는 사람 SSH 단계별 튜토리얼](server-ssh.md)준비하다 HTTPS 사이트 이후에는 App 조사하다 SSH 로그인, 연결 시작 및 고정 항목 감지。

휴대폰으로도 서버에 연결할 수 있어야 합니다. HTTPS 입구. 캠퍼스 네트워크를 통과할 수 있습니다.、VPN 아니면 스프링보드 로그인 SSH，이는 휴대폰이 공용 네트워크의 서버에 액세스할 수 있다는 의미는 아닙니다. 별도로 확인이 필요합니다. 서버에 이미 웹사이트가 있는 경우 기존 역방향 프록시에 연결하여 기존 서비스를 유지하세요.。

## 접속이 느리거나 나타남 ICMP 통나무

`Failed to send ICMP reply` ～에서 cloudflared 의 ICMP 반환 경로; 이 로그만으로는 공개 여부를 확인할 수 없습니다. HTTP 페이지를 사용할 수 없는지 여부가 페이지가 느리다는 것을 증명하는 것은 아닙니다. ICMP 로 이어진다. 현재 게이트웨이는 더 이상 이 로그만을 기반으로 연결된 고정 터널을 연결 예외로 표시하지 않습니다. 다른 터널 오류 및 프로세스 종료에는 여전히 예외가 표시됩니다.。

문제 해결 시 로컬 게이트웨이와 고정 도메인 이름을 각각 확인하세요. DNS/TLS/첫 번째 바이트 및 셀룰러 네트워크 도달 시간。Cloudflare 연결된 것만 표시된다는 것은 커넥터가 등록되었음을 의미하며 휴대폰에서 엣지 노드까지의 경로가 원활하다는 것을 보장하지는 않습니다. 가까이 가지 마세요 TLS 인증되지 않은 입구를 확인하고 열거나 빈번한 재시도 처리 지연을 늘립니다.。

합격하지 못하길 바라신다면 Cloudflare，사용 가능[자체 서버 + SSH](server-ssh.md)，아니면 현재 개발 버전에서는“네트워크 접속 → 자체 제작 트렁크 · 내부 베타”설정[소유하다 relay](shared-relay.md)。Alibaba Cloud에서 도메인 이름을 구매하면 Alibaba Cloud 서버 라인이 자동으로 사용되지 않습니다. 서버를 배포하고 서버에 대한 하위 도메인 이름을 확인해야 합니다. 마이그레이션 전 원래 입구를 유지하고, 새로운 입구를 실제 이동통신망으로 확인한 후 원래 터널의 비활성화 여부를 결정합니다.。
