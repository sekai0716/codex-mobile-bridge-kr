# 네이티브 사이드 채팅 접속 연구

조사일자：2026-10-07。초기 설문조사는 읽기 전용 검사였습니다. 이후 사용자 인증을 통해 사용자가 수동으로 생성한 기본 사이드 채팅을 사용하여 실제 전송, 수신 및 종료 실험을 수행했습니다. 수정 없음 Codex 패키지 설치 또는 대체 모델 프로세스 시작。

## 현재 로컬 미리보기：Bridge 임시 지점 관리

사용자가 수락: Bridge 임시 분기를 관리한 후 데스크톱 로그 검색 및 수동 생성에 의존하는 구현이 대체되었습니다. 이제는 독립을 통해 stdio app-server 만들다 `thread/fork(ephemeral=true, excludeTurns=true)`，측면 경계를 삽입하고 명시적인 전송을 기다립니다. 상위 채팅은 복원되거나 실행되지 않으며, Codex 데스크탑 UI。

실제 런타임 검증 결과，`deferGoalContinuation` 와 함께 사용할 수 없습니다 `ephemeral` 동일한 것이 사용되며 임시 스레드는 대상 작업을 지원하지 않습니다. 따라서 일반 영구 분기의 지연된 대상 매개 변수는 적용되지 않으며 상위 채팅에 대한 대상이 지워지지 않습니다. 임시 속성, 모델, 공급자 및 작업 디렉터리를 초기화하고 확인합니다. 확인에 실패하면 런타임이 종료됩니다.。

모든 게이트웨이 인증 클라이언트는 기본 채팅을 통해 동일한 임시 분기를 찾습니다. 페이지를 닫으면 보기만 해제됩니다. 채팅을 종료하려면 이전 페이지가 새 분기를 닫는 것을 방지하기 위해 현재 하위 채팅 ID와 일치해야 합니다. 종료, 게이트웨이 종료 또는 계정 전환 시 하위 런타임을 종료하고 메모리를 지웁니다. 내용이 작성되지 않았습니다 Bridge 역사; 자동 복구가 되지 않습니다. 현재는 각 부모마다 하나의 채팅이 있으며, 총 채팅 수가 가장 많습니다. 8 기사, 게이트웨이 로컬만 지원 host。

검증 스크립트 `scripts/smoke-side-chat.py` 진짜를 사용하다 Codex 런타임, 격리 CODEX_HOME 루프백 가짜 모델 서비스를 사용하면 모델 요청, 스트리밍 응답 및 임시 스레드를 입력하는 검증 컨텍스트 및 경계가 표시되지 않습니다. thread/list、상위 레코드는 변경되지 않고 그대로 유지되며 프로세스가 재활용됩니다. 실제 모델 인증서는 사용되지 않습니다. 실제 계정과 모바일 장치 경험은 별도로 허용되어야 합니다.。

다음 기록은 원래 경로에 대한 연구 증거를 유지하며 현재 미리보기를 수동으로 생성해야 한다는 의미는 아닙니다.。

## 초기 네이티브 인수 실험（교체）

워크벤치 독립 하위 탭이 구현되었습니다. 컴퓨터에서 열린 기본 사이드 채팅에 연결하고, 답장을 읽고, 문자를 보내고, 휴대폰 연결을 끊습니다. 일반적인 영구 채팅을 생성하지 않으며 독립형 채팅을 시작하지도 않습니다. app-server。

- 데스크톱 스냅샷은 두 가지를 모두 충족해야 합니다. `ephemeral: true`、`sideConversation: true`、`forkedFromId` 현재 메인 세션과 동일합니다. 실제 검증에서는 다음 필드를 얻습니다.。
- 재사용 원본 데스크톱 보내기 owner 의 `thread-follower-start-turn`，사용 `inheritThreadSettings: true`，모델, 공급자, 작업 디렉터리 또는 권한을 재정의하지 않습니다. 실제 테스트 메시지는 정상적인 응답을 받습니다.。
- 전송하기 전에 새로운 스냅샷을 받으세요. 사용자가 데스크톱에서 테스트 측 채팅을 닫은 후에는 기존 연결에서 더 이상 스냅샷을 얻을 수 없으며 확인이 계속 전송을 거부하고 실행되지 않습니다. `thread/resume`。
- 콘텐츠 및 전송된 중복 제거 상태는 메모리에만 존재합니다. 연결을 끊은 후 청소하십시오. 전송된 회신이 손실되면 자동 재생이 되지 않습니다. 비활성 모바일 연결 5 몇 분 후에 출시됨 follower；이건 그냥 Bridge 기본 채팅 수명이 아닌 연결 정리 시간。
- 기본 임시 채팅의 확인, 승인 및 종료는 여전히 컴퓨터에서 수행되어야 합니다. 휴대폰에서 하위 탭을 닫으면 연결만 끊어지며 데스크톱 채팅이 파괴되었다고 주장할 수 없습니다.。

현재 디스커버리 입구는 macOS 오늘 일기의 가장 최근 내용 `thread/inject_items` 라우팅 기록, 후보자만 추출 ID，그런 다음 실시간 스냅샷을 사용하여 기본 세션의 소유권과 임시 성격을 확인합니다. 일치하는 로그가 없으면 자동으로 검색할 수 없습니다. 이 메커니즘은 현재 데스크톱 버전에 따라 다르며 아직 플랫폼 간 안정적인 인터페이스는 아닙니다. 동일한 기본 세션에 여러 개의 사이드 채팅이 있는 경우 가장 최근에 검색되어 사용 가능한 사이드 채팅을 연결하세요.。

사용자가 데스크톱을 사용하기로 선택했습니다. UI 실험 경로가 생성되었지만 Computer Use 도구는 명시적으로 제어를 금지합니다. Codex 그 자체. 제한을 우회하기 위해 다른 자동화된 도구는 사용되지 않으며 확인은 사용자가 수동으로 완료합니다. 그러므로 이번 배송은**기본 사이드 채팅 인수 미리보기**，자동 생성 및 원격 파기가 아직 구현되지 않았습니다.。

## 결론적으로

기본 사이드 채팅은 컨텍스트 상속, 독립적 실행 및 기본 소멸 상태를 갖춘 현재 세션의 임시 분기입니다. 일반 기록 채팅을 나란히 표시하는 것은 동일하지 않습니다.。

기본 데스크탑 구현에서는 링크의 완전한 생성 및 닫기 위치를 찾을 수 있지만 Bridge 기존의 follower IPC 사이드 채팅을 생성하거나 삭제할 수 있는 방법은 없습니다. 이 기계가 작동 중입니다. app-server 데스크탑에 있는 표준 입력 및 출력 채널을 사용하면 재사용 가능한 채널이 발견되지 않았습니다. Unix socket 청취 끝점. 따라서 기본 메소드 이름을 아는 것은 아직 의미가 없습니다. Bridge 현재 데스크톱 인스턴스를 직접 호출할 수 있습니다.。

## 검증된 기본 프로세스

1. **만들다**：현재 세션에서 데스크톱 관리자 호출 `forkConversationFromLatest`。매개변수에는 상위 세션, 현재가 포함됩니다. host/cwd/협업 모드 및 설정 `ephemeral: true`、`sideConversation: true` 및 상위 탐색 경로。
2. **상속 컨텍스트**：관리자가 보냅니다. `thread/fork`。임시 지점 사용 `ephemeral: true`；사이드 채팅도 사용 `excludeTurns: true`，상속된 기본 채팅 기록을 새 탭의 표시 콘텐츠로 반환하지 마세요. 이는 모델이 상위 컨텍스트를 상속하지 않는다는 의미는 아닙니다.。
3. **경계 설정**：데스크톱 사용 `thread/inject_items` 사이드 대화 경계를 삽입하고 상속 내역이 참조용일 뿐이며 사이드 채팅에서 새로운 질문을 기다리고 있음을 분명히 하기 위해 특별한 지침을 추가합니다. 기본 채팅의 이전 작업은 계속해야 하는 지침으로 처리될 수 없습니다. 기본 카피라이팅은 가벼운 탐색을 선호하지만 카피라이팅은 필수 권한 격리로 사용할 수 없습니다.。
4. **표시 및 전송**：하위 세션의 데스크톱 관리자, 모델, 액세스 및 승인 상태를 상속하여 별도의 측면 탭으로 표시됩니다. 재정의를 시작할 수 없습니다 owner 메인 세션을 복원하려면。
5. **닫기**：데스크톱은 필요할 때 먼저 하위 세션을 중단한 다음 `discardConversationFromCache` 상태를 폐기합니다. 이 기계는 평범해요 host 경로 호출 `thread/unsubscribe`；임시 세션 durable host 경로 호출 `thread/stop`。관련 임시 음성 기록 및 태그 기록도 삭제됩니다.。
6. **유효하지 않은**：제거, 종료, 세션을 찾을 수 없음 등과 같은 데스크탑 상태는 소비되고 입력이 비활성화되어야 합니다. 영구 채팅으로 자동 복원될 수 없습니다. 현재 빌드에는 약이 포함되어 있습니다. 3 몇 시간 동안 활동하지 않음 owner 제거 확인을 했지만 활성 보기가 있음、follower、요청을 실행 중이거나 보류 중인 경우 논리가 다릅니다. 이는 Side Chat Unity의 절대 수명이 아니며 제품 보증에 하드코딩될 수도 없습니다. 데스크톱 종료, 연결 해제 owner 다른 상황에서도 임시 세션을 복구할 수 없게 될 수 있습니다.。

기본 종료 UI 임시 채팅이 닫힌 후에는 복원할 수 없다는 메시지가 표시됩니다. 휴대폰으로 접속 후 Web 이 의미 체계도 유지되어야 합니다.。

## 권장 사항 및 확인 임계값

지원되는 데스크탑 포털을 통해 기본 관리자에 액세스하려는 노력의 우선순위를 정하세요. 이 입국이 확정되기 전에 독립 app-server 또는 일반 채팅은 다음과 같이 패키지됩니다.“네이티브 사이드 채팅”。나중에 수락하기로 결정한 경우 Bridge 임시 관리 지점, 이 제품 차이는 별도로 식별되어야 합니다.。

모든 액세스 방식은 먼저 합성 세션 인증을 사용해야 합니다.：

- 학부모 세션 실행, 초안、owner、모델 액세스、cwd 권한은 변경되지 않습니다.；
- 하위 세션은 컨텍스트를 상속하지만 자동으로 기록 작업을 계속하지 않습니다.；
- 생성 응답 손실, 재시도 및 종료로 인해 고아 세션이나 반복 전송이 발생하지 않습니다.；
- 닫은 후에는 기록 목록에 나타나지 않으며 자동으로 복원되지 않습니다.；
- 원래 오류가 발생한 후 클라이언트는 전송을 중지하고 자체적으로 확장하거나 재구축하지 않습니다.；
- 승인 요청은 올바른 하위 세션에서 처리됩니다.；
- 게이트웨이 다시 시작, 데스크톱 종료 및 SSH 연결이 끊어졌을 때의 상태는 동일합니다.。
