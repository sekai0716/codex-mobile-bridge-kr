# 기본 시스템 푸시: 로컬 개발 액세스

현재 preview 패키지가 구성되지 않았습니다. APNs 또는 Firebase 프로젝트는 백그라운드 작업 알림의 유효성을 검사하는 데 사용할 수 없습니다. 휴대폰 받은 편지함 및 로컬 예약 알림 테스트는 시스템 푸시와 동일하지 않습니다.。

로컬 개발 링크는 컴퓨터 게이트웨이입니다. → APNs / FCM → 휴대폰 시스템. 플랫폼 개인 키는 컴퓨터 게이트웨이의 개인 데이터 디렉토리에만 위치하며 휴대폰에 패키징할 수 없습니다. App、소스 코드 또는 공개 설치 패키지. 공용 제품의 통합 푸시 전송은 아직 배포되지 않았습니다. 국내는 없어 Google 서비스 장치의 제조업체 푸시에 아직 액세스되지 않았습니다.。

## 컴퓨터 게이트웨이

소스코드 실행환경 설치 디렉터리 requirements.txt。데스크탑 패키징에는 아직 이러한 선택적 종속성이 포함되어 있지 않습니다.。

게이트웨이 데이터 디렉터리에 생성됨 `mobile-push.json`，권한은 현재 사용자에게만 읽을 수 있도록 허용해야 합니다. 구성된 플랫폼만 추가：

```json
{
  "apns": {
    "teamId": "YOUR_TEAM_ID",
    "keyId": "YOUR_KEY_ID",
    "keyFile": "/private/path/AuthKey.p8",
    "bundleId": "io.github.try2love.codexbridge.preview",
    "sandbox": true
  },
  "fcm": {
    "projectId": "your-firebase-project",
    "credentialsFile": "/private/path/firebase-service-account.json"
  }
}
```

게이트웨이는 비밀번호 보호, 모바일 알림 받은 편지함, 해당 채팅에 대한 미리 알림을 활성화해야 합니다. 모바일 로그인 세션 CSRF 등록된 장치를 확인합니다. 등록은 현재 이벤트 위치부터 시작되며 기록을 푸시하지 않습니다. 만료됨/취소된 로그인은 푸시를 중지합니다. 오류가 다시 시도되어 실패합니다. Token 삭제됩니다. 서비스 제공업체가 요청을 수신했다고 해서 기기에 알림이 표시되었다는 의미는 아닙니다.。

구성 파일에 필드가 있다는 것은 구성이 채워졌음을 의미할 뿐이며 자격 증명, 종속성 또는 전달이 성공했음을 증명하지는 않습니다. 기본적으로 외부 푸시 서비스에 연결되지 않습니다.。

## iOS

가지고 있어야 한다 Push Notifications 유능한 Apple 개발자 서명. 현재 개인 무료 서명 미리보기는 이 수락에 사용할 수 없습니다.。

1. 에서 Apple 프로젝트의 구성 App ID、Push Notifications 및 APNs Token Key。
2. 로컬 푸시를 위한 빌드 구성 `BridgePreview/Push.entitlements`，매칭 재생성 provisioning profile。이 파일은 기본적으로 개발 환경을 사용합니다. 프로덕션 서명은 일치하는 환경을 사용해야 합니다.。
3. 이 빌드에서는 Info.plist 중간 증가 Boolean `BridgePushEnabled=true`。이 스위치는 기본 미리보기에 추가되지 않습니다.。
4. 컴퓨터 측 구성 APNs 매개변수, 휴대폰 설정에서 시스템 백그라운드 푸시를 활성화합니다. 일반공고 등록 Device Token；채팅 라이브 이벤트 오픈 후 별도 등록 Activity Token。
5. 알림이 켜져 있고 게이트웨이에서 추적 중인 채팅만 스마트 아일랜드（실행 상태, 확인 대기 중 또는 이 라운드 종료）를 업데이트합니다. 작동 상태는 변경 시 업데이트 및 저주파 보존을 채택합니다.，App 다시 시작한 후 기존 활동 재구독 Token。플랫폼은 전달 빈도를 제어하지만 여전히 실제 기계 검증이 필요하며 초 단위로 실시간을 보장하지 않습니다.。

## Android

일반 작은 크기 미리보기는 그대로 유지됨 없음 SDK 건설。`mobile/android-push` 선택 사항입니다 FCM 프로젝트를 빌드하고 동일한 인터페이스와 연결 코드를 재사용합니다. 아니요 Firebase 구성 시 자동 초기화 비활성화。

1. 같은 것을 위해 applicationId 만들다 Firebase Android App，플랫폼 생성 `google-services.json` 넣다 `mobile/android-push/`。이 파일은 무시되었으며 제출되지 않습니다.。
2. 사용 Gradle 8.9、프로젝트 내에서 JDK17 및 Android SDK35 짓다 `assembleDebug`。Firebase 플러그인과 SDK 프로젝트 종속성으로 다운로드됩니다. 별도의 자리 표시자 구성을 사용하여 로컬 컴파일 확인이 완료되었습니다. 이 테스트 패키지는 배포 또는 실제 푸시용이 아닙니다. 실제 사용에는 여전히 자체 플랫폼 구성이 필요합니다.。
3. 컴퓨터 측에서 동일한 프로젝트의 서비스 계정을 구성합니다. 휴대폰을 사용할 수 있어야 합니다. Google Play services 그리고 FCM 네트워크 연결。
4. 휴대폰 설정에서 시스템 백그라운드 푸시를 활성화하세요. 시스템 알림 권한은 여전히 ​​사용자에 의해 확인됩니다.。

이 프로젝트가 국내 제조사의 지원을 받는 것은 아니다. 정식 배포 전 별도 작성 필요 FCM 대상 제조업체의 실제 기계 수용。

## 수락

- 전경, 배경으로 전환, 화면 잠금, 네트워크 트리거 격리 작업 이벤트 복원이 각각 수행됩니다. 도착 확인 후 대상 클릭 후 배송 반복。
- 계정 확인/장치 제거 및 로그인 취소 후 알림 중지。
- 알림 지우기는 현재 컴퓨터의 받은 편지함 표시에만 영향을 미칩니다. 새로운 이벤트가 정상적으로 나타납니다。
- 스마트 아일랜드의 완료 이벤트는 활동을 종료하고 만료 시 마지막으로 알려진 상태와 시간을 유지합니다.。

현재 게이트웨이 등록이 구현되어 있습니다./배포 및 클라이언트 액세스 코드 플랫폼 계정 및 자격 증명이 없으며 실제 백그라운드 푸시 승인이 아직 완료되지 않았습니다.。
