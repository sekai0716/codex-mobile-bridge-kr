# NAS / Docker 공용망 입구

이미 사용된 것에 적합 NAS 역방향 프록시 Docker 애플리케이션, 기존 도메인 이름 및 HTTPS 인증서의 사용자입니다. 필요 없음 Cloudflare。

클라이언트에 침투하는 경우 또는 HTTPS 반세대가 뛰어든다**게이트웨이가 위치한 컴퓨터**，업스트림은 컴퓨터의 루프백 포트를 직접 가리킵니다. 제공된 포트를 사용하십시오.[침투가 있었네요 / 역방향 프록시 단순 구성](../../docs/external-tunnel.md)。이 페이지는 NAS 기다리다**기타 장비**컴퓨터 LAN 주소 역생성을 위한 고급 솔루션。

```text
휴대폰 → https://codex.example.com
     → NAS 의 HTTPS 역방향 프록시
     → 이 디렉토리의 Nginx 컨테이너（선택사항）
     → 컴퓨터 http://192.168.1.10:8787
     → 같은 컴퓨터의 Codex App → 지역 또는 SSH 채팅
```

**Docker 출입문이 배치되어 있습니다.。Codex App 게이트웨이는 여전히 원본에서 실행 중입니다. Mac / Windows 컴퓨터에서。** 게이트웨이는 동일한 사용자의 데스크탑에 의존합니다. IPC、세션 데이터 및 SSH 구성; 창고를 따로 적재하다 NAS 컨테이너를 다른 컴퓨터에 연결할 수 없습니다 App。넣지 마세요 `.codex`、API Key 또는 SSH 개인 키를 다음 위치에 복사하세요. NAS。

NAS 컴퓨터의 LAN 주소에 액세스할 수 있어야 합니다. 두 개가 동일한 네트워크에 있지 않은 경우 먼저 기존 네트워크를 설정해야 합니다. VPN 또는 기타 보호된 네트워크 연결; 집 NAS 캠퍼스 네트워크에 있는 컴퓨터에는 직접 액세스할 수 없습니다. 컴퓨터는 깨어있어야 합니다，Codex App、게이트웨이 및 필수 SSH 항상 연결 가능。

## 1. 컴퓨터 구성

컴퓨터 데스크탑 런처：

1. “네트워크 및 로그인”LAN 액세스를 활성화하고 현재 포트를 유지하며 계정과 비밀번호로 로그인 상태를 유지하세요.。
2. 에서“기타 연결 구성”다음에 추가“고정 도메인 이름 · NAS / 역세대가 생겼다 / Docker”，휴대폰을 채워주세요 HTTPS 주소와 NAS 접근 가능한 컴퓨터 HTTP 주소. 클릭 가능“배포 패키지 내보내기”채워진 주소의 구성을 가져오거나“복사하여 배포 Agent”。저장 후 게이트웨이를 다시 시작하십시오. 새 소스를 사용하기 전에 실행 중인 서비스를 다시 시작해야 합니다. 전화 연결이 잠시 끊어질 수 있는 시간을 미리 준비하세요.。
3. 활성화할 필요 없음 Cloudflare 일시적인 HTTPS。
4. “모바일 알림”고정 입구를 자동으로 사용하려면 알림 점프 주소를 비워 두십시오. 이전에 기존 주소를 수동으로 입력한 경우 해당 주소를 지우거나 새 도메인 이름으로 변경하세요.。

원래 시작 매개변수 뒤에 명령줄 배포를 추가할 수도 있습니다（예: macOS，Windows 사용 `py -3 -B`）：

```sh
python3 -B run.py --lan --origin https://codex.example.com
```

예제 도메인 이름을 바꾸고 IP；비표준이 있습니다 HTTPS 포트, 허용된 소스, 예약된 프록시 Host 알림 주소와 알림 주소 모두 포트를 포함해야 합니다. 경로나 끝이 없는 소스 `/`。

## 2. 하나를 선택하세요 NAS 설정

### A. 컴퓨터로 직접 전달할 수 있는 역방향 버전이 이미 있습니다（가장 간단한 버전）.）

Synology에서는 QNAP、Nginx Proxy Manager 반전시킨 후 추가하세요.：

| 설정 | 값 |
| --- | --- |
| 공용망 입구 | `https://codex.example.com:443` |
| 업스트림 계약 | HTTP |
| 업스트림 주소 | `192.168.1.10`（컴퓨터 IP） |
| 업스트림 포트 | `8787`（컴퓨터 게이트웨이 포트） |
| Host 요청 헤더 | 외부 도메인 이름 및 포트 예약，Nginx ～을 위한 `$http_host` |
| 타임아웃 | 읽기와 보내기가 모두 다음으로 설정되어 있습니다. 300 두번째 |
| 은닉처 / 응답 버퍼링 | 닫기 |

도메인 이름은 독립적인 하위 도메인 이름의 루트 경로를 사용합니다. 현재 웹페이지는 배포를 지원하지 않습니다. `/codex/` 평등한 길 아래. 웹 사용 HTTP 긴 폴링, 필요 없음 WebSocket。로그인 및 후속 쓰기 요청 `Origin`、`Cookie`、`X-CSRF-Token` 그대로 전달해야 한다。

이미 액세스할 수 있는 경우 컨테이너를 추가할 필요가 없습니다.。

### B. 누르기를 바랍니다 Docker 애플리케이션 통합관리 입구

에서 NAS 창고를 업로드하고 다운로드하세요. 이 지점은 `feature/desktop-ntfy`，입력하다 `deploy/nas`：

```sh
cp .env.example .env
```

편집하다 `.env` ～에 `GATEWAY_UPSTREAM`，컴퓨터를 채우다 IP 및 게이트웨이 포트를 실행한 다음 실행합니다.：

```sh
docker compose config
docker compose up -d
docker compose logs --tail=50
```

NAS 나만의 것을 가져오세요 HTTPS 반세대 목표 달성 `http://127.0.0.1:18787`，그리고 외부를 유지 Host。컨테이너는 전달만 담당합니다. 인증서, 도메인 이름 및 공용 네트워크 포트는 기존 프록시에서 계속 관리됩니다.。

외부 카운터 생성도 있는 경우 Docker 그것의 `127.0.0.1` 자체 컨테이너를 가리킵니다. 될 수 있다 `BIND_ADDRESS` 다음으로 변경 **NAS 랜 IP**，그런 다음 외부 레이어 업스트림을 역방향 생성으로 지정합니다. `http://NAS근거리 통신망IP:18787`；이 안티 생성만 이 포트에 액세스하도록 허용합니다. 넣지 마세요 `18787` 또는 컴퓨터 `8787` 공용 네트워크에 직접 매핑됩니다. 공용 네트워크를 예약하려면 여러 프록시 레이어가 필요합니다. Host、캐싱을 끄고 적절한 시간 제한을 설정하세요.。

이 항목 비활성화：

```sh
docker compose down
```

이는 컴퓨터 게이트웨이를 중지하거나 원래 LAN 주소에 영향을 미치지 않습니다.。

## 3. 수락 및 문제 해결

1. ～에서 NAS 컴퓨터 게이트웨이에 연결할 수 있는지 확인하세요. 그렇지 않은 경우 컴퓨터가 깨어나는지, 게이트웨이가 LAN 모니터링, 방화벽 및 교차 네트워크 라우팅을 활성화했는지 확인하십시오.。
2. 휴대폰 꺼짐 Wi-Fi，셀룰러 네트워크를 사용하여 공용 네트워크를 엽니다. HTTPS 도메인 이름. 먼저 로그인 페이지를 확인해야 합니다. 로그인하지 않으시면 채팅 내용을 보실 수 없습니다.。
3. 로그인 후 목록, 최근 콘텐츠, 스크롤 기록, 실시간 업데이트를 확인하세요. 전용 테스트 채팅에서만 메시지와 승인을 보내보세요.。
4. 테스트 채팅을 따라가서 확인해보세요 ntfy 이 고정 도메인 이름의 해당 채팅으로 이동하려면 클릭하세요.。

| 현상 | 조사하다 |
| --- | --- |
| 502 / 504 | NAS 컴퓨터에 접속할 수 있나요？ IP:포트; 컴퓨터가 최대 절전 모드인지 여부 컨테이너인지 localhost 컴퓨터로서 |
| “이 액세스 주소는 게이트웨이 구성에서 허용되지 않습니다.” | 컴퓨터 구성에 전체 구성이 포함되어 있습니까？ HTTPS 소스가 다시 시작되었습니다. 역방향 생성의 각 레이어를 유지해야 하는지 여부 Host |
| “교차 사이트 요청은 허용되지 않습니다.” | 주소 표시줄의 도메인 이름이 허용된 소스와 일치하는지 여부 잘못 다시 작성되었는지 여부 Origin |
| 로그인 후 계속 로그인 페이지로 돌아옴 | 완전 사용 HTTPS；상담원은 유지되나요？ Cookie；캐싱 비활성화 |
| 실시간 업데이트가 자주 끊김 | 외부 및 내부 프록시에 대한 시간 초과 응답 버퍼링; 캐시하지 마세요 `/api/` |
| 알림을 통해 이전 주소가 열립니다. | 알림 점프 주소를 설정하고 새 알림을 생성합니다. 수신된 알림의 이전 링크는 업데이트되지 않습니다. |

웹페이지를 공용 네트워크에 직접 배포한다는 것은 로그인 입구가 공용 네트워크에 열려 있다는 의미이기도 합니다. 게이트웨이 비밀번호 확인 유지、HTTPS 그리고 기존 NAS 접근 통제; 노출할 필요 없어 App IPC 끝점。

## 배포하다 Agent

먼저 컴퓨터 게이트웨이 주소를 확인하세요.、NAS 컴퓨터에 연결할 수 있는지 여부, 현재 세대의 위치 및 사용자의 위치 HTTPS 도메인 이름. 역방향 생성을 사용할 때 직접 연결하는 솔루션은 이미 있습니다. A，그렇지 않으면 계획을 사용하십시오 B。원래 LAN 포트, 모델 인증 또는 변경하지 마십시오. SSH 신임장; 게이트웨이를 다시 시작하기 전에 액세스 중단을 예약하세요. 완료 후 공용 네트워크로 복귀 HTTPS 링크, 예약된 LAN 링크, 비밀번호 획득 방법, 구성 위치, 시작 및 중지 명령, 실제 승인 결과 및 확인되지 않은 항목. 아니요 NAS 권한 접근이나 공용망 진입 시 준비된 구성이 전달되며 배포되었다고 주장하지 않습니다.。

구성기준：[Docker Compose](https://docs.docker.com/compose/)、[공식적인 Nginx 미러 템플릿](https://github.com/nginx/docker-nginx/blob/master/entrypoint/20-envsubst-on-templates.sh)、[Nginx 에이전트 모듈](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)。
