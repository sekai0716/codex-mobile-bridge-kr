# Codex Mobile Bridge：DSH 플러그인에 액세스

현재 컴퓨터 변경 DeepSeek Harness 링크된 아카이브 Bridge，원래 세션, 모델, 권한 및 작업 디렉터리는 유지됩니다. 플러그인은 로컬 루프백 주소만 모니터링하고 LAN에 대한 포트를 열지 않습니다.。

## 설치 및 바인딩

1. 게이트웨이에서 Test 의“클라이언트 및 액세스 → 액세스 추가 → DSH / 사용자 정의 Harness”안으로, 확장하다“타사 클라이언트: 수동 설치 및 바인딩”，선택하다“액세스 플러그인 패키지 내보내기”。둘 다 얻을 것이다 ZIP 및 `.tgz`。현재 시중에 나와 있지 않으며 다음 사이트에서 직접 다운로드할 수 없습니다. npm 설치 패키지 이름。
2. 연결할 준비가 된 타사 열기 DSH，실제로 사용하는지 확인 **Harness 코어 버전, 데이터 디렉터리, 현재 파일（profile）**。계정과 모델은 원래 클라이언트에서 먼저 구성됩니다. 다양한 클라이언트, 다양한 profile 다양한 데이터 디렉터리를 공유하거나 사용할 수 있습니다. 단지 디렉터리가 그렇다고 가정하지 마세요. `~/.dsh` 또는 `web`。
3. 클라이언트의 플러그인 관리 포털을 사용하여 설치하는 것이 우선입니다. 지원됨 npm 파일 패키징 시 완료 선택 `.tgz`；로컬 디렉터리 사용 시 압축 해제 지원 ZIP，포함 선택 `package.json` 의 `dsh-codex-mobile-bridge` 접는 사람. 클라이언트의 요구에 따라 설치를 완료하고 다시 로드하십시오. 작동하기 전에 현재 작업을 완료하거나 중지하십시오.。
4. 클라이언트에게만 있는 경우 CLI 플러그인 관리, 사용**이 클라이언트는 다음에서 지원됩니다.** `dsh`，그 현실에 `DSH_HOME` 및 profile 로컬 패키지를 설치합니다. 예를 들어 환경과 파일이 다음과 같이 확인되었습니다. `web` 시간：

   ```sh
   dsh plugin --profile web add "/절대 경로/dsh-codex-mobile-bridge-0.2.0.tgz"
   ```

   카탈로그 양식 사용 가능 `file:/절대 경로/dsh-codex-mobile-bridge`。플러그인을 설치하기 위해 새 기본 코어를 생성하지 마십시오. 그렇지 않으면 플러그인이 다른 파일에 설치될 수 있습니다.。Electron 의 `desktop` 전용 파일의 경우 일반 npm CLI 같지 않음 Desktop 지원 명령; 클라이언트가 제공하는 런타임 및 관리 포털을 사용해야 합니다. 기존 공식 클라이언트의 원클릭 설치를 계속 사용할 수 있습니다.。
5. 플러그인이 대상 파일에서 실행되면 다음이 생성됩니다. **데이터 디렉토리 / profiles / 파일 이름 / codex-mobile-bridge / binding.json**。원래 클라이언트를 계속 실행하세요.**같은 컴퓨터**게이트웨이에서 파일을 선택합니다. 또한 사용 가능“스캐닝 Harness 데이터 디렉토리”선택 후“바인드 파일”。스캔은 ID 파일만 읽고 세션을 자동으로 바인딩하거나 시작하지 않습니다.。
6. 팝업창 확인 profile、데이터 디렉터리와 플러그인 버전이 모두 대상 클라이언트에 속한 다음 바인딩을 확인하고 활성화합니다. DSH 휴대폰 접속. 다른 것이 있다면 DSH 액세스, 먼저“모바일 액세스만 비활성화”원래 컴퓨터 응용 프로그램을 종료하지 않고 다시 전환하십시오.。
7. 휴대폰 연결 **Bridge 게이트웨이 QR 코드 또는 주소**，입력하다 DSH 채팅 목록만 있으면 됩니다. 이 경로는 원래 클라이언트의 경로를 사용하지 않습니다. DSH Mobile QR 코드. 앞으로는 먼저 클라이언트를 연 다음 게이트웨이를 시작하세요. 게이트웨이는 타사 클라이언트를 대신하여 애플리케이션을 시작하거나 종료하지 않습니다.。

아니요 `binding.json` 일반적으로 플러그인이 파일에 로드되지 않았음을 의미합니다. 파일을 직접 쓰거나 다른 컴퓨터에서 바인딩 파일을 복사하지 마십시오. 버전이 호환되지 않는 경우 코어 버전을 확인하고 profile，강제로 설치하기 위해 호환성 설명을 제거하지 마십시오.。

## 사용 및 제거

- 게이트웨이는 동시에 하나에 바인딩됩니다. DSH 입장. 전환하기 전에“모바일 액세스만 비활성화”，그런 다음 새 바인딩 파일을 선택합니다. 컴퓨터의 작업은 종료되지 않습니다.。
- 계정 및 API 타사 클라이언트 내에서 구성；Bridge 타사 클라이언트의 인증 구성을 다시 작성하지 않고도 모델 및 계정 상태를 읽을 수 있습니다.。
- “바인딩 해제”이 게이트웨이에 대해서만 선택을 취소하세요. 플러그인을 제거하려면 클라이언트 플러그인 관리를 사용하십시오. 제거해도 채팅은 삭제되지 않습니다。
- `connection.json` 로컬 연결 자격 증명이므로 다른 사람에게 보내거나 릴리스 패키지에 넣을 수 없습니다.。`binding.json` 동일한 컴퓨터에서만 사용할 수 있으며 컴퓨터 간 연결에는 사용할 수 없습니다.。
- 채팅, 승인, 알림 및 보관 종속성에 사용됩니다. Harness 코어는 해당 인터페이스를 제공합니다. 알림 상속 Bridge 이미 알림 설정이 있습니다. 보관하려면 여전히 두 번째 확인이 필요합니다. 먼저 대상 작업 중지를 확인한 다음 기본 아카이브를 호출합니다. 실패는 성공으로 위장되지 않습니다.。

이 패키지에는 타사 클라이언트가 포함되어 있지 않습니다.、Harness 핵심, 계정 자격 증명 또는 채팅 데이터. 프로토콜 구현 적응의 소스 및 라이센스는 다음을 참조하십시오. `LICENSE.coding-mobile`。

## 호환성

이것은 Harness 제한되지 않는 핵심 범용 플러그인 Electron、Tauri 또는 클라이언트 이름. 코어를 제공해야 함 `profileContext` 그리고 이 패키지 `host.mjs` 필수 서비스 인터페이스 이름만 비슷하거나 Web 페이지는 호환성을 의미하지 않습니다. 현재 검증 코어는 `@deepseek-ai/dsh` 0.2.1-rc.2：macOS 의 Tauri v0.25.0 플러그인 조합、Windows 의 Tauri 및 DSH Desktop 2.0.18 핵심과 Linux 공식 핵심. 이 범위는 모든 타사 데스크톱 기능이 허용된다는 의미는 아닙니다. 다른 핵심 버전과 클라이언트는 여전히 독립적으로 검증되어야 합니다. 게이트웨이 바인딩 시 플러그인 버전을 확인하고 인증 핸드셰이크를 수행합니다. 단지 파일을 스캔한다고 해서 그것이 연결되었다는 의미는 아닙니다.。


## 패킷 형식 및 프로토콜

게이트웨이는 두 개의 자격 증명 없는 패키지를 내보냅니다.：ZIP 압축 해제 후 로컬 디렉터리를 선택하는 데 사용됩니다. 표준 `.tgz` 지원을 위해 npm 패키지 설치 항목입니다. 패키지에 포함됨 `host.mjs` 라이센스, 설치 시 컴파일 및 설치 스크립트가 없습니다. 이 독립 저장소에는 이미 완전한 런타임과 라이센스가 포함되어 있습니다. `npm run pack:local` 재현 가능한 설치 패키지 생성；Bridge 메인 저장소에 `plugin/` 하위 디렉터리는 여전히 내보내기 프로세스에 병합되어야 합니다. host 불완전한 디렉토리는 직접 공개할 수 없습니다. 공식 플러그인 마켓은 기본 내장 스토어가 아닌 사용자가 추가한 인덱스 소스입니다. 현재 공개 색인이 없거나 npm 풀어 주다。

이 판의 설명 `engines.dsh: 0.2.1-rc.2`，검증된 코어에 해당합니다. 핵심을 사용하고 필요한 서비스를 유지하는 한 다양한 클라이언트가 검증 대상이 될 수 있습니다. 클라이언트 브랜드, 창틀 및 프로그램 이름은 바인딩에 관여하지 않습니다. 아직 검증되지 않은 코어 버전으로 범위가 확장되지는 않습니다.。

독립형 플러그인 버전은 다음과 같습니다. `0.2.x`，게이트웨이는 유선 프로토콜을 지원합니다. `protocol: 1`、메시지 개정 `revision: 11`。호환성 패치는 더 이상 게이트웨이 내장 파일과 바이트 단위로 동일할 필요가 없습니다. 바인딩 파일, 설치 매니페스트 및 인증된 실행 플러그인은 일관성이 있다고 선언되어야 합니다. 업그레이드한 후에는 원래 클라이언트에서 다시 로드해야 합니다. 설치 경로가 변경되면 바인딩 파일을 다시 선택하십시오. 작동 중인 알 수 없는 프로토콜, 버전 시리즈 또는 이전 코드는 명시적으로 거부되며 쓰기는 호환성 다운그레이드를 시도하지 않습니다. 오래된 `0.1.0` 패키지는 알려진 소스 파일 해시만 유지하고 개정 확인을 실행합니다.。

바인딩 미리보기에 실제 내용이 표시됩니다. profile、데이터 디렉토리 및 플러그인 버전. 확인 후 인스턴스를 다시 확인하세요. ID，미리보기 중에 파일을 전환하고 다른 인스턴스에 바인딩하지 마세요. 설치 소스는 여전히 사용자가 신뢰해야 합니다. 프로토콜 핸드셰이크는 플러그인 서명 또는 보안 감사가 아닙니다.。

## 독립적인 유지보수 상태

독립적인 소스 코드 창고는 [try2love/dsh-codex-mobile-bridge](https://github.com/try2love/dsh-codex-mobile-bridge)。npm 패키지와 설치 가능 시장 지수는 아직 공개되지 않았으며, 소스 코드도 시장에 나와 있다고 볼 수 없습니다. 첫 번째 가져오기 소스 보기 `SOURCE.json`，유지 관리 및 동기화 단계를 참조하세요. [기여 명세서](CONTRIBUTING.md)。
