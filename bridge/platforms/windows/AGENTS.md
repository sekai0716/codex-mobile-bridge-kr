# Windows 플랫폼 유지보수

- 이 디렉터리는 Windows 설치 검색, 같은 데스크톱 세션의 프로세스 조회, 창 종료, 프로세스 시작, 명명된 파이프, ConPTY, Claude C# 네이티브 도우미와 호출 프로토콜을 담당합니다.
- Windows 고유 문제는 이 디렉터리에서 우선 수정합니다. `bridge.clients` 또는 `bridge.features`를 역방향으로 가져와서는 안 됩니다. 계정, 연결 상태 머신, 작업 유휴 상태 확인, 권한 부여, 재시작 판단은 해당 공통 기능 계층에서 처리합니다.
- Windows 경로의 대소문자 처리 규칙, 현재 데스크톱 세션 필터링, 정확한 실행 파일 신원 확인을 유지합니다. 종료 대상을 다른 프로필, 렌더러 프로세스가 속한 앱, 검증하지 않은 런타임으로 확대해서는 안 됩니다.
- `transport.py`는 원시 바이트 스트림과 취소 가능한 I/O를 반드시 유지해야 합니다. 취소가 완료되기 전에 사용 중인 핸들을 닫거나, 이 계층에 별도의 메시지 포장 형식을 추가해서는 안 됩니다.
- `terminal.py`는 ConPTY(Windows 10 1809 이상)를 사용하며 POSIX 터미널 모듈의 일부 공용 메서드를 재사용합니다. 입력 확인, 커서, 크기, 종료 동작을 수정할 때 양쪽 구현을 확인하고, 독립적인 비즈니스 규칙을 복제하지 않습니다.
- Claude의 취소·재시도·시간 초과 조정은 공통 연결 계층에서 처리합니다. C# 도우미는 지정한 앱 창만 조작하며, ‘스크립트가 제출됨’만으로 연결이나 인증이 성공했다고 판단해서는 안 됩니다.
- 관련 Windows 테스트 픽스처와 네이티브 검증도 갱신합니다. 다른 운영체제에서 모의 테스트만 실행했다면 Windows 실기기 검증은 완료하지 않았다고 명시합니다. 디렉터리 분리나 단위 테스트를 패키징 검증의 대체 근거로 삼지 않습니다.
