# POSIX 공통 구현 관리

- 이 디렉터리는 macOS/Linux의 프로세스 시작과 신호 전송, Unix 소켓, 지속형 PTY를 담당합니다. 두 운영체제에 같은 로직을 따로 복제하지 않습니다.
- `bridge.clients` 또는 `bridge.features`를 역방향으로 가져와서는 안 됩니다. 네이티브 구현은 계정, 세션 권한 부여, 클라이언트 활성화, 재시작을 결정하지 않습니다. 경로·PID의 소유 관계와 작업 상태 확인은 호출자가 담당합니다.
- `desktop.py`는 호출자가 선택한 네이티브 작업만 수행합니다. 환경 변수, 작업 디렉터리, 프로세스 그룹 동작을 유지하며, 신호를 보내는 대상을 확대하지 않습니다.
- `transport.py`는 바이트 스트림의 동작을 유지합니다. IPC 메시지 형식과 대상 owner는 클라이언트 계층에서 처리합니다.
- `terminal.py`의 일부 메서드는 Windows ConPTY 구현에서도 재사용합니다. 입력 ID, 출력 커서, 크기, 취소·종료 동작은 공통 계약이므로 수정할 때 Windows 호출부도 확인합니다.
- 이 터미널 소스는 SSH를 통해 원격 Python에도 전달되며, 원격에는 전체 게이트웨이 패키지가 설치되어 있지 않습니다. import 추가, 파일 분리, 리소스 위치 변경 시 소스 로딩과 `scripts/gateway-resources.json`을 확인해야 합니다. 로컬 import만 검증해서는 안 됩니다.
- SSH 실행 환경은 게이트웨이가 실행되는 로컬 시스템과 다릅니다. 로컬의 Windows/macOS 플래그로 원격 shell이나 프로세스 동작을 선택해서는 안 됩니다.
- 검증은 영향을 받는 로컬 PTY, 원격 소스 로딩, Windows 공용 메서드 의존성을 포함해야 합니다. 소스 검증, 패키징 리소스 검증, 실제 터미널 검증을 명확히 구분합니다.
